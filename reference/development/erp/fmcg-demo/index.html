澄禾快消：区域经销商演示数据

状态：合成场景与造数入口；目标租户是否已写入以实际执行结果为准。更新：2026-11-03。

为什么选区域经销商​

虚构企业「澄禾商贸」从食品、饮料、纸品和日化供货商采购，通过杭州中心仓、嘉兴周转仓、 绍兴配送仓向社区便利店、连锁商超和餐饮团购客户供货。选择常温包装商品，能在当前 ERP 内 串起采购、库存、分批履约、调拨、退货和结算，无须先建设生产或冷链系统。

这是对当前实现和面试讲解目标的设计选择，不代表真实企业数据。调研来源（2026-11-03 查阅）：

  • 金蝶：快消品经销商库存与资金场景： 核对多品类、周转差异与库存资金占用；不采用营销效果数字。
  • 用友：批发分销业务： 核对供销协同、多地点库存及采购销售财务的关联。

商品、品牌、企业、联系人、规格、价格、保质期、需求与季节系数均为合成参数。 税率固定为演示参数 13%，不构成适用税率判断；参考价按单据中的未税单价填写。 不生成真实手机号、税号、银行账号或企业交易。

数据内容​

唯一可执行定义在造数脚本。

对象内容
商品24 个明确规格的 SKU，6 类各 4 个
分类饮用水与饮料、常温乳品、休闲零食、方便食品与调味、生活用纸、家庭清洁
供应商6 家主营品类明确的虚构供应商，采购货篮与主营品类一致
客户12 家明确城市和门店名的客户，社区便利店、连锁商超、餐饮团购各 4 家
仓库杭州中心仓、嘉兴周转仓、绍兴配送仓
单位全部按整箱采购、销售和库存记账，规格说明箱内包装数量
结算账户非真实银行账号，通过正常接口加密保存
历史默认基准日前 12 个完整自然月，每月每客户 2 次补货

例如「清泉饮用水，550毫升×24瓶/箱」「牧原纯牛奶，250毫升×24盒/箱」 「麦香苏打饼干，400克×12袋/箱」「净家柠檬洗洁精，1千克×12瓶/箱」。 商品编码也使用名称与规格，不再用 Product、0-11、规格A 代替业务含义。

餐饮客户购买饮料、方便食品调味、纸品家清；商超和便利店覆盖六类。夏季增加饮料需求， 春节及九月增加乳品零食需求，连锁商超使用模拟批量价格。这是确定性场景参数，非预测模型。 每月每 SKU 额外备货 10 箱，以保留库存积压及资金占用的观察案例，不代表最优补货策略。

完整业务案例​

全部通过正式 HTTP 创建、审核、过账和核销，余额、流水、来源数量、金额快照、审计和 Outbox 由现有业务实现维护，不手工拼接余额。

案例数据形成面试中可以演示的问题
月度补货按渠道货篮汇总采购并入库谁供应了哪个仓的哪些商品？
多仓配送中心仓调拨到嘉兴、绍兴为什么总库存够，本地仓还需要调拨？
季节变化夏季饮料、特定月份乳品零食增加不同月份的品类销售有什么差异？
采购退货到货外箱破损退回 2 箱入库、退货、付款净额怎么对应？
销售退货门店拒收 1 箱并形成退货信用额如何回库存、冲应收？
部分收款一家商超每次只核销 50%已发货和未收款金额有什么区别？
未收款一家商超的出库保留未核销余额待收款来自哪些单据？
分批履约订单 20 箱，出库 10 箱还有多少未发货？
赠品入库供应商随货赠品走其他入库为什么库存增加却没新增采购应付？
试饮领用试饮走其他出库为什么库存减少却没有销售收入？
盘亏实盘比账面少 1 箱差异如何通过流水追溯？
待审核保留采购、销售和出库草稿哪些单据尚未影响库存？
库存不足草稿出库需求大于当前库存 30 箱为什么审核失败？

默认有 293 张销售订单、73 张采购订单，包括当前待流转案例；其他单据按真实流程派生。 运行结果返回案例对应的实际单号。正式单号仍按系统创建日生成，business_at 才是历史业务日期。 审核和流水时间是实际执行时间，不伪造历史操作审计。

可用这些 ERP 记录进行授权的本体/Logic Pack dry-run；造数不会自动创建或发布规则， 不会把旧推导换绑到新数据，也不代表正式模型联调已完成。

能力边界​

  • 保质期只有商品参考天数，没有批次生产/失效日期及批次库存，不能声称实现临期追溯和先到期先出。
  • 每 SKU 一种记账单位，不实现箱瓶换算；渠道在客户名称和备注中，不新增渠道表或 API。
  • 没有到期日契约时只称未核销/未收款，不把它写成逾期；参考进销价不是已核算的存货成本或毛利。
  • 退货沿原来源仓回库，没有质检冻结/隔离库存；赠品和试饮不代表已有促销、返利或费用分摊引擎。
  • 保留当前草稿/已审核状态，不凭备注虚构运输中、签收、合同或授信字段。

运行与验证​

在 backend/ 默认只预览，不连接业务服务或读取凭证：

uv run python scripts/seed_erp_fmcg.py --as-of 2026-11-03 --months 12

向空 ERP 演示租户写入，使用已授权管理员的当前租户 Token，经 ERP_DEMO_TOKEN 环境变量注入， 不要将 Token 写入命令行或文件：

uv run python scripts/seed_erp_fmcg.py \
  --apply --base-url http://127.0.0.1:8000 \
  --tenant-code chenghe-fmcg --as-of 2026-11-03 --months 12

执行前复验身份、有效成员及指定租户，要求超级管理员以免受限列表误判为空。 目标 ERP 非空即停止，不混入或删除旧数据；推荐独立演示租户隔离测试残留，沿用已有套餐与模块授权。 同一租户不得并发造数或在运行期间人工编辑。一次造数是多个正式事务，任何失败停止、没有全局回滚， 已提交记录保留，不自动重试或续跑。先核查备注和审计，再决定清理或新建空演示租户重做。 旧数据清理须单独核对备份和引用影响，本脚本没有删除开关。

cd backend
uv run ruff check app tests
uv run ruff check scripts/seed_erp_fmcg.py
uv run python scripts/test_creation_isolated.py tests/modules/erp/test_fmcg_seed.py -q --tb=short

测试只在执行器创建的 chein_creation_test_ 一次性数据库运行，模块导入阶段即阻止误用业务库， 不会等 db fixture 清理数据后才判断。覆盖默认 12 个月、每条流水累计、退货、核销、库存不足拒绝、 原有 SQL 反向校验及 app_runtime 无 scope/跨租户隔离。SQL 反向校验最后 ROLLBACK。

本变更不修改 Schema、Edition、API 或前端生成客户端。浏览器、外部模型和远端 CI 验收另行记录。 旧通用 SQL 造数及材料贸易外部单据样张仍是独立历史演示集，不与新场景拼接。

  • 一次性本机 PostgreSQL/Redis 上完成全年造数与两个既有订单回归：4 项通过。 另执行 uv run ruff check app tests scripts/seed_erp_fmcg.py 与文档路径检查。
  • 已在当前开发环境创建「澄禾快消演示」租户，代码 chenghe-fmcg，沿用当前管理员的既有套餐及成员授权。 在页面的租户切换入口选择该名称；普通成员仍须走正常授权，不自动授予读取权限。
  • 首次装载使用上述真实 ERP 命令生成、反向校验通过的合成快照，在管理员维护入口中进入目标 Tenant UoW，逐行重验目标租户并重绑定当前操作者，按外键顺序单事务装载 9,880 行。 同一事务重新执行库存/结算对账，通过后提交；原默认租户的业务数据未删除。
  • 目标已有的健康配置和后台对账记录保留；不复制源测试库的登录会话、Outbox、幂等回执或其他模块数据。 演示账户按目标密钥重新加密，导入的操作历史明确标记「合成演示历史」，不冒充目标环境的历史人工操作。
  • 目标 API 已返回 24 商品、12 客户、6 供应商、3 仓库、293 销售订单、73 采购订单、291 销售出库和264 收款单， 库存/结算对账状态为 passed。独立租户没有自动搬迁旧本体、Logic Pack 或推导记录。
  • 完整 SQL 反向校验在一次性数据库通过，另有 13 项 flow_sample_missing 提示，表示未准备全部反向/草稿组合， 不代表金额或库存差异。当前目标 app_runtime 未获数据库 TEMP 权限，不能直接运行需要临时表的整份脚本； 不为验证扩大权限。目标环境使用只读 SELECT 检查库存累计、余额、交易明细金额、审核日志与核销，并复验无 scope/无关租户不可读。 上述目标检查均为 0 条差异；库存流水 2,430 条。默认租户仍保留原 278 个商品。
  • 未执行浏览器交互、外部模型、正式本体发布和远端 CI；没有 Schema 或接口兼容变更。
