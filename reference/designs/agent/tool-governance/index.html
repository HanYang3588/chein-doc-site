Tool、MCP 与 Skill 治理设计

RAGFlow 当前采用原生 Tool 接入；本文 MCP 治理规划保留，ERP MCP 继续使用现有实现。

状态：Proposed（目标设计）

已实现的只读 MCP 接入及部署步骤见工具管理实施设计。本文中的供应链签名、沙箱、写工具和完整运营审批仍是目标设计。

1. 设计原则​

Tool、MCP Server 和 Skill 都是受治理的能力资产，不是模型可以自行发现并加载的插件。模型只能看到当前 Run 经授权后的能力描述，所有调用都经过 ToolGateway；默认拒绝、最小权限、可审计、可撤销和版本固定是共同规则。

Skill 是提示词、流程约束和少量代码/资源组成的能力包，负责告诉 Harness 如何完成一类任务；Tool 是产生外部读写行为的执行接口；MCP Server 是承载一组远程 Tool 的连接边界。Skill 自身不授予权限，不能通过文本声明绕过 ToolGateway。

2. 能力对象和注册事实源​

每个对象使用不可变的 code、version 和 digest 标识。Manifest 是声明事实源，Registry 是运行态索引；数据库只保存注册表引用、配置引用、租户启停和健康状态，不保存任意 import path、URL、命令或秘密。Agent Registry 复用仓库既有 capability/provider binding 和组合根原则，不另造 Edition 模块集合。

对象作用必要元数据
ToolDefinition注册表中的单个可调用动作声明输入/输出 Schema、只读/写入、权限、数据范围、风险、超时、配额、幂等能力、owner
MCPServerDefinition一组 MCP Tool 的连接边界transport、endpoint/stdio 配置、身份、允许方法、网络策略、凭据引用、digest
SkillDefinition版本化任务说明和编排约束instructions digest、依赖 Tool/Skill、模型/沙箱要求、输出 Schema、风险
CapabilityPolicy对主体、租户、Run 和环境的授权规则allow/deny、条件、obligations、审批、配额、有效期和 policy version

命名空间示例：tool.erp.statistics.query@v1、mcp.ragflow.search@v1、skill.analysis.explain@v1。MCP 原始工具名不能直接暴露给模型。

ToolDefinition 是注册和发布时的声明，运行时下发给 Harness 的是经过策略过滤的 ToolDescriptor；两者通过 code、version 和 digest 绑定，不能由模型自行修改。

能力执行位置默认副作用必经入口
业务/平台 ToolGateway Worker 的 ToolProvider只读优先ToolGateway + DataProvider
远程 MCP ToolMCP Adapter，经 egress proxy由 ToolDefinition 声明ToolGateway + MCP policy
stdio MCP Tool独立 Sandbox 中的 MCP Adapter由 ToolDefinition 声明ToolGateway + Sandbox
文本型 SkillHarness 上下文无直接副作用Skill allowlist + ToolGateway
代码型 SkillSandbox受资源限制Skill allowlist + Sandbox + ToolGateway

3. 生命周期和发布​

DRAFT -> REVIEW -> SECURITY_SCANNED -> TESTED -> CANARY -> ACTIVE
ACTIVE -> DEPRECATED -> DISABLED -> REVOKED
REVIEW -> REJECTED

接入需提交负责人、用途、数据分类、依赖、许可证、版本、digest、权限、风险、网络/沙箱资源和回滚方案，然后完成 Schema、依赖、SBOM/漏洞、提示注入、恶意代码、网络和凭据扫描。通过 Contract、Replay、Security、Failure 和 Resource 测试后才能灰度和加入 allowlist。

版本不可变，兼容性由 Schema/Provider contract 明确。Run 创建时生成 EffectiveCapabilitySet，固定 toolset/skillset、MCP Server digest、policy version、权限快照和过期时间；运行中的 Run 不静默切换版本。撤销会阻断新调用，历史注册记录和旧 Run 的 digest 保留用于审计与回放。

4. 能力发现和调用​

Harness 只能获得 Gateway 过滤后的 ToolDescriptor/SkillDescriptor，不能读取全量 Registry 或服务器凭据。每次调用、恢复、重试、审批后和子 Agent 调用都重新做策略判定；输出还要做 Schema、大小、DLP、引用和提示注入检查。

统一的 ToolInvocation 至少记录 invocation_id、Run/Attempt/Step、descriptor ref、input hash、Snapshot/approval ref、scoped credential ref、idempotency key、policy decision、provider request ID、result/artifact ref 和时间。

工具结果缓存通过 Higress response-cache 执行，但数据所有者仍是缓存语义和 TTL 的 负责人；缓存键必须从已完成租户、权限和数据范围校验的上下文生成，缓存状态不能替代 授权。缓存键与失效规则见Agent 缓存与请求合并。

5. 权限和风险控制​

调用必须同时满足：主体权限、租户权益、Agent 入口权限、Tool 权限、Dataset/字段 ACL、当前 delegated context、风险/审批策略、网络/沙箱策略和配额。静态 required_permissions 只是门槛，真实授权必须对归一化后的资源参数执行，不能接受模型提交的 tenant_id、wildcard、任意 URL、批量范围或字段扩权。

策略判定输入包括 principal、tenant、run/session/attempt、tool/server/skill code+version+digest、operation、Dataset/Snapshot、requested fields、risk、purpose 和 policy version；输出固定为 ALLOW、DENY 或 NEEDS_APPROVAL，并可附带 max_rows、fields、mask、egress、ttl 等 obligations。

权限采用上下文衰减：Gateway 为一次调用签发短期 scoped credential，只包含目标能力、租户、Run、数据范围、过期时间和操作 ID。Skill、模型、MCP Server 和子 Agent 只能继承权限交集，不能传递用户 Token、平台主密钥或扩大 scope。写入、导出、跨组织、网络、Shell、代码执行和敏感数据访问按风险进入 Human-in-the-loop。

6. Tool 管理​

Tool 分为平台只读、业务 Facade、写入、Sandbox、Retrieval 和 A2A Tool。每个 Tool 声明副作用；只读也可能因批量导出、个人数据或跨组织范围而需要审批。Tool 输入不得含任意 SQL、文件路径、镜像名或连接参数；Gateway 注入租户/数据范围并限制行数、并发、超时、输出和成本。

写 Tool 首期不注册。未来启用时必须绑定业务幂等键、Outbox、审批、补偿和审计契约；调用未知时查询 operation 状态，不能盲目重复副作用。

Shell、代码执行、宿主破坏性操作和业务外写请求的具体拒绝/审批/Sandbox 策略见Agent 滥用防护与执行安全；ToolGateway 仍是唯一执行入口。

7. MCP Server 与 MCP Tool​

MCP Server 先注册和审核，再暴露其中 allowlist 内的 Tool；发现到的工具不能自动上线。Adapter 验证 Server 身份、TLS/mTLS 或短期 OAuth、协议版本、能力声明、证书/签名、endpoint allowlist 和 digest，并将工具映射为本地命名空间化 ToolDefinition。Server 返回的 tools、resources、prompts、Schema、URI 和文本都视为不可信数据。

stdio Server 只能在受控 Sandbox 中启动，不能继承宿主环境变量或 Socket；HTTP/Streamable HTTP 只能通过 egress proxy 访问固定域名/端口，阻断 localhost、内网和 metadata endpoint。每个 Server 使用独立凭据引用、网络策略、并发、消息大小、分页和超时预算。

MCP Server 不得根据连接成功自动获得业务权限；Gateway 仍按 tenant、Dataset/ACL、Tool Policy 和 Run budget 逐次授权。协议错误、能力漂移、健康检查失败或异常调用进入熔断/quarantine/DISABLED。未知结果先由 Server 查询状态或使用幂等键，不假设 exactly-once。

8. Skill 接入和供应链​

Skill 是可版本化 bundle（Markdown 指令、模板、可选代码和资源），manifest 至少包含 code/version/digest/owner/license、适用 Agent/Workflow、输入输出 contract、允许 Tool/Skill 依赖、模型/上下文/预算、runtime/network/data scope、risk 和审批策略。

Skill 必须由受信构建流水线签名或校验 digest，运行时只读挂载，不允许隐式安装依赖、携带长期凭据、修改系统安全规则或要求任意网络。Skill 内容、示例、引用文档和检索片段都可能提示注入；加载前做来源、长度、DLP 和依赖检查，执行中的 Tool 仍逐次经 Gateway。

Skill 支持按环境、租户、Edition、Agent Profile 灰度、禁用和回滚。Skill 本身不能授予权限；子 Skill 只能使用父 Skill 与 Run 权限交集。Run 固定 skill_set 的 code/version/digest/prompt hash，撤销后新执行失败关闭，历史 Run 保留 provenance。

9. 审计、运营和验收​

注册、审核、扫描、发布、发现、授权、调用、拒绝、审批、重试、超时、熔断、禁用和回滚都进入审计事件，记录 tenant、subject、Run/Attempt/Step、能力 code/version/digest、policy decision/version、scope 摘要、input/result hash、Snapshot/Artifact/Approval ID、provider request ID、latency、size、outcome 和 error code。原始 Prompt、Token、凭据和完整数据只在有审计理由时进入加密存储。

运营端提供按能力、版本、租户查看 allow/deny/approval、错误率、成本、延迟、MCP 断连、Skill 加载失败和预算超限的视图，并提供租户级/环境级 kill switch。kill switch 只影响新调用，存量调用按取消和终端清理策略收敛。

进入 ACTIVE 前至少通过 Contract、Security、Reliability、Governance 和 Compatibility 门禁；失败时保持 REJECTED/DISABLED，不以降权后的隐式行为继续执行。

管理 API 只由 Backend 控制面暴露，例如 GET /api/v1/agent/catalog、POST /api/v1/agent/catalog/{kind}、POST /publish、POST /approve、POST /disable、POST /rollback 和 GET /effective-capabilities。平台管理员负责注册、审核、撤销和环境级 kill switch；租户管理员只能在已授予的套餐/模块权益内启停能力；普通用户只能查看本次 Run 的脱敏有效能力集。管理 API 的状态变化递增 capability/policy version 并失效缓存，不允许直接修改已绑定 Run 的版本。
