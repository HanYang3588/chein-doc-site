本体规则、状态与可溯源推导设计（Logic Pack）

  • 状态：Proposed；P0–P4 已有本地实现与验证，派生类型语义已确认，外部门禁仍未执行。本节实施证据与交付记录描述当前事实；不表示已上线或 ADR 已签署。
  • 范围：modules/ontology、modules/erp 的 ontology.data 能力、agent/ 的引用协议、frontend/.../modules/ontology。
  • 前置阅读：设计、OWL 画布、规则/推理集成、HermiT 架构、AGENTS.md。
  • 关联调研：Semantica（MIT）的推理、溯源与策略引擎，只借鉴概念，独立实现，不复制代码（见 research.md 许可口径）。

1. 目标​

用户在系统中：

  1. 用 OWL 画布建好本体（类、属性、关系）；
  2. 为其配置业务规则、状态机和派生属性，并绑定到真实业务数据；
  3. 发布后，Agent 通过现有 MCP 通道调用；
  4. 用户与 Agent 对话时，Agent 对真实业务实例做确定性推导，回答中的每个业务结论都能展开成“事实 → 规则 → 结论”的证明树，并可被独立重放校验。

验收一句话：Agent 给出的任何“能否/是否/为什么/处于什么状态”类业务结论，要么带有可点击的 derivation 引用并可重放，要么明确回答“无法判断（缺少哪些证据）”；不存在无来源的业务结论。

非目标​

  • 不做 LLM 推理或 LLM 打分作为推导依据（Semantica 的 GraphReasoner 明确不采用）。
  • 不提供通用或模型自动写回 Action；所有 MCP 工具只读。用户明确启动的 P5C 仅通过独立 ERP HTTP 人工审核命令使用辅助证明，范围见 ADR-0017 与交付记录，不扩展旧只读 DSL Action。
  • 不拆微服务、不引入运行时微前端、不新增运行时依赖（需要时先证明标准库与现有依赖不足）。
  • 不让模型提供 SQL、脚本、URL、身份或权限；不放宽现有租户/RLS/RBAC。
  • 不替代 HermiT：HermiT 继续负责 TBox 一致性、分类与蕴含；本设计负责操作型 ABox 规则。

  • 预算额外限制单个证明节点 32KB、累计节点内容 2MiB、工作步数 100000；固定小数渲染先检查指数和长度，超限为 INDETERMINATE。infer/dry-run 通过同一呈现函数返回目标、上下文、来源、声明结论及有界摘要；不将摘要解释为完整缺证据列表。时间条件参与刷新时点比对。
  • 2026-11-01 用户确认并实现：then:type 目标类为规则派生分类。ERP 类绑定只用于该类的实例身份/字段解析，不自动断言该类型；纯引擎也不接受直接类型事实或从断言事实沿 TBox 路径穿过派生类来绕过规则。已成立的类型规则仍可沿 subClassOf 证明其父类；未成立的分类不生成已知类型，缺证据继续传播 UNKNOWN/missingEvidence。临时 ambiguous_class_binding 拒绝分支已移除，枚举值仅保留兼容。

3. 总体架构​

核心原则：

  1. Logic Pack 与 OWL 版本绑定，不改写互斥规则。 Pack 是独立的不可变制品，引用 (network_id, ontology_version_id, rdf_digest)；rdf_document 与旧 DSL 的互斥校验保持不变。运行时只有“已发布 OWL 版本 + 与其摘要一致的已发布 Pack”这一对才可被 Agent 使用，摘要不一致失败关闭。
  2. 引擎是纯函数。 输入 = Pack 正文 + 规范化事实集 + 目标；输出 = 结论 + 轨迹。无 I/O、无时钟、无随机数、无 LLM；同输入必得同轨迹与摘要。
  3. 事实只来自数据所有者。 通过 ontology.data 新增只读操作获取；模型只提交枚举与实体引用。
  4. 缺证据是一等结果。 三值逻辑 TRUE/FALSE/UNKNOWN；UNKNOWN 附 missingEvidence，永不被改写为通过或拒绝。
  5. 轨迹即证明。 每个结论保存推导 DAG 与前提取值，可在无数据源访问的情况下重放，也可刷新比对漂移。

5. Logic Pack 元模型​

Pack 正文为版本化 JSON（schema: chein.logic-pack/v1），经 Pydantic 严格校验（extra="forbid"），不接受任何表达式字符串求值。

5.1 受限表达能力（禁止图灵完备）​

  • prop/rel 一律使用完整 IRI，与绑定键精确匹配；不按 local name 或 namespace 猜测字段（2026-10-31 用户确认）。

  • 2026-10-31 用户确认补充受限合取：all{conditions: Condition[]}（1–200 项），可用于量词和聚合过滤，采用同一三值 AND、变量安全、分层和预算检查；不接受字符串表达式。此项用于旧出库诊断按商品、仓库及单据联合匹配后汇总多行需求。

  • 原子条件仅限：type（类成员，含 TBox subClassOf 闭包）、cmp（eq/ne/lt/le/gt/ge/in/between/is_null/not_null）、rel（关系存在）、state（当前状态）、forall/exists/count/sum/min/max（仅限已加载快照内的有界关系集合）、finding（引用其他规则结论，用于规则链）。

  • 表达式算子白名单：add/sub/mul/div/min/max/abs/coalesce/date_diff_days；数字用 Decimal 语义；日期只能与 context.asOf（来自数据快照）运算，不得读取系统时钟。

  • 结论种类：type（推导类成员）、property（派生属性值）、state（推导状态）、finding（带编码/严重度/消息模板的业务发现）。

  • 否定仅允许分层否定；发布时检测循环否定、不安全变量、不可达规则、结论冲突（见 5.3），失败即拒绝发布。

  • 预算：规则数、事实数、迭代轮数、派生数量、轨迹节点数均有硬上限（建议起步 rules≤200、facts≤2000、iterations≤20、derivations≤5000、trace nodes≤5000），超限返回 INDETERMINATE:budget，不截断后宣称完整。

Case 仅接受 kind: synthetic，必须使用独立夹具实例命名空间；运行时不可把 Case 或其校验摘要注册为可引用的业务 derivation。

5.2 三值语义​

  • 每个原子求值得 TRUE/FALSE/UNKNOWN。属性缺失/无权限读取/快照被截断/聚合集合不完整 ⇒ UNKNOWN（并登记 missingEvidence{ref, field, reason}）。
  • 合取：任一 FALSE ⇒ FALSE；否则任一 UNKNOWN ⇒ UNKNOWN；否则 TRUE。分层否定 not(UNKNOWN)=UNKNOWN。
  • 目标 holds(f)：存在一条 TRUE 推导 ⇒ TRUE；所有候选规则 FALSE 且快照 completeWithinScope ⇒ FALSE；其余 ⇒ UNKNOWN。FALSE 必须附“哪条前提不成立”的反证节点。
  • completeWithinScope=true 只代表授权范围内完整，对外必须保留 wholeOntologyComplete=false 语义，不得宣称全库完整（沿用 HermiT 集成口径）。

5.3 冲突与优先级​

  • 两条规则对同一主体、同一属性/状态推出不同值，或推出互斥 finding，结果为 CONFLICT，返回双方轨迹，不静默按 priority 取其一。
  • 仅当规则显式声明 overrides:[rule_id]（无环）时才允许覆盖，并在轨迹中记录“被覆盖”。
  • priority 仅决定评估顺序与展示顺序，不决定真值。

5.4 状态机​

  • 状态可来自数据字段（source.prop 经绑定映射到 ERP 状态枚举）或由规则推导。
  • ontology_state_v1 返回：当前状态、allowedTransitions（逐条守卫求值，TRUE/FALSE/UNKNOWN + 轨迹）、blockedBy。
  • 状态机只读：不会改变业务数据。写回属于后续 Action ADR。

6. 数据绑定与事实获取​

  • 绑定由 Pack 声明，数据所有者代码目录是唯一合法目标（P2 仅 ERP 固定目录 RESOURCES/CATALOG；catalogDigest 在发布及每次调用时校验，兼容性复用 _compatible_catalogs 的“完整旧契约证明的纯增量”口径）。
  • 规则 then:type 的所有目标 IRI 都是派生类（2026-11-01 用户确认），即使声明了类绑定，快照也不自动生成其 rdf:type。绑定仍可用于身份、字段、关系、样本及目标选择。不能用真实或合成断言、或断言的 TBox 继承路径跳过规则分类；仅有规则证明的类型才能继续作继承前提。
  • ontology.data 新增只读操作 fact-snapshot-v1（向后兼容，不破坏已有 traverse/reasoning-snapshot-v1）：
    • 请求：root{binding,id}、relations[]（来自 Pack 绑定的白名单）、fields[]（来自 Pack 使用到的属性）、depth≤3、maxNodes≤200；fact-snapshot-v1 还固定至多 200 条边；
    • 响应：facts[]（subject/predicate/value/type/sourceRef{binding,recordId,field,recordUpdatedAt}）、dataSnapshotId、scopeDigest、asOf、completeWithinScope、truncated、missing[{ref,reason:not_authorized|not_found|field_unavailable}]；
    • 同一 repeatable-read 只读事务；身份/owner/仓库范围由当前授权解析；数据或 scope 改变则摘要改变；
    • 复用现有 _graph(..., snapshot=True) 的授权、预算、范围签名逻辑，扩展“属性值”输出，不另造一套查询路径。
  • 后续（P5，单独评审）：Datasource 目录绑定。仅允许由已启用表/暴露字段按固定形状（主键点查 + 声明外键）生成查询，不接收任意 SQL，不缓存样本，授权沿用数据源权限。
  • 事实模型是类型化三元组 + 来源引用，实例 IRI 沿用 urn:chein:erp:<tenant>:<binding>:<uuid>，保持与 HermiT ABox 一致，使两条路径可对照。

7. 推导引擎​

位置：backend/app/modules/ontology/application/inference/（纯 Python，禁止导入 ORM、Session、HTTP、第三方 Agent/模型框架）。

  • compile(pack) -> CompiledPack：Schema 校验、绑定校验、分层、安全性、冲突/循环检测、规则依赖图、bodyDigest。
  • evaluate(compiled, facts, goal, budget) -> Outcome{truth, trace, missingEvidence, stats}：
    • 后向链：从目标反推所需规则与事实，生成最小轨迹（回答“为什么”）；
    • 前向链：对单实体执行有界半朴素不动点（回答“它有哪些结论/状态”），仅在已加载快照内；
    • 确定性：规则按 (priority, id)、事实按规范排序；输出 JSON 使用规范化序列化（键排序、Decimal 字符串化）。
  • replay(compiled, trace, expected_digest) -> bool：先核对单独保存的可信摘要，再仅用轨迹内保存的前提事实与 Pack 正文重新求值，必须得到相同结论与摘要（用于 verify）；预算失败的未完成证明不标记为验证通过。
  • engineVersion 常量写入轨迹；变更语义时递增。 当前为 chein.logic/1.3.0；旧版本轨迹可在当前权限下查看，verify 不冒充新版重放成功；refresh 按新版重算并将版本变化视为 drifted，正式新证据需重新 infer。

轨迹（证明）结构​

{
  "schema": "chein.inference-trace/v1",

9. 发布门禁（Pack）​

发布需同时满足（任一失败则拒绝，沿用单账户发布 + ontology:publish，不伪造第二审核人）：

  1. 引用的 OWL 版本已发布且 rdf_digest 一致；该版本存在本人真实 HermiT 校验任务（沿用现有门禁，不能复用他人私有或改稿前的任务）。
  2. Pack Schema 校验、绑定对数据所有者目录 catalogDigest 兼容。
  3. 编译检查：分层否定、变量安全、无环 overrides、无互斥结论冲突（静态可判定部分）。
  4. 用例门禁：所有 cases 通过，且每个 goal 至少含 TRUE、FALSE、UNKNOWN 各一个用例（缺证据路径必须被测试）。
  5. 预算上限检查：输入事实数上界为“最大节点数 × 任一资源每节点最多映射事实数 + 最大边数 × 任一关系的 IRI 别名数”；映射事实数计入属性别名与非派生类型，then:type 目标类不计自动类型事实。无关系时只加载根（1 节点/0 边），否则使用 v1 的 200 节点/200 边上界；超过 facts 上限或分层超过迭代上限，校验/发布返回 budget。规则数及用例运行量也受门禁限制。该输入上界不是完成性或生产容量预测：复杂量词/固定点仍受运行时 trace/derivation/operation 硬上限，达到上限为 INDETERMINATE；校验记录明确 completionGuaranteed=false。
  6. 已发布 Pack 正文不可变；修改创建新草稿；发布新版本将旧版本置 superseded。

10. MCP 工具契约（新增，均只读）​

沿用 AgentToolSpec(name, permission, description, input_model, handler, delegated_permissions)；处理函数逐次重验成员、RBAC、模块权益、Tenant UoW；委托权限上限由 Pack 绑定到的数据所有者读取权限推导（与现有 ontology_* 工具同一机制）。描述沿用现有中文风格，明确“不是授权”“截断不等于完整”“UNKNOWN 不等于否”。

工具输入（均为枚举/引用/受限标量）输出

约束：

  • goals/stateMachines 目录返回固定映射的 subjectBinding，模型用它构造 subject.binding，不根据类 IRI 猜测 ERP 资源；目录过滤当前无根资源读取权限的目标。关系/库存等非根证据不足时，正式推导仍可返回 UNKNOWN，不以目录发现授予权限。

  • infer/state 必须携带 goals 结果返回的 packId，目标与状态机 ID 仅在该 Pack 内解析；同名局部 ID 不允许跨 Pack 自动选择（2026-10-31 用户确认）。

  • 并发与体积上限沿用 ontology_query_busy 风格的进程级限流；响应有大小预算，超限返回摘要 + derivationId，由 explain 分页获取。

  • 旧 ontology_diagnose_v1(erp.shipment_readiness_v1) 保持不变；它作为 P3 的回归基准（见 §13）。

11. Agent 侧：引用与回答约束（顶层 agent/，不进入 Backend）​

  • 新增引用标记 [derivation:<id>]，在 agent/src/chein_agent/citations.py 中仿照 [chunk:<id>]：只允许引用本次 Run 内工具结果真实返回的 derivationId；未知/他人/过期标记剥离并告警，不得由模型凭空捏造。
  • 兜底系统提示词（agent/ 内）增加规则：
    1. 业务结论（能否/是否/状态/原因）必须先调用 ontology_goals_v1 → ontology_infer_v1；
    2. 回答必须附 [derivation:<id>]，并引用 explanation 中的前提与规则，不得补充工具未返回的事实；

    5. Memory/个人候选不能当作业务事实或前提。

  • 前端把 derivation 引用渲染为可展开的证明树（事实→规则→结论），含“验证”（调用 explain 的 verify）与“刷新比对”按钮；沿用现有工具卡片与引用 UI 模式。
  • 观测遵循现有约束：Langfuse 默认关闭，metadata-only；轨迹前提取值不外发。

14. 安全与失败关闭清单​

  • 租户/owner 只来自可信上下文；tenant_id 绝不取自 body/query/header。
  • inference_run 读取前先验证记录属于当前 tenant + owner，再验证源数据权限；不返回他人轨迹，也不区分“不存在”与“无权”。
  • 模型不能提交任意规则、表达式、SQL、脚本、URL；规则只能由有 ontology:edit/publish 的用户在 Pack 中配置。
  • 预算、限流、响应体积、轨迹保留期全部有上限；超限失败关闭。
  • Pack/引擎/目录摘要任一不一致 ⇒ 拒绝推导并返回稳定错误码（pack_digest_mismatch、catalog_incompatible、ontology_version_not_current 等）。
  • 观测失败不影响推导结果与授权；日志不记录前提明文。
  • Memory、个人候选永不进入事实集或规则。

P5C（本地实现）证明卡片跳转 ERP 人工确认；提交前重放/刷新核验，复用 ERP 审核、幂等、库存及 OutboxADR-0017 Proposed；当前验证与外部门禁见 delivery.md

16. 风险与未决项​

  • 表达力 vs 安全：AST 白名单可能覆盖不了部分业务规则；以“新增算子需评审 + 版本化 engineVersion”扩展，不开放脚本。
  • 事实覆盖度：仅 ERP 固定目录可绑定；其他业务域在无数据所有者契约前保持关闭。
  • 快照一致性：asOf 与实时业务可能漂移，因此提供 refresh 并在回答里标注时间点。
  • 轨迹含业务明文：由 RLS、owner 限制、保留期、权限重验缓解；是否需要字段级脱敏待安全评审。
  • 与 HermiT 的关系：本设计仅使用已发布 TBox 的 subClassOf 闭包（确定性、廉价）；需要完整 DL 蕴含的场景仍走 HermiT 工具，并在轨迹中以独立节点引用其 jobId/inputDigest（P3 可选）。
  • 外部门禁：远端 CI、镜像扫描、签名、N-1 演练、团队签署（ADR 由 Proposed 转 Accepted）均未执行，需人工完成。
