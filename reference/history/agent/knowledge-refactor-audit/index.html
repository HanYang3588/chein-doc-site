Knowledge / RAGFlow / Agent 重构审计

审计状态：变更前代码与官方契约审计快照；最新实现见 五阶段实施与验收。 本文是重构输入与差距清单，不替代 Agent 架构 或既有 ADR。 遵循本次需求的执行顺序：“先输出 Current Architecture，不要修改代码”。本阶段没有修改生产代码、迁移、依赖、Nacos 或业务数据。

1. Current Architecture​

项目已有动态知识管理和受控 Agent 接入，缺口主要在检索编排与治理，不能按“尚无知识系统”重新搭建。

动态检索实际调用链：

  1. frontend/apps/web-pro/src/pages/agent/index.tsx 发起对话。
  2. backend/app/platform/agent_ui_router.py 校验当前用户权限，选择提示词，签发执行令牌并代理 SSE。
  3. agent/src/chein_agent/api.py 在租户、用户、线程、Run 范围内加载 checkpoint，创建 Harness。
  4. harness.py 使用现有模型、工具和原生 middleware。JEV 仅记录判断，不改变工具集合或执行路径。
  5. 模型调用 search_business_knowledge(question)，retrieval.py 向管理后端发送问题及执行令牌。
  6. Knowledge 内部 Facade 重新校验令牌、有效用户、模块访问和 knowledge:read。
  7. application/service.py::retrieve 计算可读库和已解析文档，映射 RAGFlow ID，调用检索接口，返回前重新查询库与文档权限。
  8. 工具结果回到模型，生成 [chunk:...] 引用；citations.py 只为真实工具结果中的片段追加下载链接。
  9. 点击引用后，动态模式通过 Knowledge Facade 再次校验文档 ACL。

知识管理不经过 Agent：管理页面 → Knowledge API → 本地元数据 + Outbox → RAGFlow。检索测试也不调用聊天模型。

4. RAGFlow 能力审计​

Dataset 更新库名称、描述、启用在 Chein 更新描述没有同步到远端；启用作为 Chein 权限过滤是合理的本地职责

Citation只引用实际返回的 Chunk应替换成 Chein ID 与受控预览 / 下载链接

对照 RAGFlow v0.27.2 官方 HTTP 文档：/retrieval 支持 similarity_threshold、vector_similarity_weight、page_size、knn_top_k、knn_num_candidates、rerank_candidates_count、rerank_id、metadata_condition。top_k 是兼容别名；聊天配置的 top_n 不能照搬。重排候选数与返回数不是同一个参数。返回示例提供 similarity / term_similarity / vector_similarity，不能凭空生成独立 rerank score。多库检索要求兼容的 Embedding 模型。

Chein Backend 是 Python 3.14，Agent 是 Python 3.13。当前后端已有带超时、固定资源路径、HTTP 状态与业务 code 双校验的 HTTP Adapter；Agent 兼容模式使用锁定的官方 ragflow-sdk==0.27.2。本地安装包的 Requires-Python 为 >=3.13,<3.14，不能直接用于当前后端，也不能为了“所有地方都用 SDK”把框架或 SDK 依赖搬进错误边界。

5. 当前检索行为的具体限制​

证据入口：backend/app/modules/knowledge/application/service.py::retrieve、public_api/dto.py、agent/src/chein_agent/tools.py。

  • Agent 只传问题，没有库选择、Agent Binding、Profile、会话检索上下文或 Trace 信息。
  • 用户管理页测试可以传当前 Chein base UUID，但 Agent 路径没有使用该能力。
  • 未指定库时搜索全部可读、ready、enabled 库；超过 20 库或 500 文档会拒绝，尚无候选目录分页与语义路由。
  • 只请求并返回前 5 个片段，每段最多 3000 字符。没有独立候选召回预算、Context 总预算、去重和 Document Boundary。
  • 原问题直接发送到 RAGFlow；不利用上一轮 ALTCHA、部署环境等上下文消解指代。
  • found 仅表示返回了片段，不代表这些片段足以回答问题。
  • 没有 Evidence Sufficiency、受限 Expand、Query Rewrite Retry 或结构化 ASK_USER 退路。
  • 动态检索不会在失败时回退到静态共享数据，这是必须保留的失败关闭行为。

6. JEV 与 Tool 审计​

JEV 不是待从零引入的依赖。decision.py 已调用阿里云 System One，校验有限 Choice、Noul、分布、有限值和结果大小；decision_middleware.py 已处理超时、故障、输入预算、同 Run 去重与 checkpoint 恢复。

当前仅支持 off/shadow。shadow 在模型调用前记录 intent 等判断，随后仍执行原模型调用。没有 active 路由、动态 KB 候选、置信度 Gate 或工具调用节约，不能宣称已降低延迟与成本。

阿里云当前官方 API 支持有限 choice/noul/score，适合受控路径选择，不生成改写文本。官方地址使用业务空间 Endpoint；仓库默认 Token Plan 地址是否适用于实际账号，需要真实配置与协议验证，不能由文档推断可用。

现有工具只有日期、ERP 统计、知识检索与 ask_user。ERP 统计工具在无 scope 时仍暴露给模型，执行内部会拒绝；应该在共享工具构建入口先过滤。内置 Prompt 当前要求 ERP 前先查知识，导致明确统计问题也可能产生不必要检索，应该移除强制前置。

附件的“订单 123456”场景不是当前工具能力：ERP 工具只提供概览和时间序列。应如实报告不支持或澄清；要完成订单查询，需要 ERP 所有者提供带权限的只读公开 Facade，不能让模型生成任意 SQL/URL。

SubAgent 当前由 Harness 明确关闭，宿主文件与执行工具也被禁用。测试应证明这些边界保持失败关闭，不能为了覆盖样例自动开启。

7. 观察、恢复与安全差距​

  • Run / Tool 事件与系统运行日志已有基础设施，但没有独立 Retrieval Trace、检索参数快照、候选结果、耗时分段、Token Usage 或 Knowledge Gap。
  • JEV 答案保存在私有 checkpoint，普通日志仅记录状态和耗时；应沿用敏感内容不进入普通日志的原则。
  • ACL 在动态检索和文档点击时重新检查，这是可复用的正确边界。
  • checkpoint 可保存历史 ToolMessage 中的知识正文。当前未发现恢复前逐来源重新授权和清除撤权证据的实现；这是待验证的安全风险，不能仅凭点击下载重新鉴权宣布恢复场景安全。
  • 远端结果来自服务账号，必须继续核对 Dataset / Document 对是否位于本次授权映射；Routing/JEV 结果不能替代这个检查。
  • 现有同步消费者捕获 RAGFlow 错误、落地 failed 状态并正常返回；此类错误不会进入 Outbox 自动重试。需要明确区分可重试网络故障与不可重试权限/参数错误，不能笼统宣称已有自动恢复。
  • 在线网络调用已有 timeout，但没有这条链路的熔断器。是否添加需要实际故障/并发证据；新增功能仍需有界尝试和总预算。

8. 当前前端结构​

模块路径：frontend/apps/web-pro/src/modules/knowledge/，使用现有生成 API 客户端、ProTable 与 Ant Design。

  • 菜单：我的知识库、共享知识库、系统知识库。
  • 列表：名称、说明、可见范围、状态、启用、更新时间、固定操作列。
  • 详情：文档管理、共享管理、当前库检索测试。
  • 文档：上传、文本笔记、进度、启用/停用、删除、失败重试、下载、片段预览。
  • 共享：当前租户成员远程搜索、reader/editor、所有者排除、重复成员禁止与错误重试。
  • 检索测试：一个问题输入，当前库 ID，正文列表与空结果；没有 Profile、分数、Metadata Filter 或 Debug。
  • 未实现 Agent Binding、角色/部门 ACL、文档 Metadata、已就绪重新解析、检索 Trace/Gap 页面与统计聚合。

10. Target Architecture（待实施）​

后端 Knowledge 拥有 Catalog、最新 ACL、Binding、Profile、RAGFlow ID 映射与 Trace 的授权存储。Agent 拥有有限决策、上下文改写、检索循环、Evidence 判断和回答。模型和 JEV 只能在服务端已经授权的候选集合中选择。

关键设计约束：

  1. 共享继续作为访问视图；ownership 与 ACL 分离。先支持实际存在的 User / System / Department 与 User / Role / Department 授权。Group / Project 需真实主数据及成员目录，不能只添加前端下拉项和未校验 ID。
  2. 固定 Agent 先使用稳定服务端标识；Binding 支持 REQUIRED / DEFAULT / OPTIONAL、优先级和 routing hint。Agent ID 不能只来自模型/请求 body。
  3. 用户明确选择的库集合是硬范围上限；REQUIRED 也不能扩大用户 ACL 或显式范围。没有配置的 Agent 必须有明确兼容策略，不将空 Binding 理解为无限授权。
  4. 简单请求复用主模型的工具参数生成；复杂指代才改写，多问题才有限 Multi Query。保存原问题与实际检索 Query，拒绝把 JEV 用作文本生成器。
  5. Profile 分别定义召回候选预算、RAGFlow 重排配置、最终证据数、阈值、总上下文预算与最大尝试。管理员维护，普通用户只选择允许使用的 Profile。
  6. RAGFlow integrated rerank 与多个 Query 合并后的全局排序不是同一事实。适配器只暴露真实返回字段；跨 Query 合并后可做 Evidence Selection，不能伪造二次模型重排分数。
  7. Retry 只覆盖适用故障与证据不足，设置总调用/耗时预算；Metadata 放宽不得删除安全条件或越过明确用户过滤。权限拒绝不重试，也不回退到静态数据。
  8. 高置信 JEV 可缩小已授权候选；中间置信度或服务故障复用主模型 Router；最终 fallback 只使用已授权 DEFAULT。配置阈值必须经过评测，不用示例 0.8 冒充实测值。
  9. Context 显式保留库/文档边界、真实来源与预算，文档正文作为不可信材料。Citation 外部仅使用 Chein 标识。
  10. Trace 默认存必要 ID、参数、阶段状态和真实耗时。问题/证据正文需受控读取、保留期限和访问审计；不可通过全租户日志或 Gap 聚合绕过撤权。未知 Token Usage 记录 unknown，不能编造数字。
  11. Gap 优先从不足证据 Trace 聚合，不为仪表盘先建独立数据平台。Trace/Debug 的权限不能加入默认用户权限集合。
  12. 保留 native HITL、取消、lease 和 checkpoint。恢复需重算能力并重新授权来源；关闭的 SubAgent 继续关闭。

12. 前端目标（待实施）​

  • 保留当前 Knowledge 模块与 Mine / Shared / System 入口，增加统一检索测试、Agent 知识配置。只有组织 ownership 落地后展示团队 / 部门分类。
  • 详情在现有 Tabs 上扩展 Agent、权限、配置与受限检索日志；列表可增加真实 owner、文档/Chunk/Binding 计数，避免逐行 N+1 查询。
  • 文档使用原生 Upload / Table / Progress / Dropdown / Popconfirm；增加批量操作、Metadata 与已就绪重新解析，并明确部分失败。
  • 权限维护复用 Select / TreeSelect / Drawer，提供 READ / WRITE / MANAGE；用户必须同时满足模块操作权限和对象授权。
  • 检索测试显示实际 Query、Profile、排名与返回分数；Debug 展示 Trace 阶段与候选，仅对获授权的管理者开放。
  • 文档预览与引用统一使用 Chein URL。操作列沿用 AntD 原生固定列，不新增全局样式。

13. 测试审计与后续验收​

当前已有测试源码覆盖：

  • Backend Knowledge：HTTP Dataset 创建/超时对账/真正权限拒绝；文档上传/解析/重试/删除；对象角色边界；空检索；跨租户写入；runtime RLS 与已发布全局系统库。
  • Agent：动态 Facade delegation 与禁止静态 fallback；静态 SDK timeout/filter/rerank；工具 scope 与参数校验；native HITL；JEV 非法分布、总超时、429 无重试、off/shadow 恢复与不改变图步骤。
  • 前端：共享 reader 禁止上传、上传 FormData、配置缺失、当前库检索、成员目录空/错误/搜索与保存。

本阶段只检查测试源码，未重新执行功能测试；先前任务的通过记录不能证明本次重构已验证。

新增实现必须补：有限 KB 路由、rewrite 保真、真实参数适配、Metadata filter、rerank 故障、Evidence 充分/部分/不足、bounded retry、授权范围内 expand、Chein Citation、角色/部门 ACL、撤权后的 Trace/下载/新 Run/恢复、JEV fallback、关闭 SubAgent 的拒绝路径、批量操作部分失败。

固定评测集至少包含内部部署问题、ALTCHA 指代、错误码/配置 Key、权限问题、明确 ERP 统计、统计加规则、无可用知识、跨租户与提示注入。记录 query、期望 Chein KB / document / chunk、期望工具路径。测试真实语料上的 Recall@K、MRR、Hit Rate、Routing Accuracy，与 mock 契约测试分开；不能用手写匹配规则对自己生成的假数据证明业务准确率。

后续命令已从仓库脚本核对：

# 使用隔离测试数据库与测试配置；禁止在业务库运行清理 fixture。
cd backend

uv run pytest tests/modules/knowledge tests/modules/test_manifest.py tests/modules/test_migrations.py -q
uv run alembic check

cd ../agent
NACOS_ENABLED=false uv run --frozen ruff check src tests
NACOS_ENABLED=false uv run --frozen pytest -q

cd ..

pnpm frontend:typecheck
pnpm frontend:pro:test
pnpm build:edition -- --edition base
pnpm build:edition -- --edition items
pnpm build:edition -- --edition suite

Knowledge 自有迁移还需通过模块迁移配置执行 upgrade / downgrade / check；Platform 的 alembic check 不替代业务模块检查。共享数据库测试串行执行。真实浏览器验证桌面/移动端、权限、上传、检索、引用和 Debug；Vitest 不等同浏览器 E2E。

14. 性能与已知限制​

当前没有真实检索 Recall、路由准确率、JEV active 延迟或费用基线，不承诺加速百分比。候选召回增加、重排、改写与重试均可能增加耗时；需要按实际快慢路径记录调用数、Token、首结果时间与 p50/p95。

本次未读取或修改远端 Nacos、账号 Key、Rerank Model 配置、RAGFlow 语料及部署数据库。因此未验证服务账号是否配置重排、所有库 Embedding 是否兼容、真实 JEV 套餐/Endpoint 是否可用、撤权恢复是否存在可复现泄露、实际 RAGFlow 存储是否使用 PostgreSQL。附件中的数据库名称仅作为检索场景，不当作部署事实。

完整目标涉及 Knowledge 与 Agent 两个边界、版本化内部契约、数据库迁移和前端装配。当前完成的是第一阶段审计；生产重构、迁移执行、评测、浏览器端到端、远端 CI、镜像扫描、N-1 演练与发布尚未完成。
