Agent 技术栈与外部集成设计

状态：部分实现。当前运行时已使用 Qwen OpenAI 兼容接口、Deep Agents、LangGraph 和 LangChain；RAGFlow 共享文档检索已实现最小只读切片。AgentScope、远程 Agent、 MCP、RAGFlow 私有文档 ACL/索引版本治理和 A2A 适配器仍为目标态。

1. Provider 和适配器​

目标态业务核心只依赖 AgentHarness、ModelProvider、ToolGateway、DataProvider、RetrievalProvider、SandboxProvider、ArtifactStore 等 Protocol。当前新检索通过 Knowledge v2 HTTP Facade 接入；SDK 仅用于历史共享来源的只读兼容，不用于新私有查询。Tool、MCP Server 和 Skill 的资产治理与权限事实源见工具与能力治理。

analysis.v1 + deepagents.v1 -> DeepAgentsAdapter
analysis.v1 + agentscope.v1 -> AgentScopeAdapter
analysis.v1 + langgraph.v1 -> LangGraphAdapter
analysis.v1 + langchain.v1 -> LangChainAdapter
analysis.v1 + remote.v1 -> RemoteAgentAdapter

EngineRegistry 只登记代码显式注册的适配器；数据库只能保存 engine code/version 和配置引用，不能保存任意 Python import path。每个适配器必须通过 Contract、Replay、Semantic、Security、Failure 和 Resource 测试。

2. 技术栈职责​

当前 Agent API 使用 Qwen OpenAI 兼容模式，通过 Deep Agents 创建 Harness，并用 LangGraph PostgreSQL checkpointer 保存执行状态。Deep Agents 的文件与执行类内置工具 被显式排除，模型可看到日期和只读 ERP 统计工具；共享检索配置完整且 scope 允许时， 还可看到 search_business_knowledge。当前 checkout 的 QWEN_BASE_URL 仍直连模型服务；按模型网关基线接入 Higress 后，该地址改指向 Higress OpenAI 兼容入口。

  • Higress AI Gateway：模型网关基线，提供 Qwen 兼容入口、路由、官方 ai-cache 模型 响应缓存和 response-cache 工具响应缓存；缓存策略见 Agent 缓存与请求合并。
  • Deep Agents：提供 Agent 循环、子 Agent 或文件工具；工具必须映射到 ToolGateway。
  • AgentScope：提供消息和组件运行时；生命周期映射为统一 RunEvent。
  • LangGraph：提供 StateGraph、节点、条件边和内部 Checkpointer；Graph state 不穿过业务契约。
  • LangChain：可复用 Model、Runnable、Tool、Retriever；不自动提供 Chein 的持久化、权限和租户隔离。
  • Remote Agent/MCP：通过签名委托上下文、能力协商、超时、版本和结果 Schema 校验接入；MCP Server 不能绕过 ToolGateway 暴露原始工具。

新流程先定义业务 DTO、权限、Dataset、错误码和事件，再实现确定性校验/快照/审批/报告验证，最后由目标框架编排。子 Agent 继承原始租户、数据范围、工具白名单和预算，不能自行扩权。

3. RAGFlow​

在目标架构中，RAGFlow 只承担检索 Provider 的职责：文档解析、Chunk、Embedding、检索、重排和引用候选。它不拥有 Chein 的权限中心、Session、Run、Checkpoint 或最终报告。

当前新查询使用管理后端 Knowledge v2 Facade，由后端映射已授权且启用/就绪的 Chein 库与文档 ID，再调用 RAGFlow 官方 HTTP API。Agent 使用签名执行上下文，不持有私人知识库的服务账号允许列表；无 Facade 配置时工具不注册。官方 Python SDK 保留为历史共享来源兼容，不作为新查询 fallback。

Knowledge Catalog 与 Agent 绑定缩小选择范围；租户 Profile 控制混合检索权重、候选数、可选 RAGFlow rerank、上下文与尝试预算。返回后再检查 ACL 与来源，引用只使用真实检索 chunk 标记映射 Chein 文档 ID。下载与恢复历史证据时重新授权；失效历史不进入模型。实现、默认值与迁移见 Knowledge Retrieval v2。

当前没有索引版本固定与历史精确重放；Agent 已接入结构化 Evidence Judge、有限重试与可选 JEV active，管理端检索测试不调用模型。检索或鉴权失败不能扩大范围或回退静态共享来源。后续私有检索评测须补 source checksum/索引版本的一致性验收，不能声称旧 Run 可按同一索引重放。

4. Agent-to-Agent​

另一个 Agent 作为 agent.call.v1 能力注册，声明目标、契约、输入输出 Schema、递归深度、超时和预算。每次调用产生独立子 Run/ToolCall，父 Run 只接收 Schema 校验后的结果或 Artifact 引用；禁止循环调用和主密钥下发。

5. 切换策略​

Run 固定 contract、engine、model、toolset、workflow、prompt hash、policy 和 dataset 版本。新引擎先做 shadow/replay，比较权限、数值、引用、错误码、事件和报告结构；通过后才加入 allowlist。旧 Run 继续由原适配器恢复，适配器不可用时进入 ENGINE_VERSION_UNAVAILABLE，不得静默切换。
