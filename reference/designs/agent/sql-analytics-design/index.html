Agent SQL 分析与图表收藏设计

状态：已获用户确认；B/C/D/E 首期切片已开发，本地验证与部署步骤见 交付说明。

本文保留设计及后续范围；实际实现和未执行门禁以交付说明为准，F/G 尚未实施。 2026-10-10 用户追加要求：分析接口改由现有 MCP 发布；Agent 保留图表/快照处理，旧 HTTP 配置仅供迁移兼容。 架构约束：Agent 架构、模块化实施基线、前端架构。

1. 推荐方案与确认范围​

复用 DeepAgents、LangGraph、现有模型客户端、签名委托、ERP 权限与 assistant-ui。在现有后端内增加受控分析能力，在业务模块内保存图表收藏；不增加 Agent 框架、独立 MCP 服务或 BI 平台。

推荐先实现 结构化分析计划 QuerySpec → 受控 SQL 编译 → AST 校验 → ERP 授权执行 → ChartSpec。首期覆盖采购、销售的金额与单据数量、时间趋势、排名及已发布分类。自由模型 SQL 会显著扩大验证范围，单靠 SELECT 或 SQLGlot 解析不能保证安全。因此将模型生成候选 SQL 作为后续受限模式，复用同一执行入口，默认关闭。它只能表达已授权指标、维度及关联，不能成为直接执行 SQL 的工具。

用户确认本设计后依次实施安全查询、决策辅助、聊天图表和图表收藏。查询权限必须与安全执行一起交付，不能先开放查询、再补部门权限。首期不开放敏感明细、跨模块 SQL、自动后台分析或定时刷新。

3. 需求与交付边界​

首期完整业务切片包括自然语言分析、授权目录、受控聚合、图表与表格、明确口径、历史恢复、个人收藏、名称/描述/分类管理、删除、手动刷新、打开时刷新、相对日期和继续分析。打开时刷新默认关闭，用户显式开启后执行一次，避免进入页面就连续查询。

金额、计数、日期、空值及同比环比均有确定性规则。缺少口径、时间或有多个指标含义时沿用 ask_user。空集显示“所选范围没有数据”；查询失败显示失败；禁止把权限拒绝、空值或失败改成零。

后续支持受限模型 SQL、复杂关联、多指标散点、面积图、异常统计、看板编排与自动报告。自动化分析须另行设计服务主体、权限复验、配额和调度；本次只保存可复用的查询定义与版本，不创建空接口或定时任务。

非功能要求：拒绝优先；每次执行和取数据都验证当前权限；连接复用不残留身份；每个数字可追溯来源与口径；有界查询、输出和模型调用；取消能终止数据库查询；新能力关闭后旧聊天/知识检索可继续使用。

4. 所有权与调用链​

  • agent/ 拥有计划生成、决策辅助、原生工具、Snapshot/产物引用、模型预算、状态与事件。
  • Platform 拥有可信身份、当前 RBAC、组织和数据范围解析。抽取现有 owner 规则为窄公开 Scope DTO，原 ORM 过滤器也使用同一解析结果，避免两套角色语义。
  • ERP 拥有数据集、指标口径、分析视图、仓库授权、SQL 编译与最终业务执行。它不引入 DeepAgents/LangChain，不直接调决策模型。
  • 新 backend/app/modules/analytics / frontend/apps/web-pro/src/modules/analytics 拥有个人收藏和管理界面。它依赖 Platform 和可选分析数据能力，不导入 ERP 私有 ORM、路由或服务。
  • 使用现有 ModuleDefinition 的 capability / composition root 绑定 ERP Provider。现有 registry 只解析 Provider 元数据，调用绑定仍需补充；仅增加当前切片需要的目录和执行 DTO，不建通用插件引擎。
  • SQL 安全共用代码放在后端稳定的纯技术辅助层，接受 AST 与明确白名单，不持有业务模型。ERP 决定许可的指标与关系；SQL 查询不会由 Analytics 模块绕过 ERP 私自访问业务表。

新业务能力在所属模块 ModuleDefinition.agent_tools 声明，避免在中央写第二份业务工具目录。Analytics 复用现有 /mcp 入口及签名委托，ERP MCP 与 Knowledge HTTP 接入保留。Agent 对获准的分析 MCP 工具处理图表和快照，模型仅看到 get_analysis_catalog、analyze_data。配置 MCP 后不回退分析 HTTP；部署顺序与兼容窗口见交付说明。

5. Decision Model 的真实能力与配置​

阿里云 System One API 的模型 ID 为 decision-model-preview，协议是 POST /compatible-mode/v1/systemone。请求含 model/state/questions，返回 typed answers。它不是 Chat Completions，也不生成自由文本说明。

当前 agent/decision.py 已有 async decide(state, questions) 与 classify，使用 httpx，校验 Choice/Noul、候选集合、概率、响应大小及模型名。使用这两个入口，不新增 SDK。

7. 授权 Schema Registry 与指标​

数据集是代码审核、业务所有者发布的版本化 DTO。模型只能看到当前调用者获准的目录；不扫描 information_schema、pg_catalog 或全库表名。每个条目包含 datasetId/version/schemaHash、物理受控视图映射、字段类型、敏感级别、指标/维度、允许聚合/过滤/粒度、单位、关系基数、所需权限、必需审查策略和资源上限。物理映射只给可信执行层；模型使用逻辑标识。

首期 ERP 发布已审批采购/销售事实，区分订单与入出库，不把用户的“票据数量”默认为销售出库数量。数量按单据唯一 ID 去重；金额使用已存单据快照，遵循退货扣减及每张单据全仓库权限，防止与明细关联造成重复求和。新增指标逐一对照现有统计结果验收。

不建可任意填 SQL 的管理表。Schema/metric 由模块代码与迁移定义；描述是待理解的数据，不是提示词指令。字段注释限长、无密钥、不给模型数据库凭据。

8. QuerySpec、SQL 生成与修复​

QuerySpecV1 使用逻辑 datasetId、version、metrics、dimensions、typed filters、timeRange、granularity、sort、limit 和分析类型。权限字段、角色、owner 列表、tenantId、DSN 及任意地址不能由模型输入。

示例是目标 DTO，不代表当前 API 已支持：

{
  "version": 1,
  "datasetId": "erp.sales_posting",
  "datasetVersion": 1,
  "metrics": ["net_sales_amount"],
  "dimensions": ["business_date"],
  "timeRange": {"type": "relative", "unit": "day", "count": 30, "includeToday": true},
  "granularity": "day",
  "filters": [],
  "limit": 500,
  "analysisType": "trend"
}

“最近 30 天”在 ERP 租户时区解析成含今天的 30 个日历日，并显示解析后的范围；滚动 720 小时作为不同口径，需明确指定。SQL 使用 UTC 半开区间，日期分组用同一租户时区，不直接 DATE(UTC timestamp)。刷新时重新求绝对范围，模型不决定服务器当前日期。

首期模型从授权候选形成 QuerySpec，受控编译器生成绑定参数的 SQL；合法输入只映射已发布聚合与维度。数值解释仍由现有聊天模型完成。后续受限模式由同一 Qwen Provider 生成候选 SQL，内部调用加 nostream，结果不能直接执行。候选必须与 QuerySpec 的表、列、指标表达式、时间谓词、粒度和过滤一致；不能用模型复核代替这些检查。

内部最多一次生成与一次修复。只有语法/类型、已授权字段引用等非安全错误可修复；安全/权限/函数/资源拒绝不修复。给模型稳定错误码和已授权候选，隐藏完整数据库错误与 SQL 执行细节。修复后重新授权、验证全部 AST、语义与预算。超时不自动重跑，避免成本翻倍。

9. SQL AST 安全边界​

采用 SQLGlot 的 PostgreSQL 方言解析全部语句，要求恰好一个非空只读查询。解析成功不等于安全或可执行；SQLGlot 官方也明确它是解析/转译器而不是数据库校验器。SQLGlot 文档

首期受控编译仅产生普通聚合 SELECT。Validator 必须检测 CTE、JOIN、子查询与 UNION 的存在并明确拒绝尚未发布的结构，不能在外层看见 SELECT 就放行。后续逐项开放时增加对应 scope/lineage、关系与基数测试。

校验流程：

  1. SQL 长度与 token/AST 节点预算 → PostgreSQL 解析 → 单语句与支持的节点集合。
  2. 禁止所有写入/DDL/权限/导出/过程执行：包括写 CTE、SELECT INTO、COPY、CALL、DO、MERGE、锁定 SELECT、EXPLAIN ANALYZE 等。
  3. 逐作用域解析关系、别名、CTE 遮蔽、列来源；未限定/歧义列拒绝。允许对象必须精确匹配 Registry，拒绝系统目录、临时表、外部表函数、任意 search_path 解析。
  4. 列、函数、运算符、cast 类型及参数白名单；只允许已验证的内置聚合/日期/数值表达式。拒绝 UDF、函数重载绕过、隐式危险转换、pg_sleep、set_config、current_setting、文件/网络/dblink/大对象函数、序列操作和 advisory lock。
  5. 拒绝未知语法、解析器降级节点、SQL 注释与 hint；通过 parser/token 信息判断，不用正则拆分 SQL。字符串内的 -- 或分号不是语句分隔符。
  6. 核对指标表达式、时间范围、过滤、粒度、输出列与查询预算。COUNT(*) 是已发布聚合的明确例外；拒绝投影 SELECT *。
  7. 对校验后的 AST 输出规范 PostgreSQL SQL，再校验最终 AST；执行规范输出与绑定参数，不执行模型原始文本。任何后续 SQL 改写也须通过完整复核。

关联只能使用发布的键与关系基数；禁止笛卡尔积和任意自连接。统计头表金额不能因为一对多 JOIN 重复求和。复杂结构未证明安全时返回 ANALYSIS_SQL_UNSUPPORTED，不会自动回退自由 SQL。

SQLGlot 是拟新增依赖：标准库和当前 SQLAlchemy 无法可靠解析不可信 PostgreSQL 文本、追踪 SQL scope。批准开发后锁定实测版本、更新 backend lockfile/镜像并跑攻击语料；本轮不安装。SQLGlot 支持解析的语法范围大于产品允许范围，默认白名单保持较小。

10. PostgreSQL 角色、分析视图与数据范围​

10.1 角色分工​

专用登录角色暂命名 chein_analytics，不是用户角色，也不替代 app_runtime。只给固定数据库 CONNECT、分析 Schema USAGE、逐个已发布视图 SELECT，以及确有需要的内置函数执行权。没有超级、建库、建角色、BYPASSRLS、角色提权、表写入、对象创建或无关表访问。管理员凭据只进入现有受控 bootstrap 流程，Agent/模型不持有连接凭据。

保留 app_runtime 处理收藏、审计与业务元数据写入。现有 provision_db_roles.py 的“所有表读写”授权函数不得复用于分析角色。扩展独立、幂等的分析授权步骤，迁移与权限配置均可预览；不在请求或启动中临时 CREATE ROLE。

还要审计继承角色、PUBLIC 默认授权、临时对象、扩展、函数和 operator/cast 的可执行面。角色默认只读是兜底，不是授权依据：可信基础设施每次事务显式设只读，不接受候选 SQL 修改事务设置。视图即使可更新，也不给任何写入权限。实际角色属性与拒绝路径必须实测。

10.2 视图所有权与权限模型​

ERP 迁移拥有 erp_analytics 分析 Schema 与版本化视图，收藏模块拥有 analytics Schema。模块 migration metadata/权限装配需要显式声明 ERP 的附加 Schema，不能创建一个无人负责的共享分析表集合。分析视图是内部数据库对象，模型通过逻辑 Dataset 使用它，不开放公共数据库访问。

推荐视图由专用 NOLOGIN、非超级、非 BYPASSRLS、非基础表 owner 的受限 owner 持有，仅它有最小基础表 SELECT。chein_analytics 无该角色成员资格，也无基础表 SELECT。视图开启 security_barrier，显式执行 owner/仓库范围；基础表已有 FORCE RLS 继续约束租户。视图 owner 的底层 RLS、函数和权限逐项验收，不能由迁移超级账号持有后直接开放。

不盲目开启 security_invoker=true：它要求调用者同时具备基础表权限，与“分析登录角色只读视图”的推荐边界不同。当前推荐使用受限 view owner，并证明其 RLS 不绕过。数据库版本和对象 owner 未核对前，分析能力保持关闭。PostgreSQL 视图权限、RLS 规则

10.3 复用现有数据范围​

Platform 公开接口从当前成员、有效角色、自定义部门与部门后代解析 OwnerScope DTO。规则保持与现有 owner filter 相同：多角色范围合并；all 只在当前租户内；普通用户自身范围与获准部门用户范围合并；超级管理员标志来自当前授权层，不来自旧委托或模型。ERP 再读取自己的仓库授权及模块/指标权限。

DTO 含 userId、tenantId、scopeKind、授权 owner IDs/全租户标志、scopeFingerprint，不暴露 ORM/Session。部门归属从当前 TenantMembership 解析，不能用全局 User 的部门代替租户部门。首期同步重查，不缓存授权结论；owner 数量超出执行预算时明确拒绝，不截断范围。将解析能力放在 Platform，ERP 不在视图中 JOIN Platform 私有组织表。

可信执行器用参数设置 SET LOCAL / set_config(..., true) 的租户、principal、Scope 和仓库上下文。候选 SQL 不可访问或修改这些 setting，且不能提供其值。view 缺失任何必需上下文时返回无行或拒绝；不能将缺失 scope 解释为 all。没有接入 owner/仓库条件的关系不发布到 Registry。

权限过滤发生在聚合前。对入出库单据，视图验证全部关联仓库均有授权；只显示授权明细的局部金额会改变现有语义，禁止这种替代。每个 JOIN 来源都须已授权，管理员仍不能跨租户；跨租户控制面操作不属于此能力。

这些 GUC 是可信应用执行边界，不声称能抵御已控制执行器或窃取数据库凭据的攻击者。AST 白名单、角色限制、受控视图、租户 RLS 和凭据隔离共同成立后才能开放。

11. 安全执行、预算与取消​

每次请求执行以下顺序：验证可信身份/当前成员/模块/指标 → 解析当前 Scope → 验证 QuerySpec/AST → 必要语义审查 → 再核对授权与版本 → 获取限额 → 只读事务设置上下文 → 查询 → 限量序列化 → 权限/版本复核 → 保存 Snapshot。队列等待、模型修复或恢复后不能继续使用先前授权结果。

专用池只属于可信 ERP 执行器，优先复用已安装 psycopg/SQLAlchemy。不同数据集按 Provider 授权，不复用管理账号池。每次事务结束 rollback/commit 使 LOCAL setting 失效；失败、取消和 timeout 也清理；异常连接销毁。禁止把 scope 留在 session-level setting，禁止池按“最后一个用户”复用授权。

12. Native SQL Analytics Tool 契约​

只增加两个模型入口：授权目录 get_analysis_catalog 和 analyze_data。目录按所需数据集读取，不一次输出全库。analyze_data 输入问题、QuerySpec 和可选 chart preference；后续受限模式才接受 candidateSql。没有裸 execute_sql(sql)，校验、权限、限制和结果验证不能成为模型可跳过的分散工具。

普通趋势可以一次原生调用完成编译、执行与图表准备；复杂请求需要先目录/ask_user。入口 Decision 的 business capability 必须识别新原生工具名；active 模式的工具筛选不能误删它，也不能凭判定注册未授权工具。工具注册基于 Analytics 及数据所有者权限交集，缺少 Provider 返回明确不可用，保留原 ERP 统计与知识路径。

结果为版本化结构，包含 status、queryId、artifactId/snapshotId、dataset/version、metric metadata、resolved timeRange、授权范围标签、sourceAsOf、rowCount、quality/warnings、合法图表描述及有界模型用数据。模型用摘要与页面 Dataset 分开；敏感值首期不进入模型。错误仅返回稳定 code 和可行动说明。

页面沿用工具开始、结果、错误事件与公开过程说明；内部 SQL 生成/修复打 nostream。复用已有 Tool UI 接收结果，避免为实时和历史建立两种来源不一致的 custom 事件。若后续确需分阶段进度，增加小型有界版本化事件，绝不向用户展示凭据、原始 SQL、供应商响应或内部推理。

13. Dataset、ChartSpec 与图表规则​

新增 Dataset DTO 必须表达每列的 type、nullable、unit、precision 与逻辑角色。金额以 Decimal 计算，JSON 保留十进制字符串；大整数也不直接转换为 JS 浮点。图表数值转换检查 finite、精度与范围，无法准确绘制时展示原始数据表及提示。null 表示缺失，0 表示真实零；不能沿用 AgentChart 的 numeric 无效值转 0 的行为。

保留现有 ChartSpecV1 解析和历史兼容，为本方案发布 ChartSpecV2。由后端 Pydantic/生成 JSON Schema 维护契约，前端生成类型并做运行时验证，不分别手工维护宽松接口。保留安全上限，V2 支持空数据并输出明确状态。

14. assistant-ui、历史与权限撤销​

复用现有 AgentToolFallback 注册受控分析结果 UI，共享 ChartRenderer，保留原工具折叠、回答顺序、思考提示、引用、ask_user 和取消。首期复用已安装 @ant-design/plots，不新增图表库。用 Ant Design Card/Table/表单承载图表操作，不用自建配置编辑器。

ToolMessage 结果保存受控 artifact/snapshot 引用、口径与小型模型摘要。历史沿用现有 checkpoint → ordered parts → tool-result → 同一个 renderer。获取 rows、刷新、查看数据、收藏、继续分析均经同源鉴权 API，前端不能自由拼接外部 URL。图表失败与过期保留占位和可行动说明，不吞掉整条回答。

历史可恢复不意味着旧权限永久有效。 历史投影和新一轮模型输入都识别 analytics tool-result 的 source/scope/version，重查当前访问。Scope、模块、字段或 Schema 变化时拒绝读取旧 Snapshot，隐藏对应分析结果及含旧数据的回答片段，要求重新分析；不能只把“刷新”按钮禁用。采用 native middleware 在模型调用前屏蔽失效分析上下文，不改执行循环，也不把恢复 checkpoint 当授权。

Scope 未变化的 Snapshot 可按保留期展示，并标注“历史数据，采集于…”。已有用户看到或复制的数据无法通过权限撤销收回；本方案控制后续服务端读取与模型再使用，不宣称能撤销已经到达客户端的文本。若无法证明整段分析正文和工具结果都受撤销控制，首期历史分析功能不得开放。

15. 图表收藏、刷新与继续分析​

收藏保存 QuerySpec、Dataset/Metric 版本、图表定义、相对日期策略、名称、描述、分类、owner、原始 thread/turn/artifact 引用和定义版本。SQL 仅为受限诊断信息，不作为永久执行凭证；V1 图表缺少可刷新 QuerySpec 时明确只读，不伪造刷新定义。

个人收藏首期仅创建用户本人读写；租户管理员不因此自动读取所有个人结果。共享、跨部门管理或公共看板另行设计。复制收藏不复制执行许可。创建收藏根据服务端 artifact 读取定义，不信任浏览器回传 SQL/Dataset/owner。

刷新：当前身份/成员/RBAC/模块/范围 → 校验定义/版本 → 重新解析相对日期 → 同一安全查询入口 → 新 Snapshot → 校验 ChartSpec → compare-and-swap 更新最新引用。定义更改与两个刷新竞态用 definitionVersion/refreshGeneration 防止晚到结果覆盖。刷新失败保留可读旧 Snapshot 并标注失败；权限撤销时隐藏旧 rows，绝不能“失败回退旧数据”。

打开时刷新仅执行一次，明确显示查询中，避免组件重挂载或 tab 切换反复请求。取消、删除收藏或改定义后，旧刷新结果不再写回。刷新/收藏操作有当前用户范围及 IDOR 测试。

继续分析只传 favoriteId 和新问题。服务器重查收藏归属与来源授权，注入经校验的 QuerySpec/口径；需要数据时重新查询或使用当前 Scope 匹配的 Snapshot。前端传来的标题、历史结果或 SQL 都只是非可信描述。沿用原新消息/Run/HITL，不创建另一套 Agent。

17. API、权限与配置​

目标 Analytics API 走 /api/v1/analytics：catalog、query/内部执行、query cancel、snapshot data、favorites list/create/detail/update/delete/refresh/continue-context。查询执行绑定服务器签发的 run/query 关联；普通用户不能凭任意 runId 成为该 Run 的执行者。Snapshot 数据经数据所有者当前权限校验，再由其所有者接口读取。

收藏权限暂定 analytics:chart:read/create/update/delete/refresh，分析执行暂定 analytics:query；还必须通过源模块权限，如 erp:statistics:query。权限与导航在 Analytics ModuleDefinition 声明；菜单使用现有 access，后端为最终边界。新 Dataset 要求的新权限不能被既有统计权限隐式覆盖。

新模块先加入 Suite 的 Edition YAML，生成 Manifest、路由映射和 API 客户端；Base/Items 不装配 Analytics，也不引入 ERP 静态依赖。页面无可用数据 Provider 时说明不可用，不从菜单存在性推断可查询。

拟新增配置放对应 Nacos runtime/bootstrap Data ID，默认关闭分析执行：

  • Backend：只读连接 Secret、连接池/资源限制、分析功能开关；bootstrap 私有 Data ID 保存角色配置与迁移管理员凭据。
  • Agent：固定 Analytics Facade URL、超时、查询/模型预算、受限模型 SQL 开关。URL 来自受控配置，禁用任意模型提供的地址与重定向。
  • 现有 AGENT_DECISION_*、QWEN_* 继续分开；新增分析审查模式明确区分 optional/required，不滥用入口路由开关。

本轮不修改 Nacos 或生产数据库。开发时根据实现命名配置，不先放置未使用的环境变量。Higress 后迁移只改变模型网关配置，不移动 ERP 数据权限；聊天/System One 均需各自验证 method/body/response、超时、usage 和错误。不得对授权敏感的分析工具开启无用户隔离的网关响应缓存。

18. Redis、权限一致性与缓存​

首期只复用元数据缓存及共享频率/并发控制，不开启查询结果或“allow”决策缓存。当前 RBAC namespace bump 是全局失效工具，不足以表达用户部门、仓库、模块权益和字段版本的全部变化。

后续启用结果缓存时，执行和读取前都重查权限；key 包含 tenant/user、完整 scope fingerprint（owner/仓库/权限/权益）、dataset/schema/metric versions、规范 QuerySpec、解析后的绝对时间、时区、source version。缓存 TTL 默认短，不能把“最近 30 天”的字符串当作每日相同范围。

默认不跨用户复用结果。只缓存精确范围的完整合法 Dataset，敏感明细无缓存。Redis 故障走重新安全查询，不用陈旧权限；频率控制故障仍拒绝。权限撤销后的历史 Snapshot 不是另一种可绕过缓存。

19. 日志、审计与成本​

复用现有 structured logging / ES 适配器与 MetadataLogCallback。日志记录 trace/run/toolCall/queryId、tenant/user、dataset/schema/metric、scope hash、SQL fingerprint、规则版本、审查模型/问题 hash、status、latency、rowCount、bytes、chart status、refreshGeneration。

不记录 DSN、Key、原始用户消息、原始结果、完整敏感 SQL 或供应商响应。页面只显示用途、进度、范围、来源、耗时和固定错误说明；入口决策仍沿用既有折叠卡，不额外将风险日志全部输出到聊天。

System One 调用通过现有客户端取 request_id、usage.input_tokens、latency_ms 等有限元数据，单独计量，不假定 LangChain Callback 会覆盖 httpx 请求。缺失 usage 标为 unknown，不能记为免费或零 Token。TokenPlan 实际单价/扣费/额度留给当前账号计费页与脱敏调用记录核对。

新增工作不默认启用 LangSmith，也不为了审计部署新日志平台。审计服务写入失败时不得把完整失败查询结果发送用户；成功 Snapshot 与引用就绪后才能宣称完成。审计中断留下可追溯错误，不伪造成功状态。

20. 自动化测试与验收门禁​

开发阶段必须使用独立真实 PostgreSQL，以 chein_analytics 和 app_runtime 两种受限账号执行，禁止并行运行共享数据库测试。假模型/Mock 用于确定性协议与故障测试，不能代替数据库安全证据。

范围必须证明
AST多语句、写 CTE、SELECT INTO、COPY/DO/CALL、未知函数、表函数、系统目录、注释、引号、CTE 别名遮蔽、子查询/UNION/JOIN、危险 cast/operator 均按明确规则处理；未知 AST 拒绝
SQL 质量少时间条件、错指标/粒度、重复 JOIN 金额、订单与出库混淆、UTC/租户时区边界、退货扣减、null/零/空集、同比基期为零
角色/视图只读事务、无写权限、无基础表 SELECT、无提权、视图 owner 非绕过 RLS、缺 scope 无数据、PUBLIC/函数权限检查
业务范围self、部门/子部门/custom、多角色 all、超级管理员、跨部门/租户、无角色/无模块权益、全部仓库与混合仓库单据；与现有 ERP 统计逐项一致
并发不同租户/用户复用连接、事务异常/timeout/cancel 后归还、scope 不残留、限额竞争、lease 到期旧查询仍被限制
生命周期排队/模型修复/审批/恢复期间撤销权限；取消 SQL 活动确实终止；晚到结果不可覆盖新 Run/收藏
Decision错误允许不能绕过硬拒绝；误拒绝可观察；低置信度、畸形 JSON、Score 未支持、超时/429、冷却、恶意描述/结果、必需审查不可用
图表各开放图形、空集、Decimal/大整数、NaN/Infinity、错 encoding、超量、负值占比、不支持版本、任意代码配置、历史与浮窗恢复
收藏tenant/owner IDOR、重命名/删除/刷新、相对日期、打开刷新一次、两个刷新及改定义竞态、Schema 失效、权限变更、继续分析及旧 Snapshot 隐藏
Edition/边界Provider 缺失、Base/Items 无引用、ModuleDefinition 与生成器、迁移/head、公开 DTO 无 ORM/框架对象

验收命令沿用仓库：cd backend && uv run ruff check app tests、受影响 pytest、模块迁移测试及 uv run alembic check、Agent 测试、pnpm frontend:typecheck、前端受影响测试与 pnpm frontend:build、base/items/suite 的 pnpm build:edition -- --edition ...。OpenAPI/Manifest 仅由仓库生成器生成。

Playwright 验证完整聊天与浮窗、1080p 和手机、亮/暗主题、查询/等待/结果/取消、刷新与撤销，不只检查 TypeScript。必要真实 Qwen 联调使用脱敏静态/测试业务数据，不打印 Key 或用户内容。远端 CI、依赖/镜像扫描、签名、生产网络和恢复演练单独列证据。

21. 性能与模型能力评测​

本轮没有 SQL 实现，不能给出实测吞吐、准确率、单价或延迟收益。首个性能基线记录数据库版本、CPU/内存、行数、索引、统计信息、账号、连接数及冷/热缓存。

比较关闭/影子/生效三种分析审查策略：相同脱敏问题、真实授权范围与人工标注。覆盖趋势、排名、混合知识、缺条件、恶意 SQL、遗漏时间和错误指标。至少分开记录 intent/semantic 分类质量、误拒绝、拒绝失效、p50/p95、fallback 比例、模型次数/Token、SQL/总耗时及数据库资源。不能用一次几百毫秒的接口结果证明所有场景收益。

建议首轮最低评测集 100 条，至少含 30 条攻击/越权、20 条语义错误与 20 条合法低风险；剩余覆盖多轮/刷新/故障。数量是验收计划，不是准确率保证。任何硬拒绝绕过为零容忍；合法误拒绝、语义收益与性能达标阈值由评测后共同确认，未达标保持影子或禁用。

确定性结构化低风险路径新增 Decision 调用目标为 0；复杂路径最多 1。数据库 deadline 是强限制，模型整体等待按实际超时显示过程说明，不承诺未知网络下的全链路 p95。用 T总 = 规划 + 可选决策 + 排队 + SQL + 产物 + 表达 分别分析；普通趋势不再串行调用意图、风险、图表、结果四个模型。

22. 主要失败场景与处理​

场景处理
SQL 只读但调用副作用函数AST/function/type/operator 白名单 + DB 权限；SELECT 不当作安全证明
普通 view 由超级 owner 持有发布失败；先改受限 owner 并验 RLS，不能仅加 security_barrier
RLS 仅隔租户、漏部门/仓库Dataset 不发布；与现有 Scope 和单据全仓库规则对照
Schema 漂移或口径变更精确版本/hash 不符拒绝；不静默执行收藏旧 SQL
模型误允许/输入注入硬校验保持；模型输入与授权隔离，单轮预算限制
必需审查超时/Score 未支持拒绝或澄清，不能故障时转“自动允许”
小群体聚合/差分推断首期仅已有允许的业务指标，不含敏感人口/个人维度；以后开放先加 k 阈值与互补查询策略，单次 cell 抑制不构成充分防护
数据太多/计划过贵返回稳定超限错误并建议缩小范围；不展示误导性的截断总计
权限变化后读旧图表取数据与历史/模型上下文复验，隐藏失效内容；权限不可回退
刷新失败或晚到当前定义/权限符合才保留可读旧历史；CAS 丢弃旧 generation
Redis 安全限流故障拒绝新查询；非安全元数据缓存可以绕过
Cancel / 进程崩溃queryId 绑定连接取消、deadline、事务清理；不声称外部查询因页面断流已自动停止

23. 分阶段实施计划​

阶段实施内容退出条件
A 设计确认确认 QuerySpec 优先、首批指标、个人收藏、受限 SQL 后置、默认预算本文确认；不自行把 ADR 标 Accepted
B 安全查询与权限Platform Scope 复用、ERP Registry/视图、独立角色、受控编译/AST、超时/取消/共享限额、审计真实受限 PostgreSQL 的权限/攻击/并发测试全通过；此时仍不开放 UI
C 原生分析切片模块声明、HTTP/native 适配、授权工具目录、预算、错误、Snapshot日期/ERP/RAG/入口决策/HITL 回归无破坏，金额和数量与业务口径一致
D 图表与历史V2 契约、复用 Renderer/Plots、Tool UI、同源数据读取、历史/恢复撤权全图形及亮/暗/手机验收；失效历史和模型上下文无旧数据访问
E 收藏模块ModuleDefinition/Edition、收藏 API/表/RLS、个人页面、CAS 刷新、相对日期、继续分析IDOR/撤权/刷新竞态全通过；Base/Items 隔离通过
F 决策评测与优化复用 decide，合并语义/风险问题；影子评测；可选结果缓存达到明确质量/成本门槛才启用约束；缓存隔离证明完整
G 受限 SQL 与后续图形受限 Qwen SQL、已发布 JOIN/CTE 等、area/scatter、EXPLAIN每个开放结构独立安全/语义/真实数据库测试；功能默认关闭直至验收

不按“先账号、后权限、先 SQL、后测试”的方式对用户逐步暴露危险能力。B/C/D 形成最小安全切片，E 形成收藏闭环；F/G 不阻塞规则型分析。SQLGlot、共享限额、取消与授权复验属于必做安全能力；缓存、多个决策服务类、通用看板引擎和微服务属于可省成本项。

24. 回滚、兼容与评审结论​

关闭分析功能并撤销 native tool 注册即可回到旧 ERP/RAG/聊天路径；保留 V1 图表解析、原 AG-UI 工具事件、已有 checkpoint。入口决策仍可独立配置 off。停止新刷新、取消活跃查询、禁用分析角色登录/连接权限时须由受控运维执行，不让模型发 SQL 操作账号。

先回滚应用并保留新表/视图与个人收藏，避免回退过程中删除数据。数据库 downgrade 只在依赖调用清理、备份与版本兼容验证后执行；保留有意义审计和收藏定义。旧版本不理解 V2 时显示“不支持的图表版本”与安全占位，不能猜测字段。变更 ModuleDefinition/公开 DTO 时同步架构规范与版本策略，不改 Accepted ADR 历史。

安全自检：执行权留在数据所有者；模型不能授权；租户、owner、仓库、字段与资源都由规则控制；数据库只读与视图 owner 同时检查；收藏/历史/缓存均不构成新授权。

性能自检：单数据集规则编译、复用安装依赖、低风险零新增决策、有限查询和小型 Snapshot；不承诺未测吞吐，不默认建结果缓存。

维护成本自检：两个原生工具、一个现有进程内的 ERP Provider、一个 Analytics 收藏模块和共享 Renderer；不增加通用 Agent/BI/MCP 服务、不复制权限规则或 SDK。

确认后需落实的业务/运维输入：首批“订单/入库/销售”的明确指标口径；目标数据库版本及受控角色部署窗口；资源默认值与 Snapshot/审计保留期。建议先采用本文普通聚合、个人收藏和预算默认值，以上输入缺失的数据集不开放。
