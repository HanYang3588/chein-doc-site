Chein 原生本体设计

状态：实施设计；实际验证与限制见 交付记录。模块依赖遵循实施基线，Agent 继续遵循Agent 架构。

边界与部署​

采用模块化单体：backend/app/modules/ontology 拥有模型、版本、审核审计和查询编排；frontend/.../modules/ontology 拥有 Studio。ontology 必选依赖仅 Platform，通过 ontology.data capability 调用 ERP Provider，通过 ontology.evidence 访问 Knowledge。可选提供者缺失时，建模仍可用，映射和数据执行失败关闭。Suite 加入该模块，Base、Items、ERP Edition 不新增入口。权益须由运营显式授予。

Studio→FastAPI 模块鉴权→本体 Tenant UoW→已发布版本→固定 capability→数据所有者当前授权→数据所有者 UoW。Agent 仅通过现有 MCP 使用相同服务；不新建 Agent HTTP 查询旁路。Backend 不导入 LangChain/DeepAgents，不访问 Agent Memory，不接受任意 URL、脚本或 SQL。

元模型与 DSL​

采用严格 chein.ontology/v1 JSON：objects、properties、relations、actions、metrics、concept groups、aliases、来源引用。对象 code 与属性 code 为稳定标识；display_key 可指定内部、可查询且可展示的实例标题属性，属性与分组支持描述；binding 是代码维护的数据资源 ID，property.source 是该资源白名单字段。字段包含类型、必填、默认、枚举、上下界、精度、唯一、可查询/展示、敏感级别；首期不支持继承，关系循环是合法业务图，继承/表达式递归不在 DSL 中。

关系包含端点、语义、方向、基数、反向标识和固定 binding；不能由任意外键自动生成。发布校验同时验证关系端点、字段、唯一标识、映射类型、Provider 指纹、Metric/Action 绑定及权限。仅有未绑定概念时可以保存草稿，不能伪装为可查询对象。

Action 由代码注册固定只读 executor，Schema 不能提高其权限或改为任意调用；第一期支持对象查询/指标等无业务副作用能力。写操作不开放，后续须有审批、幂等、事务及安全验证再注册。Metric 的口径与执行绑定必须一致，不能用描述文字改变实际算法。

存储、版本与发布​

PostgreSQL ontology schema 独立 Alembic namespace。Network 保存 tenant、owner、scope、name/code/description、并发 revision 和当前发布指针。Version 保存稳定 network/version、类型化模型 JSONB、状态、模型摘要、数据目录指纹、创建/更新/审核者及时间。Audit 追加记录操作、版本、actor、摘要和时间，不存业务查询正文。Candidate 保存本人文档来源与候选 DSL，默认私人，不由模型自动发布。

JSONB 是 Pydantic 类型化领域文档，不是画布坐标；网络身份、版本、状态、审计与来源具有独立约束/索引。版本唯一约束绑定 tenant/network/version；外键包含 tenant，禁止跨租户关联。全部 tenant-owned 表 FORCE RLS。ORM scope 附加过滤并拒绝 bulk DML、无 scope 写入、归属修改；退出恢复父 scope。

2026-10-28 本次实现调整：私有及租户共享本体均允许有当前 ontology:publish 权限的单账户发布。主流程为 Draft→Validated→Published→Deprecated；前端“校验并发布”按服务端返回的 revision 顺序执行 validate、publish。已处于 Validated 或 In Review 的版本直接进入 publish，不要求另一账户审核。旧 submit/approve 操作和 In Review 状态保留兼容，历史 reviewed_by 保留，但不作为发布授权依据；未审核版本不伪造 reviewed_by，实际发布人记录在 Audit。编辑后清除验证/审核，回 Draft。所有变更带 expected revision，在网络行锁内校验；发布仍复验模型、Provider、来源、映射指纹、本人真实 OWL 校验任务和当前发布权限。发布后正文不可变，编辑或恢复历史创建新 Draft，旧版本保留审计。废弃当前版本清空发布指针，执行者不能用旧版本继续查询。删除仅允许从未发布且无候选依赖的网络。

兼容分析报告对象/字段删除、类型和映射更换、关系端点/基数、Action 参数、Metric 口径变化。破坏性变化必须显式确认并重新校验发布；查询必须携带实际发布版本，版本切换后旧请求返回冲突，不能静默换模型。

查询与数据映射​

ERP 提供真实 Supplier、PurchaseOrder、PurchaseOrderItem、Product、Customer、ProductCategory、ProductUnit 七类固定资源。后续对齐实现与范围见 OpenBKN 对齐交付。每个固定资源声明字段、主键、过滤、权限和 Schema 指纹。订单复用现有 owner/部门 scope；订单行继承父订单 scope；供应商/商品遵循现有主数据权限。遍历首先验证起点可读，随后每跳应用两端权限及 owner 过滤，在同一 ERP 事务前后复验权限与数据范围，不返回未授权节点的数量或属性。

实例按 UUID keyset 分页，单次最多 50，返回 hasMore；不接受 SQL、列名表达式或任意 join。有限子图最多三跳、100 节点、200 边、30 次 Provider 调用并有总耗时预算；截断明确返回，不能称完整图。Provider 使用 statement_timeout/lock_timeout，异常转稳定错误。来源包含 ERP 资源、记录 ID、查询时间、本体版本和指纹。

首个金额指标为“已审核采购订单含税折后金额（按供应商）”：读取当前已审核订单 total_amount，按 business_at 的 [start,end) 时间范围过滤（最长 366 天），包含税费与订单折扣，不抵减退货/付款，不叠加押金，不代表已入库或现金支出；ERP 没有币种维度，不能跨币种推广。只聚合当前 owner/部门范围。金额用 Decimal 字符串输出，按明确上限返回分组并标记截断。

目录指纹与发布快照绑定；执行时比较，漂移返回 409，必须重新验证发布。仅数据所有者证明旧映射契约逐项完全不变的纯增量目录可兼容旧发布，见精确兼容证明。无跨请求权限/结果缓存，避免撤权后旧值继续可见。Neo4j 双 Provider提供显式发布语义图投影，保留本节的数据所有权；不自动双写业务数据。没有多数据库查询器、通用规则引擎、完整 OWL Reasoner 或向量投影；受控类层级推理与独立语义工作室见本次交付。

Context Loader 与 Agent​

模块声明 search、describe、query、traverse、metric、action 六个 _v1 只读工具。搜索只读取当前发布模型和当前用户有权访问的资源，按名称/描述/别名匹配排序，Top K 与序列化字符预算；字符预算是硬输出边界，不伪称精确 Token。describe 按相关对象返回属性、可见关系、Metric/Action 与来源。每次工具执行复验成员、RBAC、模块权益和目标发布版本。

复用现有 MCP 动态工具发现、DeepAgents 规划、子 Agent 策略、超时、Checkpointer、Run、OTLP/Langfuse metadata；不新增工作流/模型框架。自然语言业务问题的真实模型选择与证据引用必须在实际部署中验收，单元测试不能证明真实 Agent 分析成功。

文档候选与模型辅助​

RAGFlow 仍负责文档正文检索。候选只保存通过当前 Knowledge ACL 的来源 ID、版本/校验和、Chunk（可得时）、提取时间和候选 DSL；来源删除/禁用/撤权或版本变更后阻止合并/发布，且不能向新无权限用户展示原候选。私人候选不能直接升级为租户正式模型，必须由有权限编辑者明确采纳，并由当前有发布权限的用户校验后显式发布。

现有 decision-model-preview 支持有限选择题；本次复用其风险提示，不能把判断当发布授权。采用现有 Agent 聊天模型与结构化 Schema 做候选生成时，必须在顶层 Agent 实现，并记录模型、Token、耗时、输入来源、未验证判断；模型建议不改生产模型。确定性校验始终可独立执行。没有真正接通模型/RAGFlow 的环节在交付中明确标待验收。

Studio​

原生 ProLayout 菜单；网络列表、对象/属性表单、关系表单及可选择节点的关系图、映射目录/测试、Metric/Action 表单、校验问题、版本 diff、审核/发布/恢复、JSON 导入导出、结构化实例查询、详情、分页、筛选、有界实例图及 Agent/MCP 集成。支持范围明确的 BKN/ZIP 预检和导出见 互操作契约。当前 Neo4j 页面使用“保存草稿 → 校验并发布 → 确认图投影”；含 OWL 规则时先在规则页完成已保存版本的正式规则校验。校验失败停止发布；校验成功但发布失败时保留已校验状态，供用户明确重试，不自动重发或投影。复用 Ant Design Token、Form、Table、Drawer、Modal；图优先原生 SVG（有界节点布局，不引入画布依赖），表单是可访问编辑入口。大规模自由拖拽/路径分析需求出现后再评估单一图框架。图形布局不成为 Schema 唯一事实源。

验证与失败条件​

覆盖严格字段验证、重复标识、无效关系、映射漂移、口径不匹配、分页、图预算、发布冲突、单账户发布及权限撤销、不可变版本、恢复与废弃、Action 白名单、撤权重验、来源墓碑、跨租户读写和无 scope/bulk DML。数据库在一次性数据库串行执行，并额外以无 BYPASSRLS 的 runtime 角色验证；不得使用在运行 Worker 的共享队列。

模块/manifest/boundary tests、API 生成、前端类型检查/组件测试、Base/Items/Suite 构建、迁移 upgrade/downgrade/check、真实浏览器流程均为门禁。生产负载、EXPLAIN、故障注入、真实 Agent、真实 RAGFlow/模型、远端 CI/镜像扫描/团队签署独立记证据，不能由局部测试代替。

2026-10-28 发布流程简化验证​

本地验证：私有/租户模型单账户直接发布、旧 In Review 兼容、发布权限撤销、来源失效、映射变化、不可变版本与 app_runtime RLS 等在新建私有 socket-only PostgreSQL 集群中通过（29 passed）；结束后销毁集群。后端 Ruff 通过。前端全量 42 files / 342 tests 通过（包含发布及规则面板 15 项用例），覆盖校验失败停止、使用校验返回 revision、发布失败后显式重试和不自动投影。TypeScript 类型检查及 Suite 前端构建通过。

Playwright 使用临时静态服务和全部模拟 API 验证真实浏览器的同账户 validate→publish→确认后 projection:POST，无 pageerror，reviewed_by 保持空值。此结果证明页面流程，不代表真实 Neo4j/ERP/HermiT 联调。未触及真实数据库、ERP、图数据库或 Nacos，也未替用户发布模型；无数据库迁移、无新依赖、无接口字段/客户端重新生成。远端 CI、生产部署及真实服务发布/投影验收未执行。

独立 RDF Resource 画布​

已有业务映射图继续使用原有受限模型；新增 Resource 画布复用当前 Network/Version/Audit，独立 RDF 正文不能混入 ERP DSL。完整 OWL 作为 rdf_document 保留，未支持的复杂表达式只读。绑定、ACL、本人 HermiT 门禁、命令重放及显式 Neo4j 原子投影的当前实现和限制见 OWL 画布。这是同一 Ontology 模块内的手动发布/投影链路，不增加跨模块旁路事件或自动导入。
