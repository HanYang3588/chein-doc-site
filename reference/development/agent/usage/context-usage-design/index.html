Agent 上下文 Token 统计与可视化设计

状态：设计与代码已完成，本地验证见文末；未宣称生产上线。本文是本功能唯一设计事实源，运行边界沿用 Agent 架构。

1. 实施前审查与证据​

本机 agent/.venv 实际安装 DeepAgents 0.7.13、LangChain 1.4.0、langchain-core 1.6.3、LangGraph 1.2.11、langchain-openai 1.6.2；前端安装 @assistant-ui/react 0.15.21。依赖以各自 pyproject/uv.lock、package.json/pnpm-lock 及安装包为准，不能用 Backend Python 环境推断 Agent。

范围实施前实现与证据设计补充
主模型agent/src/chein_agent/model_provider.py::QwenModelProvider，ChatOpenAI 兼容网关；QWEN_* 经现有 Nacos Settings 加载可选模型输入/输出/总窗口元数据
主循环harness.py::create_data_analysis_agent 使用 create_deep_agent；Memory、Knowledge、Decision、Image、Analysis Middleware 会改变实际请求在最终模型回调边界计数，不能只数原始历史
压缩DeepAgents 自带 SummarizationMiddleware，默认存在；有 profile.max_input_tokens 时 85% 触发、保留 10%，否则 170000 tokens 触发并保留 6 条；另有旧工具参数裁剪与溢出恢复观测压缩后实际请求，不重写摘要、不改依赖源码
CounterDeepAgents 使用 LangChain count_tokens_approximately，已支持 messages/system/tools；媒体使用近似代价复用此计数器，估算必须显式标记
Usageobservability.py::MetadataLogCallback、langfuse_tracing.py、公共 metrics 已读取 usage_metadata/token_usage；QWEN_STREAM_USAGE_ENABLED 默认 true（2026-10-23 修复；显式 false 仍关闭）本人会话可恢复的数值元数据，不依赖观测开关或远端 Langfuse
流式api.py 的 messages/updates/custom LangGraph 流编码为 AG-UI SSE；前端 pages/agent/index.tsx 为 ExternalStoreRuntime，events.ts 处理投影增量 CUSTOM 事件及乱序保护
历史threads.py::read_thread_history 从有 tenant/owner 约束的 checkpoint 恢复；HistoryPage 支持游标初页附带 contextUsage，无新 HTTP 查询、无全历史扫描
子 Agent/Skills当前 Harness 关闭默认 general-purpose 子 Agent，未配置 skills 源；知识辅助模型与摘要仍可能调用主环排除摘要、工具内模型及子图；按角色和模型独立统计
模型切换当前只有服务端 QWEN 模型配置，无聊天模型选择器配置切换后换新模型元数据，旧占用不沿用；不为本功能新增选择器

Context7 当前凭据校验失败。官方页面和安装版本源码交叉核对：ContextDisplay、Context Breakdown、DeepAgents。main 分支仅用于调研；摘要行为以上述已安装版本为准。

官方 ContextDisplay 是可复制源码的 UI Element，非已安装 React 包的命名导出；官方运行时包装依赖 @assistant-ui/ai-sdk::useThreadTokenUsage，当前项目没有采用该 Adapter。本次复用其 standalone 组件源码与现有 Base UI Tooltip，显式传入 usage；保留来源与许可，不引入 AI SDK 或新 UI 体系。官方组件会保留最近非零用量，因此线程/模型切换与压缩更新须设置 resetKey。

2. 数据语义​

ContextUsage 为只含数值、公开模型标识、作用域 ID 和时间的版本化 DTO。字段：version、thread_id、run_id、agent_id、model_id、lease_epoch、sequence、invocation_id、context_limit_source、context_window、max_input_tokens、reserved_output_tokens、input_budget_tokens、context_used_tokens、context_usage_percent、remaining_tokens、last_input_tokens、last_output_tokens、cached_input_tokens、reasoning_tokens、measurement_source、measurement_status、context_state、last_updated_at、session_usage_status、session_usage。未知数值为 null，不能伪装为零。

  • 模型窗口 context_window 是输入与输出合计的已知上限；max_input_tokens 是输入上限，不能互相冒充。
  • reserved_output_tokens 仅来自实际请求的显式输出预算，不能把供应商最大输出能力当作已预留额度。
  • 输入预算为已知 max_input_tokens 与 context_window - reserved_output_tokens 中可确认的最小值；仅知道总窗口、未知输出预算时不承诺输入剩余额度。
  • 环形图表示 context_used_tokens / input_budget_tokens。百分比可大于 100，图形填充裁剪至 100；remaining_tokens=max(0,budget-used)，明确表示输入剩余额度。
  • 请求准备阶段：计数实际 messages（包含 System）和已绑定的 tool schema，标记 estimated/prepared_request。不计尚未发送的输入框草稿；不声称精确预测下一次请求。
  • 调用完成：优先 AIMessage.usage_metadata，再兼容 llm_output.token_usage。input_tokens 为该次输入上下文；output_tokens 单独显示，不能加进当前输入环。回调缺少 Usage 时保留该请求估算，标记 last_request/estimated。
  • cache_read 属于输入子集，reasoning 属于输出子集，仅真实存在时显示，不重复加总。
  • session_usage 按 agent_id + model_id 分桶，仅累计实际返回的输入/输出，并记录缺失 Usage 的调用数；不同模型保留独立分桶；摘要可展示已记录 Token 数之和，但不能作为完整计费口径。统计覆盖本功能启用后、进入 LangChain 回调的调用；HTTP 决策/图片/视频供应商未纳入，不将其伪报为完整计费账单。
  • 取消/异常仅发布未确认状态；已收到供应商实际 Usage 的模型调用仍可计为真实消耗，不因整个 Run 失败而抹掉费用。没有实际 Usage 的失败估算不持久冒充实测。

3. 数据流与隔离​

使用 on_chat_model_start/on_llm_end，不在每个生成 Token 回调计数。摘要通过 lc_source=summarization 单独分类；仅主图 model 节点更新主环，带子图 namespace 的调用归入 subagent，tools 节点内模型归入 auxiliary。未知角色不能提升为主 Agent。回调只保留少量数字与调用 ID，结束即移除请求临时项，不保存 Prompt/Schema 正文。

所有 REST 数据仍经已有 JWT、成员、agent:chat、可信 delegation、本人线程与 Run 查询。持久事件使用既有 owner/tenant、运行租约校验；统计恢复显式 join 当前拥有者，不能按客户端 run_id 绕过线程校验。Backend 只透传，不导入 Agent 框架。不增加 Redis、不创建 Token 新表或启动期 DDL。

4. 模型元数据​

在现有 QWEN 配置加入可选 QWEN_CONTEXT_WINDOW、QWEN_MAX_INPUT_TOKENS、QWEN_MAX_OUTPUT_TOKENS。解析后的可确认输入预算补充 ChatOpenAI profile，让内置摘要使用同一个真实输入边界（包括从总窗口扣除实际输出预留预算的情况）；显式输出值传入模型请求并作为预留预算。其余读取可信 SDK profile；没有 profile 就返回 unknown。优先级为当前模型的显式管理员配置、当前模型 SDK profile、unknown，禁止硬编码模型表，也不借用 Memory 专用输入预算冒充模型窗口。

修改 Nacos 仍遵循当前启动加载规则，本功能不改远端配置或自动重启。新字段全部可选；不确定实际网关能力时保持空值，环显示“?”并说明上限未知，已知实际输入仍可查看。新模型首次请求前不继承旧模型占用；同模型限额变更重新计算比例。

5. 持久化、事件与恢复​

每次完成的模型调用在已有 agent_run_events 保存一条 context.usage 元数据，租约校验防止旧 Worker 写入。invocation_id 为 LangChain 调用 ID，结束回调消费后不重复计数；恢复汇总按 Run/lease/invocation 去重。只聚合 Token 数字，数据库负责 SUM，不把全会话正文拉回 Python。

CUSTOM 事件使用 agent.context_usage、agent.context_compacted，包含线程、Run、lease、递增 sequence、模型和数值 DTO。主调用在准备/完成时发布占用事件；辅助调用更新自己的累计桶后可补发主快照，不改变主上下文占用与最近主请求指标。前端拒绝其他线程/Run、旧 lease、旧 sequence，历史响应沿用现有选择版本与 AbortSignal 防护；新建会话清空数据。

历史初页可选 contextUsage 字段兼容旧客户端。页尾翻页不重复加载统计；恢复最新主模型快照及各模型分桶，模型变更时保留历史累计但将当前占用置为 unknown。没有统计数据的老会话显示未知，不为了补齐面板重新调用模型。

压缩观察局限隔离在版本适配函数：只读取 updates 中实际 _summarization_event 的 cutoff 标记，不修改私有状态、不调用私有摘要方法。取得新主请求计数后发布 context_compacted；无法取得可靠压缩前值时 before_tokens=null，不能拿历史峰值代替。工具参数裁剪导致请求变小也按下一次输入更新；若当前版本未输出可靠标记，不虚报压缩事件，环仍按实际请求下降。聊天历史不删除。

所有统计估算、持久化、恢复和发布均有异常隔离；持久化有短超时，不重试或阻断正常回答，不开启新的追踪/外发。恢复失败显示未知及数据缺失，不能清零成完整账单。估算与供应商分词可能有偏差，尤其 CJK、媒体和私有序列化；请求组成单独使用本地估算的系统提示词、工具定义、对话消息；明确标记估算，不按供应商输入强行缩放。工具结果归入对话消息。

6. 前端​

在现有输入框上方提供会话统计、Token 用量、上下文占用三项紧凑摘要，输入框保持在最下方。新建对话居中展示（包括未发送草稿）时隐藏摘要；已有会话消息、输入框停靠底部时才展示。页面与浮窗共用同一组件，窄屏自动换行。三项均支持悬浮、键盘聚焦和点击/触摸展开。Popover 使用现有浅/深主题、手机触控/键盘打开，显示模型、总窗口、输入预算、占用/百分比/剩余、最近实际输入/输出、真实缓存/推理子项、来源/状态、更新时间及独立累计桶。尚未获取主 Agent 输入占用时隐藏圆环；已有输入占用但上限未知时显示“?”，超限仍显示真实数字。

数据在现有 ExternalStoreRuntime 的本地 contextUsage 状态维护，通过 React Context 向输入框组件传递，SSE 与历史使用同一个投影，不同时再向 message steps 写另一套累计。Ring 显式传入仅输入的 totalTokens；resetKey 包含线程、模型、lease/sequence，使零值、下降和切换均生效。使用数字快照更新，不重建 Thread 或清空消息。

启用与限制​

无需数据迁移，也无需新增密钥。先部署匹配的 Agent 与前端。已有 QWEN_STREAM_USAGE_ENABLED 仅在目标兼容网关确认支持流式 Usage 后启用；本次没有改变该开关。需要完整百分比时，在现有 Agent Nacos Data ID chein-agent-runtime.yaml / Group CHEIN 配置经过核实的 QWEN_MAX_INPUT_TOKENS，或同时配置总窗口 QWEN_CONTEXT_WINDOW 与实际输出预算 QWEN_MAX_OUTPUT_TOKENS。SDK Profile 已有输入上限时可直接复用。未核实的字段保持 null，不能照抄某个演示模型的窗口。

三个新字段全部可选；输出预算会改变实际模型请求上限，须依据目标模型文档配置，不能当成只影响 UI 的数字。配置仍按现有启动规则读取，本任务没有修改远端 Nacos、共享数据库、既有进程或生产部署。目标模型窗口、真实 Streaming Usage、计费、负载/TTFT、远端 CI 和部署联调尚未验证。

当前无聊天模型选择器；服务端模型配置更新并重载后，恢复接口会按新模型清除旧占用，再在实际调用时更新。压缩前 Token 没有可靠快照时保持 null。分类 Breakdown 与每个子 Agent 的独立面板暂未实现；当前默认子 Agent 已关闭，回调测试证明并行子图不会进入主环。累计仅覆盖本功能记录且具有实际 Usage 的调用；缺失调用与持久化故障会单独标识，不能当作完整费用账单。

2026-10-23 统计与展示修复​

  • 默认请求流式 Usage（stream_options.include_usage）。兼容网关若不支持可显式关闭；已有 Nacos 的 false 覆盖默认值，需改为 true 并按既有加载规则重启 Agent。没有真实 Usage 的历史调用不能补算为精确消耗，不会自动重放模型请求。官方语义见 ChatOpenAI。
  • 在既有 context.usage JSON 中追加可选 duration_ms、first_token_ms、tokens_per_second、context_breakdown；分桶追加 cached_input_tokens 与 cache_usage_calls。无需表结构迁移，旧事件缺失新字段时显示未知；恢复仍由数据库按本人租户/线程/角色/模型汇总。
  • 首 Token 时间跳过空控制块，TPS 使用供应商输出 Token 除以首内容至结束的时间；包含供应商已计入输出的推理 Token。页面明确时间指标对应最近主模型请求，调用数为累计模型调用，不能冒充用户轮数或工具步数。
  • 辅助调用完成时发布保留主上下文的累计快照，防止最后一个辅助调用的消耗只能刷新历史后看见。输入、缓存、输出、推理不会重复累加；缺失 Usage 显示未完整记录，不伪装为零。缓存仅在全部调用均返回缓存数时计算会话命中率。
  • 本地回归覆盖真实 SDK 的模拟 SSE（验证 include_usage 与最终 Usage chunk）、空 chunk、缓存、耗时、估算组成、去重、辅助用量刷新及前端异常/降幅/切换。完整页面浏览器联调仍受现有初始化接口 504 阻塞；独立组件预览使用合成数据，不代表真实供应商验收。

2026-10-23 明细对齐与按需说明​

真实开发页面曾缺失两列 Grid 模板的 CSS 规则，使标签与值排成上下两行。三个面板共用的明细改为逐行 Flex 两端对齐、固定行间距，并限制值宽度，未知状态与有值状态使用相同布局。统计面板及上下文组件改用已有 Base UI Popover，保留悬浮打开、点击和键盘操作，让面板内的圆形感叹号可以安全打开嵌套说明。计数、耗时、缓存口径、上下文及组成估算的说明统一放入指标旁的圆形感叹号弹框；TTFT/TPS 定义、累计分组口径及失败解释也按需展开，主面板仅保留简短指标名、数值和状态；缺失数据保留简短状态和说明入口。调用次数明确标记“累计模型调用”，不从调用次数、事件 sequence 或图调度步推导业务步骤序号。

Token 账本 P0 接入​

费用计量口径改由 Token 计费设计 与交付维护。原 context.usage、会话历史、乱序保护与上下文占用环继续保留；observe 模式下会话用量优先读取本人账本，性能移入诊断折叠区。off 模式沿用原显示；账本无行时保留旧累计并标记历史数据。账本会包含估算及独立决策/图片调用，不能要求其所有范围与旧 LangChain 已测量累计相等。
