本体与业务结合

本体把业务中的“对象是什么、对象之间有什么关系、哪些规则能够推出结论”写成可维护的定义。Chein 用 OWL 工作区维护概念，用 Logic Pack 表达受限业务规则，再从获准的业务数据生成有来源的推导。

适用范围：Suite Edition，已启用 Ontology，并已授予对应编辑、查询或发布权限。本文描述源码支持的流程；实际环境还需完成启用操作单。

OWL 工作区​

图 1：OWL 画布按类展示字段及数据类型，顶部集中提供工作区、保存、校验和发布入口。 查看原图。

从数据目录建立业务概念​

  1. 在数据源管理中建立连接、同步目录，核对表是否启用、字段是否暴露以及脱敏设置。
  2. 打开“AI 工作台 → OWL 可视化构建器”，创建独立空白工作区；也可以从文件创建独立本体。
  3. 从画布右键菜单选择“从已有数据源新增类 / 属性”，选择表、字段及必要的关系端点。
  4. 在画布中完善业务名称、类层级、对象属性和数据属性，再保存本体。

例如，把“销售出库单”定义为类，把单据状态定义为数据属性，把关联仓库定义为对象属性。名称便于理解；记录身份仍由数据所有者提供的稳定标识确定。

目录导入只复制定义。 它不会自动建立实时映射。选中带目录 IRI 的对象后，原始表面板可以按当前预览权限读取数据；面板不会把样本保存为本体实例。详情见目录导入与原始表预览。

校验并发布业务定义​

编辑保存形成可继续修改的正文；发布形成不可变版本。使用“校验当前草稿”取得本人、当前输入对应的 HermiT 成功任务，再执行发布。修改正文后需重新校验。

原生工作区的正文、版本和权限由 PostgreSQL 管理。历史 Resource 绑定工作区另有显式 Neo4j 写回流程，两者不能混用。复杂 OWL 校验与业务规则求值也有不同职责：HermiT 检查声明的逻辑语义，Logic Pack 生成受限业务规则的证明。详见构建器说明与推理集成交付。

图 4：规则与状态入口要求先校验并发布本体。 查看原图。

用规则解释业务状态​

在工作区的“规则与状态”入口配置 Logic Pack，绑定已发布 OWL 版本及数据目录摘要，再选择要推导的目标和业务实体。系统从获准快照求值，保留证明及使用的前提；可在本人推导记录中核对来源并重放。

结果如何理解下一步
TRUE当前快照和规则支持该结论查看证明，并继续核对业务操作权限
FALSE当前规则求值得到否定结果查看导致否定的前提
UNKNOWN现有证据不足以判断补充合法来源或修正规则，重新推导

缺少数据不等于满足条件；授权子图的结论也不能代表全库。假设分析只比较允许修改的标量字段，结果属于假设，不能用来审核业务单据。详细边界见Logic Pack 设计与实施证据。

结合 ERP 销售出库审核​

当前首个带证明的业务动作是人工销售出库审核：

  1. 对本人有权访问的真实出库单生成有效推导，核对证明与来源。
  2. 从获准入口进入 ERP 审核页面，检查单据、版本和当前库存条件。
  3. 由当前用户确认。ERP 重新校验证明、数据快照、归属和审核权限，再执行库存事务。
  4. 在业务页面核对最终单据状态；推导成功本身不表示审核已完成。

过期、他人、合成、假设或数据已变化的证明不能用于审核。Agent 的相关 MCP 工具保持只读，卡片提供跳转；模型不能凭 TRUE 结果自动执行审核。当前实现和外部门禁见本体交付与ADR-0017（提案）。

外部数据与 ERP 的边界​

Logic Pack 外部绑定和目录复制导入是两条路径。首版外部绑定仅支持 PostgreSQL 单连接、UUID 单列主键、已启用表及已暴露且未脱敏字段；不混合 ERP 与外部数据源快照。其他主键或无法保证授权与一致性的驱动会被拒绝。

完整配置见本体启用操作单和数据源交付。
