Langfuse v4 官方能力与 Chein 集成方案调研

调研状态：Proposed。工作区依赖见审计。以下区分官方说明、固定版本源码和仍需执行的实验；未安装 SDK。

1. 版本选择与资料使用​

建议先以部署文档已经选用的 Python SDK 4.17.0 为 P1 候选，服务端模板 4.56.0 为对照；二者是独立版本序列。部署镜像和安装版本最终须现场核实，不把候选写成生产事实。

已下载官方 langfuse-python 的 v4.17.0 源码到系统临时目录，只读审查 client.py、resource_manager.py、span_processor.py、span.py、attributes.py、langchain/CallbackHandler.py、score_ingestion_consumer.py。官方 tag 对应 commit f6b704032006a3193d038e1ad9f08c18a66f84e0。同时只读审查 PyPI 发布的 langchain-openai 1.6.2、OTel SDK/OTLP HTTP exporter 1.45.0 源码；后者是验证最低候选依赖行为，并非当前 Chein 已安装版本。

文档网站滚动更新，源码 tag 才是固定 SDK 行为依据。SDK overview当前对应 Python v4/JS v5；不用 v2 的 langfuse.callback、client.trace() 或旧 Root 对象示例。Observations/Metrics 新 API 依赖服务端 v4。Python SDK v4.7.0 以上是当前文档中 v4 实时摄取的最低补丁门槛；迁移模式仍须核实。自托管 v4 兼容说明。

Context7 文档连接返回 API Key 无效，已改查官方网站及固定版本官方源码；不把连接失败当作缺少产品能力。

2. 能力、限制和推荐接线​

Queues/batching后台批量；flush_at、flush_interval 可调；flush 是同步操作常驻 FastAPI 不需逐请求 flush；关停有界问题单独处理必要，不采用“异步即零损耗”结论
Samplingclient trace 级采样；0–1，默认 1；尊重 OTel 采样固定环境比例可直接使用；动态 importance/tail 不是同一能力高固定比例；保留独立全量错误/计数

Scores评分可以关联 trace/observation/session，typed value新后端反馈接线才可用；不能直接信浏览器 trace_id高，先规则/人工，再 Judge
Experiments SDKdataset + task + evaluator 对比；可运行本地数据集复用自有 evaluation.py；实验必须调用受控应用路径高，在隔离测试环境运行
LLM Judge在线/批量按规则评估；需要内容、模型配置和预算生产 metadata-only 不足以评估回答忠实性；版本/许可需现场核对条件推荐，内容留 Chein 内部，外发 Score
Prompt→TraceLangfuse 管理的 Prompt 可关联版本当前 Nacos 是正文发布事实源；无 Langfuse PromptClient不引入第二发布系统，先 metadata 版本指纹

以上支持能力已通过官方文档验证；与 Chein 全部锁定版本组合的运行兼容性仍待实验验证。Python 的同步 Callback 方法可用于 async Runnable，不意味着回调逻辑无需执行线程/GIL/context 切换；不能照搬页面 JS callbacks background 的参数到 Python。

3. 固定 SDK 源码核对结果​

3.1 Callback 生命周期、流式和恢复​

v4.17.0 CallbackHandler 实际构造参数包括 public_key 与 trace_context；旧文档中的 user/session/sample_rate 构造参数不适用。源码用 UUID→Observation 的可变字典管理 invocation；on_llm_new_token 第一次触发时记录 completion_start_time，不为每个 Token 建 Observation。这可提供模型首 chunk 时刻，不能替代浏览器首可见文本时间。

同一 handler 内有按 LangGraph thread metadata 保存的 pending resume 关联，但这是内存状态。Chein 每次执行/恢复重建 Agent、跨进程重领 lease，因此不能依赖它完成长期恢复关联。每 execution 新 handler、显式 trace_context，并用稳定业务 Run/Session 分组。

Chain/Tool 的异常分支会更新 status_message，业务失败以错误码/类别导出；原始错误文字要过滤。结构化辅助模型调用应继承 callbacks；是否在工具/中间件/并行任务中均正确继承，需要 Chein 的锁定版本合同实验。固定 Callback 源码。

3.2 SDK 与 OTel 的组合关系​

resource_manager._init_tracer_provider：没有全局 Provider 时创建；有 Provider 时复用。后者的 sampler/resource 配置不能靠再次给 Langfuse 传 sample_rate 改写。每 public key 的资源管理器有共享状态；初始化集中在 lifespan，不能每请求重复造 SDK/后台线程。

默认 exporter filter 只选 Langfuse/GenAI/已知 LLM scopes；未来的 FastAPI/HTTP/DB Span 不一定导入 Langfuse。适当筛选可避免通用 APM 全量副本，但父被过滤会形成外部父引用，不能谎报为丢失业务根。P1 导出显式 Agent 根；P2 如要求完整可见 BFF 根，应明确选择其有限、已脱敏 Span。mask_otel_spans 只保护 Langfuse exporter，未来另一 exporter 需自己的安全策略。固定资源管理器、官方 advanced features。

3.3 队列、超时、重试和关停​

项v4.17.0 固定源码 / OTel 1.45.0 候选源码事实Chein 设计约束
span batchLangfuseSpanProcessor 继承 OTel BatchSpanProcessor；flush_at→max batch，flush_interval 秒→schedule 毫秒不混用日志队列或 score batch 默认值
span queueSDK 构造函数没有统一 queue_size；OTel 默认队列 2048，batch 512，delay 5000ms；环境 OTEL_BSP_* 可控制与采集对象内存共同测量；队列满可丢 Span，非可靠审计
timeoutclient 默认 LANGFUSE_TIMEOUT=5 秒；SpanProcessor 将秒映射 exporter；BSP timeout 并非全部网络/关停时间总上限显式候选 timeout=2；测试 DNS/TLS/重试整体耗时
OTLP retryHTTP exporter 重试临时网络/可重试状态，受自身 deadline；没有 Langfuse 通用 max_retries 配置所有队列不新增应用重试循环，不承诺无限断网缓存
score / media queue资源管理器两类 Queue 各 100000；media 可关；score consumer 默认 batch 15、interval 1s、max_tries 3P1 禁用媒体且不发 Score；P4 用独立反馈发送路径限速
flushforce_flush() 后 join score/media 队列，同步且没有总体 timeout 参数HTTP/SSE 路径禁止 flush
shutdown调用 flush 并 join consumer，注册 atexit；join 无总体 deadline不能把 asyncio.wait_for(to_thread(shutdown)) 宣称为停止线程；有界关停必须实验验证
multi-worker已有 fork 重初始化处理；各进程独立线程/队列worker 初始化后创建客户端；跨进程不能用内存 handler 关联

这些是只读源码核对，尚未进行故障注入。尤其需要区别 span exporter 与 score consumer 的重试实现、单位和队列。来源：固定 SpanProcessor、固定 Score consumer、OTel SDK 1.45.0 发布源码、OTLP HTTP exporter 1.45.0 发布源码。

5. 方案比较与选择​

等级是设计判断，不是压测结果；“覆盖高”指已存在的框架执行，不包含被禁用的能力。

维度A：仅 CallbackB：Callback + 少量 SDK SpanC：原生 OTel 重建全部埋点D：现有日志 + Langfuse
集成复杂度/侵入低/低中/低到中高/中到高低到中/低，取决于搭配方式
DeepAgents 覆盖框架高，业务阶段低框架高，业务阶段可补需自行桥接或引入 instrumentor日志有事件，树依赖 Callback/SDK
工具覆盖Tool 外壳高，内部 HTTP/DB 低在所有者补阶段，高可以高，但需维护全部语义全量元数据日志，细节用 B
Token/质量完整性原始 Usage/回调支持决定能补 System One、缺失标记和 Score仍需业务及模型语义适配日志不替代 usage/Score
性能序列化/回调有成本A + 少量 Span；需测instrumentor/collector/filter 的额外成本需测避免正文和重复 exporter 可控，需测
维护/版本风险小；框架兼容需测适中；SDK tag 固定最大；自维护协议/属性/映射复用既有日志，低额外维护
扩展非框架业务困难能逐步统一 OTel/APM通用 APM 强，但当前无此基础HTTP/安全排障和 AI 分工清楚

选择 B + D：官方 Callback 作为框架桥，SDK 补 execution/decision/retrieval/query/persist 等必要阶段，ES 保持现有全量元数据和异常能力。A 不足以看到 System One、权限、持久化和跨服务；C 当前要求重建已有框架桥并增加维护；D 单独只保留散点日志。B 本身已经基于 OTel，不需要再给同一模型同时装 OpenAI wrapper/OpenInference/LangSmith exporter。

未来 SkyWalking 接入以其部署版本支持的 OTLP 接收方式另做 POC，不能直接把 Python OTel exporter 与 SkyWalking 插件视为已兼容。先保留 W3C 标识和单 Provider 组合根，避免现阶段为未部署 APM 新增 Collector。见OTel sampling和OTel Collector 变换。

6. 本次官方资料结论的边界​

System One 官方响应的 usage.input_tokens、request_id、latency_ms 可用；协议不生成文本。不能人为补输出 Token，也不能把自报 confidence 当校准准确率。阿里云官方 System One API。

Higress AI Statistics 可提取模型及输入/输出 Token；是否已安装插件、路由名能否返回、透传 Header/缓存计量如何表现，都没有 Chein 实际环境证据。Higress AI Statistics。

Langfuse 自托管的原生自动 Data Retention 当前官方标为 Enterprise Edition；未配置时无限保留，不可把 OSS 当作有默认 TTL。Dataset 项目与 trace 的删除生命周期不同，需独立设计审批/删除。官方 Data Retention。

v4 后续管理查询采用 Observations API v2、Metrics API v2、Scores API v3/Experiments；不要照搬旧 traces get-by-id 或 dataset-run-items API。4.56.0 模板可对照实例 /api/openapi.yaml 核验真实契约，再生成/使用客户端。当前 Public API。
