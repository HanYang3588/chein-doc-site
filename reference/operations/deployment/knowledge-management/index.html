启用知识库管理

知识管理由 Suite Edition 的 knowledge 模块提供。页面和数据权限见产品说明。已有 RAGFlow 外部知识库不会自动导入；通过本系统创建的新库由本模块维护。

1. RAGFlow 和连接配置​

先在 RAGFlow 配好服务账号的默认 Embedding 模型，创建该账号的 API Key。知识库默认使用这个模型，后端创建 permission=me 的 Dataset；Chein 的个人分享不改变 RAGFlow 的团队权限。API Key 只放服务端，不发给浏览器。

管理后端、Outbox 和 Schedule Worker 使用相同的私有 Nacos Data ID chein-backend-runtime.yaml：

RAGFLOW_BASE_URL: "http://ragflow.internal:9380"
RAGFLOW_API_KEY: "替换为服务账号 API Key"
RAGFLOW_TIMEOUT_SECONDS: 20
RAGFLOW_RETRIEVAL_TRANSPORT: "http"

地址填写外部实际可访问的 HTTP 根地址，不带 /api/v1；端口取实际容器映射或网关入口，不能仅凭示例使用 9380。RAGFlow 部署说明端口映射。

Agent 的私有 Data ID chein-agent-runtime.yaml：

AGENT_KNOWLEDGE_URL: "http://chein-backend.internal:8000/api/v1/knowledge/internal/agent/v2"
RAGFLOW_TIMEOUT_SECONDS: 20

开发时可以用 http://127.0.0.1:8000/api/v1/knowledge/internal/agent/v2；容器中用后端服务 DNS，不能用 127.0.0.1 指向其他容器。后台和 Agent 原有 Ed25519 委派公私钥必须匹配；已有 v1 配置会自动规范化为 v2。

动态模式不需要 RAGFLOW_SHARED_DATASET_IDS、RAGFLOW_SHARED_DOCUMENT_IDS，也不需要 Agent 持有 RAGFlow API Key。设置 AGENT_KNOWLEDGE_URL 后，不会回退到旧静态允许列表。连接参数是进程启动配置，首次配置或改地址后重启相应进程；此后知识库、上传、启停与共享变更不需要重启，也不需要更新 Nacos。

如果文档已上传，但对话提示“没有可用的知识检索工具”，先检查 Agent 实际读取的 chein-agent-runtime.yaml：模板中的 AGENT_KNOWLEDGE_URL: null 表示不启用知识工具，后端的 RAGFlow 地址不会自动成为 Agent 的检索入口。此地址填写管理后端 Facade，而非 RAGFlow 地址。配置后重启 Agent，再检查当前用户拥有 agent:chat、knowledge:read；可检索库须已就绪、启用且当前用户有读取权限，Agent 绑定不能为 Disabled，文档也须解析就绪且参与检索。工具已注册但召回为空时，再检查选库、检索参数及文档内容，不能将两种问题混为一谈。

管理后端 Python 3.14 使用官方 HTTP API管理知识库、文件和解析。当前 0.27.2 官方 SDK限定 Python >=3.13,<3.14，不强行加入后端。检索默认使用同一 HTTP Adapter，原生 Tool 和配置见集成说明。官方 MCP 客户端与登记命令保留，仅显式 RAGFLOW_RETRIEVAL_TRANSPORT=mcp 时启用，失败不自动降级。Agent 原有 SDK 只保留为旧共享资料模式兼容入口。

2. 构建、迁移和授权​

沿用项目现有迁移管理员与 runtime 凭据配置，不把管理员连接给 API/Worker。先构建 Suite，运行现有 prestart 流程；手动拆开时等价步骤如下：

pnpm build:edition -- --edition suite
cd backend
# 迁移管理员环境；仅使用已有部署中的凭据。
uv run python -m app.platform.provision_db_roles
uv run python -m app.modules.migrate --edition suite
uv run python -m app.platform.provision_db_roles
# 菜单与内置角色播种同样由维护 CLI 使用管理员配置。
uv run python -m app.initial_data

迁移创建 knowledge schema 和独立版本表 public.alembic_version_knowledge；租户表与系统公共目录均强制 RLS。回滚删除该模块本地表，但不会调用 RAGFlow 删除远端 Dataset；有业务数据时先完成正常删除/备份，再安排数据库降级。

维护 CLI 自动选择私有 bootstrap 配置，独立管理员连接的配置与旧安装兼容说明见后端启动文档。

如果启动提示 Enabled build modules are not ready: knowledge，说明该模块尚未完成上述迁移或状态登记；不能手工把状态改成 ready。若迁移提示 permission denied for table alembic_version，检查 bootstrap 账号对历史表的权限：数据库 owner 不一定是历史表 owner，必须由历史表 owner/DBA 授予迁移所需权限后再运行 Edition 编排器。API 始终使用 runtime 配置。

如果升级代码后知识库页面出现 current transaction is aborted，它表示此前已有 SQL 失败，不能仅根据最后一条 set_config 判断原因。检查最早的数据库异常，以及 SELECT version_num FROM public.alembic_version_knowledge 的结果；只执行初始迁移的安装缺少新版字段与权限表，需要用迁移管理员重新执行本节迁移及授权步骤，然后重启后端。模块曾经登记为 ready 不代表数据库已包含后续版本的迁移。

Platform/Knowledge 作用域在数据库异常退出时恢复内存中的父 scope，保留原始异常；事务所有者负责回滚，PostgreSQL 同时撤销事务级权限设置。API 关闭 Session，Outbox 只回滚消费者的 savepoint，保留外层重试记录。调用方捕获数据库异常后，必须先回滚失败事务再复用 Session；普通业务异常仍会正常执行权限清理。

在“租户套餐”的模块权益中启用 knowledge，并在目标租户启用模块偏好。菜单不能代替 Edition 装配或套餐权益。播种知识目录及七个子页面菜单（先父目录、后子菜单），默认租户的普通用户/管理员角色获得个人知识操作权限；其他已配置角色由管理员按需分配 knowledge:read/create/update/delete/share，不能假设历史自定义角色自动获得权限。

系统知识库创建和全平台发布还要求平台超级管理员身份；普通租户管理员没有跨用户读取私有库的旁路。前端刷新权限与菜单后显示“知识库管理”。

已有安装的菜单初始化与 admin 无权限​

菜单和角色初始化入口是 backend/app/initial_data.py，可以重复执行；它从模块声明生成菜单并为默认租户内置角色补充授权，不需要另写菜单 INSERT SQL。数据库表结构仍由第 2 节的 Alembic 迁移负责。已经完成迁移时，只初始化菜单与权限：

cd backend
uv run python -m app.initial_data

这个脚本同时播种其他平台基础数据，只自动处理默认租户内置角色；已有其他租户或自定义角色应通过管理页面明确授权。脚本不会自动购买/启用新模块权益，也不会把普通用户提升为平台超级管理员。

如果 admin 已是平台超级管理员，但接口返回 TENANT_MODULE_ENTITLEMENT_REQUIRED，应启用租户的知识库权益，而不是继续给角色加菜单。平台超级管理员可以在“租户套餐”启用 knowledge（影响使用该套餐的租户），或通过现有接口只为指定租户授予例外权益：

curl --request POST 'http://127.0.0.1:8000/api/v1/platform/modules/tenants/<目标租户UUID>/overrides/knowledge' \
  --header 'Authorization: Bearer <当前平台超级管理员访问令牌>' \
  --header 'Content-Type: application/json' \
  --data '{"effect":"grant","reason":"为该租户启用知识库管理"}'

该接口记录操作人和审计日志、刷新权限缓存；每次调用都会新增例外记录，不应当作重复播种命令。不要把实际令牌保存到仓库。若返回 TENANT_MODULE_DISABLED，另在目标租户启用模块偏好（PUT /api/v1/platform/modules/tenants/<目标租户UUID>/knowledge，JSON 为 {"is_enabled":true}）。完成后重新登录以加载最新菜单与权限。

如果授权记录存在、模块已就绪，却只看到“功能目录 / 暂无可用功能”，检查 /menus/me 是否只返回 /knowledge 父目录。旧版本 Schedule/Agent 的无 scope 权益查询会因 RLS 看不到授权例外，错误缓存“未授权”并过滤子菜单。当前共享查询入口会绑定可信租户作用域，且拒绝在已有作用域中切换租户；缓存 namespace 的首次失效也会从默认版本 1 正确提升到 2。升级后需通过既有 MODULE_ACCESS 与 RBAC namespace 失效机制刷新旧结果，再在页面刷新权限或重新登录；不要新增重复授权记录或清空整个 Redis。

3. Worker 与操作检查​

后端启动时默认自动托管 Outbox 和 Schedule，不需要再开两个终端或项目。它们复用后端的 Suite Manifest、app_runtime 角色和 RAGFlow 配置，后台线程执行同步工作，不阻塞 HTTP 事件循环。启动日志中的 Background worker acquired leadership 表示取得对应任务的执行权。

多个 API 进程/实例竞争 PostgreSQL session advisory lock，每类任务仅有一个执行者；其余实例等待，执行者退出后自动接替。两个执行者各占用一个专用锁连接，工作 Session 不与 HTTP 请求共享。关闭/热重载先停止领取新任务、等待当前工作结束，再关闭专用连接释放锁。外部调用仍受 RAGFlow 超时约束，但一个任务可能包含多次调用，关闭耗时不能简单等同于单次超时。故障会记录堆栈、释放锁并重试，Outbox 的租约、重试和 Inbox 幂等规则保持不变；Schedule 故障接替可能再次执行，应继续保持任务幂等。

默认 Compose 只启动后端内置任务。已有安装升级时停止旧的独立 Worker 容器/进程，避免旧版本没有选主逻辑而重复执行 Schedule。若以后确实要拆开部署，在 Nacos chein-backend-runtime.yaml 设置 BACKGROUND_WORKERS_ENABLED: false 并重启后端，再启用 Compose 的 standalone-workers profile，或使用兼容命令：

cd backend
NACOS_CONFIG_DATA_ID=chein-backend-runtime.yaml uv run python -m app.modules.outbox_worker
NACOS_CONFIG_DATA_ID=chein-backend-runtime.yaml uv run python -m app.modules.schedule_worker

Outbox 消费创建、上传、启动解析和删除，Schedule 刷新解析进度；关闭内置任务且未启动独立 Worker 时页面会停在“待同步”或“解析中”。RAGFlow 同步失败记录在页面，修复服务配置后点击“重试”；文档在 RAGFlow 已被人工删除且没有临时上传内容时，需要重新上传。

旧版本创建知识库前使用 RAGFlow 的 name 精确查询；该接口对尚不存在的名称返回 code 102（提示无访问权限），会使首次创建提前失败。当前 Dataset 与首次上传文件都改用 keywords 查询并核对完整名称，未找到时正常创建或上传，响应超时后重试则复用已存在的资源；没有忽略真实的权限或认证错误。升级后点击失败知识库的“重试”，无需为此更换 API Key 或调整租户权限。

验证顺序：创建个人库 → 等待就绪 → 上传小 Markdown 文件 → 等待解析就绪 → 分块预览/检索测试 → AI 对话引用 → 分享给使用者 → 撤销分享后确认原链接与检索失效 → 删除后确认 RAGFlow 和本地记录清理。

文件上限为每个 10 MiB，类型为 PDF/DOCX/XLSX/CSV/TXT/MD/PPTX/HTML；下载上限 20 MB，分块按供应商分页读取；文本预览最多 200 KB，Office 预览当前页解析文本。上传暂存于模块数据库，RAGFlow 上传并启动解析后清除暂存。v2 检索默认最多 3 个库、配置上限 10 个、500 个可用文档；旧 v1 只读兼容入口的上限为 20 个库。超过时明确拒绝；大规模部署需扩展分批召回，不能放宽 ACL 或不带文档允许列表去检索。

维护者现在可以编辑分块与文档 Metadata，支持批量重新解析。仍不自动扫描私人对话、原位替换文件或自动向系统库发布。更新内容可上传新文件/笔记，解析成功后停用或删除旧文档。

4. Knowledge 升级​

knowledge_retrieval_v2 增加 Agent 知识绑定、租户检索 Profile 和私有 Trace。升级、权限、兼容与回滚步骤见 实施与验收。新查询与引用使用 Chein ID；现有 Agent Facade v1 配置自动规范化为 v2，无需维护 Nacos 用户知识列表。每个库可维护 Required/Default/Optional/Disabled 与路由说明；这不会授予用户访问权限。

Profile 默认最多选择 3 个库、尝试 2 次、召回 30 个候选、上下文最多 5 个片段/12000 字符；管理员可用 knowledge:configure 调整，普通用户不默认获得配置或 debug 权限。明确选库的检索测试不会扩大到其他库。RAGFlow 重排需服务账号实际配置模型，不能只填任意 ID。文档抽屉支持 Metadata 写入与分块编辑，经内置 Outbox 同步。管理端检索测试仍不调用模型；Agent 执行证据判断与有限重试。新增治理迁移、权限、回滚与真实验收要求以上述实施报告为准。

本次补齐的处理记录迁移、旧共享写入保护、页面与真实联调证据统一见实施与验收。升级后执行菜单播种，再刷新菜单或重新登录。

导航收口（2026-10-04）​

本轮无数据库结构迁移。发布后用维护连接运行 cd backend && uv run python -m app.initial_data 更新菜单并使 RBAC 缓存失效，再刷新前端。Knowledge 显示三个入口；旧分类菜单只更新可见性，ID/自定义角色关联不删除。新前端与新 menus/me 行为应一起发布；降回旧前端前播种旧导航恢复入口。初始化不会新增自定义角色权限或模块权益。
