后端开发规范

本文件适用于 backend/ 下的所有修改，并补充仓库根目录 AGENTS.md。

1. 技术与代码风格​

  • 使用 Python 3.14、FastAPI、SQLModel、SQLAlchemy、Alembic 和 Pydantic v2 的现有模式。
  • 时间统一使用 app.core.clock.get_datetime_utc() 和带时区字段。
  • 使用结构化查询 API；除迁移、RLS setting 和明确封装的基础设施外，不新增裸 SQL。
  • Router 负责 HTTP 契约、依赖注入和事务边界；可复用业务规则进入 application/service 或当前所属上下文服务。
  • 错误使用稳定 HTTP 状态与项目异常映射，不能向客户端泄露密钥、SQL、堆栈或内部对象。
  • 新生产代码直接导入物理所有者模块。不要从 app.models 或 app.core.db 引入已迁移模型、数据库连接或 bootstrap 服务。

2. Platform 边界​

  • app/platform/core 不导入 Infra、Router 或业务模块。
  • app/platform/infra 可以依赖 Platform core 契约，但不能拥有 RBAC、租户或业务单据状态。
  • app/platform/bootstrap.py 是组合根，只编排；配置、导航和 RBAC 播种分别保存在现有子 bootstrap。
  • Platform 表必须在 app/platform/migration_metadata.py 中有且仅有一个 owner。
  • 旧 app.api.routes.*、app.audit、app.mail、app.storage 等兼容路径只做转发，不增加新逻辑。

3. 业务模块边界​

modules/platform_voice/ 是 Platform 同源 WebSocket/一次性票据与当前授权适配包，不是 Edition 模块，不拥有模型协议、Agent 执行或转写历史；运行时边界见 实时语音设计。

modules/platform_automations/ 是由现有 Platform ModuleDefinition 挂载的 Agent HTTP 适配包，不是独立业务模块。仅重验当前身份、签发既有短期 delegation、选择提示词、复用站内信/邮件及代理 Agent API；任务、调度、Run、模型与工具编排不能进入该包。

新增或扩展模块遵循：

app/modules/<module>/
  module.py
  public_api/
  domain/
  application/
  infrastructure/
  routes/
  migrations/
  • module.py 是模块声明入口，定义 Router、权限、菜单、迁移、事件和生命周期组件。
  • Knowledge 默认由 Agent 原生 Tool 调用现有授权 HTTP Facade 与应用服务，RAGFlow MCP 仅为显式可选传输；不得新增重复 KnowledgeService。实现范围见 docs/agent/ragflow-native-tool-integration.md。
  • 只读 Agent 工具也在 ModuleDefinition.agent_tools 声明，查询与授权留在数据所有者模块。app/modules/agent_tools.py 只负责 MCP 装配和发布，不拥有业务数据；禁止从 Nacos 配置加载 Python 路径、stdio 命令或任意请求 headers。
  • public_api 不得反向导入 domain、application、infrastructure、routes 或 FastAPI。
  • Repository 和 ORM 由模块 infrastructure 拥有；Platform 和其他模块不得直接查询这些表。
  • 必选模块依赖必须同时存在于 ModuleDefinition.dependencies 和静态 import 中；可选依赖只能走 capability。

4. 鉴权与数据权限​

  • 业务模块路由使用 require_module_access；Platform 路由使用精确的 permission dependency。
  • 列表、详情、更新、删除和导出必须使用一致的数据权限范围，不能只保护列表接口。
  • 超级管理员绕过只能发生在现有授权层，不能散落到 Repository 或查询条件。
  • 用户、租户、角色、菜单等 Platform 主数据通过 Platform 公开端口访问，业务模块不能导入 Platform ORM。

5. Tenant UoW 与 RLS​

  • API 在认证依赖解析可信 tenant 后激活 Platform/模块 UoW；Worker 从事件信封进入 UoW；Schedule 逐租户执行。
  • 写入 tenant-owned 实体时，调用方提供的 tenant ID 不能覆盖 UoW tenant；跨租户写入必须在 flush 前失败。
  • tenant ID 不可变。禁止通过 update DTO、bulk update 或 ORM merge 改写归属。
  • Platform 新增 RLS 表时同步更新 TENANT_SCOPED_MODELS、Alembic policy、授权脚本与 runtime 回归。
  • UoW 退出必须恢复父 scope；最外层退出必须清空 PostgreSQL app.tenant_id，防止连接或 Worker 事务残留。
  • OAuth2/OIDC、TenantMembership/Profile、全局 Outbox 和 module audit 等特殊表不得直接套用普通 policy；先落实实施基线中的可信 resolver/控制面拆分。

6. 数据库迁移​

  • Platform revision 放入 app/alembic/versions，接 Platform 当前 head。
  • 模块 revision 放入模块自己的 migrations/versions，使用独立 schema 和版本表。
  • 不修改历史 revision，不硬编码可能变化的 head；使用 Alembic ScriptDirectory 获取实际 head。
  • upgrade 和 downgrade 必须处理 policy、constraint、index、schema 与数据兼容。
  • 运行时角色需要新表权限时，更新幂等授权流程并验证角色属性。
  • 维护 CLI 在导入数据库 Engine 前选择私有 bootstrap 配置的 POSTGRES_ADMIN_URL；该凭据只放 bootstrap Data ID，API/Worker 使用 runtime POSTGRES_URL。不在共享数据库连接入口自动升级权限。

7. Outbox 与公开契约​

  • 业务状态和 OutboxEvent 在同一事务提交。
  • 发布事件使用发布模块 public_api.events 中的版本化 Schema，不传 ORM 或自由格式内部对象。
  • 消费者副作用和 InboxReceipt 在同一嵌套事务，失败必须完整回滚。
  • 不跳过 delivery、lease、retry、dead-letter 和 required/optional consumer 规则。
  • API 生命周期默认托管 Outbox/Schedule 后台线程；复用现有 Worker 和模块声明，不在 Router 内启动旁路任务。多进程/实例通过运行时数据库 advisory lock 选主，停止时完成当前任务并释放连接；独立 CLI 仍为兼容入口。
  • 公共命令应有幂等键；公共查询返回 DTO，不返回 Session 或 ORM。

8. 后端验证​

SQL 分析复用 Platform 的 owner/部门范围解析。ERP Provider 逐次校验源权限、模块权益和仓库范围，通过独立 chein_analytics 只读账号查询受保护视图；禁止在 API/工具内创建角色。Analytics 不导入 ERP 私有实现，只经 capability 读取 DTO，工具由现有 MCP 组合根统一发布；HTTP 接口仅作旧配置兼容，不能成为 MCP 撤销后的回退路径。个人收藏 UoW 同时限制 tenant/owner；新作用域退出必须恢复父 scope。共享分析 DTO 及 Agent JSON Schema 通过仓库生成器维护。

常用命令：

cd backend
uv run ruff check app tests
uv run pytest <受影响测试> -q
uv run alembic check

完整数据库测试使用管理员连接；RLS 验证必须额外使用 app_runtime：

$env:POSTGRES_SERVER = 'localhost'
$env:POSTGRES_USER = 'app_runtime'
$env:POSTGRES_PASSWORD = '<local-runtime-password>'
uv run pytest tests/platform/test_platform_tenant_scope.py <受影响路由测试> -q

不要在文档或规范中固化本地密码。最终交付说明必须区分管理员回归和 runtime 角色回归。

Agent 长期记忆边界​

modules/platform_memory 仅适配 Platform 当前身份/权限、同源 BFF、既有 Outbox 和私有 Worker HTTP 调度，不是 Edition 模块。RAGFlow Native Memory Adapter、owner 到私有 Memory 的映射、策略与提交元数据只在顶层 agent/；Backend 不查询这些表、不导入模型框架。离开对话通知只转发已授权的 thread/Run 引用；Agent 按新增问答创建一次同步批次，Worker 沿用逐轮出站和来源校验，BFF 不持有正文或批次调度。所有操作仅限当前 tenant/owner，不能信任外部 user_id、Memory ID 或管理员身份来扩大正文范围。不明提交不盲重试，关闭后停止保存/召回，删除/撤权与恢复保持失败关闭。见 Native Memory 设计。

HermiT 计算适配​

Action 推理前置条件由已发布定义派生，模型不能自填准入公理。完整 ActionQuery 摘要绑定既有任务标签，执行前后重验本人任务、当前发布/来源、根和正向蕴含；含 OWL/SHACL 但未配置条件时拒绝执行。required/range/precision 复用 runtime.property_value；实际 ABox 的唯一性、关系上界和 SHACL 在隔离语义 Worker 检查，不将 OWL 开放世界解释为完整性证明。内部状态轮询不输出证据；正式输出前后仍完整重验授权与快照。TBox 缓存仅保存按完整正文键控的有界序列化结果。

modules/ontology 复用现有登录、模块权限、发布快照和来源权限，调用可选 services/chein-reasoner；不在 Backend 引入 Java/OWL 框架或另建任务库。上传/版本及查询/取消/导出均绑定当前 tenant/owner，外部调用后重新验证来源。配置、签名或依赖故障返回稳定拒绝错误，不回退到其他本体工具。见计算服务设计。

Logic Pack 引擎与存储​

ontology/application/inference/ 是无 I/O 的纯函数包，不导入 ORM、Session、FastAPI、模型框架或时钟；时间只来自快照 asOf。快照与 IRI 的结构校验不能替代外层当前授权及发布摘要核对；Case 仅允许合成夹具和独立 fixture IRI；不得把真实 ERP 快照自动转存共享 Pack，也不能将合成轨迹注册为可引用的业务 derivation。重放的预期摘要必须来自可信存储记录，预算失败不成为已验证证明。

Logic Pack 通过当前 Network 可见性与不可变正文保护；InferenceRun 同时限定 tenant 和 owner_user_id。元数据操作仍走 OntologyUnitOfWork，到期删除也只允许当前本人 scope，不引入无 owner 的清理旁路。实际接线范围与门禁见 Logic Pack 实施证据。

一次性数据库不隔离 PostgreSQL 集群级角色。数据库回归只能使用执行器提供的运行角色凭据/授权，不得在测试中调用角色 provision 或改写共享角色密码/属性；需要验证角色创建/变更时使用独立临时 PostgreSQL 集群。

Logic Pack 外部绑定经可选 datasource.ontology-data capability，首版只允许 PostgreSQL 单连接 UUID 单列主键；不能混合 ERP 与 Datasource 快照。Ontology 的 logic_binding_reference 是 tenant-only 最小删除索引，不含私有正文或样本；写入仍须可见草稿，Datasource 仅通过当前删除权限下的只读 capability 检查布尔引用，不能借索引读取他人 Pack/inference_run。保存与删除共用事务锁；不得引入静态可选模块依赖。见 ADR-0017 与 Logic Pack 交付。

Logic Pack 的人工出库审核由 ERP 的 approve-with-evidence HTTP 命令拥有，Ontology 只经可选 ontology.action-evidence capability 核验本人业务证明。首次提交复验 replay 与 fresh 快照；已完成幂等回执的重试只复验当前权限/归属/证明，不重复库存写入。证明是人工辅助证据，不是 ERP 事务内通用规则硬门禁。Agent 卡片仅跳转授权的 ERP 隐藏页面，MCP 仍只读，见 ADR-0017 与 Logic Pack 交付。

OWL 原生编辑状态 mode=native 复用 builder_binding 的 Tenant UoW/FORCE RLS 与不可变归属，当前正文仍在 Version.rdf_document。原生创建、预览、保存、校验和发布不能隐式初始化 Neo4j Provider，也不能经 Resource project 路径写回。mode=resource 的旧绑定仍完整检查连接与图摘要。保存原生正文按 revision 乐观并发并清空旧任务回执；发布继续绑定本人真实 HermiT 输入，不因本地构建而跳过门禁。
