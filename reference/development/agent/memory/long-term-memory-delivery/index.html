Native Memory 迁移与交付

本次长期记忆实现替换为 RAGFlow Native Memory。设计、旧调用链审计和固定版本源码依据见 Native Memory 设计。以下区分本地验证、现有服务探测与生产启用；没有改写远端 Nacos，没有在共享数据库执行新迁移或删表。

当前实现​

  • RAGFlow 保存 raw/semantic/episodic/procedural，执行提取、Embedding、检索及 FIFO。Agent 不再安装 LangMem，不保留旧提取工具、pgvector/ES 投影或直连 Embedding 客户端。
  • 每个 tenant/owner 独立 me Memory。真实 user_id、稳定 Agent ID 和每轮关联 session_id 仅由服务端填写（页面映射回原会话 ID）；前端与模型不能选择空间。所有读取前后重验当前授权与版本，拒绝跨用户/租户引用，不缓存用户记忆正文。
  • PostgreSQL 只保存 native policy、space、delivery、sync_batch、block、event 及不含正文的生命周期路由目录，均有明确作用域。共享、候选确认、任意文本编辑及管理员查看他人正文入口已移除。
  • 成功 Run 在终态事务中保存 checkpoint/message 引用；入队失败保存 deferred 引用事件，之后补偿。已有视频 Worker 私有 HTTP 调度继续使用，不需要新增 Worker；Agent 自带兼容独立 CLI。
  • 每个成功轮次的用户原文与最终助手文本均增量出站，不再做寒暄、业务问答或敏感文本的本地价值预筛；系统/个人提示词、文件/媒体字节、工具原始输出与思维链仍不作为问答提交。自动同步保持单独 opt-in，离开对话后按新增问答生成一次同步批次再后台处理（10 轮为一条记录），Agent 不能预先声称已保存。
  • 记忆只注入本次模型请求，checkpoint 仅保存 space/version/具体消息 ID 引用。关闭、遗忘或清空后旧引用失败关闭并净化衍生历史；会话删除先记录来源屏障，再删除原会话。会话状态、压缩、审批和恢复机制保留。

已确认的部署事实​

2026-10-21，使用 Backend Nacos 中现有 RAGFlow 连接只读探测 /api/v1/system/version，返回 v0.27.2。本机 Agent Python 3.13.7，已安装 ragflow-sdk==0.27.2；该 SDK 的同步 requests transport 缺少原生超时，既有 Knowledge 路径保留其已有受限线程封装，Memory 使用项目已有 httpx 的异步、可取消、有界传输。没有升级 Python 或 RAGFlow SDK。

真实模型目录和写入验证确认完整标识：

AGENT_MEMORY_EMBEDDING_MODEL: text-embedding-v4@qwen-embedding@Tongyi-Qianwen
AGENT_MEMORY_LLM_MODEL: deepseek-v4.1-flash@qwen-token-plan@OpenAI-API-Compatible

原生 API 会将 model@instance 解释为 model@provider；初次直接提交因此失败。Adapter 现支持已有短名，先在模型目录中按类型唯一匹配，再转换成三段标识；同类型重名时拒绝执行，须使用完整标识。使用完整标识提交后，Raw 先出现，约 15 秒后 Semantic/Episodic/Procedural 均产生，进度从 0.15/0.35 变为 1。两个独立测试空间、搜索范围、内容详情、消息停用及遗忘请求均通过；所有合成空间已删除，没有发送真实业务正文。新 Adapter 在创建空间前校验服务版本和模型目录，不能仅凭创建成功认定模型可用。

只读数据库盘点：旧目录/策略各 1 行，item/revision 各 2 行，Job 2 行；未安装旧 memory_embedding 和新 Native schema。没有读取或在文档记录旧正文。该盘点不代表旧 ES 投影已清理；旧独立 ES 索引需按实际资产归属另行核对，绝不能删除 RAGFlow、日志或其他业务索引。本机未运行 RAGFlow Docker 容器，远端镜像 digest 未确认。

启用顺序​

先将旧配置中的 AGENT_MEMORY_ENABLED 关闭并停止旧版本记忆写入/调度，备份旧数据，再部署一致的 Backend、Agent 和前端。启用标志为 true 而缺少 Native 必填配置时，Agent 启动校验会拒绝运行，必须先完成配置再启用。本次是 Memory 契约替换，旧客户端的编辑/共享/候选确认协议不兼容；不能让旧 Runtime 接管新 Memory lineage，也不能双写或自动回退旧引擎。

  1. 确认迁移配置连接的实际目标库。迁移、备份/清理及合成验证 npm 脚本仅在自己的 CLI 进程中设置 AGENT_MEMORY_ENABLED=false，避免把运行引擎的必填项带入维护命令；不更改 Nacos 或运行中进程的开关。chein-agent-migration.yaml / CHEIN 仅包含 Agent 迁移凭据和实际 runtime role；API/Worker 始终使用 runtime 配置。

  2. 在仓库根目录安装 Native 元数据，并升级 Platform 权限迁移：

    npm run agent:memory:migrate
    NACOS_CONFIG_DATA_ID=chein-backend-bootstrap.yaml npm run migrate:edition -- --edition suite

    Native 安装依序追加 0008_native_memory、0010_memory_governance、0011_memory_sync_batches，不删除旧正文。Platform 的 c0f4b2e13d95 接在当前 head 后，清理 agent:memory:share/admin 菜单及其授权；保留无关自定义子菜单。该命令也会执行该 Edition 的其他待执行迁移。发布后通过现有 redis_cache.bump_namespace 更新 RBAC/MODULE_ACCESS 缓存。

  3. 复用上表中已有的连接、地址与密钥；当前只需新增 AGENT_MEMORY_LLM_MODEL，保留已有 Embedding 短名。不要重复追加同名 YAML 字段，不要照着示例重新生成密钥或把现有输入预算改为 0。其他新部署才需要按示例补齐缺项。

  4. 沿用当前 AGENT_MEMORY_MAX_INPUT_TOKENS: 32768，并确认不超过聊天供应商实际支持的输入上限；新部署默认 0 会停止注入，不能把提取模型的窗口当聊天模型窗口。容量默认 5 MiB/用户，FIFO；检索初值 top_n=6、similarity=0.2、keywords_weight=0.7 只是可评估起点，不宣称最佳。完整字段见 运行配置示例。旧向量 URL/密钥/维度/ES 配置不再使用。

  5. 按需重复原生合成验证，明确会调用配置的 RAGFlow 模型：

    npm run agent:memory:verify -- --live

  6. 将全局 AGENT_MEMORY_ENABLED 设为 true，发布/重启相关进程。仍然只运行现有 npm run dev，也可单独运行已有模块脚本；不要把 migrator 配置注入这些进程。

  7. 用户在“我的长期记忆”中分别开启“使用长期记忆”和“离开会话时自动保存”。默认均关闭；开启时才创建私有空间，不通过 GET 页面加载隐藏创建。提交、提取中和最终完成是不同状态，可在原始对话和处理任务中刷新查看。

旧数据迁移与最终清理​

先导出到项目外的私有文件。CLI 使用 migration-only 连接、只枚举旧 Memory 表；备份包含完整旧行，不打印正文，文件必须 0600，不能替代数据库 PITR/完整 schema 备份。历史 SQL migration 保持不变，恢复时先在隔离库重建历史结构并审阅恢复结果。

npm run agent:memory:legacy -- export \
  --backup "$HOME/.cache/chein/backups/memory-before-native.ndjson"

新引擎不自动继承旧候选、共享授权、已过期或已删除记忆。本人重新开启 Native 自动记忆后，维护操作者可明确选择已审阅的私人确认记录，重新提交给 RAGFlow 原生提取：

npm run agent:memory:import -- \
  --tenant <可信租户UUID> --owner <本人用户UUID> --item <已审阅旧记忆UUID>

该入口仍经私有 dispatch 重验成员和当前权限，不代替本人 opt-in；只保存不可变 item/revision 引用并复用现有 Worker，不复制旧正文到新表。旧分类、ID 和向量不会原样保留。共享/候选/敏感/业务工具来源不会自动导入。达到 INDEXED 后再清理；UNKNOWN 或仍待处理的导入会阻止清理。

最终删除旧结构是独立、显式的操作：

npm run agent:memory:legacy -- retire \
  --backup "$HOME/.cache/chein/backups/memory-before-native.ndjson" \
  --confirm-delete-legacy

CLI 在锁内重新计算当前旧数据快照，与备份逐字节摘要匹配后才执行 0009_retire_legacy_memory.sql。备份过期、权限不足或外部外键依赖都会失败并回滚；不使用 CASCADE，不删 Checkpoint/会话/业务表。旧 migration 记录保留。Platform 权限清理和 Native 安装不能恢复已删除的旧内容，数据恢复依赖已审阅备份。

原生接口限制与故障行为​

  • POST /messages 返回成功仅标记 SUBMITTED；Raw 与后台提取不是同一提交点。原生 API 没有可靠幂等键，SENDING 进程失联、发送后超时、HTTP/业务错误均进入 UNKNOWN，禁止盲重试。仅能证明未发送的连接失败最多 3 次有界重试；显式重试也只接受这类 DEAD。
  • 使用 Raw 内容 HMAC 与任务 progress 关联提交，只有精确匹配且 progress=1 才标记 INDEXED。不保存内容副本，不把“无提取结果”或提交成功伪装为四类完成。当前每次核对最多 5 个任务、每会话最近 20 个 Raw；超出窗口或重复正文无法唯一关联时保持未确认，需要运维核对，不能重提冒充修复。Native 提取失败由 RAGFlow 侧恢复，Chein 不伪造不存在的提取重试 API。
  • 待处理同步批次默认每人上限 20（显式旧私人记忆导入占独立名额）。当前 generation 的批次及成员保留，以维持来源关联、增量去重和准确状态；旧 generation 的终态成员与空批次超过 30 天清理，审计元数据保留 180 天；UNKNOWN 不按时间盲删。当前 Worker 每 5 秒处理一个 owner，真实用户规模、轮转时间和峰值吞吐仍须压测，不将本地测试当作生产容量证明。
  • 消息列表按 Raw 分页并嵌套提取结果，类型过滤只作用于当前页；语义搜索返回有界相关结果。页面明确说明这个边界，不伪造按类型全局分页。消息 ID 以字符串传递，避免 JavaScript 大整数精度丢失。
  • 纠正流程：先在管理页遗忘错误条目，再在新一轮对话明确表达正确事实；自动保存开启并离开该会话后由 Native 重新提取。不会原地伪编辑，也不保证旧条目 ID 或分类被保留。
  • 消息 DELETE 是原生遗忘标记，非物理擦除。Chein 先保存来源墓碑，所有入口排除记录及迟到衍生记录；停用可重新启用，遗忘不可伪编辑恢复。清空立即换 generation 并关闭策略，旧空间异步 DELETE；服务不可用时仍可先隔离并排队，功能关闭时继续清理。
  • 普通账号/成员停用或权限不足会暂停保存和召回并保留原空间，不触发不可逆擦除；恢复身份后由本人重新开启。归档、匿名化和租户归档才通过生命周期事件安排删除。
  • 生命周期 Outbox 只持久标记可信 tenant/owner 的路由撤销，由 Worker 逐 owner 进入 RLS 作用域完成擦除，不在请求中跨用户读取正文或无限循环。
  • Memory 管理响应使用 no-store；搜索失败不会回退全局查询。召回不可用时继续普通对话并记录安全错误类型；带失效 lineage 的恢复拒绝执行旧工具并要求新轮次。
  • 不导出系统/个人提示词、工具原始结果或模型思维链。RAGFlow API 不返回完整调用 Token/成本，Chein 只记录授权、召回、提交、维护元数据，不能虚构提取模型 usage 或精确成本。正则检查不是完整 DLP，扩大业务来源前须取得数据所有者的可撤销授权契约。

回滚与外部门禁​

优先关闭新保存和召回，保留当前版本的撤销/历史校验。migrate_memory.py --downgrade 只接受完全空的 Native schema；非空元数据不能随意删除。完整应用回退必须审阅旧客户端、已删除授权、空间与旧数据备份，不自动让旧引擎接管。

仍待目标环境完成：远端镜像 digest、生产迁移/PITR 恢复演练、旧独立 ES 索引归属清理、真实用户启用、模型质量与阈值标注、四类提取分布、并发/轮转/TTFT/费用压测、分布式故障及 N-1、镜像扫描签名和远端 CI。实际生产配置与数据库尚未修改。

增量 checkpoint 源消息读取修复（2026-10-21）​
