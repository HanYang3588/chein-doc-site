采购业务：订单 -> 入库 -> 退货

状态：操作与事实说明（以 purchase_routes.py、purchase_stock_routes.py 为准）。

适用范围：采购订单、采购入库、采购退货。

相关：表结构见 01-数据地图.md；库存过账细节见 04-库存管理.md；付款核销见 05-财务结算与核销.md。

1. 单据链与数据流​

采购订单 CGDD (purchase_order)
   └── 采购入库 CGRK (purchase_in)         库存 +，回写订单 received_quantity
          └── 采购退货 CGTH (purchase_return) 库存 -，回写入库 returned_quantity 和订单 returned_quantity
                 └── 付款单 FKD (finance_payment) 核销 purchase_in（正方向）/ purchase_return（负方向）

关键点：

  • 入库必须挂在已审批的采购订单行上，purchase_in_item.purchase_order_item_id 是强约束。
  • 退货必须挂在已审批的采购入库行上，purchase_return_item.purchase_in_item_id 是强约束。
  • 一张订单可以多次入库（分批收货），校验口径是"剩余未收数量"而不是订单总量。
  • 结算金额写在表头 settled_amount，只由付款单的审批/反向改动，业务单据自己不改。

2. 建单阶段的校验（HTTP 层之前的领域规则）​

环节校验失败表现
采购订单供应商存在且 is_active409 Supplier is unavailable
采购订单商品存在且 is_active、单位存在且 is_active409 Product is unavailable / Product unit is unavailable
采购订单明细数量与单价 > 0，tax_rate 在 0~100422（DTO 校验）
采购订单discount_amount 不超过 product_amount + tax_amount409 Discount exceeds order amount
采购入库订单必须为 approved409 Purchase order must be approved
采购入库明细数量 <= order_item.quantity - received_quantity409 Receipt quantity exceeds remaining order quantity
采购退货入库单必须 approved，订单存在409 Purchase return source is unavailable
采购退货数量 <= 入库行可退量，且 <= 订单行可退量建单/改单 409 Return quantity exceeds receipt quantity；审批 409 Return quantity exceeds available received quantity
库存过账产品/仓库启用、库存不能为负409（见 04-库存管理.md）

金额计算统一在 application/trade_document_amounts.py 与 application/purchase_orders.py： 明细 product_amount = quantity * reference_price，tax_amount = product_amount * tax_rate / 100， 折扣按 discount_rate 计算或直接用 discount_amount，全部 ROUND_HALF_UP 保留 4 位小数。

3. 审批时发生了什么（数据流转）​

3.1 采购订单审批（POST /api/v1/erp/purchase-orders/{id}/approve）​

  1. 校验 status = draft 且 version == expected_version，否则 409 Purchase order version conflict。
  2. status -> approved、version += 1，写 approved_by / approved_at。
  3. 写 document_action_log（action = approved）。
  4. 发事件 erp.purchase_order.approved（Outbox，允许无订阅者）。

订单审批不产生库存分录，也不影响库存。

3.2 采购入库审批（POST /api/v1/erp/purchase-ins/{id}/approve）​

  1. 校验入库单 draft + 版本号，订单为 approved，明细数量在剩余可收范围内。
  2. 调用 InventoryPostingService.post，为每条明细写一条 stock_ledger （ledger_type = purchase_in、delta_quantity = +数量），并更新 stock_balance。
  3. 回写 purchase_order_item.received_quantity += 明细数量。
  4. status -> approved、version += 1，写审批人/时间。
  5. 写 document_action_log，发事件 erp.purchase_in.approved。

3.3 采购入库反向（POST .../purchase-ins/{id}/reverse）​

前置条件（任一不满足直接 409）：

  • 单据必须是 approved，且 version == expected_version；
  • 明细没有下游退货：returned_quantity > 0 时 Purchase receipt has downstream return documents；
  • 没有被已审批付款单引用：Purchase receipt has approved settlement documents；
  • 原分录齐全：Purchase receipt has no reversible posting；
  • 关联采购订单仍存在：Purchase order is unavailable；
  • 订单行 received_quantity 不小于本次冲回数量：Purchase order receipt quantity is inconsistent。

执行：写反向分录（ledger_type = purchase_in_reversal、reversal_of_id = 原分录 id、 数量取负）、received_quantity -= 明细数量、status -> draft、version += 1、 审计 action = reversed、事件 erp.purchase_in.reversed。

3.4 采购退货审批 / 反向​

  • 审批：库存减少（ledger_type = purchase_return、数量取负）， purchase_in_item.returned_quantity += 数量、purchase_order_item.returned_quantity += 数量， 然后 status -> approved。
  • 反向：要求没有被已审批付款单引用、退货数量仍可回退；写 purchase_return_reversal 分录 （库存加回），两个 returned_quantity 减回，status -> draft。

4. 排查：常见问题与查询​

Q：采购订单显示"已收数量"不对

对照 purchase_order_item.received_quantity 与 purchase_in 的汇总（只统计 approved）：

SELECT poi.line_no, poi.quantity, poi.received_quantity,
       COALESCE(SUM(pi_item.quantity) FILTER (WHERE pi.status = 'approved'), 0) AS approved_in_qty
FROM erp.purchase_order_item poi
JOIN erp.purchase_order po ON po.id = poi.purchase_order_id AND po.tenant_id = poi.tenant_id
LEFT JOIN erp.purchase_in_item pi_item
       ON pi_item.purchase_order_item_id = poi.id AND pi_item.tenant_id = poi.tenant_id
LEFT JOIN erp.purchase_in pi
       ON pi.id = pi_item.purchase_in_id AND pi.tenant_id = pi_item.tenant_id
WHERE poi.tenant_id = '<tenant>' AND po.no = '<订单号>'
GROUP BY poi.line_no, poi.quantity, poi.received_quantity
ORDER BY poi.line_no;

两者不一致通常说明历史上有过反向操作（status 回到 draft 的入库单仍保留最后 version， 其反向分录在 stock_ledger 里 reversal_of_id IS NOT NULL）。

Q：入库单审批报"数量超过剩余可收"

说明 quantity > order_item.quantity - received_quantity。检查是否有其他入库单已占用额度 （purchase_in.status = 'approved'），或订单总量本身需要调整。

Q：入库单无法反向

按上面的三段前置条件逐项查：下游退货（purchase_in_item.returned_quantity）、 已审批付款（finance_payment_item + finance_payment.status = 'approved'）、原分录是否存在。

Q：某供应商当月采购总额

SELECT SUM(total_amount) - (
         SELECT COALESCE(SUM(total_amount), 0) FROM erp.purchase_return
         WHERE tenant_id = '<tenant>' AND supplier_id = '<supplier>'
           AND status = 'approved' AND business_at >= '<from>' AND business_at < '<to>'
       ) AS net_amount
FROM erp.purchase_in
WHERE tenant_id = '<tenant>' AND supplier_id = '<supplier>'
  AND status = 'approved' AND business_at >= '<from>' AND business_at < '<to>';

Q：怎么确认审批人/审批时间

purchase_order / purchase_in / purchase_return 表头都有 approved_by、approved_at； 完整的动作轨迹（含反向原因 reason）在 erp.document_action_log：

SELECT occurred_at, action, old_status, new_status, actor_id, reason
FROM erp.document_action_log
WHERE tenant_id = '<tenant>' AND resource_type = 'purchase_in' AND resource_no = '<单号>'
ORDER BY occurred_at;
