Ant Design Pro 前端迁移设计

状态：React 已是默认开发、构建和 Docker 入口；本文保留兼容范围与验收要求，不代表所有发布门禁已通过

适用范围：已由 Vue Vben Admin 切换的 React Ant Design Pro 管理前端及其后续验收；不改变 FastAPI、PostgreSQL、Nacos、ERP 或 Python Agent 的服务边界。

1. 目标与非目标​

1.1 目标​

以仓库已落地的 Ant Design Pro / React 应用为管理前端基线，保留以下重构目标；依赖版本与实现事实见前端架构，不以未经核实的“上游最新版”覆盖当前锁文件：

  • 功能、数据口径、URL、权限和错误行为 1:1 保持兼容，包括平台管理、租户、认证、文件、消息、ERP 和数据分析助手。
  • 页面视觉、布局、动效和组件选择遵循 Ant Design Pro 原生设计体系，不复刻 Vben 的像素级 CSS。
  • 迁移后只保留一个生产管理前端；切换前允许 Vben 与 Pro 并行运行并回归验证。
  • 所有浏览器请求继续经同源 FastAPI API/BFF；不新增浏览器直连 Agent、模型、RAGFlow 或数据库的路径。

1.2 非目标​

  • 不重写 FastAPI 业务 API、数据库迁移、RLS、Nacos 配置、ERP 领域逻辑或 Python Agent。
  • 不把 Vue 组件、Vben 样式、Pinia store 或 Vue Router 代码机械转换为 React。
  • 不为了“界面完全一样”复制 Vben 的间距、颜色、菜单或标签栏。产品行为一致，视觉采用 ProLayout、Ant Design token 和 ProComponents 的原生结果。
  • 不在迁移第一阶段引入新的微前端、React/Vue 双运行时同页混用，或独立 AI 前端服务。

1.3 当前实施状态（2026-09-20）​

  • frontend/apps/web-pro 是唯一管理前端；根脚本、workspace、Edition 构建和 Docker 均使用 React。旧 Vue 应用及 workspace 公共包已从源码树删除。
  • React 已有认证、平台、租户、Items、ERP、Dashboard、个人中心、动态菜单/权限和 Manifest 校验实现；功能是否等价仍按具体页面与真实后端回归验证，不从框架迁移推导验收完成。
  • Agent 已接入 assistant-ui 会话与同源 BFF SSE；深度思考开关、ChartSpec 主页面接线和 Markdown 消毒链路的实际边界见Agent UI，不再沿用早期“全部已支持”的描述。
  • 当前业务页面仍有集中 pages/ 实现，React 静态模块注册生成和 Base dist 裁剪仍需收口。 CI 已切换到 React 检查和客户端 drift 检查；远端通过结果需另行核对。
  • 2026-09-18 的旧迁移记录包含本地构建和 Stub 浏览器 smoke，不能当作当前源码或真实后端 的完成证据；本次不复制其测试数量、菜单数量或历史通过清单。
  • 未由本次源码清理证明：真实 FastAPI/PostgreSQL/Redis/Python Agent E2E、线上部署、回滚 演练与远端供应链门禁。

2. 当前技术栈​

具体版本、用途和实际目录统一见前端架构与技术栈。

  • 默认应用：React 19、TypeScript、Umi Max 4、Ant Design 6、ProComponents 3。
  • 管理界面：手动 ProLayout + 后端菜单/权限 + Manifest 适配；不是 Umi 自动 Layout 模板。
  • Agent：assistant-ui、Base UI、本地 UI 原语和 Tailwind 的独立全屏布局。
  • 请求/状态：Umi request、initialState 与 React Hooks；Query/Zustand 已声明但未形成统一业务状态层。
  • 契约：根 generate:api 使用 Hey API，从 FastAPI Edition 组合生成；不是模板 oneapi.json。
  • 构建：Umi max dev / max build。

3. 目标架构与迁移边界​

React 前端的职责仅是展示、交互和调用受保护 API。可信用户、租户、模块权限、数据权限、RLS、会话持久化和 Agent 委托仍由现有后端控制。前端隐藏按钮不是授权边界。

3.1 当前交付与回滚边界​

  1. 默认命令运行/构建 web-pro，本地端口 5174。
  2. 验收使用后端契约与授权矩阵，不写入前端专属数据库迁移标记。
  3. 仓库部署配置已经指向 React，但实际环境、构建产物、代理和浏览器 URL 仍须现场验证。
  4. 只有真实流程、受影响 Edition、产物隔离与回滚演练通过后，才能宣布发布验收完成。
  5. 旧应用已从源码树删除；回滚仍需实际环境与制品演练。

4. 必须保留的契约​

契约React 端要求
认证保持当前登录、刷新、登出、验证码/滑块验证、MFA、OIDC、OAuth2 授权页面的 API 与失败状态；不得把 token、密码或 Nacos 配置写入源码。
用户与租户当前用户、租户切换、菜单和权限必须从后端受保护接口获取；请求拦截器保留 Authorization 与统一 401/403 处理；租户来自已验证 JWT/受控切换，不信任浏览器自带 tenant_id。
动态菜单读取后端菜单树；目录、页面、按钮权限和排序与后端结果一致。React 采用受控 component-key 到页面组件的映射，未知 key 必须失败关闭。
Edition Manifest每次启动/路由初始化前继续比对后端 Build Manifest 的 schema、digest、source revision；不兼容时显示现有稳定错误，不能静默继续。React 侧清单必须由仓库命令生成，不能手工编辑。
OpenAPI新客户端由 FastAPI OpenAPI 生成；保留 API 版本、DTO、分页、错误码和上传下载行为。
Agent BFF继续使用 /api/v1/agent-ui 的会话、历史、归档、删除、SSE 聊天和取消 Run 接口；浏览器不得直连 agent:8100。
Agent 安全渲染Markdown 禁止 raw HTML 并消毒；图表只接受 ChartSpecV1；工具、引用和图片必须使用后端授权的结构化数据/短期 URL。

以下是功能覆盖基线。具体字段、权限码、接口和错误码以现有 FastAPI OpenAPI、后端菜单种子及页面实际行为为准。

5.1 Agent UI 兼容范围​

会话、历史、流式文本、工具状态、取消、归档和删除继续使用同源 BFF 契约。管理系统 返回入口保留；Agent 全屏布局复用现有 assistant-ui 的 Thread/ThreadListSidebar、Base UI 与 Tailwind 组件，不要求全部改回 Ant Design 外壳。

深度思考、ChartSpec、引用、图片及 Markdown 安全的当前接线与目标要求统一见 Agent UI 设计。功能清单是验收目标，不能因组件/类型已存在就勾选完成。

6. 目录与所有权​

真实目录见前端架构；新业务接入方式见模块指南。

当前初始化在 src/app.tsx，工作区/pageMap 在 src/pages/Workspace.tsx，菜单/权限/Manifest 适配在 src/runtime，Platform 生成客户端在 src/services/generated/platform，模块客户端 在 src/modules/<module>/api/generated。现有 ERP、Items、Agent 集中页面需逐步归位， 不能继续增加第二套注册器或全局业务 API。

禁止将后端 DTO 另立事实源，或把 ERP 领域规则、Agent Prompt/Tool 搬入 React。

7. 分阶段实施与交付门禁​

阶段交付通过条件
0. 基线盘点当前 URL、菜单、权限、接口、截图与关键流程清单与后端菜单/OpenAPI/现有页面核对，形成缺口表
1. Pro 基座web-pro、ProLayout、request、i18n、错误页、动态菜单/Manifest 适配未登录跳登录；登录后菜单和权限与后端一致；Manifest 不匹配失败关闭
2. 平台闭环认证、个人中心、系统/租户/运营页面增删改查、上传、分页、权限拒绝与表单校验通过
3. ERP 闭环主数据、单据、库存、资金、统计关键单据状态流转、数据回显、导出和权限校验与现有 API 一致
4. Agent 闭环会话、SSE、思考、工具、图表、取消、历史恢复不直连 Agent；刷新/切换历史正确；断流/错误可见；受控内容安全降级
5. 切换演练生产构建、部署配置、回滚制品和对比报告全部 Edition 构建、关键 E2E、浏览器控制台/网络检查和人工验收通过

7.1 最低验证矩阵​

# React 应用自身
pnpm frontend:typecheck
pnpm frontend:pro:test
pnpm frontend:build

# API 类型生成（需要后端依赖与配置，不要求 HTTP 服务已启动）
pnpm generate:api -- --edition suite

# Edition、动态菜单与 Manifest
pnpm build:edition -- --edition base
pnpm build:edition -- --edition items
pnpm build:edition -- --edition suite

以上脚本已在当前仓库存在。frontend:e2e 目前是 Vitest 别名，不能替代真实浏览器回归；当前 frontend.yml 已检查 React 构建和生成客户端 drift，绿色状态仍不能证明真实浏览器验收。

关键 E2E 至少覆盖：登录失败/成功、租户切换、无权限访问、用户与角色管理、一个 ERP 主数据页、采购或销售单据流程、库存/付款页面、Agent 新建会话后首条消息才持久化、会话历史恢复、归档/删除、SSE 取消和图表渲染。

8. 风险与决策​

风险控制措施
把 Vben 样式硬搬到 Pro，得到两套冲突设计只迁移功能和行为；所有新 UI 先选 ProComponents/Antd 原生组件
前端重写时放松权限或租户隔离API 仍由后端授权；E2E 覆盖 401/403 和跨租户负向路径
动态菜单在 React 中退化为静态路由实现后端菜单 + Manifest 校验 + 受控页面映射，未知页面失败关闭
OpenAPI 类型漂移生成客户端，不手写生成目录；后端契约变更后重新生成
Agent 改造导致浏览器直连或不安全渲染延续 BFF、SSE、Markdown/ChartSpec 边界，加入安全回归测试
一次性删除 Vben 导致无法回滚并行应用和切换演练；验收后再单独删除旧应用

9. 完成定义​

默认交付入口已经切换；只有以下条件全部满足后，才能宣布 React 发布验收完成并批准旧应用退役：

  1. 后端菜单暴露的所有可访问页面在 React 端有受控映射，且权限行为一致。
  2. 平台、ERP 和 Agent 的关键用户闭环可用，数据与接口不变。
  3. React UI 使用 Ant Design Pro/Ant Design 原生风格，不依赖 Vben CSS、Vue 运行时或 ant-design-x-vue。
  4. Build Manifest、OpenAPI 生成、认证、租户、错误处理、上传下载和 Agent BFF 安全边界通过验证。
  5. 生产构建、关键自动化回归、人工验收与回滚演练均有实际证据。
  6. 旧 Vue 应用已从源码树删除；该事实不能替代新前端的观察期与回滚演练证据。
