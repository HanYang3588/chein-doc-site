OWL 规则与推理集成交付记录

本地交付，不代表生产上线或 ADR 签署。现状调研、复用清单、架构图、状态机、权限与快照设计见集成设计；基础计算部署见架构。ADR-0015 保持 Proposed。

行为变化​

  • 规则保存在既有 Version.definition 的 owl_rules，包含 code/name/description/Turtle。规则与本体共用编辑、双人审核、发布、停用及恢复，不新建规则系统。空规则不进入历史摘要；规则变化按破坏性变更处理。JSON 往返、合并、Neo4j 投影及正式 RDF 导出保留规则。
  • 受控声明和规则经既有隔离 RDF Worker 确定性组装，保留十进制 lexical form、分离空白节点、拒绝 Imports/未知命名引用。OWLAPI 检查 OWL2DL 全局限制及未解析三元组；HermiT 检查一致性和不可满足类。草稿检查不接受 ABox。发布每一步必须绑定本人、当前完整输入与正文/映射摘要对应的成功任务；改稿、换版本、过期、撤权或他人任务不能复用。
  • Neo4j 继续保存授权发布投影；PG 是正文、审核和 ACL 权威源，ERP 拥有实时实例。n10s 保留基础语义与预览能力；有复杂规则的版本禁止用基础类别推理冒充完整 OWL 结论，显式 query/traverse 维持原路径。没有写入共享 GraphConfig/Namespaces/Shapes，也没有自动物化。
  • 用户确认首批 ERP 采购、销售、库存。ERP 的 ontology.data / reasoning-snapshot-v1 复用固定映射、owner/部门/仓库权限及 Tenant UoW；数据行来自独立只读 REPEATABLE READ 事务，当前授权使用 READ COMMITTED 复验。有界根选择器为对象 code、记录 UUID、1–3 跳；50 节点/200 边/30 次数据查询，沿用 SQL/总时间限制。任何截断或缺权限均不计算。
  • 稳定 IRI 使用可信 tenant + 数据所有者 binding + UUID。数据属性要求 Property.type 与单一 XSD range 匹配，decimal 不经浮点数，整数与布尔严格区分，dateTime 必须有时区。可空值不生成断言，更不生成闭世界否定。
  • ReasonerSource.data 绑定 dataSnapshotId、scopeDigest、asOf 和选择器。快照哈希覆盖排序行/边及权限范围；完整 OWL 原子保存在既有私有 journal。读取/结果/导出/取消及历史证据均重验当前授权与数据哈希；变化后拒绝旧结果。completeWithinScope=true 仅描述本次授权映射/跳数内未截断，wholeOntologyComplete=false，局部一致不能证明全库一致。
  • 新增两个 ModuleDefinition/MCP 工具：ontology_reason_v1 与 ontology_reasoning_result_v1。默认已发布 TBox；显式 abox 才读取授权 ERP 快照。支持实例分类、对象属性及固定蕴含，types/property-values 可由服务端确定根 IRI。模型不能上传公理、SQL、URL 或身份，不能修改发布规则或替代 ERP 事务校验。
  • DeepAgents 原生 middleware 在失败、不一致、未完成或不完整结果后停止依赖推理的模型决策。单轮最多两次推理调用；确定的 IRI 参数错误只允许一次受控修正，并须再次实际调用工具。依赖推理的操作不能与推理在同批并行执行。模型和历史恢复前重验证据；新工具不自动取得 Memory 来源权限。
  • Neo4j Studio 增加 OWL 规则及本人任务页签。原生表单生成继承、等价、互斥、逆属性、传递和有序链，高级模式保留 Turtle；合法性以服务端检查为准。任务页支持状态、本体/规则版本、时间和输入类型筛选，服务端另提供 operation 筛选。assistant-ui 复用现有模块渲染器，按真实 job 状态轮询，显示快照/哈希/时间/参数/引擎/Trace、分页结果及取消，不伪造内部阶段。
  • 原有 ECS/OTLP 记录 job、操作、状态、错误、耗时、输入哈希与 Trace 引用；OWL、Token、业务事实及系统提示不写 ES。RunEvent/ToolMessage 关联 ToolCall 与 jobId。观测故障不改变计算成功状态；任务持久化故障拒绝接收。

API、数据及兼容部署​

公开增量：

接口契约
POST /api/v1/ontology/reasoner/rules-validation保存版本 + expected_revision + Idempotency-Key；真实独立检查
GET /api/v1/ontology/reasoner/jobs本人 keyset、status、network_id/version、operation、kind、created_from/to

原 job/read/results/export/cancel当前版本/权限及 ERP 快照复验，不输出过期证据

筛选和 ACL 作用于本人游标页，页可能为空但仍有 next；客户端必须保留游标继续读取。不会为填满页而无界扫描私有任务。本人身份不来自筛选参数。旧 TBox Source 省略 data，旧 journal 缺少新增参数 metadata 时返回 null；不重算历史输入。内部 Source.data 与 validate-rules、Job metadata 见 services/chein-reasoner/openapi.yaml。

没有 PG 模型、索引或迁移变更，Version.definition 仍是 JSONB，Audit 沿用原事务与摘要，RLS 不变。每次输入、结果及状态使用既有单实例私有 journal；默认 24 小时/1000 任务，不是永久审计库。生产须确认保留策略与卷备份。ES ILM 见统一监控。

部署顺序：先兼容 Backend，再 Java，再 suite 前端及既有 MCP 审核发布。Backend 新字段需能读旧 journal；新能力在 Java 就绪前保持关闭。旧 Backend 对新增字段采用严格校验，不能先让新 Java 响应破坏旧读取。旧服务不认识新操作必须拒绝，不回退基础推理。未自动修改正常 Nacos、MCP 注册或共享图配置。启用新规则后，旧进程不认识正文扩展；N-1 降级必须先演练，关闭计算不等于转换或删除已有规则。

剩余门禁与限制​

  1. 组织/全库 ABox 关闭。 本轮按用户确认只接采购、销售、库存的授权有界映射。全库完整性、隐藏事实一致性、组织关系必须由对应数据所有者另立契约，不能外推本轮局部结果。无自动 Neo4j 物化、撤销或业务写入。
  2. 跨用户/部门任务正文审计未启用。 当前本人任务与当前可见来源是安全边界；现有“读取本体”权限没有授予读取他人 ERP 快照的含义。需要独立审计权限、可见数据范围、保留与访问审计设计后实施。独立“触发来源”筛选也尚无持久化契约；当前 kind 是输入类型，不伪装成 Agent/人工来源。
  3. 无形式证明/justification 模块；LLM 解释不等于 HermiT 形式证明。不完整结果、未蕴含、局部一致不能用于全局否定或生产事务授权。
  4. 登录后的真实浏览器 E2E/响应式截图未完成。正常页面到达登录/ALTCHA 后停止并关闭临时页，没有绕过认证或提交验证码；36 项组件测试不替代该门禁。没有截图写入源码目录。
  5. 目标 Ubuntu、认证 Nacos/Higress/TLS、生产 n10s 兼容矩阵、跨实例/持久卷恢复、长期并发失败率、队列等待和缓存命中率尚未验证。ERP 模型样本耗时约 63.6 秒，当前逐次重验会增加查询开销，上线前须压测，不能据单次样本承诺 SLO。
  6. 远端 CI、漏洞扫描/签名、LGPL 法务、生产备份/审计保留、N-1 演练与团队 ADR 签署未执行。没有创建分支、暂存、提交、推送或修改远端注册状态。

2026-10-27 审查后修复​

本节是上述交付后的补充修复。此前的真实模型、容器、Neo4j/ES 样本属于历史本地证据，本次没有把它们算作重新执行的验证。

问题当前处理与证据
参数修正可夹带业务工具，撤权后清空证据继续调用模型agent/src/chein_agent/reasoning_middleware.py 同时拦截模型与工具；修正仅允许同名推理工具一次单独调用，去除修正时的未验证解释；证据复验失败返回确定性说明。空错误对象、异常字段类型和非文本内容块也返回可读失败，不触发二次解析异常。原生 DeepAgents 图回归确认业务处理函数没有执行。重复相同任务只复验一次，单次最多 10 个不同任务，超出预算停止并提示。
usable 与业务许可混淆，未蕴含被当作通过application/agent_reasoning.py 返回 ALLOW/DENY/INDETERMINATE/ERROR、原因、查询公理和输入/定义/数据摘要；authorizes_action=false。ALLOW 仅表示逻辑查询正常完成；蕴含查询缺失布尔结果也拒绝。无 justification 时明确 proof_available=false，不生成伪证明链。
Action 没有确定的服务器推理关卡public_api/dto.py 增加可选 Action.precondition={class_uri,depth}。application/reasoner.py 从已发布条件派生根分类查询，将完整 ActionQuery 的规范化 SHA256 写入已有任务标签；runtime.action 执行前后复验本人成功任务、相同参数、版本、根、scope/数据快照及正向蕴含。只有原固定只读执行器，不增加 ERP 写工具。
声明约束没有进入实际 ABox 检查required/range/precision 原已由 runtime.property_value 检查；unique/关系基数原有目录发布门禁。本次 application/semantics.py 补充授权快照内唯一性、关系上界及真实 ABox SHACL 检查，复用原禁网隔离 Worker。OWA 存在量词不能替代字段完整性；授权范围外的事实不视为否定。
分页被误当作计算截断reasoner.evidence 在 1000 条预算内每页最多 100 条收齐，校验相同结果 metadata、总量和重复项，并在读取前后重验当前来源。不完整/预算溢出仍拒绝；UI 区分正常翻页与不完整结果。
重复拼装与轮询开销内部 read_pending 只读本人状态，最终输出前后仍完整复验。纯 TBox 序列化使用完整正文键控的 lru_cache(maxsize=16)；不缓存权限或 ERP 实例，不改变独立可终止 JVM。
ERP 业务口径与实体身份未定义数据所有者 catalog/describe 返回 reasoning_facts。年度汇总沿现有租户时区、当年截至今日、审核入/出库减退货；订单指标独立保留原口径。现有模型没有信用额度、合同、客户年度采购聚合映射，tax_no 可空且不唯一；明确不支持，不自动 sameAs，不把退货赊欠结算当授信。
编辑/执行缺少对应入口SchemaEditor 配置已声明前置类；InstanceExplorer 先创建校验任务，再由用户显式执行，改参/切换上下文清除证明并忽略迟到请求。含 OWL/SHACL 而没有条件时显示配置提示并停用执行按钮。后端仍是强制安全边界。

兼容与启用​

无需新的数据库迁移或运行时依赖。省略 precondition 时不改变旧定义序列化/摘要；新增 ReasonerInput.action 和 ActionQuery.reasoning_job_id 不要求改 Java journal 格式。含 OWL/SHACL 的旧 Action 停止执行，应新建草稿，选定真实业务条件、完成双人审核后发布；不能自动把根类选作前置条件冒充业务规则。没有规则且没有条件的原只读 Action 沿用原授权执行链。任意 query/traverse 仍是显式事实读取，不授予动作权限，也不声称已经通过所有业务规则。

发布 Backend、Agent 与 suite 前端后，需按现有流程重新审核发布 MCP 工具契约；本次未修改 Nacos 配置、MCP 注册和远端状态。回滚到不认识 precondition 的旧 Backend 前必须停用新定义并演练 N-1；不可直接运行旧进程解释新发布正文。全量对话最终裁判、信用/合同管理、跨资源法人主数据和形式证明引擎均未新增；这些需要真实业务数据契约，不能用提示词或模型猜测替代。
