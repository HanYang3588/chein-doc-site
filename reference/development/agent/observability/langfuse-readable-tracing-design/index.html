Langfuse 可读链路与脱敏问答设计

状态：用户已授权按此方案实施；实现与验证结果见文末。本文补充 总体设计，不替代已接受的 ADR。观测始终不能改变权限、租户隔离、Run、审批或 checkpoint 的语义。

1. 实际问题与证据​

当前运行配置为 metadata-only-v1，因此消息 Input/Output 被源端 Callback 和导出白名单主动删除。它适合检查时延、Token 和错误，不能用于阅读问答或判断回答质量。

2026-10-14 的只读 API 检查发现：一条新会话的 BFF 请求约 191.3 秒、Agent execution 约 188.4 秒，模型调用约 11.3 秒，实际用量 6986 Token。多层 framework.chain 没有语义信息；两次消息关联写入显示 cancelled。此次普通对话没有调用知识、分析或图片工具，不能据此认定这些功能未埋点。决策模式为 off，缺少决策节点符合配置。

代码证据：api.py 在每个消息片段上执行取消检查和 lease 心跳，checkpoints.py 为每个控制面操作新建 PostgreSQL 连接。只读探测测得建立连接约 216–246ms，连接加基础查询约 346–367ms；消息关联的总预算仅 500ms。反复连接是可验证的额外开销，关联超时与预算过紧相符；尚不能把整个 191 秒全部归因于数据库。 必须用连接复用测试和部署后的新链路复测确认改善。

历史 trace 不回填。优化后只验证新请求，避免把旧页面的空消息误认为新代码失效。

2. 方案与公开依据​

采用“可选择的脱敏问答、稳定执行节点、结构化工具摘要、现有性能与反馈”。复用当前 SDK、Stage、映射、RLS 和反馈表，不增加服务、运行时依赖或数据迁移。

  • Langfuse Trace 最佳实践：一次工作单元一个 Trace，Session 关联会话；根节点放用户问题与回答，各次模型调用保留独立 Generation，名称稳定且有语义。
  • Langfuse 源端脱敏：数据离开应用前处理，导出层继续设白名单。
  • 社区仅元数据方案及维护者答复：无正文观测也是合理模式，需要保留。
  • RAG 可观测性示例：需要实际查询、证据与结果才能分析检索质量。本次不把原始文档外发，也不宣称已经具备正文级忠实度评测。
  • Psycopg 连接池：复用现有安装依赖，事务成功提交、失败回滚后归还连接。

3. 采集契约​

2026-10-21 补充：下表的 redacted-content-v1 正文能力仅在 Memory 关闭时生效。Memory 开启则从采集与最终导出两层阻止问答，不能通过直接设置 SDK I/O 属性绕过。每个导出的 Agent Span 都记录 data_policy、effective_data_policy 与 content_suppression_reason（policy / memory_enabled / none）；配置模式不再被当作实际正文可用性的证明。对应本地验证见 优化交付。

数据默认 metadata-only-v1显式 redacted-content-v1
tenant/user/session/run/messageHMAC 引用相同
当前用户问题、可见回答不发送脱敏、截断后发送
每次聊天模型调用模型、实际用量、时间加最近一条用户文本和本次回答；标注为选取的问答，非完整模型上下文
系统/个人提示词、历史消息、模型思考、工具参数和原始结果不发送不发送
知识检索数量、证据充分性、阶段状态相同，不发送文档正文
SQL/图表授权、行数、执行/快照状态相同，不发送原始结果表、SQL、业务资源地址
图片Provider、用量、大小、生成/持久化状态相同；用户当前问题可包含生成描述，不发送图片、Base64、签名 URL
反馈分数、类别、同步版本相同；纠正文本只存 Chein
异常、HTTP header、连接串固定错误类别相同，不发送原始异常

问答先去除个人提示词分隔段，再过滤常见密钥赋值、Bearer/JWT、PEM 密钥、邮箱、手机号、身份证号、长编码串和 URL。单条最多 800 字符，单个 I/O 仅一条 user 或 assistant 消息，整个 JSON 必须小于 4096 字符，保留截断标记与选取范围；不递归导出任意对象。内容只允许出现在 agent.execution 和 model.chat 的 I/O 中，模型的额外字段、思考和工具调用参数仍删除。SDK 之前选择文本，导出之前再次校验并过滤。

模式名不是安全保证。规则无法识别全部姓名、商业秘密或自然语言中的敏感内容，回答也可能复述业务数据。 开启后选取文本会存入自建 Langfuse 及其存储。管理员应确认访问范围、保留期限和业务允许范围，再通过私有配置主动启用；高度敏感环境继续用 metadata-only。Backend 与 Chein 观测查询仍仅返回元数据，不因此开放正文接口。不开 debug 或媒体上传。

4. 链路语义​

保留现有业务 Stage 和每次 Generation。将已知固定框架名称映射为 agent.workflow、agent.model-step、agent.tools-step，已知工具映射为有限业务名称；未知名称保持 framework.chain 或 tool.invocation，不能把运行期名字、用户输入或 ID 直接当 Span 名称。保留未知父节点以维持完整父子关系，可在 Langfuse 中按名称过滤；本次不实现复杂的父节点重写。

问答为空时输出明确的选取范围和空消息列表，不能伪造调用或工具结果。取消/失败时允许根节点保留已生成的部分回答，根状态仍为 cancelled/failed/incomplete。重放/恢复不能把旧回答伪装为新的输出。

5. 控制面连接复用与超时​

Agent lifespan 创建私有 AsyncConnectionPool：每个进程最多 8 条、懒建立连接、获取连接最多 2 秒、连接建立最多 5 秒。只有 Agent 控制面使用；LangGraph checkpointer 保持现有连接生命周期。数据库未配置时不创建连接池；数据库故障由原业务错误路径处理，不在启动阶段预建库或修改权限。

所有 open_agent_database() 调用复用这一入口，保留每片段的取消和 lease 重验。使用现有非特权运行角色，每次借还均清空 tenant/owner/analysis 的会话 scope；业务授权保持原样，RLS 的 scope 仍以事务内 set_config(..., true) 设置，事务失败或取消必须回滚。连接失败/重置失败由池丢弃，不共享一条全局连接。独立脚本和没有 lifespan 的测试仍支持短连接，不默认建立全局池。

消息关联总预算改为 2 秒，且在超时转换为 TimeoutError 后记录 unavailable/timeout，不再把可选关联的预算耗尽误标为用户取消。真正的任务取消仍传播并记录 cancelled；关联失败隐藏可选操作、业务对话继续。不是只调大超时：先去除重复连接，延长预算用于数据库多次往返，并有上限。

6. 配置、兼容与回滚​

无需修改 Langfuse Docker、网络、RustFS、PG/Redis 或现有表结构。在 Agent 私有运行配置中选择：

# 默认保留无正文策略；只有允许采集脱敏问答时才修改这一项。
AGENT_OBSERVABILITY_DATA_POLICY: "redacted-content-v1"
LANGFUSE_MEDIA_UPLOAD_ENABLED: false
LANGFUSE_DEBUG: false

保留原有 Langfuse 地址、项目 Key、HMAC Key、环境、采样率和查询/反馈开关。更新代码和私有配置后重启 Agent；Backend 的 metadata OTLP 配置不变。本文实施不自动修改在线 Nacos。回滚为 metadata-only-v1 并重启 Agent；停止未来正文上传不会删除已经采集的数据，历史清理由管理员按保留策略处理。

7. 验证与交付门槛​

  1. 真实 SDK + 内存导出证明：默认策略没有任何消息正文；新策略有可读的选取问答，系统/个人提示词、思考、工具参数/结果、异常、图片等 canary 不外泄，所有 I/O 有界；并发父子和身份隔离继续成立。
  2. 独立临时 PG 验证连接被复用、并发不共享连接、失败/取消回滚、下一租户无 scope、租户/owner FORCE RLS 不变，以及 Run 的 lease/取消负向场景。不能用生产数据库做测试清理。
  3. Agent ruff 与相关 pytest。未修改前端和 API 契约时不重生成客户端或重做 Edition；若触及这些边界则执行相应门禁。
  4. 用户部署后发送新问答，确认策略、消息、语义节点、Token、状态、消息观测操作，以及模型和 SSE 总时间。此前 191 秒是问题样本，不是性能基线；本地合成实验不能替代真实 P95/P99、故障矩阵和 RAG 评测。

8. 实施记录​

设计先行落盘后已完成本地实现；尚未启用在线正文采集或宣称已上线验收。

  • agent/src/chein_agent/trace_content.py：有限文本选择、常见敏感内容过滤、截断及严格 I/O 信封校验。
  • agent/src/chein_agent/langfuse_tracing.py：两种策略、真实 Callback 问答、有限框架/工具名称、双层过滤和部分输出；根输出在 execution 结束时写一次，避免每 Token 反复序列化。
  • agent/src/chein_agent/api.py：在既有授权/claim 后选择当前问题，记录已产生的可见回答。
  • agent/src/chein_agent/checkpoints.py、main.py：复用私有控制面池，连接借还清 scope，shutdown 关闭；checkpointer 未改。
  • agent/src/chein_agent/telemetry_store.py：有界关联预算及准确的 timeout/cancelled 分类。原有鉴权、lease、映射、反馈和 RLS 不变，无新表或依赖。

2026-10-14 实际本地验证：

cd agent
NACOS_ENABLED=false uv run ruff check src tests
# 以下三个 TEST_* URL 必须指向自行创建并迁移的隔离临时 PG。
NACOS_ENABLED=false TEST_AGENT_DATABASE_URL="$isolated_runtime_url" \
  TEST_TELEMETRY_ADMIN_URL="$isolated_admin_url" \
  TEST_TELEMETRY_RUNTIME_URL="$isolated_runtime_url" uv run pytest tests -q
cd ../backend
uv run ruff check app tests

Agent 与 Backend ruff 均通过。Agent 全量 221 passed、1 skipped；跳过的是原有 test_real_snapshot_owner_rls_immutable_rows_and_expiry，它只接受固定端口和库名的既有分析专用 fixture，本次未放宽该条件。新增连接池测试使用独立临时 PG 和非特权运行角色，验证连接复用、并发不同连接、会话 scope 清空、跨 tenant/owner 隔离、事务错误回滚，以及真实取消 pg_sleep 后回滚。原有反馈 RLS、quota/revision、Run lease 负向和 SDK 父子关系回归通过。SDK 仅设置 trace ID 时会创建未导出的合成父节点；父子测试核验所有 execution 内部节点，不把 SDK 合成父节点误判为业务节点缺失。

本地 loopback 合成 SELECT 实验：20 次短连接中位数 3.022ms，20 次连接池借用中位数 0.296ms，池共建立 2 条连接。这只证明复用机制有效，不能推出真实网络或整轮 SSE 的 P95/P99 改善幅度。临时 PG 已关闭；实际 Nacos、Docker、网络和远端中间件未修改。

相对文档链接与 git diff --check 通过。本次未修改前端、API DTO 或 Edition，不执行这些无关构建。远端 CI、镜像扫描/签名、真实会话页面、性能故障矩阵和内容质量评测尚未验收；需要用户部署后按第 6、7 节验证新 trace。先前交付中的其余外部门禁仍有效。
