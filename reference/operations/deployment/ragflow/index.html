RAGFlow 独立部署操作手册

当前默认：Chein 使用原生 Tool 和官方 HTTP API，无需启用 MCP。本手册保留 MCP 部署步骤供可选恢复，恢复要求见原生 Tool 集成；下述 MCP 启用待办属于旧接入方案。

状态：已有 HTTP 知识库接入；官方 MCP 原生客户端与发布命令已实现。当前远端 MCP 端口未响应，容器启用、Nacos 登记与真实 MCP 检索仍待验证。

适用范围：在另一台 x86_64 Docker 主机运行 RAGFlow v0.27.2，复用已有 PostgreSQL、Redis、Elasticsearch 和 RustFS。

1. 部署文件与端口​

文件作用
Dockerfile基于 infiniflow/ragflow:v0.27.2，加入配置模板与入口脚本；不包含运行时凭据。
service_conf.yaml.template从容器环境变量生成 PostgreSQL、Redis、ES、S3/RustFS 连接配置。
entrypoint.sh启动 RAGFlow 管理服务；RAGFLOW_ENABLE_MCP=true 时启动官方 MCP，默认 host 模式。
ragflow.env.example运行参数示例，复制后填写真实值，绝不放进镜像或提交 Git。
run.sh对下文 docker run 的本地封装；已有同名容器时拒绝覆盖。

当前端口映射为 127.0.0.1:9380 -> 容器 80（Web/API）、127.0.0.1:9381 -> 容器 9381（管理 API）、127.0.0.1:9382 -> 容器 9382（MCP）。即使 MCP 未启用，run.sh 仍会映射 9382。远程访问这些宿主端口需另行配置受控代理或 VPN；不要直接开放到公网。

2. 首次部署前准备​

  1. 在目标机确认 Docker daemon 可用：docker info。确认目标架构：docker info --format '{{.Architecture}}'。本手册的构建命令固定输出 linux/amd64 镜像。
  2. 为 RAGFlow 准备独立 PostgreSQL 数据库和账号、Redis logical DB、Elasticsearch 账号、RustFS bucket/访问密钥。共用中间件实例可以，共用 Chein 业务数据库与账号不可以。
  3. 确保目标机能访问这些中间件。若以容器名连接，先确认它们与 RAGFlow 在同一个 Docker 用户自定义网络，例如 chein-shared；其他情况在参数中填写目标机可访问的 DNS/IP。容器内的 localhost 指向 RAGFlow 容器自身。
  4. 确认构建机和目标机都可访问你的私有 Registry，并使用目标机也能解析的 Registry 地址。示例中的 registry.example.com:5000 必须换成真实地址；localhost:5000 只表示各自机器本机。

私有 Registry 要求登录时，在两台机器分别运行 docker login registry.example.com:5000，按交互提示提供凭据。

RAGFlow 的建表由其官方入口在启动时执行；当前 entrypoint.sh 没有传 --init-model-provider-tables，不要把模型 Provider 表迁移写成已执行。首次部署和版本升级都应检查实际启动日志，并按目标镜像版本的迁移要求处理。

3. 构建并推送镜像​

在仓库根目录执行。Mac 为 Apple Silicon 时也按目标机架构构建：

docker info
docker buildx build --platform linux/amd64 \
  -t registry.example.com:5000/chein/ragflow:v0.27.2 \
  --push deploy/ragflow

这一步构建并推送派生镜像。目标机只需拉取镜像，不需要仓库源码或 Dockerfile。镜像标签要与实际部署版本一致；后续升级使用新标签，不覆盖旧标签。

4. 在目标机准备参数​

将 ragflow.env.example 的内容复制到目标机仓库外的私有文件，例如 /run/secrets/chein-ragflow.env，填入目标环境的值，并将文件权限设为 0600。参数文件使用 Docker --env-file 格式，即每行 KEY=value，不要加 YAML 冒号或 Shell export。

配置组必要参数用途
固定选择DB_TYPE=postgres、DOC_ENGINE=elasticsearch、STORAGE_IMPL=AWS_S3、API_PROXY_SCHEME=python使用已有 PostgreSQL、ES、RustFS 和 Python 服务。
PostgreSQLPOSTGRES_HOST、POSTGRES_PORT、POSTGRES_DBNAME、POSTGRES_USER、POSTGRES_PASSWORDRAGFlow 自有元数据库。
RedisRAGFLOW_REDIS_HOST、RAGFLOW_REDIS_DB、RAGFLOW_REDIS_USERNAME、RAGFLOW_REDIS_PASSWORD队列与缓存；Redis Cluster 不支持逻辑 DB 隔离时需专用实例。
ElasticsearchRAGFLOW_ES_URL、RAGFLOW_ES_USERNAME、RAGFLOW_ES_PASSWORD全文及向量检索；URL 应包含 http:// 或 https://。
RustFSRUSTFS_ENDPOINT、RUSTFS_REGION、RUSTFS_ACCESS_KEY、RUSTFS_SECRET_KEY、RUSTFS_BUCKET、RUSTFS_PREFIXS3 兼容对象存储；预先创建 bucket，使用独立 prefix。
管理员ADMIN_DEFAULT_PASSWORD首次创建管理员时使用，不能保留模板值。

示例默认关闭 MCP。要启用官方 host 模式，在目标机私有参数文件设置：

RAGFLOW_ENABLE_MCP=true
RAGFLOW_MCP_LAUNCH_MODE=host
RAGFLOW_MCP_HOST_API_KEY=

host 模式从客户端的 Authorization: Bearer 读取真实 RAGFlow API Key，不需要启动密钥。self-host 模式仅保留兼容：它用启动时的真实 RAGFlow API Key 代理所有调用，不进行逐客户端 API Key 校验；该值不能随机生成，不建议本项目使用。两种模式都需限制端口网络访问。

旧派生镜像的入口脚本固定 self-host 且要求启动密钥，必须用更新后的入口构建新镜像并重建容器；只修改本地文件或执行 docker restart 不会更新远端镜像及容器环境。官方 v0.27.2 MCP 为独立进程，默认不启动，Streamable HTTP 地址为 http://主机:9382/mcp。Go 版本的 /api/v1/mcp 不适用于此镜像。依据见固定版本启动规范。

5. 目标机拉取并运行​

下列命令与当前 run.sh 的容器名、网络、端口、日志 volume 和重启策略一致。按实际环境替换镜像地址与网络名称：

docker pull registry.example.com:5000/chein/ragflow:v0.27.2
docker network inspect chein-shared
docker volume create chein-ragflow-logs

docker run -d \
  --name chein-ragflow \
  --restart unless-stopped \
  --network chein-shared \
  --env-file /run/secrets/chein-ragflow.env \
  -p 127.0.0.1:9380:80 \
  -p 127.0.0.1:9381:9381 \
  -p 127.0.0.1:9382:9382 \
  -v chein-ragflow-logs:/ragflow/logs \
  registry.example.com:5000/chein/ragflow:v0.27.2

中间件不在 Docker 网络内时，可将 --network chein-shared 改为实际网络设置，并把参数文件中的主机地址改成容器可访问的地址。

若目标机也有本仓库的 deploy/ragflow/run.sh，可改用：

./deploy/ragflow/run.sh \
  --env-file /run/secrets/chein-ragflow.env \
  --network chein-shared \
  --image registry.example.com:5000/chein/ragflow:v0.27.2 \
  --no-build

--no-build 要求镜像已在目标机；run.sh --check 校验必填键、固定选项、MCP 模式及 self-host 密钥是否填写，不能代替连接验证。

6. 验证与重建​

docker ps --filter name=chein-ragflow
docker logs --tail 100 chein-ragflow
curl --fail http://127.0.0.1:9380/api/v1/system/healthz

若启用了 MCP，日志中应出现 Starting MCP Server，再用持有真实 RAGFlow API Key 的客户端连接 http://127.0.0.1:9382/mcp 并列出工具。当前 Chein 的预览和 Nacos 发布命令见工具管理实施设计。必须先真实握手，再登记固定 endpoint 和 Schema；登记完成后才设置后端 RAGFLOW_MCP_SERVER。Agent 经 Chein 授权 Facade 使用检索，不直接访问原始 RAGFlow 目录。

验证一次上传、解析和检索，才能确认 PostgreSQL、Redis、ES、RustFS 与模型配置都可用；仅健康接口通过不足以证明整个 RAG 流程可用。

调整参数或换镜像标签时，先备份 RAGFlow 数据库、对象存储和 ES 索引，再在维护窗口停止并删除已确认名称为 chein-ragflow 的容器，用第 5 节命令重建；chein-ragflow-logs volume 会保留。旧镜像标签可保留用于应用层回退，但数据库迁移不会自动回滚，跨版本回退前要验证数据兼容性。

7. 凭据与仓库状态​

deploy/ragflow/ragflow.env 和 deploy/ragflow/service_conf.yaml 是本机运行配置，已列入 .gitignore；忽略规则不会取消此前的 Git 暂存。提交前应检查：

git status --short

若这两个文件出现在暂存区，先取消暂存并确认没有进入提交。仓库根目录的镜像归档也是本地制品，不应作为源码提交。

8. 接入管理系统和 Agent​

Suite 新安装使用知识库管理启用的动态模式：在管理页面创建、上传和维护共享，不配置固定 Dataset/Document ID。以下静态接入仅保留用于旧的已批准公共资料。

旧静态共享资料模式​

  1. 在 RAGFlow 建立只含所有租户均可阅读的业务文档的专用 Dataset，上传并完成解析。可从 docs/erp-knowledge/ 选择已核对的正式文档；demo/ 是虚构素材，不得当成真实业务事实。
  2. 在 RAGFlow 检索测试中确认问题能命中目标片段；若启用 RAGFlow 的 rerank，记录该模型 ID。切片、Embedding 和 rerank 由 RAGFlow 完成。
  3. 从 RAGFlow 取得 Dataset ID 和每个已批准 Document ID，在 Agent 的私有 Nacos 运行配置中填写 RAGFLOW_BASE_URL、RAGFLOW_API_KEY、RAGFLOW_SHARED_DATASET_IDS、RAGFLOW_SHARED_DOCUMENT_IDS；按需填写 RAGFLOW_RERANK_ID。示例键见 chein-agent-runtime.yaml.example。Agent 需使用 Python 3.13。
  4. 重启 Agent，发起“ERP 库存余额应该参考哪份文档”的对话，检查 AG-UI 工具事件包含 search_business_knowledge、返回的 document/chunk ID 均在批准范围内；回答引用了 chunk 时，检查页面下方的“参考文档”链接可下载对应文件，刷新会话后链接仍在。配置缺失时工具不注册。

当前检索只面向明确列出的共享文档。不能把包含租户私有数据的 Dataset 或 Document ID 填入该列表。索引版本和源文件 checksum 尚未固定，重建索引后的历史 Run 不能保证按原证据回放。
