数据源与数据表管理交付说明

2026-10-30，本地工作区实现及验证记录；不代表远端 CI 或生产部署。参考上游提交与设计分析见 DataVines 提炼。

功能与边界​

Suite 新增独立 datasource 业务模块，只依赖 Platform；Base、Items、ERP Edition 不装配。实现数据源分页/搜索/类型筛选、动态连接表单、连接测试、加密凭据、编辑保留密码、版本冲突保护和引用删除阻断。列表状态是最近一次测试结果，不能当作持续健康监控。

目录持久化 database/table/column，保留主键顺序、字段类型/长度/精度/可空/默认值/生成表达式/注释、外键有序字段对、索引和估计行数。新增源自动提交首次采集，手动全源/单表刷新通过现有 ScheduleHandler 执行；每次租约最多10表、60秒，批次间持久化游标，旧 attempt 不能覆盖恢复后的任务。成功才事务发布；失败保留旧目录。未见实体记 missing_or_inaccessible，重建同名实体分配新 ID，不自动继承旧配置。

人工配置独立保存业务名称、描述、标签、启用、字段暴露和脱敏。首次采集发现的所有表（包括标为“不建议”的表）默认启用；升级前保存为停用且配置 revision=1 的旧表，在下次成功同步发布该表时启用并递增配置版本。所有人工配置入口都会递增版本，因此 revision>1 的配置（包括手动禁用）保持原状；业务配置和敏感字段暴露规则不变。适配仅在当前租户、数据源和已成功发布的表范围内进行，使用行锁与同步事务，重复同步不重复改写；无需新增迁移，后端加载最新代码后点击“同步元数据”生效。人工配置过的旧表可用现有批量启用入口调整。支持批量启停/标签、前缀或关键字筛选、临时/日志/备份表提示；批量操作和单表配置都有外键依赖提示及一并启用。单表带依赖使用 dependency_revisions，目标集合和配置版本变化会冲突，全部配置在同一事务提交。

默认启用及旧表适配调整的验证：一次性 PostgreSQL 集群内运行现有隔离测试入口，模块迁移 upgrade/check/downgrade 及 Suite 迁移装配通过，数据源27项测试通过、2项跳过（未配置真实 MySQL 及 H2 JDBC 驱动）；覆盖新表启用、旧初始配置适配与幂等、手动禁用后同步保留、依赖启用、敏感字段隐藏与租户/RLS。uv run ruff check app tests 通过，临时数据库和集群已清理。未改写开发数据库数据，无新增接口或迁移；远端 CI 和真实业务库联调未执行。

前端入口 /datasources，使用现有 ProTable、Ant Form/Drawer、虚拟 Tree 和分页字段表；搜索防抖300ms。树一次取50表，服务端搜索覆盖尚未加载的表。表详情分字段、键/索引、预览、变更四个 Tab；配置作为次级入口。保存表、字段或批量配置后刷新当前详情与配置列表、清除旧样本，保留树缓存、已展开节点、当前选中表和详情 Tab；配置保存不触发数据库目录重载。元数据同步完成仍刷新目录。采集任务可在重新进入页面后恢复轮询。

首次同步在所有批次采集成功后才统一发布目录；采集期间无目录不代表连接失败。页面显示中文任务状态、已采集/总表数及进度，完成后自动重载数据库和表，目录请求失败提供重试，避免把加载失败显示成空目录。PostgreSQL 显示已配置的数据库与所选 Schema；每个连接仅采集显式选择的范围。Chein 自身 ERP 模块的迁移 Schema 是 erp，不是 public；可在同一连接内同时选择 public、erp、agent 等有权限的 Schema，页面不会根据数据源名称推断。

字段表分页显示类型、长度、精度、小数位、可空、默认值、主键、注释及业务配置；点击行左侧展开按钮可查看已采集的完整字段属性，包括生成表达式和驱动特有属性。主键按有序字段名展示，索引和外键使用有标题的表格；未提供的元数据不伪造。

这次目录展示修正的验证：受影响组件3文件9项测试通过（新增首次同步进度/完成自动加载、完整字段属性、加载失败重试3项），前端类型检查通过；真实登录页面已确认同步成功、表目录和字段展开详情，验证截图通过开发归档入口保存至 RustFS。变更仅涉及 Catalog、模块中文文案、组件测试与本文，不修改后端接口、迁移或已保存连接；未重跑后端数据库测试，也未执行远端 CI。

预览仅接受目录表 ID 和行数，不接受 SQL；固定 SELECT、引用标识符、白名单列、默认20/最多100行，最多200列。exposed=false 不查询；redact/last4 在服务端执行，单元格和响应有字节预算，结果不入库且 no-store。预览前复验结构，外部读取后重新检查当前权限/权益。MySQL 使用只读事务，驱动读写和连接超时5秒、SELECT 执行限制及 metadata lock 超时5秒；表描述累计超过20秒拒绝发布。DNS 解析沿用系统 resolver，平台仍须配置可靠 DNS 及出站防火墙，不能把应用超时当作网络隔离替代品。

本次没有本体生成、Ontop、任意 SQL 编辑、跨模块数据读取或 Agent 工具。仅预留 nullable IRI；未来实际建立跨模块映射时，还必须由映射所有者增加稳定的引用/删除契约，不能仅凭这些空字段宣称已接入本体。

文件与所有权​

  • 后端：backend/app/modules/datasource/{module.py,routes.py,public_api/dto.py,application/,infrastructure/,migrations/}；六张表、权限和生命周期均由模块声明。
  • 组合：editions/suite.yaml、模块 registry、Platform runtime grant；公开 web_api 注入加密和无缓存授权复验。evaluate_module_access(use_cache=False) 保留原请求路径默认缓存语义。
  • 前端：frontend/apps/web-pro/src/modules/datasource/{pages/,components/,api/,locales/}，受控 page-registry 与菜单语言；OpenAPI 客户端和 Manifest 通过现有生成器更新。生成器为各模块共享同一组件 Schema，因此其他 generated 类型文件也包含新增 DTO，未手工改写。
  • 测试：backend/tests/modules/datasource/test_datasource.py、backend/tests/modules/test_manifest.py、前端模块组件测试；一次性环境入口为 backend/scripts/test_datasource_isolated.py、test_datasource_mysql.py。
  • 契约：接口与数据库说明、完整迁移 DDL（未发布资料）。

启用与迁移​

macOS/Linux 操作脚本为 scripts/datasource-setup.sh，从仓库根目录按顺序运行：

uv sync --project backend --frozen
pnpm --dir frontend install --frozen-lockfile
bash scripts/datasource-setup.sh build
# 备份目标数据库、停止目标 API/Worker 后再执行以下两步。
bash scripts/datasource-setup.sh migrate
bash scripts/datasource-setup.sh seed

迁移执行所有待执行的 Suite revision，并将运行角色密码同步为 bootstrap 中的值；不是只建 datasource 表。seed 会同步全局菜单、默认套餐菜单和默认租户内置角色绑定。脚本默认维护 Data ID 为 chein-backend-bootstrap.yaml、运行 Data ID 为 chein-backend-runtime.yaml，可分别用 DATASOURCE_BOOTSTRAP_DATA_ID、DATASOURCE_RUNTIME_DATA_ID 覆盖。沿用已有 .env 中的 Nacos 连接信息；私有 bootstrap 必须含管理员连接及匹配的运行角色密码，runtime 不得含 POSTGRES_ADMIN_URL。具体配置规则见初始化文档。脚本不修改 Nacos、用户授权或服务进程。

数据源的主机、端口、库名、账号和密码均在页面填写；不需要配置网络或端口白名单。默认 TLS 要求运行环境信任 MySQL 证书。部署后沿用现有方式重启 Suite API、Schedule Worker 和前端；未提供自动重启命令，以免停止其他工作进程。在“租户管理 → 目标租户 → 模块权益”开通 datasource 并启用；自定义套餐需补齐菜单范围，非默认租户同步租户菜单，再给角色分配所需权限：datasource:read/create/update/delete/test/sync/preview/configure（每个均为完整独立权限，例如 datasource:read）。重新登录后从 /datasources 进入。

  1. 使用 Suite 生成和构建：pnpm build:edition -- --edition suite。按现有部署流程用管理员迁移凭据执行 pnpm migrate:edition -- --edition suite；再执行现有 runtime 角色授权脚本，使 app_runtime 获得 datasource schema 权限。
  2. 运行现有 Platform 初始化/导航同步流程，明确授予套餐或租户 datasource 权益及用户所需 datasource:* 权限；新模块不会自动向历史套餐开通。
  3. API/Worker 仅使用 runtime 数据库连接。业务 MySQL 使用 SELECT 账号，连接地址与端口在页面设置，不额外要求运维配置白名单。
  4. 默认校验证书与主机名；私有 CA 可由运行环境信任库/SSL_CERT_FILE 提供。DATASOURCE_ALLOW_INSECURE_TLS 默认 false；隔离测试明确打开它，生产应配置可信证书。
  5. 沿用 SECRET_KEY 派生 Fernet 密钥。必须备份并规划重加密轮换；直接换 key 会使历史连接不可解密。本次不增加 KMS。
  6. 新增 PyMySQL 运行依赖并更新 backend/uv.lock，镜像沿用 uv lock 安装。无前端新依赖。数据库为新增模块 schema，不改写历史 revision；降级将删除模块数据，需先备份。未变更本体发布契约。

可重跑验证​

DATASOURCE_TEST_ADMIN_URL 必须指向隔离 PostgreSQL 测试集群的管理员连接，禁止开发/业务库。集群需按现有部署方式准备非 BYPASSRLS 的 app_runtime 角色（Platform 历史迁移依赖该角色）。脚本自动创建 chein_ds_test_<uuid> 数据库，验证 datasource upgrade/check/downgrade，再编排 Suite 迁移；结束强制删除该子库。不会把继承的业务 POSTGRES_URL 当作测试目标。

  • pnpm backend:test:datasource：PostgreSQL 持久化/API/RLS；未提供 MySQL 测试连接时明确 skip 实联。
  • pnpm backend:test:datasource:mysql：Docker 自动创建含502张表的 MySQL 8、仅 SELECT 的 reader 和随机密码，等待就绪后运行上面的隔离数据库测试，finally 删除容器和卷。镜像默认 mysql:8.0，可用 DATASOURCE_TEST_MYSQL_IMAGE 指向预先取得的官方镜像。密码仅在系统临时目录600权限文件和子进程环境中传递。
  • cd backend && uv run ruff check app tests；对应 module/manifest/import boundary/access 测试；uv run alembic check 以及 datasource namespace check。
  • pnpm frontend:typecheck、pnpm frontend:pro:test；pnpm build:edition -- --edition base、items、suite。Edition 生成会切换本地 Manifest，必须串行构建，完成后保留 Suite，再运行完整前端测试。

数据源类型扩展（2026-10-30）​

当前 Chein 注册15种数据库类型，完整清单和验证状态见下表。PostgreSQL 复用已有 psycopg/SQLAlchemy；Doris/StarRocks 复用 PyMySQL；ClickHouse/Databend 复用 httpx；新增 JPype1 连接 JDBC、PyMongo 处理 BSON/认证/连接池。现有依赖和标准库不提供后两种协议能力，不自行实现它们。表单从后端取得类型和字段；列表类型筛选也改为动态加载，切换类型会清理旧参数并采用该类型默认值，提交仅包含该类型声明的字段。

PostgreSQL 默认端口5432，连接表单使用 schema_names 多选采集范围；测试连接先返回有 USAGE 权限的非系统 Schema，每个连接管理一个数据库，不跨库，也不自动把新发现的 Schema 纳入采集。历史 schema_name（默认 public）继续作为单 Schema 配置读取。目录以配置数据库为根，按 Schema 分组懒加载表；表描述保存真实 Schema，跨 Schema 外键通过完整数据库/Schema/表名解析；未纳管目标显示为未解析。复合主键顺序、字段类型/长度/精度/默认值/注释、外键和索引均读取数据库真实元数据，行数为估计值，未统计时 null。事务只读，连接超时5秒、服务端 statement_timeout/lock_timeout 为5秒，预览最多100行/200列并限制单元格。PostgreSQL 使用 libpq 的连接/TLS和服务端语句超时；未声称具有 MySQL 驱动同样的 socket read/write 超时。TLS verify-full 使用 libpq 的证书信任配置；使用自签名 CA 时配置运行环境的 PGSSLROOTCERT，普通连接仍需现有 DATASOURCE_ALLOW_INSECURE_TLS 显式许可。

连接 JSON 增加带默认值的 schema_name，兼容历史 MySQL 记录；类型相关默认端口在创建、修改和测试时由后端字段描述解析。已生成 OpenAPI 客户端，未修改数据库表结构或历史迁移。旧前端与新增契约不同，部署时需同步更新 Suite 后端/前端及 Manifest。

新类型的部署与边界​

MySQL、PostgreSQL、Doris、StarRocks、ClickHouse、Databend、MongoDB 不需要另启 Java 服务；所有业务地址、端口、Schema、账号/密码仍只在页面填写。执行 uv sync --project backend --frozen 安装当前锁定的 PyMySQL、JPype1、PyMongo；后端 Dockerfile 已加入发行版默认的 headless JRE，厂商 JAR 不打入源码或自动从网络下载。

Oracle、SQL Server、DM、Hive、Impala、Presto、Trino、MaxCompute 使用进程内 JDBC。部署方需提供与自身 Java/数据库版本匹配、来源及依赖经过审核的驱动包，放到只读目录：默认 /opt/chein/jdbc，本机可通过 runtime 的 DATASOURCE_JDBC_DRIVER_DIR 指向其他目录。这是驱动文件位置，不是连接地址或网络白名单。只加载代码注册的8个驱动类；不开放页面上传驱动或填写 Java 类。需要包含厂商分发包的全部依赖，不能只复制一个缺少依赖的薄 JAR。JAR 变更后重启 API/Worker；同一进程 JVM 只启动一次，不热换驱动。生产发布需把这些外置 JAR 一并纳入制品清单、哈希/签名及依赖漏洞扫描；Python lock 扫描不覆盖 JAR。

检查脚本不连接业务数据库；ready 仅代表 JVM/驱动类可实例化，不能当作连接、TLS、元数据或预览验收。缺少 JRE/JAR/传递依赖时返回 driver_unavailable，不向浏览器返回 Java 堆栈。Java 按 Python API/Worker 进程懒加载，每个 JVM heap 上限256MiB；例如4个活跃 JVM 仅 heap 上限合计1GiB，另有 Python/native 开销，需在容器资源预算中计算。

JDBC 查询固定设置最大行数；除离线 ODPS 不执行其无效的 setter 外，设置 Statement 超时。Oracle/SQL Server/DM/Presto/Trino 还要求驱动网络超时确实生效，否则返回 timeout_unavailable。Hive/Impala 使用驱动 URL 的 socketTimeout=5000，MaxCompute 固定 REST/Tunnel 读/连接5秒、禁止自动网络重试，并强制 https_check=true；这两个适配因上游明确不支持 setNetworkTimeout 而使用原生参数。ODPS SDK 的 REST/Tunnel 超时单位是秒，不是其 README 表格写的毫秒，已按实现及厂商使用说明配置并测试参数。结果集/Statement/连接均关闭；池每源最多2连接、全局最多缓存16源，JVM全进程共享。JDBC 调用额外有客户端截止：连接测试/预览5秒，库表描述20秒，争用最多等待5秒；超时异步尝试 Statement.cancel，不返回迟到结果。进程内最多2个 JDBC I/O 操作及2个取消调用；若驱动永久不返回，后续 JDBC 调用失败关闭，不持续增加线程，也不把仍在执行的连接放回池。不能据此保证云端作业已经取消或不产生费用，必须由部署方完成厂商取消/断网测试。JDBC 的 readOnly 提示不能证明强制只读，连接器仅生成固定元数据/SELECT，部署必须使用最小只读账号。所有查询的厂商强制取消、网络断连及账号权限仍须实联复验。

MaxCompute 的 host 填 Endpoint 主机（不含协议和 /api），port 默认为443，database 为 Project；Schema 留空选择普通 Project，非空选择 namespace Schema。非关系引擎不把排序键或非强制 Key 冒充主外键；JDBC 对这类引擎不调用关系约束/索引接口，预估行数未知为 null。元数据完整性取决于厂商驱动；备注为空不伪造业务注释，未命名外键无法安全分组时失败关闭。

Databend 改用原生 HTTP：本次检查的上游 JDBC 实现对 HTTPS 调用了 trust-all 的 setupInsecureSsl，而且网络/Statement 超时 setter 不执行限制，不能直接照搬。JDBC 客户端源码、TLS 实现。Chein 使用验证证书/主机名的 httpx，POST /v1/query，处理分页/最终确认和失败取消；next/kill 地址只允许回到该连接的同源查询接口，拒绝重定向、跨源凭据转发和额外查询参数。max_execute_time_in_seconds=5，排队5秒，单查询客户端20秒预算，socket5秒，累计8MiB/10000行上限；预览 SQL 仍最多100行。Doris/StarRocks query_timeout=5，仅 SELECT 账号；ClickHouse 使用 readonly=1、max_execution_time=5 和有界 HTTP 读取。

新增适配与已有加密、Tenant UoW、RLS、权限、采集租约和预览校验共用，不增加服务或数据库迁移；这次新增的是连接 JSON 的默认 Schema、TypeDescription.notice 和驱动实现。部署需同步更新 Suite 后端、前端及生成 Manifest，并重启实际承接请求和采集的进程。旧 MySQL 连接 JSON 无需补字段。

PostgreSQL 多 Schema 采集​

新增/编辑 PostgreSQL 数据源时，先测试连接，再在“采集 Schema”中多选，保存后同步。测试发现最多1000个有 USAGE 权限的非系统 Schema（排除 information_schema、pg_ 前缀），单连接最多选择100个；发现不等于表读取授权，采集仍逐表检查 SELECT 权限，最多10000表。空 Schema 也保留分组，新增 Schema 必须重新测试并明确勾选。Schema 名称只能作为绑定参数或引用标识符使用，不接收 SQL。MySQL 仍是配置数据库下的表列表。

schema_names: [] 只允许用于测试发现；创建/修改连接须至少选一项（schema_required/422）。测试返回的 schemas 受测试权限保护，外部调用后再次复验当前授权。保留 schema_name 兼容旧调用；schema_names 未提供时按旧单值采集。目录根 properties.schemas 保存最近成功发布的采集范围，不另建 Schema 配置实体。PostgreSQL 表/字段路径加入类型和 Schema，避免同名或旧路径碰撞，首个成功发布通过旧表记录中的真实 Schema 保留原表/字段 ID、启用状态、业务配置与外键引用；不把另一 Schema 的同名表误认作旧表。

树展开某一 Schema 时按其范围取50表，加载更多沿用原分页；搜索查询全部已选 Schema，在对应分组下展示结果，表配置页通过 Schema 列区分同名表。单表刷新、预览与结构复验均使用实体自身的 Schema，而不是连接中的旧单值。取消勾选后的全量成功同步会将范围外旧目录标记 missing，重新纳入仍按既有重建规则分配新身份，不自动继承敏感配置。

目录浏览布局与分支加载​

目录使用 Ant Design 原生 DirectoryTree 和 Splitter：MySQL 为数据库 → 表，PostgreSQL 为数据库 → Schema → 表。左右面板占满页面剩余高度，可拖动分隔条；窄屏改为上下布局，树保持虚拟滚动。顶部移除重复的数据库与 Schema 下拉，直接通过树展开；同步状态、计数和搜索同一工具栏显示，最近同步时间与失败码收进提示，不再单独展示状态卡片。

各 Schema 独立缓存表分页，展开只加载当前分支；收起、重开和打开其他分支不清空已加载表或当前表详情。首次请求合并重复加载，过期响应不会写回新目录，分支失败单独重试；显式刷新/成功同步后重新读取目录。全局搜索仍由后端覆盖未加载表，结果按 Schema 分组，清除搜索恢复原分支及展开状态。每次取50表，更多表由分支内“加载更多”获取。

存量表默认启用修正（2026-10-30）​

“新表默认启用”不会自动更新数据库里的旧默认值。此前只在元数据成功同步时提升未修改过的旧记录；OWL Reader 又按 enabled=true 查询，因此未重新同步的旧目录可能只显示少数已启用表。新增模块迁移 0002_enable_default_tables.py（datasource_enabled_defaults_v2），在部署时一次性将 active table、enabled=false 且配置 revision=1 的记录启用并增加 revision，不依赖再次访问业务数据库。

配置 revision>1 表示已保存过配置，无法可靠区分停用意图与其他配置编辑，保持原状态；需启用时使用现有表配置或批量启用。迁移不改变字段 exposed/mask_policy、Schema、业务名称或 IRI；随后手动停用仍由现有配置版本保留。回退 revision 不撤销数据修正，避免覆盖迁移后的用户选择；需要恢复原配置时使用部署前备份。迁移在维护连接执行，row_security=off 仅用于让权限不足时明确失败，不能绕过 FORCE RLS；不修改 RLS 策略或 runtime 权限。

已有环境按既有流程备份并停止 API/Worker 后，在仓库根目录执行：

bash scripts/datasource-setup.sh migrate

连接复用现有 Nacos bootstrap 配置；该命令会执行所有待迁移 Suite revision，并非只运行这一项。前后端须使用本次生成的 Suite Manifest。完成后重启后端，关闭并重新打开 OWL 目录导入弹窗以重新读取状态。未增加地址、密码配置或额外服务。维护命令尚未对实际业务库执行。

本地回归覆盖 125 张目录表仅两张启用的旧数据场景：迁移后 124 张可按 50/50/24 分页读取，显式保存停用的第 125 张不返回，敏感 phone 字段保持隐藏，重复升级不改变结果。一次性 PostgreSQL 集群完成 upgrade/check/downgrade、Suite 迁移及数据源测试 28 passed、2 skipped（未提供真实 MySQL 与外置 H2 JAR）；包含临时 PostgreSQL 连接器与 app_runtime 隔离测试。Base、Items、Suite 构建通过，保留 Suite 生成结果。此记录不代表目标环境已升级或远端 CI 已执行。

补充验证：Ruff、前端类型检查、Manifest/迁移配置检查 12 项通过；目录 Reader 与导入弹窗 5 项测试重跑通过。弹窗批量选择失败重试测试首跑超时、未改代码重跑通过，仍有测试时序不稳定的可能。未对用户正在操作的真实浏览器和业务数据库执行修正或完成端到端验收。

Logic Pack 外部事实接入​

2026-11-01 新增只读 datasource.ontology-data v1。此前“仅预留 IRI、没有跨模块读取”的结论限于目录导入路径；Logic Pack 现在可通过独立 capability 绑定单连接 PostgreSQL UUID 单列主键表，读取启用/暴露且未脱敏字段的有界 RR 快照。目录复制导入仍不读取样本或建立活跃映射。Ontology 拥有最小引用索引，Datasource 删除经只读引用 capability 与事务锁阻断已引用连接；实际验证、迁移与限制见 P5B 交付。

OWL 原始表浏览（2026-11-03）​

新增目录实体到源表的只读定位接口；已暴露字段可定位父表，停用/失效/不可见实体拒绝。preview 请求兼容增加 offset（0–10000、分页时 limit≤50），响应增加 has_more 和 next_offset；旧的不带 offset 的100行预览保持原语义。分页使用额外一行判断下一页，不运行 COUNT 或构造虚假总数，不缓存行数据。PostgreSQL/MySQL 及 HTTP/兼容驱动生成有序限行查询，JDBC 使用既有方言限行与有界 cursor 跳过，MongoDB 排序/skip/limit 后只投影暴露字段；保留超时、只读与输出大小限制。

数据仍由 Datasource 的当前 Tenant UoW、read/preview 权限、结构摘要及字段配置约束；返回后重验当前 preview 权限。UI 不额外改写值，但不绕过既有脱敏或数据库 RLS。原元数据 Reader 保持不读样本，新的 public_api/preview.ts Reader 按 Manifest 单独注入 OWL，不建立活跃绑定。无 DDL、角色授权、运行依赖或 Nacos 配置变更，API/Manifest 只通过命令生成。UI 操作见 OWL 原始表面板。
