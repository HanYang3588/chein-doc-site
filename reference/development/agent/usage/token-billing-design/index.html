Agent Token 计量、计费与分级额度设计

状态：Proposed（P0 已有本地实现，交付范围与未完成项见实施交付；P1–P3 未实现）。本文是该功能的唯一设计事实源；运行边界沿用 Agent 架构。实现提示词见 Codex 开发提示词（未发布资料）。文中“当前”均指 2026-11-02 工作区，“目标”均为设计，不代表已上线。

1. 结论摘要​

问题决策
账本由谁持有顶层 agent/ 持有计量、计价、计数器与执行期拦截；Backend 只做 BFF（鉴权、RBAC、部门目录、管理 UI 代理），沿用 platform_automations / platform_memory 的“表归 Agent、Backend 为适配包”模式。
是否引入新基础设施不给 Agent 新增 Redis/新服务。计数器、账本、汇总全部在现有 Agent PostgreSQL，同事务写入，天然精确、幂等。Redis 仅由 Higress 限流插件自己使用。
层级租户 → 部门（沿用现有部门树，含子部门汇总）→ 用户。多层同时生效，任一层耗尽即拒绝（最严格者胜）。
额度口径同时支持 tokens（原始口径，与 Higress 一致）与 cost（按价格目录折算，跨模型公平）；日 / 月两种周期。
Higress 的角色L1 保护熔断（TPM/日限流 + 用量采集 + 供应商密钥收口），不当作权威额度账本。精确的分级预算在 L2（Agent）。
开源复用采用 Higress ai-token-ratelimit + ai-statistics（+ 可选 ext-auth）；价格种子复用 LiteLLM/genai-prices（MIT，仅作人工审核的种子）；指标命名对齐 OpenTelemetry GenAI 语义约定；Langfuse 仅用于对账观测。不引入 LiteLLM Proxy、OpenMeter、Lago（理由见 §3）。
与现有统计关系上下文窗口占用（ContextUsage）保持不变；计费口径改为以新账本为准，会话“Token 用量”切换为账本读取；前端把工程诊断与“我还能用多少”拆开。
分期P0 计量+计价+只读看板（observe）→ P1 Higress 熔断 → P2 分级额度与执行 → P3 对账/告警/导出。每期可独立回滚。

3. 开源方案调研与选型​

核对方式：Higress 插件以 alibaba/higress main 分支 README 与 ai-token-ratelimit/main.go 源码为准（2026-11-02 读取；插件有“无版本号的行为变更”，部署前必须固定插件版本并做契约测试）；其余为公开文档与搜索结果，标注“待实测”的不得当作事实。

3.1 Higress 现成能力（已确认）​

插件能力对本需求的限制（源码/文档核实）
ai-token-ratelimit（priority 600，依赖 Redis）按 header / param / consumer / cookie / IP 维度，秒/分/时/日窗口的 token 限流；rule_items ≤ 10 条，多条命中按 OR 叠加，任一触发即拒绝；limit_by_per_header 配 key:"*" 可对“每个 header 取值”各自独立计数① 请求阶段只读检查 current > threshold 才拒绝，响应阶段才 INCRBY 累加，故允许“最后一次越界”和并发越界；② 窗口为从首次使用起算的固定 TTL，无自然日/月、无月周期；③ 阈值写在插件配置里，按租户/部门/用户差异化需改网关配置，且 per_header 的 * 只能给“所有取值同一阈值”；④ 缺少该 header 的请求不命中该规则（等于放行）；⑤ Redis key 含 {rule_name}，升级会使旧计数失效。
ai-statistics（priority 200）输入/输出 token、模型、首字时延等指标与日志；可用 attributes 把请求头（如租户/用户）写入 ai_log；内置 cached_tokens、reasoning_tokensPrometheus 标签只有 route/cluster/model/consumer，不可把租户/用户做标签（基数）；租户级归因只能走访问日志。
ai-quota（priority 750）按 consumer 的固定额度、可查询/刷新/增减只有 consumer 一个维度、无层级、无周期重置、无审计，不满足“租户→部门→用户”。
ext-auth / key-auth / transformer前置鉴权；转发头；增删请求头仓库已有 deploy/higress/reasoner-ext-auth.yaml.example 先例（forward_auth）。

3.2 其他开源/商用候选​

方案能力结论
LiteLLM Proxy（MIT 核心）虚拟 Key、用户/团队/Key 预算、花费日志、价格表不作主路径：已有 Higress，叠加会形成双网关与第二套身份；公开资料显示 Organization 层与组织级预算属企业版（待按目标版本实测）；租户→部门→用户需自行映射。可复用其 model_prices_and_context_window.json 作价格种子。
pydantic/genai-prices（MIT）多供应商价格数据与计算库，Python/JS价格种子来源之一；不在运行时拉取，人工审核后入库，避免价格漂移与供应链风险。是否覆盖通义/Qwen 待实测。
Envoy AI Gateway / APISIX ai-rate-limiting / Kong AI同类 token 限流（Envoy 基于 Global Rate Limit + Redis，支持 cost）能力类似但需更换网关，不选。其设计（预检 + 事后按实际用量扣减）与本设计一致，可印证方案。
OpenMeter（Apache-2.0）事件计量、实体/权益（Kafka + ClickHouse）额外基础设施过重，现阶段不引入；P3 预留事件导出。
Lago（AGPL）/ Kill Bill面向客户的计费、发票本需求是内部分摊/限额，不需要发票；若未来对外售卖再接，AGPL 需法务评估。
Langfuse（已可选接入）追踪与模型成本分析仅观测与对账，不得作为授权或账本；默认 metadata-only，不外发内容的约束不变。
OpenTelemetry GenAI 语义约定gen_ai.client.token.usage 等命名采纳命名，降低日后接入观测平台的成本。

3.3 选型结论​

  1. 网关层（L1）：Higress ai-proxy（收口供应商密钥）+ ai-statistics + ai-token-ratelimit（TPM/日熔断）+ 可选 ext-auth。只做保护与采集。
  2. 应用层（L2，权威）：Agent 内的账本、计价、分级预算与执行。理由：身份/部门/Run/线程/角色只有 Agent 知道；月周期、成本口径、软硬限制、告警都是 Higress 插件不具备的；Agent 现有 PostgreSQL 已满足事务与幂等。
  3. 不重复造轮子的部分：网关限流、网关指标、价格种子、指标命名均复用开源；自研仅限“分级预算 + 账本 + 执行”这一业务特有部分。

4. 目标架构与职责边界​

组件职责禁止
Agent usage/ 包UsageRecorder、pricing（纯函数）、BudgetGuard、TokenBudgetMiddleware、聚合 Worker、/token-budget/* 内部 API信任请求体中的租户/部门；记录 Prompt 或回答正文
Backend modules/platform_token_budget权限校验、部门树/负责人解析、写入委托令牌声明、HTTP 代理、审计转发。不加入 Edition、不导入 Agent/模型框架持有 Token 表；绕过委托令牌直连 Agent 数据
Higress供应商密钥收口、请求头透传至日志、TPM/日熔断、指标作为额度事实源；因 Redis 故障改变 L2 判断
前端展示与管理交互以隐藏按钮作为安全边界

5. 层级与额度语义​

  • 作用域：tenant（scope_id=tenant_id）、department、user。部门用量包含全部子部门（账本记录用户所在部门的祖先链快照，见 §6.2）。
  • 策略：(scope_type, scope_id, period) 唯一。period ∈ {day, month}，按配置时区（AGENT_TOKEN_BUDGET_TIMEZONE，默认 Asia/Shanghai）的自然日/月；上限字段 limit_tokens、limit_cost_micro 可单独或同时设置（同时设置则任一超限即触发）。
  • 默认策略：is_default=true 且 scope_id IS NULL，仅适用于 department / user，表示“该类每个实体各自独立的默认额度”（类似 Higress limit_by_per_header + "*"）。显式策略优先于默认策略。
  • 生效规则：对一次调用，收集 租户 + 祖先部门链上每个部门 + 用户 的有效策略，逐个检查；任一 hard 策略已用尽 → 拒绝；soft 仅提醒；observe 只统计。不要求子额度之和 ≤ 父额度（允许超配，管理页给出提示）。
  • 执行模式：observe（只统计）/soft（80%、100% 告警，不拦截）/hard（≥100% 拦截新 Run 与后续模型调用）。
  • 平台上限：运营方可为租户创建 source='plan' 的租户级策略，租户管理员不可修改或删除（后续与 TenantPlan 绑定）。
  • 精度声明：采用“检查在前、结算在后”。允许的最大越界 ≈ 并发在途调用数 × 单次调用上限（QWEN_MAX_OUTPUT_TOKENS 与输入预算）。v1 不做预占（reservation）；若验收发现越界不可接受，作为 P3 增强（预占+TTL）。该精度与 Higress 插件行为一致，不得向用户承诺“精确到 1 token 不越界”。
  • 无归属调用：没有用户上下文的租户级后台调用（例如知识入库）只计入 tenant，owner_id 取系统占位并在账本标 attribution='tenant_only'。自动化 Schedule 运行记入其所有者。

6. 计量（Metering）​

6.1 统一入口 UsageRecorder​

  • 一个函数式入口 record_usage(ctx, call)，由以下调用点复用，禁止各处自行写表：
    • LangChain 主/摘要/子 Agent/工具内模型：扩展现有回调（与 ContextUsageCallback 同一 on_llm_end，但记账不依赖上下文统计开关，且独立异常隔离）。
    • 决策模型、图片、视频、知识管线、语音：在各自 httpx/WS 调用完成处调用。覆盖清单由实现阶段逐点审计并写入交付文档（§12 P0 验收）。
  • invocation_id：LangChain run_id（或 provider request id）+ role；(tenant_id, invocation_id) 唯一，重复记录静默忽略。
  • 取消/异常：已收到供应商 Usage 的调用照记；无 Usage 的流中断记为 usage_source='estimated'（沿用现有本地估算器）并标 cost_status，预算按估算值计入（保守），报表显式标“含估算”。
  • 记账失败不得影响回答（短超时、不重试、计数器丢失由对账兜底）；但 hard 策略下记账失败须记录告警，避免长期静默漏计。

6.2 数据模型（Agent 迁移 0012；以下为设计草案，实现以迁移为准）​

-- 全局价格目录（无 tenant_id，只读授权给运行角色，写入仅超级管理员 BFF 路径）
CREATE TABLE agent_model_price (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  provider TEXT NOT NULL, model_id TEXT NOT NULL,
  usage_kind TEXT NOT NULL CHECK (usage_kind IN ('llm','embedding','image','video','audio')),
  currency CHAR(3) NOT NULL DEFAULT 'CNY',
  input_micro BIGINT, output_micro BIGINT, cached_input_micro BIGINT, unit_micro BIGINT, -- 每百万 token / 每张 / 每秒，单位为币种的百万分之一
  tiers JSONB, -- 可选 [{"max_input_tokens":..,"input_micro":..,"output_micro":..}]
  effective_from TIMESTAMPTZ NOT NULL, effective_to TIMESTAMPTZ,
  source_note TEXT NOT NULL, created_by UUID NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now()
); -- 追加式：不更新历史行；同 (provider,model_id,usage_kind) 的生效区间不得重叠

-- 账本：追加式，租户级 FORCE RLS（仅数值与引用，无正文）
CREATE TABLE agent_usage_ledger (
  seq BIGINT GENERATED ALWAYS AS IDENTITY,
  tenant_id UUID NOT NULL, owner_id UUID NOT NULL,
  department_id UUID, department_path UUID[] NOT NULL DEFAULT '{}', -- 根→叶快照
  attribution TEXT NOT NULL DEFAULT 'user' CHECK (attribution IN ('user','tenant_only')),
  invocation_id TEXT NOT NULL, run_id TEXT, thread_id TEXT, lease_epoch INT,
  role TEXT NOT NULL, provider TEXT NOT NULL, model_id TEXT NOT NULL, usage_kind TEXT NOT NULL,
  input_tokens BIGINT, output_tokens BIGINT, cached_input_tokens BIGINT, reasoning_tokens BIGINT, quantity BIGINT,
  usage_source TEXT NOT NULL CHECK (usage_source IN ('provider','gateway','estimated')),
  price_id UUID, cost_micro BIGINT, currency CHAR(3),
  cost_status TEXT NOT NULL CHECK (cost_status IN ('priced','price_missing','not_applicable')),
  occurred_at TIMESTAMPTZ NOT NULL, recorded_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, invocation_id)
);
-- 索引：(tenant_id, occurred_at)、(tenant_id, owner_id, occurred_at)、(tenant_id, thread_id)、GIN(department_path)、seq

-- 执行用计数器：与账本同事务 UPSERT，精确且幂等；为所有作用域×周期常驻维护，新增策略可即时生效
CREATE TABLE agent_budget_counter (
  tenant_id UUID NOT NULL, scope_type TEXT NOT NULL, scope_id UUID NOT NULL,
  period TEXT NOT NULL CHECK (period IN ('day','month')), period_key TEXT NOT NULL, -- 2026-11 / 2026-11-02
  tokens BIGINT NOT NULL DEFAULT 0, cost_micro BIGINT NOT NULL DEFAULT 0, calls BIGINT NOT NULL DEFAULT 0, estimated_calls BIGINT NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, scope_type, scope_id, period, period_key)
);

-- 报表汇总：由聚合 Worker 按 seq 水位从账本滚动（不在请求热路径）
CREATE TABLE agent_usage_rollup (
  tenant_id UUID NOT NULL, day DATE NOT NULL, scope_type TEXT NOT NULL, scope_id UUID NOT NULL,
  leaf_department_id UUID NOT NULL DEFAULT '00000000-0000-0000-0000-000000000000', -- 仅 user 行有意义
  model_id TEXT NOT NULL, role TEXT NOT NULL, usage_kind TEXT NOT NULL,
  calls BIGINT NOT NULL, input_tokens BIGINT NOT NULL, output_tokens BIGINT NOT NULL,
  cached_input_tokens BIGINT NOT NULL, reasoning_tokens BIGINT NOT NULL, quantity BIGINT NOT NULL,
  cost_micro BIGINT NOT NULL, estimated_calls BIGINT NOT NULL, unpriced_calls BIGINT NOT NULL,
  PRIMARY KEY (tenant_id, day, scope_type, scope_id, leaf_department_id, model_id, role, usage_kind)
);

CREATE TABLE agent_token_budget_policy (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(), tenant_id UUID NOT NULL,
  scope_type TEXT NOT NULL CHECK (scope_type IN ('tenant','department','user')),
  scope_id UUID, is_default BOOLEAN NOT NULL DEFAULT false,
  period TEXT NOT NULL CHECK (period IN ('day','month')),
  limit_tokens BIGINT CHECK (limit_tokens > 0), limit_cost_micro BIGINT CHECK (limit_cost_micro > 0),
  enforcement TEXT NOT NULL CHECK (enforcement IN ('observe','soft','hard')),
  warn_percent INT[] NOT NULL DEFAULT '{80,100}',
  source TEXT NOT NULL DEFAULT 'tenant_admin' CHECK (source IN ('plan','tenant_admin')),
  enabled BOOLEAN NOT NULL DEFAULT true, version INT NOT NULL DEFAULT 1,
  created_by UUID NOT NULL, updated_by UUID NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (limit_tokens IS NOT NULL OR limit_cost_micro IS NOT NULL),
  CHECK (is_default = (scope_id IS NULL)), CHECK (scope_type <> 'tenant' OR NOT is_default)
); -- 唯一索引 (tenant_id, scope_type, COALESCE(scope_id, zero-uuid), period)
-- 另有 agent_token_budget_audit（策略变更前后值）、agent_token_budget_alert（policy+period_key+threshold 唯一，去重告警）、
-- 无 RLS 的 agent_usage_tenant_directory（仅 tenant_id，供聚合 Worker 枚举，对应现有“控制面目录只含路由 ID”先例）

RLS 决策：账本/计数器/汇总/策略/审计/告警均为租户级 FORCE RLS（app_runtime），而非 Memory 那样的 tenant+owner 双层——这些行只含数值与引用且租户管理员本就应见全租户用量。个人视角由 SQL 中强制 owner_id = 当前可信用户 实现，并加负向测试；价格目录为全局只读。聚合 Worker 通过无 RLS 的租户目录枚举租户后逐租户进入租户作用域。

6.3 计价（pricing.py，纯函数）​

  • cost_micro = round_half_up(tokens × price_micro_per_mtok ÷ 1_000_000)，输入分 缓存命中/未命中，输出含推理；按 tiers 以本次输入 token 数选档；媒体按张/秒。全部整数运算，禁止浮点。
  • 价格按 occurred_at 取生效版本，账本固化 price_id 与 cost_micro，历史不因调价重算；找不到价格 → price_missing，token 仍计、费用为空，不阻断。
  • 费用是“公开标价估算（showback）”，不等于供应商实际账单（折扣、资源包、免费额度）；财务结算需与供应商账单核对（P3）。
  • 价格种子：从 LiteLLM/genai-prices 或供应商官方页面人工整理，经超级管理员界面或迁移后的受审计写入；不在运行时联网取价。

7. 额度执行（Enforcement）​

  1. Run 准入：Agent 创建/恢复/重放/编辑 Run 前调用 BudgetGuard.admit。耗尽则不创建 Run，返回 HTTP 429、错误码 token_budget_exceeded，附 scope_type/period/reset_at/enforcement，BFF 原样透传。
  2. 调用前拦截：TokenBudgetMiddleware.abefore_model 放在 Harness 中间件链首位；非 LangChain 路径（决策/图片/视频）在发出请求前显式 check。耗尽时当前 Run 以 budget.exceeded 事件结束，保留 checkpoint，额度补充后用户可续跑。
  3. 结算：record_usage 在一个事务内：插入账本（幂等）→ 对 (tenant, 各祖先部门, 用户) × (day, month) 单语句 UPSERT 计数器（按 (scope_type, scope_id) 固定顺序以避免死锁）→ RETURNING 新值判定阈值，向告警表 ON CONFLICT DO NOTHING 插入，首次插入才发事件/通知。
  4. 热点与降级：租户行是写热点，事务极短（目标 p99 < 10 ms）；若实测 TPS 超出，再评估把计数器前置到 Redis（须新增依赖论证）。策略在进程内缓存 15 s，Redis 不参与。
  5. 策略变更生效：写策略后缓存最长 15 s 内生效；删除/降低额度立即触发下一次准入重算，无需重启。
  6. 失败语义：计数器查询失败 → hard 策略下新 Run 准入失败关闭（503，token_budget_unavailable），进行中的 Run 失败放行并告警；soft/observe 一律放行。
  7. 模型无法拒绝：模型/工具参数不能提供租户、部门、用户、额度或绕过标志；ExecutionOptions 只能收窄，不能放宽额度。

8. Higress 集成（L1）​

8.1 链路​

Agent(ChatOpenAI, base_url=Higress, api_key=网关 Consumer 凭据) → key-auth →（可选）ext-auth → ai-token-ratelimit → ai-proxy（持有真实供应商密钥）→ 供应商；ai-statistics 采集。上线后供应商密钥从 Agent 配置移除，仅存于 Higress。

8.2 请求头契约（Agent → Higress）​

x-chein-tenant-id、x-chein-department-id（叶部门，可缺省）、x-chein-user-id、x-chein-run-id、x-chein-purpose（main/summarization/decision/...）。由 QwenModelProvider 在每 Run 构造时注入（default_headers；决策等 httpx 路径同理）。

  • 可信前提：Higress 路由仅内网可达并要求 Agent 专用 Consumer 凭据；对外入口必须 transformer 清除入站 x-chein-*。头缺失时 ai-token-ratelimit 不命中，因此 P2 的 ext-auth 应对缺头请求直接拒绝。
  • 不外泄：ai-proxy 之后必须用 transformer 删除 x-chein-*，避免租户/用户 UUID 发往第三方供应商。验收需抓包确认（待实测，插件顺序与 header 透传行为随版本变化）。

8.3 L1 配置示例（保护性熔断，非业务额度）​

rule_name: chein-llm-fuse
rule_items:
  - limit_by_per_header: x-chein-tenant-id
    limit_keys: [{ key: "*", token_per_minute: 2000000, token_per_day: 50000000 }]
  - limit_by_per_header: x-chein-department-id
    limit_keys: [{ key: "*", token_per_minute: 600000 }]
  - limit_by_per_header: x-chein-user-id
    limit_keys: [{ key: "*", token_per_minute: 120000, token_per_day: 3000000 }]
rejected_code: 429
rejected_msg: '{"code":"gateway_token_rate_limited"}'
redis: { service_name: <redis service FQDN>, database: <专用库>, username: <ACL 用户> }

要点：这些是“所有租户/部门/用户同阈值”的默认熔断，故意设得宽松；各租户/部门/用户的真实预算在 L2。OR 叠加使个别实体无法在网关层“放宽”默认值，因此不要为差异化额度生成网关配置。Higress 拒绝（429）需在 Agent 映射为 gateway_rate_limited（可重试，退避），与 token_budget_exceeded（不可重试）区分。

8.4 ai-statistics 与对账​

  • attributes 将 x-chein-tenant-id/department-id/user-id/run-id 以 request_header 写入 ai_log（as_separate_log_field），并开启 cached_tokens、reasoning_tokens。
  • P3 对账：Prometheus 的 route_upstream_model_consumer_metric_input_token/output_token（模型粒度）对比账本同小时同模型总量，偏差超阈值告警（暴露漏计或绕过调用点）；租户级对账需把访问日志接入现有日志管线，是否具备待确认。
  • 网关层指标是对账依据，不回写账本（避免双写）；仅当出现“已确认漏计”时，用 usage_source='gateway' 经受审计的补录命令处理。

8.5 可选：网关预检（P2b）​

Higress ext-auth(forward_auth) 调用 Agent 内部只读端点 GET /internal/token-budget/gateway-check（读计数器，不写），耗尽返回 429。价值：所有走网关的模型流量（含绕过 Agent 中间件的调用点）统一受控。代价：每次 LLM 调用多一次内部 HTTP+一次 PG 读；failure_mode_allow 须与 §7.6 一致。是否启用以 P2 压测结果决定。

9. 身份与委托令牌变更​

  • Backend _delegation（agent_ui_router.py:172）在签发时从 TenantMembership.department_id 沿 Department.parent_id 上溯，写入 dept_id 与 dept_path（根→叶，深度上限 12，检测环）；新增 scopes：agent:budget:view_self（所有聊天用户）、agent:budget:view_tenant、agent:budget:manage、agent:price:manage，以及 BFF 解析后的 budget_view_departments（部门负责人可见范围，≤ 200）。
  • Agent DelegatedContext 新字段全部可选：旧令牌仍可用，缺部门则记 department_id=NULL、只参与租户与用户层，并在报表中显示“未归属部门”。滚动发布顺序：先发 Agent（接受新旧令牌），再发 Backend。
  • 部门调动：账本使用用量发生时的快照，历史不迁移；管理页明确“按发生时部门归属”。

11. 前端方案​

11.1 现有问题​

  1. 三个芯片语义混杂：性能（调用数、tok/s、TTFT）是工程诊断，普通用户无从行动。
  2. “Token 用量”只覆盖当前线程、仅已记录调用，无费用、无月度、无额度，出现 ≥、“缺失调用”等需要解释的状态。
  3. 弹层信息过密（单层 8–12 行 + 多个帮助图标）。
  4. 缺少“余额”类信息，用户无法预判是否会被拦截；耗尽时没有明确的恢复路径。

11.2 新交互​

  • 输入框上方三芯片（保持位置与“新建对话居中时隐藏”的既有规则）：
    1. 会话用量：12.3k tok（租户开启费用可见时附 ¥0.021）；弹层二层结构——概览（输入/输出/缓存/推理）→ 展开“按模型/角色”→ 折叠“诊断”（原调用数、tok/s、TTFT）。数据改读账本，旧线程无账本行时回退旧累计并标“历史数据”。
    2. 我的额度（仅存在适用策略时显示）：显示最紧约束，如 本月 62%；≥80% 琥珀、≥100% 红。弹层逐层列出 租户/部门/个人 × 日/月：进度条、已用/上限、重置时间、模式（提醒/硬限制）；最紧项高亮。无权限查看租户/部门绝对值的用户只看百分比。
    3. 上下文占用：保持现有环与明细，不改语义。
  • 阈值与耗尽：80% 内联提示条；100% 且 hard：输入框禁用并显示原因（哪一层、何时重置、联系部门负责人/管理员），已有会话仍可只读。soft 超限只提示。gateway_rate_limited 显示“请求过于频繁，稍后重试”，与额度耗尽文案区分。
  • 管理页（Platform 菜单，权限受控）：
    1. 用量看板：时间/部门/用户/模型/角色筛选；KPI（总 token、费用、调用数、估算占比）、趋势、Top N、组织树下钻；导出 CSV；“含估算/价格缺失”显式标注。
    2. 额度策略：组织树表格（用量/上限/百分比/模式），行内编辑；默认策略区；超配提示；变更需二次确认并写审计。
    3. 价格目录（仅超级管理员）：版本历史、生效区间、来源说明。
    4. 事件：阈值告警与拒绝记录。
  • 个人“我的用量”入口复用 me/usage，不展示他人数据。zh-CN/en-US 文案并入既有 locale；无障碍沿用现有 Tooltip/Popover 键盘与触控约定；无策略时不出现额度芯片，避免空状态噪音。

13. 安全、租户与隐私​

  • 租户/部门/用户一律来自已验证委托令牌，禁止 body/query/header 的 tenant_id；BFF 写策略时校验目标部门/用户属于当前租户。
  • 新表迁移须同步 RLS 模型集合、runtime 角色（app_runtime，无 BYPASSRLS）测试：读写、批量 DML、无 scope、跨租户负向。
  • 账本不含 Prompt/回答/工具参数；仅数值、模型名、ID。用户删除时保留账本但将 owner_id 替换为墓碑 ID（保留计费事实，去除可识别性），保留期到期批量清理。
  • 策略与价格变更全部写审计；价格仅超级管理员；导出需 view_tenant 且记录审计。
  • 不向 Langfuse/外部观测发送新增身份字段；指标标签禁用租户/部门/用户。

14. 测试矩阵（最低）​

并发结算精确与无死锁；(tenant, invocation_id) 幂等；多层策略最严格胜、默认策略独立计数；部门树含子部门汇总、部门调动不改历史；日/月翻转（时区边界）；价格版本在月中变更；tiers 与缓存/推理计价；缺 Usage/取消/异常；准入 429 与运行中耗尽续跑；observe/soft/hard 三模式；计数器不可用的失败语义；跨租户与他人读取负向（app_runtime）；委托令牌新旧兼容；Higress：头注入、缺头、x-chein-* 外泄、429 映射、插件版本契约；前端：unknown/observe/soft/hard/blocked、乱序事件、窄屏与深浅色。验证命令沿用根 AGENTS.md §10 验证矩阵。

当前实施差异（2026-11-02）​

设计状态仍为 Proposed。用户另行指定继续 P1–P3；实际代码、验证及剩余门禁以交付为准。

  • BFF 复用现有 /api/v1/agent-ui/token-budget，不是另建 /agent/ 前缀。
  • transformer 默认 AUTHN 阶段早于统计；清理示例显式覆盖出站阶段，不能仅按默认优先级推断顺序。固定源码 commit 不是部署镜像摘要，目标版本和抓包仍待实测。
  • 不缓存策略（失效窗口为 0），关闭模式不增加额度图节点；默认策略告警的 period_key 拼接实体 UUID，保持每实体独立去重。
  • 追加迁移 0013，不改写 0012。全局价格以追加写入函数提供受审计写入口，运行账号不能直接修改价格表。价格区间不得重叠；已有开放区间无法直接追加重叠版本，需要另行审核封口迁移，禁止静默改历史。
  • 语音按 response.done 的实际文本/音频 Usage 结算；无分类不能猜价格。当前 RAGFlow 适配契约不返回提取/Embedding Usage；硬策略下阻止无法计量的请求，完整纳管仍需上游契约。
  • 对账使用人工核对并归一化的模型总量 JSON；不假装已接入生产 Prometheus 或供应商账单。预占只提供边界评估，不开启冻结或保留机制。网关 ext-auth 预检在压测结论前不启用。
