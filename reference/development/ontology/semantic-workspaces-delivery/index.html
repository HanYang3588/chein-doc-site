双本体工作区与十一阶段交付

本文保留双工作室的历史验收记录。Legacy、Neo4j 独立页面现均已退役；当前管理入口为 OWL 可视化构建器，共用 Provider/发布/推理保留。范围和迁移见 Neo4j 页面退役。

状态：2026-10-25 工作区实现及本地验收记录，不表示目标环境已经升级。原始十一阶段要求、后续审计和本次补齐功能统一在此核对；双 Provider 设计中的早期测试记录保留为历史。

页面及操作​

入口数据范围操作方式
/ontology 业务本体工作室workspace=legacy保留原对象、字段、关系、Action、Metric 表单和查询流程
/ontology-neo4j Neo4j 语义本体workspace=neo4j语义模型库、类图、URI/类/属性层级与业务映射、RDF 预览、SHACL 样本验证、审核、显式图投影与推理

页面分类与运行 Provider 是两个维度：分类决定在哪个工作室编辑；Nacos 的 ONTOLOGY_PROVIDER 决定 Agent 从哪个 Provider 读取当前获准发布版本。分类不授予权限，创建后不可改变。旧网络迁移为 Legacy，不自动转换、复制或发布。Legacy 页面收到 Neo4j 网络链接会转到对应工作室。

Neo4j 页面流程：创建语义模型 → 从当前授权目录建立业务映射，或预览并采用 RDF → 编辑类、属性、父类、domain/range、命名空间 → 保存草稿 → 约束样本验证 → 校验/提交 → 另一成员审核/发布 → 显式投影 → 查看投影状态、运行类映射推理和导出。已发布版本编辑会新建草稿，原发布正文不变。投影须同时有 ontology:publish 与 ontology:query，配置展示只读，不在页面填写数据库密码或覆盖全局插件配置。

数据与能力边界​

PostgreSQL 仍拥有定义、版本、双人审核、发布指针和 ACL；ERP 拥有实时实例、行权限、仓库授权和业务事务。本体只通过固定 ontology.data capability 访问实例。图中既有外部 Resource 数据不会因存在便成为 Agent 可读本体；必须先导入受控草稿、完成固定映射与审核，再显式投影。

标准语义支持 Turtle、RDF/XML、JSON-LD、N-Triples；保存类、对象/数据属性、URI、单一标签及语言、说明、父类/父属性、domain/range、本体 URI、局部命名空间。固定 urn:chein:mapping: 词汇承载对象/字段/关系映射。未知谓词、复杂 OWL 公理、多值歧义标签、循环或过深层级明确拒绝，不静默损失语义。扩展模型使用 RDF/JSON 导出；旧 BKN 无法表达时拒绝导出而不删除扩展。

解析限制为 128 KiB、2,000 三元组；类和属性各最多 100，层级最多 10。拒绝远程 JSON-LD context、导入 URL、DTD/ENTITY。解析及 SHACL 在禁网子进程中执行，5 秒超时、最多两个并发进程，Linux 额外限制地址空间。新增 rdflib 与 pyshacl：现有依赖/标准库不能可靠解析上述语法和执行 SHACL Core；锁文件同步，镜像沿用既有 uv sync --frozen 安装路径。

SHACL 为模型局部的受限 Core 校验，验证保存/提交的有界样本，并作为发布门禁；不等于全部实时 ERP 行已通过 SHACL，也不替代 ERP 事务校验。拒绝 SPARQL、JS、规则、远程导入及复杂路径。未加载原生全局 Shapes 时不会宣称 n10s SHACL 可执行；禁止为某个请求覆盖共享 GraphConfig、命名空间或 Shapes。

Neo4j 投影保存快照、元素、类/属性/数据类型及固定层级/映射边。读取先验证 tenant/network/owner/scope/version/正文与映射摘要，再调用固定参数化查询。原生 n10s.inference.nodesInCategory 结果必须与已发布层级推导一致；它返回当前授权类到对象的 Schema 映射，不把类别成员当作实际 ERP 实例。不是 OWL DL 推理器。

目录仅新增不相关映射时，ERP 可以提供旧目录精确兼容证明：按原七类资源及原关系/指标/Action 的全部契约重新计算旧摘要，只有完全相等才声明兼容；本体还须只使用这组旧绑定且无语义扩展。已发布正文和旧摘要不改写。未知摘要、旧绑定实质变化、语义扩展或新绑定混入均失败关闭，不是忽略映射指纹。

审计 R1 最终撤权漏检、R4 加载历史版本、R5 最后一次读取越过预算已在共享入口修复并加入回归。R2 通过标准语义子集、受审核业务映射与原生 n10s 推理接入闭环；R3 增加销售订单/出库/库存/仓库固定映射与只读出库诊断。审计历史中的“待修复”描述不代表当前实现状态。

销售诊断使用既有审批、剩余数量、有效商品/仓库、非负库存等固定契约；五项来源读取权限逐次复验。结果标明来源、时点及 read_only_snapshot_not_posting_authorization，不能据此授权真正出库。直接 ERP 工具结果标明 ontology_used=false，不能声称使用过本体。

本次分批验证，不把重叠测试相加：原本体及边界/Manifest 回归 109 passed、2 skipped；随后新增工作区、历史兼容、销售诊断、真实模型及迁移专项继续独立验证。最终补充：工作区/历史兼容/销售诊断及四组真实模型 4 passed；迁移、SQL 分类不可变触发器及有语义数据时禁止降级 2 passed；Provider/边界/语义/Schema 单元 69 passed；Agent 专项 31 passed；前端两页面 26 passed（包含审核接口路径回归）。base/items/suite 构建及 API 生成通过，类型检查独立执行。浏览器使用真实构建产物与一次性 PG 的正常 HTTP API，不以 mock 请求代替页面验收。

正常 Neo4j 2026.10.1 实测：投影往返、重复/并发投影、错误 scope/version 拒绝、事务回滚、四并发读与池复用、三类属性边、原生 n10s 推理与 RDF 预览均通过。执行计划命中 NodeUniqueIndexSeek，没有全节点扫描。20 次读、并发 4 的本地小样本 P50=31.83ms/P95=38.70ms，只衡量图快照读取，不是 Agent 或生产 SLA。原生插件版本未能读取，n10s_version=null；过程存在不等于全部原生功能可用。

部署、迁移与回滚​

本次新增 ontology_semantic_workspace_v1，给 Network 增加默认 Legacy 分类、CHECK 与禁止修改分类的数据库触发器；不改历史 revision。升级遵循现有操作单，先审查全部待迁移项，再由维护流程迁移并授权新表，随后同步菜单/套餐/租户角色、重新部署 Backend/Agent/前端。新增两个 Ontology MCP 工具及 ERP 诊断工具需经既有工具目录审核发布；不因代码存在便自动扩权。

现有正常 ONTOLOGY_NEO4J_ENABLED、NEO4J_URI/DATABASE/USERNAME/PASSWORD 沿用，Agent 不取得 Neo4j 密码。运行策略仍由 Nacos ONTOLOGY_PROVIDER 和显式 fallback 开关决定，当前加载方式需重启 Backend。Neo4j 快照约束初始化仅显式维护命令执行，正常请求不建约束。

应用回滚优先切 ONTOLOGY_PROVIDER: legacy 并重启，保留 PostgreSQL 与图数据。数据库降级在存在 Neo4j 工作区时明确拒绝，不能直接删分类列；须先由数据所有者制定受审核导出/保留方案，不自动清空网络。新格式发布后，回滚到不认识 semantic 的旧程序有兼容风险，不能只切 Provider 就认定旧二进制可读取新模型。

依赖供应链门禁：按当前 CI 命令对锁定 Backend runtime 运行 pip-audit，既有 9 个包共报告 77 条已知漏洞，门禁未通过；新增 rdflib/pyshacl 及其新增传递依赖、Neo4j Driver 未报告漏洞。本任务未顺带升级既有框架，不能将功能验收称为可直接生产发布。

尚未执行：目标业务数据库升级、正常部署的菜单/MCP 发布与服务发现验证、远端 CI、镜像构建/扫描/签名、生产负载/P95、N-1 部署演练和团队签署。原共享 n10s 全局 Shapes 缺失保持原状，未覆盖 GraphConfig/命名空间，也未删除现有索引/约束；生产实例上其他原始 RDF 的批量治理不属于自动动作。
