OpenBKN 核心本体能力对齐：审查与实施设计

状态：P0–P3 代码已实施；按本设计的受控只读范围验证，最终验证记录见第 8 节。不是 OpenBKN 全产品等价或生产上线声明。

1. 结论与证据范围​

当前 Chein 与 OpenBKN 的本体管理并不等价。 Chein 已有可治理的业务模型、版本审核、固定 ERP 数据映射和受控查询；OpenBKN 的模型组织、数据源绑定、实例探索、行动执行与开发集成范围更广。不能将“都有对象、关系和行动标签”视为功能等价。

本设计将核心目标定义为：网络管理 → 对象/属性/关系/行动/概念分组建模 → 数据映射 → 实例查询与关系探索 → 导入导出与 Agent 消费。遵守用户要求，身份、RBAC、数据权限与审核沿用 Chein；既有草稿、历史版本、固定 capability 和权限契约继续兼容。

审查包含本地真实页面（http://localhost:5174/ontology）以及两份官方源码快照。未部署 OpenBKN 的完整服务，因此上游页面交互结论是源码对比，不是对上游运行环境的可用性或性能认证。

4. 目标页面与主要流程​

网络列表保留管理平台布局、模块入口与权限。点击网络进入工作区，标题包含名称、范围、当前查看版本/状态；常用操作按当前权限与状态可用。修改会产生未保存标记。刷新、关闭、切换网络以及未来的路由离开均不得静默丢弃内容。

工作区分为：

  1. 总览：网络说明、对象/关系/行动/指标/分组数量、可选择的类型图、发布及映射状态。不把 Schema 数量当业务实例数量。
  2. 模型管理：对象与属性、关系与类型图、行动、指标、概念分组、数据映射。按 code/名称查找；详情编辑与删除按稳定标识定位；明确搜索仅覆盖当前完整模型。
  3. 实例探索：绑定当前发布版本；对象实例表 → 实例详情与来源 → 有界邻居展开；可返回列表继续分页，失败与截断明确展示。查看历史模型时仍标明执行使用当前发布版本，避免误读。
  4. 发布管理：校验问题、差异、破坏性变更确认、提交、他人审核、发布、废弃/恢复、审计。不允许管理员前端自批越过既有后端约束。
  5. 候选与导入：文档辅助、来源、候选对比与明确采纳；JSON/.bkn 预检 → 差异 → 当前草稿 → 保存/重新审核。导入文件不能指定权限或执行身份。
  6. 集成体验：复用已有 Agent 与 MCP 工具，展示所选已发布网络及真实调用证据；不另建工具执行或模型配置系统。

空状态提供对应创建入口；无读权限不请求业务数据；无查询权限仍可看授权模型但不能执行。数据 Provider 不可用时保留草稿编辑，并将数据执行标为不可用。所有列表、表单、查询都有加载、防重复提交、稳定错误和重试路径。

5. 权限与后端边界​

操作继续使用的 Chein 权限与附加约束
网络/模型读取ontology:read；当前成员、Edition/模块权益；private 仅 owner；Tenant UoW + RLS
建模、分组、映射草稿、导入ontology:edit；expected_revision；已有来源复验，不改变数据所有权
审核/发布/废弃ontology:publish；审核人与最后编辑者分离；已发布正文不可变；目录指纹一致
实例查询/遍历/指标ontology:query；实际发布版本；数据所有者逐次复验源权限与记录范围
行动执行ontology:query + ontology:action:execute；executor 白名单；原数据权限继续适用

新增 Provider 仍通过 ModuleDefinition/capability 装配。跨模块只能公开 DTO/稳定接口；不从 ontology 导入 ERP ORM，不引入任意 SQL/URL/脚本、上游 ACL 或上游 runtime。新数据源、写行动、Cypher 执行、全局语义索引不能用 UI 实现掩盖架构扩展；需要单独设计、能力约束、负向测试与交付证据。若需改变现有架构/Accepted ADR，先提出替代 ADR，不能在本功能中静默改写。

6. 分阶段实施与验收​

P0：现有契约可达与编辑可靠性（已实施）​

  • 总览与模型分类数量；模型内搜索。
  • 概念分组 CRUD 与成员选择；对象别名编辑。
  • 编辑/删除按 code 定位，跨页与过滤后不操作错对象。
  • 编辑保留未展示约束；删除前列出依赖并阻止悬空引用。
  • 刷新与关闭保护未保存修改；查询行动权限随操作即时更新。
  • 组件回归、前端类型检查、Suite 前端构建、真实页面核对。
  • RustFS 截图归档：首次上传与 pnpm dev:artifact --retry 均失败，六张截图已保存在项目外待发缓存 ~/.cache/chein/dev-artifacts/。

不修改 API/数据库/模块装配，不增加依赖，因此无迁移和客户端再生成。保留原 JSON、历史快照与版本发布流程。本阶段完成后也不能称全量 OpenBKN 核心对齐。

P1：工作区、列表与实例体验（已实施）​

后端在授权网络集合内支持 q/scope/排序及稳定游标，不用全表加载后前端筛选。前端工作区 URL 携带 network/version/section，兼容原 Studio 入口与未保存保护。基于现有 query/traverse/metric/action 做实例表、详情、下一页、有限图展开、业务指标表、来源与截断提示；网络/版本/操作变化清空旧结果，迟到响应不能覆盖新上下文。敏感字段继续由运行时裁剪。

验收：只读/编辑/发布/执行四类权限；无已发布版本；源权限撤回；无效 UUID；分页边界；网络/版本切换；Provider 503/漂移 409；三跳及预算截断；小屏幕与键盘操作。服务端测试使用一次性数据库串行运行。

P2：.bkn 互操作与更完整的建模（已实施）​

先定义 .bkn 支持子集与能力映射表，再实现导入解析、严格 DTO 转换、引用校验、差异预览和导出。主键/展示属性、属性约束、关系反向语义等先复用已有 DTO，新增字段才版本化升级契约。多文件导入校验路径穿越、文件数/字节/压缩预算；拒绝执行内容、未注册来源或行动。旧 JSON 与已发布版本继续可读，不能无损转换时明确诊断。

验收：支持子集 round-trip；跨文件引用；重复 ID；错误类型/不支持执行器；超预算/路径穿越；导入不能提升权限；失败不改变草稿。需要 API 改动时重新生成客户端，不手写生成类型。

P3：数据与能力扩展（受控只读范围已实施）​

按实际业务注册更多数据资源、关系与指标；源模块拥有查询与权限，ontology 拥有语义。先交付更多受控只读行动，再单独评估写行动。语义检索和高级图查询采用现有安全能力或单独 ADR，不把字符串表达式直接落为 SQL/Cypher。保留现有 Agent/Knowledge/MCP 边界。

验收：每种新 Provider 的当前权限、跨租户/owner/部门负向测试、指纹变化、来源墓碑、超时、幂等与恢复；写行动另加事务/审批/审计门禁。此阶段未实现前，对外文案必须保留功能范围说明。

8. P1–P3 实施与交付范围​

P1 实际实现​

  • 服务端网络名称/标识/描述搜索、scope 筛选、id/name/updated 排序、升降序与稳定 keyset 游标；过滤先进入原 Tenant/owner scope。旧 UUID after 游标默认按 id 继续兼容，新的排序游标绑定筛选参数，不能跨筛选复用。
  • 工作区从遮挡主界面的 Drawer 改为原生管理页；同一路由的 network/version/section 参数支持定位与刷新恢复。保留列表筛选与游标；浏览器离开和工作区关闭/刷新保护未保存内容，身份/租户变化清空工作区。
  • 网络信息默认折叠。实例表、属性与来源详情、下一页、类型化条件、有限实例图、邻居展开、业务指标表和截断提示均有界；技术 JSON 收入折叠项。执行仍使用当前发布版本，并明确显示版本。
  • 网络/版本/操作/筛选/权限变化使结果失效，迟到响应不能覆盖新上下文。浏览器 DOM 不需要保存未授权敏感列，数据源仍在服务端逐次裁剪与授权。
  • 集成页列出既有六个 MCP 工具、权限和当前发布标识，可复制上下文后进入已有 Agent；不会自动调用模型或执行发布。

P2 实际实现​

  • JSON、BKN 多文件、ZIP 使用统一预检 → 差异 → 明确采纳 → 保存/审核流程；实现按标识合并和整体替换。
  • 支持展示属性、属性/分组描述、默认值、精度、范围、枚举、反向关系和执行器选择。隐藏字段编辑保留、稳定 code 与后端严格校验继续生效。
  • 支持子集、原生结构/Chein 扩展、容量及失败关闭行为见 BKN 互操作契约。不将不支持的外部行动悄悄转换成已授权执行器。

P3 实际实现​

ERP 继续作为数据所有者，增加 Customer、ProductCategory、ProductUnit，共七类固定资源；仅声明业务所需的非敏感字段，不暴露客户联系方式或银行信息。增加商品—分类、商品—单位、分类父级及受控反向关系；共十二个固定方向关系，遍历仍有三跳/100 节点/200 边/30 调用/15 秒预算。

指标由一个扩展为三种：已审核采购金额、税额、订单数，均按供应商和原时间口径、当前 owner/部门范围执行。金额保持 Decimal 字符串。行动扩展为 object_query_v1、object_detail_v1、object_neighbors_v1；详情/邻居必须提供实例 UUID；拒绝与契约不符的筛选/游标参数。新目录模板仅由当前授权目录生成，不给用户补授权。

新增源能力复用已有 customer/product-category/product-unit 的 list 权限，声明到现有工具 delegation 上限；数据所有者每次重验当前 RBAC。关键词搜索增加业务名称/别名匹配，并在相关性相同时保留网络更新时间顺序；这不是向量语义搜索。

写行动评估结论：本次不注册。当前本体没有通用写操作事务/幂等/补偿协议，且现行边界明确仅允许只读。任意数据源接入、通用 Cypher、全局向量索引、写行动和 OpenBKN Safe/Trace 全产品仍需单独设计/ADR；这是原 P3 的评估项，不计作已交付执行功能。身份、RLS、审核与权限体系没有替换。

兼容与运行影响​

没有新增运行时依赖、数据表或迁移；API/DTO 增量扩展后使用仓库生成器生成客户端及 Manifest。旧 JSON/历史正文保持可读。目录指纹变化会阻止旧发布模型继续执行，应保存为新草稿并重新校验、双人审核发布。不会自动修改用户模型、业务数据、角色授权或已发布 MCP 服务版本。
