Chein 阿里云 Decision Model 接入与能力路由

更新：2026-10-09。代码支持 off / shadow / active，默认 off；阿里云 Token Plan 个人版实联协议已本地验证。真实业务准确率、生产端到端、Higress 转发和发布仍未验收。 本文维护决策接入事实；运行时边界以 Agent 架构为准。Decision Model 与 TypeSafe Jev 的底层模型关系未验证，不把其他供应商的指标套用到阿里云。

2026-10-25 兼容扩展：对话可关闭当前 Run 的决策辅助，缺省保留本文系统配置；实际控制范围、恢复与验证见对话控制。

1. 位置与现有调用链​

assistant-ui → /api/v1/agent-ui/chat
  → Backend 当前成员 / RBAC / 模块权益 / 提示词选择 / 签发 delegation
  → Agent /internal/agent/v1/ag-ui → 验证 Run / Thread / delegation → Run lease
  → 从 PostgreSQL checkpoint 恢复消息，注册已授权的工具
  → create_data_analysis_agent(Qwen)
  → KnowledgeAuthorizationMiddleware 重验历史知识证据
  → DecisionMiddleware：可选入口判断与工具范围选择
  → DeepAgents 原生模型 / 工具循环 / interrupt_on
  → ERP HTTP Facade 或受审核 MCP / Knowledge v2 Facade / 日期 / ask_user
  → AG-UI SSE → 原 assistant-ui 渲染、引用、暂停、取消和审批

当前已经有独立的 decision.py、原生 Middleware、checkpoint 私有状态、Nacos Settings 和 Qwen ChatOpenAI 入口。本次沿用这些入口，没有新增 Router 服务、另一张任务图、另一套 Agent 框架或模型注册中心。

DeepAgents 继续拥有规划、工具参数生成、工具选择和执行；当前通用子 Agent、文件系统和代码执行边界保持既有配置。chat / knowledge / deep_agent 是同一原生执行器的处理策略，不代表部署了三个服务，也不切换生成模型。

RAGFlow 由后端 Knowledge 应用服务调用官方 HTTP API，官方 MCP 是后端的显式可选 Adapter。Agent 只通过授权的 Knowledge Facade 访问目录和检索，不持有私有库的 RAGFlow 凭据。查询改写、目录选择、证据 Judge、最多三次尝试及回写前重验已存在于 knowledge_pipeline.py，本次没有再实现一套。

自研 MCP 工具通过 Nacos 已审核版本发现，先按 scope 和只读元数据筛选，再由官方 LangChain MCP Adapter 转成工具；每次调用重验注册状态与 delegation，业务服务端继续检查成员、权限、模块权益和 Tenant UoW。路由建议不能增加工具、scope 或租户访问权限。

2. 官方 API 核对​

核对日期为 2026-10-09：

  • Token Plan 入口是 POST https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/systemone，Bearer 套餐 Key；当前限定个人版，不能据此假定团队版可用。Token Plan 官方接入
  • 请求使用 model、state、questions。state 可为文本、对象或数组；问题支持 Choice、Noul、Score。返回 answers，Choice 包含 choice/probabilities/confidence，Noul 包含 noul（P(yes)）；另有 model/request_id/usage.input_tokens/latency_ms 元数据。本实现消费 Choice/Noul，不把接口包装成聊天模型。System One API
  • 官方 Python 示例提供 typesafe-sdk。项目已有 httpx，直接按同一官方 HTTP 协议调用，未增加 SDK。一次请求可同时判断多个问题，与批量推理作业不同；模型信息标记批量推理不支持。API 示例、模型信息
  • 模型信息列出 65,536 token 输入/上下文、北京和新加坡、1,200 RPM / 2,000,000 TPM、限时免费。它们不是对 Token Plan 账号配额或收费期限的保证；实际套餐权益和账单按控制台核实。没有从这些页面确认独立并发数、服务超时 SLA 或正式稳定版替代型号，代码不依赖这些假设。模型信息
  • 通用错误参考包含鉴权、模型不存在、参数、额度/欠费、限流及服务错误；在线按 HTTP 状态降级，不向 UI 透传上游正文。错误参考

同一请求中的问题独立判断：Primary Route 与各能力需求不能隐式依赖其他问题的答案。代码负责合并建议，开放参数及回答仍由 Qwen 生成。

3. 轻量能力目录与路由规则​

capabilities.py 用一个描述表维护当前注册能力，不绑定模型供应商。

能力执行入口可用依据
chat原模型 handler，保留 ask_user原 Qwen 执行器
knowledge原目录和 search_business_knowledge 工具本次授权工具集合中存在知识工具
business原 ERP 工具或已审核的业务 MCP 工具本次授权工具集合中存在业务工具
complex_task原 DeepAgents handler 与原生规划现有 Harness

registered 来自描述表；enabled 来自 AGENT_DECISION_DISABLED_CAPABILITIES；available 同时要求启用和已授权工具存在。Qwen 未配置仍由原模型入口报错，不属于 Decision Model 的降级范围。此禁用配置只控制路由建议，不代替业务模块禁用或 RBAC；off/shadow/失败回退的原 Agent 仍按服务端权限执行。

问题表从描述表生成每个能力的 requires_<code> Noul 问题，另有 Primary Route、多意图、改变数据请求。有效答案转换为 primary_route + required_capabilities，因此一次请求可需要知识、业务和复杂规划。

情况active 行为
首轮精确问候/感谢本地规则选 chat，不调用 Decision Model；只保留 ask_user
首轮普通聊天，高置信度且无能力依赖chat：只保留 ask_user，Qwen 原生流式回答
单一内部知识问答，高置信度knowledge：只保留知识工具、日期、ask_user
业务查询、日期查询、组合任务、多意图deep_agent：保留完整的已授权工具，DeepAgents 自行规划
明确能力不可用，或需要的已注册能力被禁用/缺工具unavailable：只保留 ask_user，追加限制说明给 Qwen，由其流式告知用户，不执行替代业务工具
低置信度、未知、能力需求不确定、改变数据判断不确定原 deep_agent，依靠既有提示词、工具权限和 HITL 澄清
有先前用户/助手消息的续问跳过入口判断，保留完整已授权工具，使用 checkpoint 上下文
显式开启深度思考API 传可信配置标记，跳过入口判断
ask_user/审批恢复、暂停恢复或 checkpoint replay不新增入口判断；同 Run 已持久化的选择仍有效

目前采用保守的“所有续问保留原 Agent”规则，不猜测代词、不自动给每轮重新分类。新 Run 保存 skipped 状态覆盖上一轮的窄工具选择；重放/恢复不复用其他 Run 的旧路由。旧 checkpoint 没有新字段时按原路径执行。

active 对同一 Run 的每次模型调用持续使用选择结果，且在原生 awrap_tool_call 中拦截模型幻觉产生的被排除工具调用。此限制只能减少工具；工具自己的授权和业务校验仍必须执行。shadow 记录建议与原生 custom 状态，完全不筛减工具。

4. 配置与 Higress 迁移​

所有配置由原 Nacos bootstrap / Settings 读取，环境变量优先；当前没有热更新监听，变更后重启 Agent。样例见 Agent Nacos 配置。

AGENT_DECISION_MODE: "shadow" # 部署时先观察；代码与模板默认 off
AGENT_DECISION_BASE_URL: "https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1"
AGENT_DECISION_PATH: "/systemone"
AGENT_DECISION_API_KEY: null
AGENT_DECISION_MODEL: "decision-model-preview"
AGENT_DECISION_TIMEOUT_SECONDS: 1
AGENT_DECISION_CONFIDENCE_THRESHOLD: 0.8
AGENT_DECISION_ALLOW_HTTP: false
AGENT_DECISION_DISABLED_CAPABILITIES: []
AGENT_DECISION_MAX_INPUT_CHARS: 16000

仅在两个 HTTPS origin 完全相同且没有独立决策 Key 时复用 QWEN_API_KEY。不同 origin 必须显式配置 Key；客户端不跟随重定向，也不读取环境代理。密钥不进入模型 state、日志或前端事件。

未来 Higress 配置示例：

# 生成模型另配 QWEN_BASE_URL / QWEN_API_KEY / QWEN_MODEL
AGENT_DECISION_BASE_URL: "https://higress.example.com/decision/v1"
AGENT_DECISION_PATH: "/systemone"
AGENT_DECISION_API_KEY: "replace-with-gateway-credential"
AGENT_DECISION_MODEL: "decision-model-preview" # 或网关已配置的别名

网关必须能转发 System One 的 method、body、鉴权和响应契约，路由到官方 /compatible-mode/v1/systemone。不能因为 ai-proxy 支持 Chat Completions，就认定它支持 /systemone。网关转换或透传与网关版本有关，本次未部署或验证 Higress 插件。

路径配置只能是固定相对路径，不允许换 origin、查询串或路径穿越。可信私网测试网关需要 HTTP 时，显式打开 AGENT_DECISION_ALLOW_HTTP 并设置独立决策 Key；HTTP 不自动复用聊天 Key。生产仍优先 HTTPS。

协议相同的供应商只改地址、路径、模型和 Key；协议不同时替换隔离的 decide(state, questions) 适配器，保持有限问题和规范化 answers 契约，路由策略与主模型入口无需绑定新供应商。

5. 预算、降级与观测​

入口仅发送当前用户正文、能力可用状态和本次工具名称，不发送完整历史、个人提示词、delegation 或工具结果。当前请求上限 4,000 字符；共享 adapter 限制序列化 state 默认 16,000 字符，覆盖 Knowledge 的证据决策。这里是本地字符预算，不宣称精确 token 计量。

HTTP 和整体 await 同时使用可配置 timeout。在线不重试；连接/HTTP 错误、超时、无效 JSON、未知问题、错误类型/选项/分布、NaN、越界概率或错误模型回显均降级。实际供应商故障打开进程内 30 秒冷却；输入预算和缺配置直接本地回退。没有额外开发降级 Agent、缓存或分布式健康协调器。

Choice 校验完整候选集合、有限概率、概率和与置信度；Noul 校验有限的 P(yes)。需求概率介于拒绝/接受门槛时不窄化工具。置信度不等于实际正确率，必须使用业务样本校准。

checkpoint 私有 decision 保存问题 hash、模型配置名、Run ID、模式、结果、route、工具范围及耗时；不会让 BFF 输入覆盖该状态。供应商日志只记录异常类型与 HTTP 状态；入口日志记录结果、路径和耗时，不保存正文。agent.decision custom 事件发送 ID/status/mode/model，终态补充非负耗时、有限的处理建议和固定原因码，继续复用 LangGraph → AG-UI → assistant-ui Data UI。页面以默认折叠的入口决策记录展示，shadow / active 均可见；影子建议未参与路由，原始输入、概率响应、私有状态和凭据不透传。记录只存在于当前流，历史消息不补回该 UI。跳过判断或本地问候规则不额外展示供应商运行事件。

已有 Run lease、取消、暂停、SSE、引用和审批流程继续生效；没有构造快捷执行的工具消息，也没有改变 HTTP DTO。

6. 扩展图片、视频与图片理解​

本次没有注册这些未来能力或伪造执行结果。新增时：

  1. 在所属业务模块实现具体服务、输入/输出契约、当前用户授权、额度、失败/取消与产物访问；视频异步创建/轮询/通知由该能力所有者实现。
  2. 通过既有公开接口/工具装配到 Harness。副作用工具保留 interrupt_on 和审核要求，不把新增工具直接标成只读。
  3. 在 CAPABILITIES 增加 code、描述和实际工具名。当前 mcp_ 前缀代表现有业务工具；增加非业务 MCP 能力时将业务映射收窄为审核过的具体工具，避免把所有 MCP 视为业务数据。
  4. requires_<code> 问题随描述表生成。新能力默认走已有 deep_agent handler，参数继续交给执行工具/主模型。只有原生工具确实不能承载时才增加执行入口，不提前创建插件框架或任务 DAG。
  5. 增加已注册/禁用/未配置/无权限/复合需求/超时测试；确认流式结果或异步任务可被现有 UI 正确呈现后上线。

输入模态与任务能力分别管理；附件类型不能替代意图判断。未来图片或视频参数、状态机、存储和权限不进入 Decision Model。

7. 修改范围、验证与剩余门禁​

主要文件：capabilities.py 新增描述表；decision.py 更新问题与官方 HTTP adapter；decision_middleware.py 更新策略、续问跳过与工具循环守卫；harness.py 传实际注册工具集合；api.py 传深度思考标记；settings.py、Nacos 模板增加网关和预算配置；test_decision.py、test_settings.py 增加验证。根 AGENTS、Agent 架构与文档索引同步。既有工作区修改保留，没有新增依赖、锁文件修改、数据迁移或 Edition/Manifest 变更。

本地命令（从各工程目录执行，数据库测试串行）：

cd agent
NACOS_ENABLED=false uv run --frozen ruff check src tests
NACOS_ENABLED=false uv run --frozen pytest tests -q
# backend Python 门禁
cd ../backend
uv run --frozen ruff check app tests

本地验证：Agent 和 Backend Ruff 均通过；Agent 全套 106 passed / 1 skipped，跳过项需要已迁移的独立 TEST_AGENT_DATABASE_URL。现有 Nacos SDK 与 Starlette 各有一条依赖弃用提示。测试覆盖官方请求/返回结构、概率校验、429/超时与冷却、重定向、Higress 自定义路径/别名/HTTP Key、能力缺失/禁用、复合任务、低置信度、MCP 与知识路径、工具循环拦截、续问、HITL 恢复、编辑/replay、SSE 与原生图执行兼容。文档相对链接和 git diff --check 通过。

本次实联通过现有 Nacos 读取 Agent 配置，使用官方 Token Plan 地址和配置中的 Key，未修改真实配置。一个单样例（5 秒测试预算）及三个静态样例（实际配置 1 秒预算）均收到有效 Choice/Noul；后三次本地耗时约 285–319 ms。普通解释归 chat（0.98），复杂任务归 deep_agent（0.96）。知识问答样例的主要分类是 chat（0.47），能力判断却包含 knowledge，按代码的置信度门槛回到原 Agent。它证明协议可用和必须保留降级，不能证明路由准确率或整体加速。组合任务即使能力建议漏项，仍保留全部已授权工具供 DeepAgents 规划。

当前真实模式仍为 off。部署后先配置 shadow、重启，收集脱敏人工标签，比较 off/shadow 的答案、工具序列、审批、耗时与费用，再决定 active。回滚设置 off 并重启，不需要回滚数据库；旧 checkpoint 兼容。恢复原代码版本时可忽略新的私有字段。

未验证：真实业务评测、PostgreSQL 重启恢复、受限 runtime 数据库测试、真实浏览器端到端、Higress 透传、远端 CI、镜像扫描/签名及生产发布。没有实现多模态能力、复杂任务完成度评估或快捷绕过主模型执行；查询扩写和证据充分性复用当前有界检索流程。
