Fast Vben Admin Agent Development Standard

本文件是所有自动化编码模型、代码生成模型和人工协作者的仓库级开发规范。进入任何子目录工作时，还必须读取并遵守距离目标文件最近的 AGENTS.md。子目录规范只能补充本文件，不能放宽本文件中的架构、安全和验证要求。

  • 规范版本：1.0
  • 架构基线：管理平台见 docs/modular-architecture-implementation.md，前端当前实现见 docs/frontend-architecture.md，Agent 见 docs/agent-architecture.md
  • 维护方式：架构变更与相关 AGENTS.md 在同一变更中更新

1. 开始工作前​

在修改代码前，按顺序完成：

  1. 阅读本文件和目标目录下的 AGENTS.md。
  2. 阅读与任务相关的事实源、ADR、现有实现和测试。
  3. 执行 git status --short，识别并保留用户已有修改。
  4. 用 rg 定位现有实现、调用方、测试和兼容入口。
  5. 明确变更边界、数据所有者、迁移影响、Edition 影响和验证范围。

不要只依据需求描述、文件名或旧对话推断当前实现。代码、迁移、CI 和当前文档才是工作区事实。

2. 决策优先级​

发生冲突时按以下顺序处理：

  1. 当前任务的明确要求。
  2. 已接受的 ADR。
  3. 当前变更所属范围的架构基线：Agent 使用 Agent 架构，管理平台使用 模块化架构实施基线。
  4. 模块开发指南和目标目录规范。
  5. 当前代码与测试反映的兼容约束。

不要直接改写已经 Accepted 的 ADR 历史结论。需要改变已接受决策时，新增 ADR 并声明替代关系。Proposed ADR 不能由模型自行改成 Accepted；必须有团队签署和文档要求的演练证据。

3. 固定架构​

  • 管理平台的架构形态是“模块化单体 + 构建期 Edition 组合”。数据分析 Agent 是独立顶层运行时，其边界以 docs/agent-architecture.md 为准；当前阶段不拆业务微服务、不引入运行时微前端、不维护产品分支。显式启用的 HermiT 隔离计算例外位于 services/chein-reasoner，不拥有用户/RBAC、发布本体或 ERP 数据；见 docs/ontology/reasoner/architecture.md（ADR-0015 仍为 Proposed）。
  • platform 是每个 Edition 必选的交付模块。kernel、system、infra 只是 Platform 内部限界上下文，不得加入 Edition YAML 或单独授权。
  • items 是业务模块样板。新增 IOA、ERP 等模块必须复用同一种模块契约、迁移、公开 API、事件和前端装配方式。
  • 管理平台的新业务能力进入 backend/app/modules/<module_code> 和 frontend/apps/web-pro/src/modules/<module_code>，不得继续扩大中央业务模型、中央 Router 或全局业务页面。Agent 的前后端接入适配器遵守该规则，工作流、工具和模型依赖只进入顶层 agent/。Platform 仅管理 Agent 提示词的租户/用户/RBAC 元数据、Nacos 正文存取与运行前选择；Agent 负责兜底提示词与执行，不在 Platform 引入 Agent 框架依赖。
  • 业务模块只能依赖 Platform 稳定公开接口和其他模块的 public_api。禁止导入其他模块的 domain、application、infrastructure、routes 或 ORM 实体。
  • 可选能力通过 capability 契约和组合根选择 Provider。禁止从可选模块实现建立静态依赖。
  • 只读业务 Agent 工具由所属模块的 ModuleDefinition.agent_tools 声明。MCP 协议适配在后端组合根挂载；模型编排、工具发现与 Run 策略仍在顶层 agent/。工具处理函数逐次重验成员、权限、模块权益及 Tenant UoW；实施范围见 docs/agent/tool-management-implementation.md。
  • 可选 Langfuse SDK 仅在顶层 agent/ 接线；Backend 可使用 observability/ 的通用 metadata OTLP 适配层，不导入 Agent/模型框架。默认关闭，默认采用 metadata-only 与 HMAC 身份引用；仅显式 redacted-content-v1 允许有界的脱敏问答，系统/个人提示词、工具原始结果、媒体和纠正文本不外发，契约见 docs/agent/langfuse-readable-tracing-design.md；反馈和消息映射由 Agent 持有，查询先重验租户与拥有者。观测失败不能改变 Run、checkpoint、审批或授权；运行边界与实施证据见 docs/agent-architecture.md 和 docs/agent/langfuse-delivery.md。
  • 实时语音模型协议、音频与工具桥接只进入顶层 agent/；modules/platform_voice 仅提供当前授权、短期一次性票据与同源 WebSocket BFF，不加入 Edition。语音与文字共用 Thread/Checkpoint，服务端以 PostgreSQL advisory lock 互斥；模型参数不能构造身份，语音打断不能撤销业务事务。见 实时语音设计。
  • Agent 能力路由复用原生 Middleware 与已授权工具注册结果；决策供应商协议隔离在 agent/，建议不能授予权限或替代 DeepAgents 规划。模型网关配置须区分聊天与决策协议，多轮续问和恢复保留现有执行路径。
  • Creation 数据库测试使用 pnpm backend:test:creation 的一次性数据库，禁止与独立视频 Worker 共用队列。
  • 视频 Provider、prompt 补充与创建工具属于顶层 agent/；Suite Creation 拥有视频 Job/Asset，独立视频 Worker 只调用签名 Agent HTTP，不导入模型框架。状态与恢复以数据库为准，已提交任务禁止自动重提，见 docs/agent/video-generation-design.md。
  • 图片 Provider、优化与生成工具属于顶层 agent/；Suite 的 creation 模块拥有图片元数据、权限和 RustFS 生命周期。图片 UoW 与 RLS 同时约束 tenant/owner；仅租户 Schedule 与已授权存储渠道引用计数使用受控维护作用域，个人 HTTP/模型工具不能继承该旁路。见 docs/agent/image-generation-design.md。
  • SQL 分析的纯 QuerySpec/ChartSpec DTO 位于 app.modules.analysis_contracts，不得导入 ORM 或业务实现。Analytics 经 capability 调用 ERP 数据所有者，目录、查询、scope 与取消通过现有 MCP 组合根发布；Agent 包装获准的 MCP 工具生成图表快照，不将原始结果工具重复交给模型。MCP 启用时不回退分析 HTTP 接口。ERP 受保护视图 schema 由 MigrationSpec.additional_schemas 声明，不授予通用 API 运行账号；快照由顶层 Agent 持有，个人收藏由 Analytics 持有。实施与兼容窗口见 docs/agent/sql-analytics-delivery.md。

4. 唯一事实源​

Agent Automations 的业务表、Trigger、Scheduler 和执行服务由顶层 agent/ 拥有；Backend 的 modules/platform_automations 仅是 Platform HTTP 授权/通知/BFF 适配包，不是 Edition 模块，不引入模型或调度依赖。Scheduler 必须独立运行并先取得 PostgreSQL leader guard；业务查询必须逐 tenant/owner 进入双重 RLS scope，控制面目录只能包含路由 ID。见 docs/architecture/agent-automations.md。

5. 多租户与安全红线​

  • 租户身份只能来自已验证 JWT、可信事件信封、受控 client-to-tenant resolver、Schedule 的平台枚举结果或显式受审计的平台入口。
  • 不得直接信任 body、query、header 中的 tenant_id。公开回调必须先通过租户编码、客户端凭据或其他可信映射解析租户，再进入 UoW。
  • Tenant-owned 数据必须在对应 TenantUnitOfWork 内访问。API、Worker、Schedule、CLI 使用相同隔离原则。
  • privileged=True 仅用于已经完成平台级授权的受控跨租户操作。调用点必须可审计，并具有跨租户负向测试。
  • ORM tenant 过滤不是 PostgreSQL RLS 的替代品；RLS 也不是可信租户解析的替代品。扩展 RLS 时必须同时更新模型集合、迁移、runtime 角色测试和调用路径。
  • 不得假设所有带 tenant_id 的历史表已经启用 RLS。OAuth2/OIDC、租户全局目录和全局模块运行时表的前置设计见实施基线和 ADR-0013。
  • 运行时进程使用无超级用户、无建库/建角色、无 BYPASSRLS 的 app_runtime。迁移管理员凭据不得注入 API 或 Worker。
  • 禁止提交密钥、真实密码、访问令牌、个人数据或生产连接信息。

6. 模块、API 与事件​

  • 业务模块后端入口必须使用 require_module_access("<module>", "<permission>")，Platform 管理能力使用对应 require_permission。
  • 前端权限只用于交互体验；真正的安全边界必须在后端。
  • 跨模块公开接口只暴露 DTO、不可变值对象、稳定错误码和版本化契约，不暴露 ORM、Session、Request 或第三方 SDK 对象。
  • 改变其他模块业务状态时使用事务 Outbox。事件 Schema 放在发布方 public_api.events，消费者按 event ID 幂等处理。
  • 无消费者、可选消费者、重试、租约、死信和回执必须遵循现有 Outbox 状态机，不能新增旁路投递方式。
  • 破坏性 HTTP、DTO、事件或公开 API 变更必须提供版本策略、兼容窗口和迁移说明。

7. 数据库与迁移​

  • 历史 Alembic revision 一经进入共享历史不得改写；新增 revision 接在正确 namespace 的当前 head 后。
  • Platform 使用 Platform Alembic 链；业务模块使用自己的 schema、版本目录和版本表。
  • 模型、约束、索引、外键、RLS policy、降级逻辑和授权必须在迁移中显式表达。
  • 禁止用启动时 create_all、请求副作用或手工 SQL 替代迁移。
  • 修改迁移体系后必须运行对应 migration tests、alembic check 和受影响 Edition 构建。

8. 生成代码与兼容入口​

  • 不手工编辑 OpenAPI 生成客户端、类型文件或 Build Manifest。修改源契约后重新生成。
  • app.models、app.core.db 以及旧 Router/Infra 路径是兼容门面，不是新增生产依赖入口。
  • 不删除兼容门面，除非任务明确包含迁移期结束、所有消费者审计和破坏性变更方案。
  • 生成器输出只是起始代码。合并前必须迁入目标模块结构并补齐权限、租户、迁移和测试。

9. 修改原则​

  • 优先遵循现有模式；只在减少真实复杂度或匹配既有边界时增加抽象。
  • 变更保持最小且完整：修复根因、所有调用方、测试、迁移和文档，不做无关重构。
  • 不回滚、覆盖或格式化与任务无关的用户修改。
  • 禁止为了让测试通过而放宽鉴权、租户隔离、RLS、错误处理或契约校验。
  • 对暂不能安全完成的范围，明确前置条件和失败关闭行为，不用占位实现伪装完成。

backend/tests/conftest.py 的 db fixture 会初始化并清理 User、Item 和 Outbox 数据；必须使用一次性测试数据库，禁止对开发或共享业务数据库执行。筛选单测前检查其直接及间接 fixture，不能仅凭文件名判断无数据库副作用。

11. 完成定义​

只有同时满足以下条件才能宣称完成：

  • 行为与任务一致，失败路径和权限边界明确。
  • 架构依赖方向、事实源和模块所有权未被破坏。
  • 数据迁移、兼容策略和回滚影响已处理。
  • 测试覆盖与变更风险匹配，实际命令已成功完成。
  • 文档描述当前事实，不把目标态、建议或本地结果写成已上线事实。
  • 明确列出未执行的外部门禁，例如远端 CI、镜像扫描、签名、N-1 演练或团队签署。

“文件已创建”“局部测试通过”或“实现看起来合理”都不构成完成证据。

12. Git、依赖与交付​

  • 未经明确要求，不创建分支、不暂存、不提交、不推送、不创建 PR，也不修改远端状态。
  • 禁止使用 git reset --hard、强制推送或其他会覆盖未提交工作的操作。不要回滚无法确认来源的修改。
  • 新增运行时依赖前，先证明标准库和现有依赖不能合理解决问题；同步更新 lockfile、镜像和供应链检查。
  • 不在功能任务中顺带升级框架、格式化全仓库或重写无关生成文件。
  • 交付说明至少包含：行为变化、关键文件、实际执行的验证、未执行的验证、兼容/迁移影响和已知剩余风险。

开发验证截图​

  • 浏览器验证截图使用 scripts/save-dev-artifact.mjs 的 saveDevArtifact(bytes, { business, name }) 保存，保存时直接上传 RustFS；禁止写入工作区 output/playwright/ 或其他源码目录。业务分类使用 agent-ui、knowledge 等短编码。
  • 原生浏览器工具返回的截图字节可直接传给该入口；需要落盘才能工作的工具，临时文件只放系统临时目录，随后通过 pnpm dev:artifact --business <code> --name <filename> 从 stdin 归档并清理临时文件。
  • 连接配置独立存放在项目外的 ~/.config/chein/dev-artifacts.json，不得提交密钥。上传失败保留项目外的 ~/.cache/chein/dev-artifacts/ 待发文件并明确报告失败；用 pnpm dev:artifact --retry 重试。系统“存储渠道”仅控制业务上传接口，不控制开发工具截图。接入与验证见 docs/operations/development.md。

Agent 上下文用量边界​

上下文占用只使用主 Agent 最近已准备/已执行请求的输入 Token，不能用会话累计、输出或子 Agent 用量替代。模型限额复用当前模型配置/Profile，缺失时显示未知；统计只保存数值与本人 Run 引用，沿用现有事件、租约、授权与历史恢复，失败不能影响执行或重做摘要。设计见 上下文 Token 统计。

对话执行偏好只能收窄当前已审核 MCP 工具，Provider 固定枚举须在 delegation 验证后解析并隔离请求；设置绑定现有 RunEvent，恢复不可悄悄切换。关闭 Qwen 决策只能回到已有默认路径，不能关闭权限、业务校验或 Memory 证据门禁。见对话控制。

Datasource 数据源边界​

modules/datasource 拥有 Suite 外部连接凭据、持久目录、业务配置、外键和采集任务，使用独立 schema、Tenant UoW 与 FORCE RLS；采集复用模块 ScheduleHandler。只允许代码注册的驱动，连接地址与端口由有权限的用户在页面配置，不设应用级网络/端口白名单。预览只查询已启用表的暴露字段，不接收任意 SQL、不缓存样本行。Ontology IRI 仅预留引用，不授予本体或 ERP 数据访问；后续跨模块映射须新增公开引用契约。见 数据源交付。

OWL 前端可由组合根按 Manifest 可选注入 datasource/public_api/catalog 只读目录 Reader，消费方只类型引用 DTO；沿用数据所有者 HTTP 授权。已启用表与已暴露字段仅复制为已有草稿命令，不保存活跃映射、不读取样本、不写回数据源 IRI，见 OWL 目录导入。

OWL 原始表面板通过组合根另行注入 datasource/public_api/preview Reader，不能把元数据 Reader 当作数据访问授权。仅从目录导入 IRI 的实体 ID 定位源表，数据所有者逐次核验 tenant、模块及 read/preview 权限、启用/暴露/脱敏配置和结构摘要。允许选中对象后在当前页面自动加载，折叠后停止加载并清除展示数据；不保存样本或建立活跃映射。分页保持现有只读、超时及大小预算，不接收 SQL、租户或任意地址，也不向外部连接注入或绕过其他模块的 RLS/业务 scope。

Ontology 本体边界​

Neo4j 独立语义本体页面已退役，Ontology 管理入口为 OWL 可视化构建器；不得因页面退役删除构建器及 Agent 共用的 Neo4j/发布/推理能力。范围及菜单清理见 页面退役。

Neo4j/Legacy 只切换授权后的发布语义读取；PostgreSQL 仍是发布、审核及 ACL 唯一事实源，ERP 仍拥有实时实例。图投影必须显式执行；空结果、权限/Schema/摘要错误不得故障回退，不混合 Provider 结果。见 双 Provider 设计。

本体定义、版本、发布授权与审计属于 modules/ontology；ERP 通过代码维护的 ontology.data capability 提供固定只读映射，Knowledge 通过 ontology.evidence 复验来源。模型不能指定 SQL、脚本、URL、身份或权限；已发布正文不可变，当前发布版本及映射实质变化时失败关闭；仅允许数据所有者按完整旧契约证明的纯增量目录兼容，禁止忽略摘要。私有及租户本体均允许有当前 ontology:publish 权限的单账户发布；校验、来源复验、本人 OWL 校验任务和不可变版本门禁不变，不伪造第二审核人。个人候选及 Memory 不能自动发布为租户本体。工具通过现有模块 MCP 装配，业务源权限由工具声明推导 delegation 上限并在数据所有者逐次重验。设计见 本体架构。

Neo4j 与 Legacy 管理工作区独立，分类不可改；RDF 必须先进入受控草稿并通过校验与显式发布，标准语义只支持声明的有界子集。SHACL 为禁网隔离进程的模型样本门禁，不覆盖共享 GraphConfig/命名空间/Shapes，也不替代实时 ERP 校验。见双工作区交付。

复杂 OWL TBox 公理保存在版本正文的 owl_rules，随本体经当前发布权限校验后发布，禁止作为 n10s 基础推理的隐式扩展。发布门禁必须绑定本人真实 OWLAPI/HermiT 校验任务与当前完整输入/正文/映射摘要；不能复用改稿前校验或他人私有任务。正式 Agent 工具仅接受已发布版本，失败或未完成结果不得进入依赖它的模型决策；历史推理证据重验当前权限。ERP ABox 只能经数据所有者 reasoning-snapshot-v1 的只读 RR 有界快照；身份/owner/仓库由当前授权解析，数据或 scope 摘要改变即失效。授权子图结论不代表全库完整性，也不能替代 ERP 事务校验；组织或全库 ABox 无对应契约时保持关闭。见集成设计。

发布 Action 的 precondition 只绑定已声明类及固定 ABox 深度；执行必须引用本人成功任务，并复验完整规范化参数摘要、发布版本、根、数据/权限快照与正向蕴含。含 OWL/SHACL 而无前置条件的 Action 失败关闭；普通显式事实读取仍使用原授权链。逻辑 usable 不等于业务许可，未蕴含为无法判断，不能改写为通过。参数修正只允许同一推理工具一次调用，不夹带业务操作。结果分页须在既有总预算内收齐；纯 TBox 序列化缓存不能缓存授权或 ERP 实例。现有 ERP 未提供授信/合同和跨资源法人唯一标识时，不创造事实或按名称/税号自动合并。

Logic Pack 的受限 AST、三值求值、证明与重放位于 Ontology 的 application/inference/，禁止在该包读取数据库、网络、模型或系统时钟。Case 仅为独立命名空间的合成夹具，真实 ERP 样本只走授权 dry-run/本人私有推导记录，禁止自动转存共享 Pack。快照 IRI/sourceRef 一致性不构成身份或来源授权；外层必须按当前可信身份取得数据所有者快照及已核对摘要的发布公理。Pack/推导元数据由 Ontology UoW 与 FORCE RLS 约束；推导记录同时按 tenant+owner 隔离，过期清理也不能借此扩大读取范围。HTTP/MCP/Agent/UI 已接线；规则 then:type 目标类不从绑定自动断言，只能从规则证明取得（包括其继承证明），见 Logic Pack 设计与实施证据。

Knowledge 检索边界​

Knowledge 模块通过 Platform 公开组织目录访问 USER/ROLE/DEPARTMENT，不能直接导入组织 ORM。全平台系统库保持独立全局 RLS 与显式 writer；统一逻辑资源不等于合并物理租户策略。Knowledge 原生 Tool 默认经已有应用服务调用官方 HTTP API；RAGFlow MCP 保留为显式可选 Adapter，接入事实见 docs/agent/ragflow-native-tool-integration.md。Agent 的语义路由与 Judge 留在顶层运行时，必须限制于已授权目录，回写证据判断前重验文档状态。部署与真实评测事实见 docs/agent/knowledge-retrieval-delivery.md。

Agent 长期记忆边界​

长期记忆唯一引擎为 RAGFlow Native Memory。顶层 agent/ 持有私有 Adapter、可信 tenant/owner 到独立 me Memory 的映射、开关、提交状态和来源拒绝记录；正文、四类提取、Embedding、检索和 FIFO 由 RAGFlow 管理，不新增 LangMem、pgvector 或独立 ES 投影。默认 Agent Nacos 可按白名单复用 Backend runtime 的 RAGFlow 地址/API Key/超时，不导入其他 Backend 配置或迁移凭据，不混用不完整连接。公共 API Key 的外部 user_id 不是鉴权；所有空间从当前可信身份解析，列表/详情/搜索/最近消息/修改/遗忘均重验当前成员与权限，管理员不能因此读取他人正文。默认 PRIVATE，不自动迁移旧共享数据。

Backend modules/platform_memory 仅为 Platform BFF、当前授权、Outbox 生命周期和私有 Memory HTTP 调度适配，不加入 Edition 或导入模型框架。开启自动同步后，成功 Run 只持久化来源引用，离开 Agent 页面、切换会话或关闭助手时按新增问答归成一个同步批次（例如 10 轮为一次任务），由现有 Worker 逐轮提交用户原文和助手最终回复；不离开不自动出站，不用 System One 做保存/提取价值过滤。批次只保存来源引用，保留迟到成功 Run、去重、容量调度与逐轮提交状态；列表按批次显示，新增元数据迁移先于新代码启用。RAGFlow 官方负责提取和检索；它不保证语义去重或事实准确。复用视频 Worker 独立调度线程与 Agent PG leader guard；不明提交禁止盲重试，不回放已终止旧任务。元数据保持 tenant/owner FORCE RLS；关闭、清空、会话删除及恢复重验版本和来源墓碑。新记录通过每轮 delivery 关联具体来源，召回、详情和继承历史复用现有 Analysis/Knowledge/Memory 授权；未知工具或来源不明失败关闭。Backend 只签发当前已有的固定只读来源权限，Memory 不能授予业务权限。助手输出是低信任历史参考，不作用户事实或当前业务真值。保留 Checkpointer、会话历史、压缩和审批。现行架构、备份、迁移及启用证据见 Native Memory 设计和交付，旧价值治理仅保留历史说明。

HermiT 仅接受 Backend 当前授权后签发的专用短期 delegation；不接受登录 Token 或未验签身份头。版本入口复验当前发布正文与完整来源可见性，上传仅为本人私有计算。禁止远程 Import、自动 Neo4j 物化及默认 Agent 全量推理；有限任务使用独立可终止 JVM 与单实例私有卷。设计与验证见 HermiT 计算服务。

Logic Pack 外部绑定与目录复制导入是独立路径。外部绑定通过可选 datasource.ontology-data capability，仅支持 PostgreSQL 单连接 UUID 单列主键与已暴露未脱敏字段的固定只读 RR 快照，不混合 ERP/外部源。Ontology 的 logic_binding_reference 为 tenant-only 最小删除索引，不含正文或样本；Datasource 只通过当前删除权限下的只读引用 capability 获取布尔结果，不能借此读取他人 Pack/推导。绑定保存与连接删除共用事务锁。原目录复制导入仍不建立活跃映射。实施状态见 Logic Pack 设计与交付，ADR-0017 保持 Proposed。

Logic Pack 的人工出库审核由 ERP 的 approve-with-evidence HTTP 命令拥有，Ontology 只经可选 ontology.action-evidence capability 核验本人业务证明。首次提交复验 replay 与 fresh 快照；已完成幂等回执的重试只复验当前权限/归属/证明，不重复库存写入。证明是人工辅助证据，不是 ERP 事务内通用规则硬门禁。Agent 卡片仅跳转授权的 ERP 隐藏页面，MCP 仍只读，见 ADR-0017 与 Logic Pack 交付。

OWL 原生工作区通过 builder_binding.mode=native 标识，正文与发布版本仍归 PostgreSQL Network/Version/Audit；空白新建和可选文件导入不读取、绑定或投影共享 Neo4j Resource。编辑保存沿用 ontology:edit，发布仍须本人当前 HermiT 校验与 ontology:publish。历史 mode=resource 接管保留平台检查、原文件、图摘要及显式写回门禁；不得把原生工作区伪装成 Resource 绑定，见 OWL 画布。

Token 计量与额度边界​

Token 账本、版本价格、计数器、策略执行及聚合/告警 Worker 由顶层 agent/usage 持有；Backend 的 modules/platform_token_budget 仅提供可信身份、部门目录、授权 BFF 和 Platform 站内通知适配，不加入 Edition、不导入 Agent 框架、不查询 Agent 表。账本只含数值与引用，使用租户 FORCE RLS；个人读取额外绑定当前 owner，部门采用签名 delegation 的发生时快照。模式默认 off；observe 只记账提醒，enforce 下所有适用 hard 策略共同约束新 Run 及后续模型调用。计数器故障时 hard 新准入失败关闭，运行中故障放行并告警；费用缺价及并发在途消耗不构成精确费用上限。Higress 仅负责 L1 宽松熔断，配置示例和 Agent 接线已实现，目标插件摘要、顺序、抓包和取消对账仍待实测。RAGFlow 当前接口缺少内部 Usage，hard 策略下暂停其付费提取/搜索，不能伪造纳管完成。实现与外部门禁见 Token 计费交付。
