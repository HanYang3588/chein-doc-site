Chein 数据分析 Agent 架构

  • 状态：P0 与 Phase 1 已落地；Suite 新增规则型 SQL 分析、Agent 快照、聊天图表和个人收藏，并完成本地验证。业务写入工具、Higress 缓存、独立 Worker 和通用产物仍为目标态；Suite Knowledge 模块提供动态私有知识 ACL。
  • 适用范围：Chein 的 Agent 前端入口、管理后端接入层和顶层 agent/ 运行时

本文是 Chein 数据分析 Agent 的架构事实源。现有 PRD.md、TRD.md、ERP 与模块化文档描述移植自 Fast Vben Admin 的管理平台及其业务模块，不替代本文。

1. 结论​

Agent 自动化的业务任务、Run 历史、Trigger、调度与执行服务由顶层 agent/ 持有；Backend 仅提供同源 BFF、当前权限重验、提示词选择与现有通知适配。Scheduler 是独立进程，不在 Web lifespan 启动；任务与运行使用 tenant/owner FORCE RLS，控制面 owner 目录仅保留路由 ID。具体设计和验收边界见 Agent Automations。

Chein 采用“管理平台 + 独立 Agent 运行时”的形态：

  • frontend/apps/web-pro 使用 React / Umi Max / assistant-ui，已接入 Agent 对话、会话历史、工具事件、取消与原生工具审批控件；Suite 的 ChartSpecV2 经组合根工具 renderer 接入主线程和浮动聊天，ChartSpecV1 继续兼容。深度思考、渲染安全与产物接线的实际状态见Agent UI；完整任务结果页仍为目标态。
  • backend/ 继续拥有登录、租户、RBAC、配额、文件授权和对外 API；当前通过 backend/app/platform/agent_ui_router.py 提供 Agent UI BFF，并提供固定 ERP Statistics Facade。
  • agent/ 是独立 Python 工程和独立运行进程，负责模型调用、工作流、工具执行和检查点， 不导入 backend/app；已持有受限分析快照，通用报告与对象存储产物仍为目标态。
  • 管理后端通过版本化的内部 HTTP 契约调用 Agent，不能直接导入 Deep Agents、LangGraph、LangChain 或 Agent 内部图节点。
  • Agent 不复制用户、租户和角色系统；每次执行只接受管理后端签发的短期可信执行上下文。
  • Platform 管理提示词的租户、角色、岗位和用户适用范围，Nacos 原生 Prompt 管理中文正文及发布版本；BFF 在每次对话开始时通过官方 Python SDK 读取 latest 并按当前登录用户组合，Agent 只接收本次 Run 的结果。部署与旧正文迁移步骤见提示词管理。

初期不拆更多微服务、不做运行时插件市场、不做多 Agent 组织系统。先完成一个安全、可恢复、可观测的数据分析闭环。

2. 产品边界​

首个可交付闭环是：用户在一个会话中提交问题和已获授权的数据，系统异步执行分析，持续返回进度，必要时等待用户确认，最终返回带来源说明的答案和可下载产物，并允许基于上下文继续追问。

首期已选定受控 ERP 统计 Facade 作为唯一主要数据入口；文件上传、外部数据库、互联网搜索和企业 SaaS 连接器按真实需求逐个增加。

明确不在首期范围：

  • Agent 自主修改生产业务数据。
  • 无限制的 Shell、网络和宿主机文件访问。
  • 任意第三方 Python 包动态安装。
  • 多模型智能路由、自建向量数据库、长期人格记忆。
  • 为每种模型、工具或节点提前建立一层自定义框架。

3. 系统边界​

边界规则：

  1. 浏览器只访问管理后端，不直连 Agent、模型供应商或数据源。
  2. 当前 Agent UI/API 接入适配器位于 backend/app/platform/agent_ui_router.py 和 backend/app/platform/agent_delegation.py；它调用 Platform 的提示词选择服务，不直接操作 Nacos，也不导入工作流节点或模型 SDK。未来如迁入模块目录，保持相同边界。
  3. agent/ 拥有 Agent 领域实现和自己的 pyproject.toml、迁移、测试及镜像。
  4. 两边只共享序列化协议，不共享 ORM、数据库 Session、运行时状态对象或内部异常。
  5. 初期可共用 PostgreSQL 实例和对象存储，但使用独立 Schema、迁移链、运行角色和数据所有权。

4. 技术职责​

四项既定技术各司其职，不再建立重复的编排层：

技术在 Chein 中的职责
Higress AI Gateway统一 Qwen 兼容模型入口和路由；使用官方 ai-cache 缓存模型响应，使用 response-cache 缓存工具响应，见 缓存设计
Deep Agents复杂分析任务的计划、上下文管理和按需子任务；简单单循环不足以满足需求时才启用完整能力
LangGraph唯一工作流状态机，负责持久化检查点、暂停、恢复和取消语义
LangChain模型与工具接口、结构化输出和必要的中间件

Prompt、工具 Schema、模型配置和图版本都必须有稳定版本号，并在每次 Run 上记录实际版本。不要把 Python 函数路径或框架内部状态暴露为外部协议。 当前提示词只在 Run 事件中记录正文摘要，完整的版本快照与历史重放仍是目标态。Nacos 正文不可用时使用 Agent 内置中文兜底提示词；个人提示词作为用户偏好附加到用户消息，不提升为系统指令。

有限选项判断见 阿里云决策模型与能力路由。复用原生 Middleware、已授权工具和私有 checkpoint 状态，默认关闭；shadow 记录建议，active 区分 chat / knowledge / deep_agent 与所需能力集合，对同 Run 持续缩减工具。续问、恢复和显式深度思考保留现有路径；能力不可用不执行替代工具。决策协议和聊天协议分别配置，Higress 透传仍待验证。Token Plan 官方协议已本地实联，业务评测与生产验收待完成，自动写入仍未开放。

6. 运行与状态机​

当前实现使用 queued、running、waiting_approval、waiting_input、succeeded、 failed 和 cancelled。ask_user 的文字回答进入 waiting_input；敏感工具确认进入 waiting_approval。取消通过 cancel_requested_at 记录；排队和待确认 Run 可直接取消， 运行中 Run 协作式停止。

queued -> running -> succeeded
                 -> failed
                 -> cancelled
                 -> waiting_approval -> queued
                 -> waiting_input    -> queued
  • 当前由 BFF 生成 run_id 并按租户和用户范围作为幂等键；重复请求返回原 Run。 独立的 Idempotency-Key 请求头和更细冲突语义属于目标态。
  • 当前 Agent API 从 PostgreSQL 领取任务并使用有期限的 lease；进程退出后，同一 Run 可由恢复请求重新领取。独立 Worker 自动调度仍未实现。
  • Deep Agents interrupt_on 保护新增的非只读工具；已审查的日期、ERP 统计和共享知识检索工具保持只读。ask_user 只允许文字 respond；写操作决策只允许 approve/reject，防止文字答复被视为写入成功。决定按 checkpoint ID 和动作顺序一次提交，拒绝会跳过工具并把理由反馈给模型；决定写入 queued Run 后再恢复图。当前没有写入工具，不能把审批基础设施解释成已开放业务修改。
  • 检查点重跑仅允许下一节点为模型且没有待审批中断的检查点；LangGraph 会重新执行其后的节点。未来开放写入工具前，业务侧必须提供幂等键和效果审计，防止崩溃恢复或重跑重复写入。
  • 每个可能重放的节点都必须幂等。外部副作用必须有业务幂等键，并在执行前完成权限与审批。
  • 工具参数错误、执行超时、服务不可用及权限拒绝通过原生 ToolErrorMiddleware 返回脱敏的 ToolMessage(status="error")，由模型说明失败及未完成部分，不把工具失败等同于整轮执行失败或零数据。ERP summary 同时返回采购/销售摘要，不接受 type/start/end；仅 time_series 接受这些条件。参数或工具选择错误最多在当前已授权契约和路由内修正一次，相同失败调用不重复执行；超时、撤权及服务异常不自动重试或改用旁路。本轮两次工具失败或不可修正失败后关闭后续工具，只允许模型说明。取消、审批中断、租约丢失、模型/检查点/运行预算等错误维持原执行边界；正式推理继续遵守更严格的失败阻断，不能借通用错误处理放行推导决策。消息卡片沿用服务端中文 Run 错误，历史缺错误文本时显示本地兜底，不输出 SDK 默认英文或原始堆栈。
  • 取消是协作式的：停止后续模型与工具调用，保留已有事件和产物，不把已发生的外部副作用伪装成已撤销。
  • 用户请求暂停后，Agent 在下一个 LangGraph 节点更新处检查请求，使用同步持久化的 checkpoint 保存 paused Run；恢复沿原线程 checkpoint 继续并重新解析 Nacos 系统提示词，个人提示词在新消息或编辑原消息时生效。节点内的模型或工具调用不会被暂停中断。编辑用户消息只允许从该消息对应且下一节点为模型的 checkpoint 分支执行；运行中普通消息在浏览器的 assistant-ui 队列等待，当前回答完成后按顺序启动新 Run，显式“引导”才触发协作取消并优先发送纠偏提示。前端队列与停止、审批、会话切换的实际接线见 Agent UI。该机制尚未提供独立 Worker 或 MQ 自动恢复调度。
  • 运行达到最大时长、模型调用数、工具调用数、Token 或费用预算时失败关闭，不能无限循环。

当前仅用 PostgreSQL Run 表和 lease，不引入消息队列。将来接入 MQ 时，消息只传 tenant_id/run_id 作为唤醒信号，消费端仍以数据库原子领取为准；发布通知需事务 Outbox 和幂等消费，避免数据库提交成功但消息丢失。当前没有 Outbox、自动 Worker 或跨进程调度。

7. API 与流式交互​

当前公开入口由管理后端提供：Agent UI BFF 使用 /api/v1/agent-ui，内部 Agent API 使用 /internal/agent/v1。当前已提供 Thread 管理、历史消息、/chat SSE、Run 取消、待审批查询与决定、恢复 Run、检查点列表与受限重跑； 内部 Agent API 还提供 Run 与事件查询。目标态最小能力包括：

  • 创建/查询 Thread。
  • 创建、查询和取消 Run。
  • 读取 Run 的结果、事件和产物（产物为目标态）。
  • 提交补充输入或审批决定。
  • 读取健康与协议版本，不暴露 Prompt、密钥或内部拓扑。

前端进度采用 SSE；用户输入、取消和审批继续使用普通 HTTP。Agent 对话页面使用 AG-UI 事件承载文本、工具、状态和结构化 UI，具体 BFF、renderer、图表和 RAGFlow 引用协议见 Agent UI 设计。SSE 事件至少区分状态变化、工具进度、审批请求、产物就绪和错误。持久化事件使用单调递增序号支持断线续传；Token delta 可以只实时发送，重连后以已持久化消息快照恢复。

文字聊天继续使用 SSE；实时语音新增独立的同源 WebSocket 接入，复用原 Thread、Checkpoint 和授权。默认关闭、模型协议、转写顺序、互斥与验收边界见 实时语音设计。

8. 认证、租户与授权​

  • 管理后端先执行登录、租户成员关系、Agent 模块权益和权限校验，再创建执行。
  • 当前已实现 agent:chat 入口权限、agent:approval:decide 允许执行权限和 erp:statistics:query 数据 scope；本人拒绝动作或回答 ask_user 仅需 agent:chat；目标态再细分 agent:thread:create、agent:run:execute、agent:run:view 和 agent:admin:configure。
  • 管理后端向 Agent 签发短期执行令牌，至少包含 iss、aud、exp、jti、tenant_id、user_id、run_id 和允许的 scopes。Agent 必须验证签名、受众、有效期和 Run 绑定关系，不信任普通转发 Header 或请求 Body 中的租户 ID。
  • Agent 数据使用独立非超级用户运行角色并启用租户隔离；生产前必须具有无 scope、伪造 tenant、跨租户 ID、bulk DML 和 Worker 复用连接的负向测试。
  • 查看 Run、下载产物和提交审批都重新检查当前权限；创建时有权不代表以后永久有权。
  • 管理员查看其他用户数据必须走显式、受审计的管理入口。

9. 工具与数据安全​

工具默认只读、显式注册、参数强校验。模型提出工具调用不等于获得权限。

自研只读工具采用模块声明、后端 FastMCP、已有 Nacos AI SDK 和 LangChain MCP Adapters，详见工具管理实施设计。/mcp 复用管理后端进程与端口；Agent 每个 Run 加载固定版本和已授权工具，逐次核对 Nacos 撤销，业务端重验当前授权。摘要写入 mcp.tools.bound RunEvent，恢复发现变化要求新建 Run。Knowledge 使用原生 Tool 与独立应用服务，默认调用官方 RAGFlow HTTP API；原有语义路由、Judge、引用和历史授权不变。官方 MCP Adapter 保留，必须显式选择传输模式，不在 Agent 重复注册知识检索能力。日期保持原生工具，写工具未开放。

  • 数据库分析使用专用只读账号、只读事务、语句超时、结果行数和返回字节上限；不能依赖 SQL 字符串黑名单防写入。
  • 上传文件校验大小、类型和租户归属，解析在隔离目录或沙箱中进行，产物不得覆盖原文件。
  • Shell/代码执行只能进入短生命周期沙箱，限制 CPU、内存、磁盘、时长和网络；不得挂载宿主 Docker Socket、仓库密钥或平台数据库管理员凭据。
  • 网络访问默认拒绝，只允许已配置连接器的目标地址，并阻断环回、链路本地和云元数据地址，防止 SSRF。
  • 密钥不进入 Prompt、模型上下文、RunEvent 或日志。工具只接收 credential 引用，由服务端解析并使用。
  • 数据源内容、网页和文件均视为不可信数据；其中的文字不能改变系统策略、授权或工具允许范围。
  • 写数据、发送消息、删除资源和产生费用的高风险动作首期禁用；以后启用时必须同时满足权限、策略、人工审批、幂等和审计。

用户提交代码、生成代码、宿主命令、破坏性操作、业务外请求和直接/间接注入的详细设计见Agent 滥用防护与执行安全。

10. 产物、保留与删除​

Suite 已实现受限分析快照：Agent 保存不可变的 agent.analysis_snapshot；ERP 拥有受保护分析视图与审计，Analytics 拥有个人收藏，模块间经版本化 capability/DTO 交互。分析目录、查询、scope 和取消由已有 FastMCP/Nacos 链路提供，Agent 保留两个模型工具处理有界摘要与快照，不向模型重复暴露底层结果工具。查询不增加 Decision 调用，历史授权校验包装模型调用而不增加 Graph 步骤。快照读取和历史模型输入都重验当前源权限；预算、传输兼容窗口、配置和延期范围以 SQL 分析交付 为准。

对话可按 Run 选择本体 Provider/已审核工具、关闭类继承推理及 Qwen 决策辅助；设置持久化于既有 RunEvent，恢复沿用原设置。默认和故障保持原执行路径，不扩大权限或开启部署关闭的能力，见对话控制。

正式推理的模型与工具入口共同失败关闭：证据撤权、未知或任务失败不能清除历史后继续业务决策；一次参数修正只能调用同一推理工具。逻辑结果不授予业务权限；发布 Action 可声明前置分类，Backend 将完整动作参数与本人任务、当前授权 ABox 快照及正向蕴含绑定，执行前后复验。含 OWL/SHACL 而未声明条件的 Action 拒绝执行。普通事实读取保持原 RBAC/数据所有者链路，不把每次聊天强制送入 HermiT。详细契约见本体推理集成。

业务本体复用相同模块 MCP 授权链路与原六个工具，Schema 作为低信任 ToolMessage 按需交付，不预先整图注入 System Prompt。Neo4j/Legacy 的存储切换留在 Ontology 模块内；PostgreSQL 管发布/审核/ACL，ERP 管实时业务实例，Agent 不持有图数据库凭据或任意 Cypher。显式图投影、只对连接/超时回退、有界上下文和 metadata-only stage 见 双 Provider 设计与验证。

  • Artifact 使用 tenant/thread/run 作用域的对象键，记录 MIME、大小和内容校验值。
  • 下载必须经管理后端授权后返回短期签名 URL 或代理流，不能暴露永久公共地址。
  • 原始输入、对话、检查点、事件、Prompt 快照和产物分别设置保留策略；生产启用前由产品和合规负责人确定默认期限。
  • 租户删除或数据擦除必须覆盖 Run 元数据、检查点、缓存和对象存储，并保留法律要求的最小审计记录。
  • 备份与恢复必须同时覆盖 Agent 数据库和对象存储引用，避免只恢复一侧形成悬空记录。

Higress ai-cache 模型响应缓存和 response-cache 工具响应缓存只用于减少重复调用， 不是事实源；缓存作用域、失效和验收见Agent 缓存与请求合并。

11. 分析正确性与可追溯性​

  • 数值计算、聚合和筛选由 SQL 或受控代码工具完成，模型负责提出步骤和解释结果，不让模型凭文本猜算关键数字。
  • 每个结论可关联输入文件校验值或数据源、查询/代码版本、执行时间、数据时间范围和是否发生抽样、截断或缺失值处理。
  • 报告明确区分数据事实、模型推断和建议；证据不足时返回限制说明，不能补造数据。
  • 同一 Run 使用固定的数据快照或明确记录数据读取时间。继续追问若切换到新数据，必须让用户可见。
  • 金额、时区、单位、空值和精度规则由工具参数或数据集配置确定，不由 Prompt 临时猜测。
  • Thread 内继续使用消息和摘要；跨 Thread 长期记忆须显式 opt-in，自动保存须单独开启。成功轮次只持久化来源引用；离开 Agent 页面、切换会话或关闭助手后，将新增问答归为一次同步批次（如 10 轮为一条记录），由 Worker 逐轮提交原始用户文本与最终助手回复，不做本地价值筛选；业务问答可保存，使用时重验来源权限；提取、分类与遗忘由 RAGFlow 负责。关闭后停止保存与召回，Memory 不代替实时业务查询。

长期记忆运行边界​

唯一长期记忆引擎为 RAGFlow Native Memory，固定验证版本为 v0.27.2。顶层 agent/src/chein_agent/memory/ 只保留轻量异步 Adapter、可信 tenant/owner 到独立私有 Memory 的映射、开关、提交引用与来源墓碑；PostgreSQL 不再存新记忆正文或向量，LangMem 与独立 ES/pgvector 运行实现已移除。公共 Key 下 user_id 是外部归属字段，所有 API 都由服务端映射 Memory ID，并在读前后重验当前授权和策略版本；默认 PRIVATE，不提供共享或他人正文管理入口。

Backend modules/platform_memory 仅为 BFF、当前授权、Outbox 生命周期与私有 HTTP 调度适配。复用现有视频 Worker 调度线程和 Agent PostgreSQL leader guard；运行时不接收迁移凭据。提交不明不得自动重提，关闭/清空/删除会话先建立版本或来源屏障，后台删除在功能关闭时仍可推进。历史展示、模型与审批恢复继续校验 usage 引用；旧引用或撤权失败时净化衍生历史。LangGraph Checkpointer、短期历史、摘要和中断恢复保留。

默认 Agent Nacos 在未指定 RAGFlow 连接时只复用同 namespace/group 的 Backend runtime 地址、API Key 与超时，禁止导入其他 Backend 字段或迁移凭据。模型短名必须在目录中按类型唯一解析，不能静默选择供应商。

Memory 提取与混合检索使用 RAGFlow 官方默认方案，Chein 不再用 System One 判断保存/提取价值。每轮独立 session 关联本地 delivery，原文无证据信封，允许召回有当前可验证来源的 Raw 与衍生记录；既有明确批准记录兼容。历史 usage 包含具体消息来源，新回复包含助手生成内容的低信任标记。业务来源权限和继承的记忆来源在召回、展示和恢复时重验；无法证明来源时失败关闭。metadata migration 0011_memory_sync_batches 是启用新提交路径的前置门禁；批次只保存引用，FORCE RLS 与外键绑定 tenant/owner/generation，旧 SUBMITTED/UNKNOWN/终态不归批或重放。详见 Native Memory 当前设计；旧价值治理方案仅保留历史说明。

记忆默认关闭，已核实模型输入窗口前不注入；开启 Memory 时观测仍强制 metadata-only。架构与协议限制见 Native Memory 设计，迁移、备份、回滚及本地/生产门禁见交付记录。

12. 可观测性与质量​

聊天上下文占用与累计消耗分开统计：顶层 Agent 在最终模型回调边界生成数值快照，复用 Run 事件与历史初页，经已有 BFF/AG-UI 发送给官方 ContextDisplay standalone 组件。模型上限仅来自当前 QWEN 配置或可信 Profile，未知时不显示虚构百分比；不依赖 Langfuse 启用、不新增 Token 表或外发 Prompt。统计失败不得改变压缩、审批、租约或正常回答。字段、模型/角色隔离、压缩、恢复及实施证据见 上下文 Token 设计。

本地日志使用 request_id、thread_id、run_id 和 tenant_id；启用 Langfuse 后，Agent execution 日志关联真实 OTel trace_id。BFF→Agent→MCP/授权 HTTP 传播已接线；只在受信委托验证后使用 traceparent。观测目标包括：状态耗时、排队耗时、模型/工具调用次数、Token/估算费用、重试、审批等待、错误分类和产物数量。

默认只记录元数据，不记录原始 Prompt、工具结果、数据行、密钥和完整模型响应。在线选取问答仅受显式数据策略控制，Memory 开启时仍强制仅元数据；离线合成评测外发需逐项审核、独立项目和预算。

当前外部观测和启用步骤见 Langfuse P1–P5 实施：默认关闭，Langfuse SDK 仅在顶层 Agent，Backend 使用共享通用 OTLP 适配层，各进程不替换全局 Provider。每次成功 claim 的 lease_epoch 建 execution 根和 Callback，业务阶段采用有限名称和元数据；HMAC 身份引用与默认 metadata-only 白名单保持；显式选择 redacted-content-v1 时仅采选取的有界脱敏问答，采集范围、连接复用和剩余风险见 可读链路设计。Agent 持有启用后的消息/执行映射、版本化反馈及 FORCE RLS，Platform BFF 校验权限，Agent 再验证 tenant/owner/run/thread 后查有限子树。反馈纠正文本不外发，Score 用持久随机 ID 去重，失败保留本地待同步。

全量低基数技术指标独立于 Trace 采样；离线 Dataset/Experiment 与独立 Judge 只处理审核过的合成材料，不发布 Prompt。观测失败不改变核心执行；生产性能、真实评测与新配置环境验收待完成。Langfuse 不是 Run、RunEvent 或 Checkpoint 的事实源。LangSmith 观测接入 保留为未实施设计，不同时注册两套 Callback。

2026-10-21 的代码侧优化保留上述边界：Agent 继承验证后的真实 OTel 父上下文与采样标志，无父链执行通过 Provider ID generator 保留确定性 Trace ID，不用 SDK trace_context 制造父节点。导出记录配置/有效数据策略及正文抑制原因，手工失败阶段写入安全 ERROR 状态；Memory 批次以独立维护根和 HMAC 引用关联，CLI Worker 复用初始化/关停。首个 SSE RUN_STARTED 先于可选观测映射写入发出。代码与本地验证、未验收范围见 审计后优化交付。

缓存命中率、节省的模型调用和缓存失效指标遵循Agent 缓存与请求合并， 缓存指标不得记录原始问题或回答。

测试分四层：

  1. 工具参数、策略、状态转换和预算的确定性单元测试。
  2. 使用假模型和假数据源的图执行、暂停、恢复、取消和幂等集成测试。
  3. 后端到 Agent 的认证、租户隔离、SSE 重连和产物授权测试。
  4. 固定小型评测集，检查答案正确性、来源引用、工具选择、成本和回归；评测用例进入版本控制，不依赖线上用户数据。

不要求模型输出逐字一致，断言结构化结果、事实、约束和允许误差。

13. 部署与故障语义​

首期最少包含 agent-api 和 agent-worker 两个进程，可由同一镜像启动；共享 Agent 代码和数据库，不拆独立工具服务。

  • liveness 只表示进程可响应。
  • readiness 要求数据库、迁移和检查点存储可用；模型供应商或单个连接器故障显示 degraded，并在创建相关 Run 时返回稳定错误。
  • 部署先迁移再滚动更新。正在运行的旧版本 Run 通过记录的 graph/prompt/tool 版本继续或明确失败，不能静默切换语义。
  • 数据迁移采用 expand/contract；回退应用版本不自动 downgrade 数据库。

本地开发可使用单 Worker 和单模型配置。只有指标证明需要时才增加并发队列、优先级、模型路由和跨区域部署。

Agent 工程独立选择框架实际支持的 Python 版本，不因为管理后端当前使用 Python 3.14 就强制保持一致。初始化时锁定并记录 Deep Agents、LangGraph、LangChain 和模型 SDK 的兼容版本。

14. 已知风险与取舍​

  • Deep Agents 当前仍快速演进，因此只允许它影响 agent/ 内部实现；内部 HTTP v1 和持久化业务状态不能使用框架私有类型。
  • 模型输出非确定，关键计算交给工具，并用固定评测集而不是逐字快照控制回归。
  • AgentRun 与 checkpoint 同时存在容易形成双事实源，因此前者只管控制面，后者只管图执行状态。
  • 独立进程增加一次网络调用，但换来依赖隔离、独立扩缩和故障边界；首期仍共用数据库与镜像代码，避免继续拆分。

15. 实施顺序​

Phase 0：契约和单条竖切​

  • 初始化顶层 agent/ 独立工程。
  • 定义内部 v1 DTO、执行令牌和错误码。
  • 只接入一个模型、一个数据入口和一个只读工具。
  • 打通创建 Run、SSE 状态和最终文本结果。

Phase 1：可恢复与可交付​

  • PostgreSQL checkpoint、AgentThread 会话元数据、最小 Run lease、同一 Run ID 幂等、协作式取消、有序 RunEvent、人工审批中断/恢复及受限检查点重跑已落地；当前由 Agent API 单进程执行，进程中断后的自动调度恢复仍待实现。
  • 当前已交付日期、只读 ERP 统计 Facade 和可选的共享知识检索工具；权限边界见 Phase 1 运行控制与只读数据工具及外部集成设计。
  • 产物存储与授权下载、预算、结构化日志、指标和最小评测集仍待实现。

Phase 2：安全扩展​

  • 独立审批明细与有实际写入场景的端到端审批演练。
  • 第二个连接器或沙箱代码执行，以真实用例二选一。
  • 只有复杂任务评测证明收益后才启用子 Agent 和更深的计划能力。

16. 完成定义​

Agent 首个版本只有在以下条件同时满足时才算可交付：

  • 用户能完成“提交数据与问题 -> 查看进度 -> 获得答案和产物 -> 继续追问”的闭环。
  • 后端与 Agent 没有内部代码依赖，内部 v1 契约具有兼容测试。
  • Worker 重启后 Run 可恢复，重复请求不会重复执行已完成副作用。
  • 无权限、跨租户、伪造执行令牌、越权产物下载和只读数据源写入均失败关闭。
  • 取消、超时、预算耗尽、模型故障和工具故障有稳定状态与用户可理解错误。
  • 日志中没有密钥和原始业务数据，Run 可通过 ID 完整追踪。
  • 最终答案中的关键数字可以追溯到实际工具结果，并明确数据范围、截断和推断。
  • 固定评测集和关键 E2E 通过；实际模型冒烟的供应商、模型和费用有记录。
  • 部署、迁移、备份、恢复和数据删除步骤经过一次可重复演练。

17. 实现前必须确认​

以下选择会改变数据契约或安全模型，不能由实现者自行猜测：

  1. 首个数据入口是文件上传还是外部数据库。
  2. 首个模型供应商、允许发送的数据等级和预算上限。
  3. 对话、检查点、上传文件与产物的保留期限。
  4. 是否允许任何外部网络访问或代码执行；若允许，批准人和隔离要求是什么。

其余未决项按本文的首期默认值实施，不为未来可能性提前搭框架。

Knowledge 模块接入（v2 检索）​

Agent 新查询仅通过 Knowledge Facade。AGENT_KNOWLEDGE_URL 原 v1 地址自动规范化为 v2；没有地址或缺少 agent:chat / knowledge:read 时不注册目录与搜索工具，不回退静态 SDK。Knowledge 校验当前成员、RBAC、模块权益、库和文档 ACL、就绪/启用状态与 Agent 绑定；后端拥有 RAGFlow 远端 ID 映射和凭据。

模型可以读取授权目录、形成独立 Query 并明确选择 Chein 库 ID；省略选择时使用 Required 与一个按词项/优先级排序的 Default，无结果时有限扩展。租户 Profile 控制候选数、混合权重、RAGFlow 重排、选择/尝试上限与字符预算。相似度不证明语义充分性：管理端测试保守报告 PARTIAL / INSUFFICIENT；Agent 使用结构化 Evidence Judge 或高置信度 JEV，按预算重写/增选并在回写时重验文档与分块。失败或预算用尽时澄清，不生成未证实的内部事实。

新引用只暴露 Chein 库/文档 ID，下载经过 BFF、Agent 和 Knowledge 当前身份重新授权。每次模型执行前重新授权 checkpoint 中的历史知识来源；拒绝或无法确认时清除旧工具结果和衍生回答并持久化，仅保留最新用户消息。v1 下载与历史 SDK 来源解析继续兼容，静态 SDK 不用于新私有查询。

Profile、Trace 与绑定由 Knowledge 模块所有。Trace 仅作者且具 knowledge:debug 权限可读，并重新检查相关库 ACL；没有持久化 Chunk 正文或凭据。详情提供原生 Ant Design 的绑定、配置与检索测试。当前改动、限制、迁移与本地证据见 Knowledge Retrieval v2，管理步骤见知识管理。

Knowledge 扩展使用 Platform 公开组织目录，支持 USER/ROLE/DEPARTMENT ACL 与部门逻辑所有权；新更改复用现有文档期望状态和 Outbox，不引入额外 Worker/LLM 后端。实现报告见上述交付文档。

图片创作边界​

Suite 新增 Creation 图片模块：元数据、权限、配额及 RustFS 生命周期归 Backend，Qwen Images Provider、优化与生成工具归顶层 Agent。Agent 生成与重新生成工具沿用原生 HITL；管理页经确认框调用相同生成服务。个人图片使用 tenant/owner UoW 与 RLS，清理由既有租户 Schedule 执行；受授权的存储渠道引用检查只返回租户计数，不授权管理员读取他人的私人图片。配置默认关闭，设计与验证状态见图片生成与创作中心。

会话目录由 Agent 按 owner 与更新时间进行 SQL keyset 查询；历史展示按固定 checkpoint 的完整轮次分页，仍复用 checkpoint 状态，不建立另一套消息事实源。接口兼容、作用域和读取开销见 会话与消息游标加载。

视频创作边界​

视频 Job、资源、额度、私有存储及完成事件由 Suite Creation 持有；顶层 Agent 只持有 Token Plan Provider、prompt 补充和创建任务工具。独立 Creation 视频 Worker 经签名 HTTP 调用 Agent 的单次 submit/status/result 操作，复用 PostgreSQL leader runner，不在 Web lifespan 启动。视频 job 是后台状态事实源，与 Run/checkpoint/SSE 生命周期独立。数据库为任务队列，Redis 丢失不会丢任务；恢复已有 task_id 时禁止重新 submit。现状调查、约束、配置与验收范围见 AI 视频生成。

Token 计量与额度边界​

Token 账本、版本价格、计数器、策略执行及聚合/告警 Worker 由顶层 agent/usage 持有；Backend 的 modules/platform_token_budget 仅提供可信身份、部门目录、授权 BFF 和 Platform 站内通知适配，不加入 Edition、不导入 Agent 框架、不查询 Agent 表。账本只含数值与引用，使用租户 FORCE RLS；个人读取额外绑定当前 owner，部门采用签名 delegation 的发生时快照。模式默认 off；observe 只记账提醒，enforce 下所有适用 hard 策略共同约束新 Run 及后续模型调用。计数器故障时 hard 新准入失败关闭，运行中故障放行并告警；费用缺价及并发在途消耗不构成精确费用上限。Higress 仅负责 L1 宽松熔断，配置示例和 Agent 接线已实现，目标插件摘要、顺序、抓包和取消对账仍待实测。RAGFlow 当前接口缺少内部 Usage，hard 策略下暂停其付费提取/搜索，不能伪造纳管完成。实现与外部门禁见 Token 计费交付。

Semantica 私有旁路实验​

新增显式选择的独立计算例外，依赖只在 services/chein-semantica，Agent 仅 HTTP，Platform 仅专用授权签发。PRIVATE 工作区不读取既有本体，Provider绑定沿用RunEvent；不提供OWL DL门禁。状态为本地验证、未部署；见设计（未发布资料）及ADR-0018（未发布资料）（Proposed）。
