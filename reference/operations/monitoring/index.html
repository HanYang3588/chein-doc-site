监控与告警

运行日志（本地实现，生产接入待验证）​

记录与数据边界​

Backend、Outbox/Schedule Worker 和独立 Agent 共用 observability/ 的 Python logging 适配层。适配层将记录转为 ECS 9.5.0，脱敏后放入有界内存队列，再由后台线程批量写入 Elasticsearch。业务代码继续调用 logging.getLogger(__name__).info/error/exception；结构化事件可传入 extra={"event.action": "order.completed", "custom": {"order_id": id}}。

日志不得包含 Prompt、模型输出、工具参数、请求或响应体、密钥及个人数据。浏览器只能通过已鉴权的 /api/v1/logs/runtime/browser 上传有限错误元数据；服务端覆盖时间、租户、用户、服务和环境字段。

HTTP 记录包含方法、路径、路由模板、状态码、耗时、Request ID、已验证的租户/用户，以及 custom.request / custom.response 摘要。只保留请求 content-type、content-length、accept 和响应 content-type、content-length；查询参数只保留名字，不记录值。Backend 的受控错误响应另记录错误码。采集不读取或重放请求、响应体，文件上传和 SSE 保持流式行为；HTTP 耗时表示响应头返回前的时间，Agent 执行耗时通过运行/调用事件排查。

未处理异常和转换为 HTTP 5xx 的异常记录类型、脱敏消息与堆栈；Agent 的模型/工具回调、流式执行失败也记录异常。序列化不采集局部变量，去除 SQLAlchemy 附带的 SQL/绑定参数、Pydantic 的输入详情和带 body 的上游 SDK HTTP 异常正文；堆栈最多 8 KiB，超长保留头尾并标记截断。单纯返回上游 5xx 不会产生本地异常堆栈，此时 BFF 记录上游服务、方法、路径和状态。业务代码仍须避免把敏感内容写入自由文本异常消息，通用脱敏规则无法识别所有业务隐私。

默认排障粒度为“请求/响应摘要 + 错误堆栈 + 关联 ID”，无需常态采集全量正文。若某个问题必须查看正文，应另做受控、限时、特定接口的诊断，并明确字段白名单、权限和留存；不能直接打开全站正文日志。

统一字段包括 @timestamp、ecs.version、message、log.*、service.*、event.*、trace.id、span.id、transaction.id、http.*、url.path、user.id、error.* 与受控 labels.*。复杂附加值进入 custom（ES flattened，单条最多 8 KiB）。没有可信租户的日志不会出现在普通租户查询中。

Agent 回调只记录模型和工具调用的元数据、耗时；知识检索 Tool 使用 rag.retrieval.* 事件。Backend 已挂载可选 /mcp，Agent 可通过 MCP 调用获准的只读模块工具；MCP 的独立端到端 tracing/span 接入尚未在此验证。trace.id 只消费已有可信上下文；将来接入 SkyWalking 时提供该上下文即可。未来 Incident/AI 工具应调用 LogQueryService 的固定查询方法，不接收任意 ES DSL。

Elasticsearch 准备与权限​

Data Stream 分别命名为 logs-chein.backend-<environment>、logs-chein.agent-<environment> 和 logs-chein.web-<environment>。部署前在目标 Elasticsearch 8/9 集群运行 deploy/observability/provision.py，创建受控 Index Template 和 ILM policy。脚本读取 LOG_ES_URL、LOG_ES_USERNAME、LOG_ES_PASSWORD，可选读取 LOG_RETENTION_DAYS（暂定默认 14 天）。实际保留期从 rollover 后计算；生产值需按日志量、磁盘容量和合规要求确定。

Chein 写入账号只授予这些 Data Stream 的写权限，查询账号只授予读权限；不要复用 RAGFlow 账号，生产连接使用 HTTPS。临时 Elasticsearch 8.11.4 容器已验证 provision、写入及租户过滤查询；目标集群的版本、容量和凭据尚未确定，生产 provision 与读写未验证。

故障行为与查询授权​

Backend 和 Agent 的 Nacos Runtime 示例包含 LOG_ES_ENABLED、LOG_ES_URL、写入账号、版本、Git SHA/分支、部署/容器 ID 和队列参数。Backend 另外使用 LOG_ES_READ_USERNAME、LOG_ES_READ_PASSWORD 查询。ES 未启用认证时，用户名和密码可同时留空；查询与 provision 脚本不发送认证头。查询与 provision 的用户名、密码只填写一项时拒绝连接，不会回退使用其他账号。ES 写入默认关闭。

运行日志页面会持续展示查询失败原因，区分未启用、查询配置不完整与 Elasticsearch 查询失败。关闭采集时，浏览器日志上报仍返回 204，但不会写入 ES。WARN 筛选同时匹配 Python 日志的 warning 和浏览器日志的 warn，兼容已有日志。

页面提供“全部系统 / 管理后端 / AI Agent / Web 前端”分类，复用 service.name 筛选。详情按请求/响应、错误/堆栈、同请求日志和完整 JSON 展示。同请求查询匹配服务端 labels.request_id 或前端已上报的 custom.api_request_id，跨系统读取此记录前后 15 分钟，最多展示 50 条，始终沿用当前租户授权范围。浏览器报告的关联 ID 是排障线索，不是可信身份；页面单独标明来源。Backend 与 Agent 使用已有委托上下文传递 Request ID。Worker 日志目前归入管理后端，未独立划分进程分类。

本次摘要字段使用已有 custom 映射和查询接口，无数据库迁移、OpenAPI 变更或新增 Nacos 配置。部署后重启 Backend 和 Agent，并更新 Web 前端；历史缺失字段无法补回。ES 仍须具备现有 Index Template（尤其 custom 的 flattened 映射），部署准备见上节。

日志写入、查询和 provision 脚本直接连接配置的 ES 地址，不继承系统或环境代理。ES 必须能从运行进程所在机器或容器直接访问。

启用后，ES 故障不会阻塞业务：后台线程短暂重试，队列满则丢弃，chein_log_dropped 记录丢弃量；查询 API 返回 503。进程崩溃也可能丢失内存队列中的记录。重要审计仍由 PostgreSQL 的登录/操作日志承担。

/system/logs/runtime 需要 system:runtime-log:list 权限和当前租户的 all 数据范围。全局超级用户可显式切换跨租户查询；默认系统管理员不会自动获得此权限。

排障与后续能力​

按顺序检查开关、模板和 ILM、写入账号权限、ES _bulk 错误、进程日志、dropped 计数，再检查页面查询账号和 RBAC。前端构建已有 commit hash；将同一发布版本填入 LOG_WEB_VERSION，将来 Source Map 才能按版本匹配。Template 已预留 error.fingerprint；未来 Incident 可按服务、错误类型、规范化消息和栈顶帧聚合，但当前尚未计算。当前没有 Source Map Server、SkyWalking 或 AI Incident。

健康检查​

  • GET /api/v1/utils/health-check：存活探针，仅说明进程可以响应 HTTP 请求。
  • GET /api/v1/utils/health-status：就绪状态，返回 PostgreSQL 和 Redis 的可用性。数据库不可用时不得把实例放入业务流量；Redis 不可用时服务会降级为不使用缓存。

Prometheus 指标​

GET /metrics 输出 Prometheus 文本格式指标，包括：

  • fast_vben_http_requests_total：按请求方法、路由模板和状态码统计的请求总数。
  • fast_vben_http_request_duration_seconds：按请求方法和路由模板统计的请求耗时直方图。
  • fast_vben_http_requests_in_progress：当前处理中的请求数。
  • Prometheus 默认进程与 Python 运行时指标。

生产环境必须将 /metrics 限制在监控网络内。可同时设置 METRICS_AUTH_TOKEN，Prometheus 请求需携带 Authorization: Bearer <token>。不要把 Token 写入仓库或公开的抓取配置。

示例抓取配置：

scrape_configs:
  - job_name: fast-vben-admin
    metrics_path: /metrics
    static_configs:
      - targets: ['api.internal.example:8000']
    authorization:
      type: Bearer
      credentials: ${FAST_VBEN_METRICS_TOKEN}

推荐告警规则​

groups:
  - name: fast-vben-admin
    rules:
      - alert: FastVbenApiErrorRateHigh
        expr: |
          sum(rate(fast_vben_http_requests_total{status_code=~"5.."}[5m]))
          / clamp_min(sum(rate(fast_vben_http_requests_total[5m])), 1) > 0.02
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: API 5xx error rate is above 2%
      - alert: FastVbenApiLatencyHigh
        expr: |
          histogram_quantile(0.95, sum(rate(fast_vben_http_request_duration_seconds_bucket[5m])) by (le)) > 1
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: API p95 latency is above 1 second
      - alert: FastVbenReadinessDown
        expr: probe_success{job="fast-vben-readiness"} == 0
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: API readiness endpoint cannot be reached

将告警接入现有的 Alertmanager、企业微信、钉钉或邮件渠道；告警通知中不要包含访问令牌、密码、MFA 密钥或完整用户请求参数。
