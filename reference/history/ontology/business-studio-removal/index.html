业务本体工作室退役

本文记录 2026-10-28 的退役范围。2026-10-30 又移除了 Neo4j 独立工作室，当前入口及保留边界见 Neo4j 页面退役，下文当时的“保留”清单不代表当前页面仍可用。

范围为已确认的 Legacy 管理页面及独占入口；不是移除整个 Ontology 模块，也不是删除 Legacy Provider 或历史本体数据。此前设计、交付和审计文档中的旧工作室描述保留作历史记录，当前入口以本说明及模块声明为准。

已删除内容​

分类路径与范围
前端页面和测试frontend/apps/web-pro/src/modules/ontology/pages/Studio.tsx、SchemaEditor.tsx、InstanceExplorer.tsx、ModelImport.tsx、Studio.test.tsx
前端注册frontend/apps/web-pro/src/runtime/page-registry.ts 移除 modules/ontology/studio；对应测试断言该入口不存在且 Neo4j 仍按 Edition 注册
国际化modules/ontology/locales/{zh-CN,en-US}.ts 删除旧页面独占的 114 个双语 key，保留共用及全部 Neo4j/Reasoner 文案
后端菜单backend/app/modules/ontology/module.py 仅删除 /ontology 的 NavigationSpec；Neo4j 仍为本模块第一个导航项，排序规则不变
后端 APIbackend/app/modules/ontology/routes.py 删除旧页面独占的 GET /api/v1/ontology/templates/procurement；调用方已随页面删除。旧客户端收到 404，不提供兼容窗口；Neo4j 使用的 /templates/catalog 与底层模板函数保留
生成客户端通过 pnpm generate:api -- --edition suite 更新，移除旧模板方法，更新 Manifest 的契约摘要；不手改生成结果

未发现能安全认定为该页面专属的运行时依赖、环境变量、Docker 服务或 CI job，因此没有删除依赖或配置。

保留边界​

  • Neo4j 页面、样式和测试：Neo4jStudio.tsx、Neo4jStudio.module.css、Neo4jStudio.test.tsx；规则和任务面板 ReasoningPanel.tsx、ReasoningPanel.test.tsx、ReasoningTask.tsx 保留。
  • /ontology-neo4j、menu.ontologyNeo4j、modules/ontology/neo4j 及其权限和导航顺序保留。
  • PostgreSQL ontology.network/version/audit/candidate、ORM、Tenant UoW、RLS、发布与审核底座保留。两个历史迁移文件未修改。
  • 共用网络、版本、模板目录、发布、查询和 MCP 接口保留；ERP ontology.data、Knowledge ontology.evidence 和所有 ontology:* 权限保留。
  • Provider、Neo4j/n10s、RDF/SHACL、HermiT 服务及适配器、现有配置和依赖保留；不改变 Edition 的模块集合。
  • docs/ontology/neo4j-*.md、semantic-workspaces-delivery.md、reasoner/ 及相应实现和测试保留。

存疑而保留​

内容原因及后续处理
Neo4j 页面的旧工作室跳转和提示Neo4jStudio.tsx 对非 Neo4j 网络仍跳转 /ontology；ontology.neo4j.libraryHint 仍提及旧工作室。按不修改 Neo4j 实现的要求保留。后续需单独授权修订为不可用提示；目前旧链接不能再打开旧工作室
Legacy Provider 与 workspace=legacy API 能力Provider 是现有 Auto/Neo4j 故障策略的一部分；网络 API 和 DTO 是共用契约。移除页面不等于禁用 Legacy API，不能宣称旧功能的全部后端都已删除
文档候选与 AI 建模辅助/assist、/candidates、application/assistance.py、agent/src/chein_agent/ontology.py、Candidate DTO/表及测试保留；建议器已支持 semantic/OWL，Neo4j 文档记有候选辅助，不能仅按当前 UI 调用方判为专属
BKN/JSON 互操作application/interchange.py、/imports/preview、版本 /export 及相关 DTO/测试保留；OWL 规则测试依赖 JSON merge 保留正式规则片段
旧网络与版本记录已发布正文、审计、Agent 历史来源及潜在图投影关联不能仅按 workspace 删除。应先做独立数据引用审计、备份与清退方案
原设计和交付文档design.md、delivery.md、research.md、openbkn-alignment.md、bkn-interchange.md 还记载共用 DSL、ERP 映射、安全和历史证据，按存疑保留规则不整篇删除

关键词检索仍会命中以上保留内容、历史迁移、清理脚本、回归测试，以及其他模块的“当前租户”“尚未发布”等通用文案；这些不代表旧页面仍被注册。

手工数据库清理​

脚本：scripts/cleanup-business-ontology-menu.sql。这是独立的 psql 清理脚本，不加入自动 Alembic 链，不在启动、构建或请求中执行。

执行前提：新版本已部署并停止旧版本的导航播种；备份 public.menu、public.rolemenu、public.tenantplanmenu；由有权限维护这些表的人员核对目标数据库及旧菜单记录。未知自定义 component 不匹配，不按共享 permission_code 删除。

脚本只匹配 route_path='/ontology' 且 component 是 modules/ontology/studio 或已知 #/、.vue 兼容形式的菜单。事务内锁定菜单和关联表，删除该菜单对应的角色/套餐关联及菜单本身。若发现子菜单则中止并回滚，先由维护者确认归属和迁移位置。重复执行无副作用；保留 Neo4j 菜单及排序、全部共用权限和所有本体业务记录。

使用已有受控维护连接，通过 psql -X --set=ON_ERROR_STOP=1 --file scripts/cleanup-business-ontology-menu.sql 执行；连接信息由维护者在项目外配置，不写入脚本。删除记录不能从代码推导完整恢复，数据库回滚需依赖备份；代码可按分步提交回滚。

本次只在全新、仅开放私有 Unix socket 的临时 PostgreSQL 集群及合成表中执行脚本测试，未连接真实数据库、ERP、Neo4j、Nacos 或生产环境。真实环境清理尚未执行，因此已有数据库中的旧菜单可能仍显示；未知组件将无法解析到已删除页面。
