Agent 交互前端设计

状态：React assistant-ui 已接入 FastAPI BFF/AG-UI；以下逐项区分实际接线、独立组件与目标态

适用范围：web-pro 应用

管理前端框架、生成客户端和交付入口见前端架构；Agent 运行时事实源仍为Agent 架构。框架重构不改变后端授权与运行时边界。

1. 当前 UI 选型与入口​

frontend/apps/web-pro/src/pages/agent/index.tsx 使用 AssistantRuntimeProvider 和 useExternalStoreRuntime，将本地会话/消息状态接入 assistant-ui。界面复用 src/components/assistant-ui 的 Thread、ThreadListSidebar、消息、输入、推理与工具部件， 以及 src/components/ui 的侧栏、Base UI 交互原语、Tailwind 样式和 Lucide 图标。

pages/Workspace.tsx 完成菜单与权限检查后，在管理布局的内容区域渲染 Agent；会话侧栏保留新建、搜索、会话列表和折叠功能，已移除品牌标题和返回管理系统按钮。会话区使用 assistant-ui，管理页面继续使用 ProLayout/Ant Design/ProComponents。

单层会话项目​

聊天侧栏的项目可独立展开/收起，对应会话缩进显示在目录下，可同时展开多个项目。项目内不展示“今天/昨天/更早”日期分组；未归类会话直接与项目平级展示，保留日期分组，不再创建“未分组”目录。支持新建、重命名和删除项目。 会话的原生更多菜单提供“移动到项目”，可移回未分组；在指定项目中新建的会话在首条消息被服务端接受时归入该项目，空白草稿不落库。 展开/收起项目不取消当前回答，也不切换正在阅读的对话；展开项目后，新建会话仍归入该项目。项目不共享提示词、知识库或聊天上下文。 每个展开目录独立调用现有项目筛选分页接口，复用游标分页器与原生会话行，失败可重试，收起时取消请求并拒绝迟到响应。 项目首屏请求期间仅在项目图标位置显示小转圈，返回后展示列表或空状态；分页和重试继续保留已有行。根列表直接复用页面的未分组会话分页，不再额外查询全部会话；搜索仍查询全部项目。 搜索覆盖全部项目和未分组会话，清空搜索后恢复原有展开状态；完整页面与浮动助手共用同一列表。 项目和会话目录 BFF 只签发 agent:chat 委托，继续经过当前入口权限和 Agent tenant/owner 校验；执行、历史授权与审批请求仍计算各自所需的完整权限。目录读取不再逐项查询工具、Memory 等执行权限，也不读取对应模块权益缓存。 2026-10-20 本地只读测量：同一有效成员身份各重复 5 次，委托生成的中位耗时在超级用户路径由约 655ms 降至 0.22ms；模拟普通 RBAC 路径由约 2120ms 降至 3.24ms，每次额外权限 SQL 由 17 条降至 0 条。这仅衡量委托生成，未涵盖 HTTP、入口认证或 Agent SQL，不能作为生产接口时延。 同日本地验证通过：pnpm frontend:typecheck、pnpm frontend:pro:build、前端全量 273 项测试、Backend Ruff 及目录 BFF/委托 20 项测试。已登录浏览器确认项目行转圈、会话返回后展示且控制台无错误；截图已按开发归档入口上传 RustFS。无接口结构或数据库迁移；生产时延、生产 SQL 执行计划和远端 CI 未验证。

根列表中的项目与独立会话可以混合拖动排序，项目内会话可单独排序；按住 Alt 使用上下方向键也可调整顺序。 会话拖到项目行中间归入项目，拖到项目边缘用于排序；拖到根列表空白区域可移出项目。插入线/项目高亮区分排序与归类。 归类复用现有授权 API，失败保留原归属；排序只作为按当前租户/用户隔离的浏览器偏好保存，不改变数据库分页顺序，也不跨设备同步。 分页只排序已加载会话，不为拖动拉取全部历史；日期标题始终按会话自身的活动时间显示，手工跨区排序时可出现多个同名日期区段。 新建/重命名项目时，名称输入框左侧可选择 8 个 Lucide 图标；图标随项目存储在 Agent，旧项目默认文件夹，旧调用省略 icon 时保留原图标。

归档会话管理​

菜单采用「AI 工作台 → 数据分析助手 / 已归档会话」，保留聊天地址 /agent， 新增 /agent/archives。统一目录及提示词、知识库、创作分组见前端导航。归档是当前用户的会话生命周期操作，放在工作台目录下； 不属于系统设置或租户级日志。原会话侧栏底部的归档折叠列表已移除， 普通会话行的“归档”操作保留，聊天运行时不再预取归档列表。

页面位于 src/modules/platform/agent/Archives.tsx，通过受控 pageMap 注册， Base、Items、Suite 均可用，继续要求 agent:chat。同源 BFF 与 Agent 逐次验证租户和拥有者，未新增权限码、接口、依赖或数据库结构。 导航播种保留 /agent 菜单 ID，并为已有聊天角色及套餐补齐目录与归档页关联； 部署后通过现有 cd backend && uv run python -m app.initial_data 初始化流程更新菜单， 重新登录或刷新应用以加载新菜单。

归档页使用 Ant Design 原生 Table（紧凑行、标题、更新时间、固定操作列）和 DatePicker.RangePicker，页面不显示内容区标题、说明或独立刷新按钮。 标题搜索延迟 250ms 后提交；更新时间按浏览器本地日期筛选，包含结束日期当天。 浏览器将起始日零点与结束日次日零点转换为带时区时间，由 BFF 转发 updated_from（含）/updated_before（不含），Agent 在数据库查询中筛选。 排序固定为 (updated_at DESC, id DESC)，表格显示 updatedAt，不使用归档时间替代。 时间范围变化会清空旧记录与游标，后续页沿用相同搜索/时间条件；清空日期恢复全部时间范围。

保留待回答标记、取消归档、永久删除确认及失败重试，恢复/删除后同步当前 Workspace 保留的聊天运行时；已归档深链仍为只读。复用现有游标“加载更多”，计数明确表示已加载数量； 没有全量计数，不伪造表格总页数。小屏使用表格内部横向滚动；项目筛选与“全部删除”仍不展示。 时间参数为兼容性可选参数，无结构迁移；启用筛选须同时更新 Agent、BFF 与前端。

3. BFF 契约​

路径统一位于同源 /api/v1/agent-ui：

方法路径用途
GET / POST/threads查询、创建会话
GET/threads/{thread_id}/messages读取持久化历史
PATCH / DELETE/threads/{thread_id}归档、恢复或删除
POST/chat{ threadId, message, deepThinking? }，响应为 SSE
GET/threads/{thread_id}/pending-approval读取当前 checkpoint 的待确认动作
POST/runs/{run_id}/decide、/runs/{run_id}/resume提交决定并恢复同一 Run
GET/threads/{thread_id}/checkpoints、/threads/{thread_id}/resumable-run查询可重跑检查点与可恢复 Run
POST/threads/{thread_id}/checkpoints/{checkpoint_id}/replay、/threads/{thread_id}/messages/{message_id}/edit受限重跑与消息编辑
POST/runs/{run_id}/cancel?thread_id=...协作式取消
POST/runs/{run_id}/pause在安全检查点暂停
POST/memory/threads/{thread_id}/leave以当前拥有者身份通知离开会话，可携带最后已知 run_id；需 agent:memory:create

/chat 的 run_id 由 BFF 生成。当前 BFF 不公开 Run 详情、事件 cursor 补发或通用产物 下载接口。前端普通请求复用认证路径；流式请求由 pages/agent/api.ts 使用同源 fetch， pages/agent/sse.ts 解析分片并处理结束/错误。

开启“离开会话时自动保存”后，成功回复只留下持久待保存引用；切换或新建会话、离开聊天页、关闭浮窗时异步通知后台，Worker 才提交此前尚未处理的合规轮次。通知使用 keepalive，不等待记忆提交/提取，不阻塞历史加载；只发送会话和 Run 引用，不从浏览器上传对话正文。重复离开由服务端幂等处理。任务页以“等待离开会话”区分尚未放行的 PENDING 任务；强制关闭浏览器或断网可能未送达通知，此时再次离开该会话可触发。已取消或未完成回复不保存，删除会话仍走撤销屏障。

4. 消息与运行状态​

当前消息是 assistant-ui 的 ThreadMessageLike 扩展（AgentMessage），不是旧 Vue ChatMessage 模型。events.ts 将 SSE 投影为 text、reasoning、tool、citation、image 等 消息部件/事件；index.tsx 负责应用到当前选中会话。

  • 线程列表由 BFF 提供；新会话首条消息发送时创建，支持历史加载、切换、归档/恢复与删除。
  • TEXT_MESSAGE_CONTENT 更新文本；REASONING_MESSAGE_CONTENT 可投影为 reasoning part。
  • TOOL_CALL_* 更新工具名、参数、结果与计时，由现有 assistant-ui 工具部件渲染；参数流结束与执行完成分开处理。工具分组与单次调用在运行中仅使用闪光文字，不显示转圈图标；完成、失败、取消和待审批仍保留状态图标。
  • 等待响应使用灰色闪光“正在思考”；工具等待按实际调用显示知识库检索、目录查询、ERP 统计、日期确认或问题准备等目的，多工具或未知工具使用通用任务提示。结果返回且尚未开始下一段正文时，提示正在核对结果并整理回答；失败显示失败提示，不根据等待时长或空结果声称找到依据。入口决策沿用自己的闪光状态记录。已移除等待与 Markdown 流式输出的圆点。正文末尾最多 48 个字素按距离逐渐变淡，随着后续输出恢复正常颜色；末尾文字在呼吸的亮相位恢复到所在正文的正常颜色，避免固定低透明度使动态效果难以辨认。最后一个正文块的底部视觉行以 4 秒周期平滑呼吸，周期由稳定的 Markdown 容器提供，追加文字和换行不重新开始。段落、列表项、标题和表格单元格共用该效果，代码保留原生渲染。完成、取消或断流会还原正文颜色，减少动画模式关闭闪光、呼吸及渐淡效果。完整页面与浮窗共用此渲染，不改变 SSE、引用核对或历史数据。
  • Agent 装配在已选择的 Nacos 系统提示词或内置兜底提示词后统一附加公开过程说明规则：耗时查询前简短说明目标和用途，同批工具合并说明；真实结果返回后，需要继续查询才说明已确认事实、缺口与下一步，能够回答则直接给结论。说明随现有文本流和工具调用输出，保留原生消息顺序与历史；不新增模型调用、SSE 协议、执行循环或提示词配置，也不自动发布或改写 Nacos 正文。规则是对模型的行为要求，不是每次必然遵循的执行保证；页面状态提示覆盖模型省略说明时的等待阶段，不展示内部推理或原始日志。
  • CUSTOM(name="agent.decision") 经白名单校验后更新命名 data part，由官方 makeAssistantDataUI 展示可展开的入口决策记录，支持 shadow / active。记录包含运行、完成、回退或中断状态，以及模型名称、完成耗时、处理建议和固定原因；shadow 明确标注建议未参与路由。异常断流和取消会结束转圈。它只展示当前流状态，刷新历史不补回决策记录；不展示原始日志、提示词、供应商响应或推理正文，也不把本地规则、上下文跳过或知识检索内部判断伪装为入口模型调用。配置与运行时边界见 决策模型接入。
  • APPROVAL_REQUESTED 将 Deep Agents 的中断映射为现有 ToolFallback.Approval，在 assistant-ui ViewportFooter 的输入框上方显示独立圆角卡片，回答正文中不重复显示待确认控件。确认选项纵向排列并编号，执行参数可展开查看；允许执行仍需 agent:approval:decide，选项不得超出该动作的 allowedDecisions。ask_user 使用同一卡片的文字回答模式，Enter 发送、Shift+Enter 换行，不伪造跳过必填问题的回答。多项请求逐项显示并标注进度，全部回答后统一提交到 BFF，由 LangGraph Command(resume=...) 恢复；原流结束前禁用提交，提交失败重新读取待确认动作。已提交记录保留在同一 assistant 消息内，完整页与浮窗共用此交互。刷新页面从 Agent checkpoint 重新读取待确认动作，不新增 API、数据库或第二套审批状态。
  • 同一用户问题中的工具调用、待回答卡和继续执行共用一条 assistant 消息；历史待确认卡并入当前回答，提交失败替换相同工具 ID 的卡片，避免重复部件。运行中或等待用户输入时不渲染消息操作栏，结束后仅在回答末尾展示。新用户消息、编辑重跑和重新生成保留各自的回答边界。
  • 会话列表的可选 pendingInput 字段由 Agent 按当前租户与用户的 waiting_input Run 查询投影，显示“待回答”标记；不逐会话请求 checkpoint，不新增持久化状态或轮询。实时提问、历史待确认动作和当前批次回答同步标记，未答完时保留，提交失败重新读取待确认动作。完整页与浮窗共用原生列表项和 custom 元数据；普通工具或敏感操作审批不作为待回答问题。
  • 审批继续、断线恢复与消息编辑重跑会按页面 URL 保留的业务场景重新读取当前 Nacos 系统提示词；个人提示词仍作为用户消息的一部分，修改后需发送新消息或编辑原消息才能生效。Nacos 内容变更后的重跑可能生成不同回答。
  • 对话界面不提供手动“暂停到检查点”入口，保留原生停止和消息编辑；已有可恢复 Run 仍可继续执行，并重新读取 Nacos 系统提示词。后端暂停/恢复 API 保持兼容，暂停仅在当前模型或工具节点完成并持久化后生效，不撤销正在执行的工具。运行中普通发送（按钮或 Enter）进入 assistant-ui 原生队列，当前回答结束后逐条按 FIFO 发送；队列显示在输入框上方，可移除或点击“引导”。引导会协作取消当前 Run，等待其结束后优先发送该提示，保留上下文和其他排队项；取消失败显示错误并等待原运行结束，不并发启动替代运行。原生 Ctrl/Cmd+Shift+Enter 仍可直接引导。等待补充输入或审批时挂起队列，继续执行结束后再处理。手动停止保留待发项并暂停自动发送，下次显式发送重新启动队列；已发送消息编辑、重生成、切换会话或身份重置会清空队列，URL 导航也使用同一切换入口。待发消息只保存在当前页面内存，刷新后不恢复，不新增后端 MQ、API 或数据库迁移。
  • 待发队列只显示消息行，不显示等待说明。拖动左侧手柄或在手柄上使用上下方向键可调整实际发送顺序；编辑按钮将该条消息移出队列并回填输入框，重新发送后加入队尾，不取消当前回答或清空其他待发项。输入框已有草稿时暂时禁用队列编辑，防止覆盖；当前未启用附件队列编辑，包含非文本内容的待发项禁用编辑。完整页与浮窗共用此交互。
  • 已发送的用户消息使用 assistant-ui 原生编辑框；运行中提交编辑会先清空并挂起待发队列，协作取消当前 Run 并等待其结束，再由 Agent 自动定位该消息对应的模型前检查点创建新分支。先前会话上下文保留，该消息之后的回答由新分支替换；首条消息尚未收到运行 ID 时打开的编辑框会在提交时解析持久化消息 ID。取消失败时不启动编辑 Run，切换会话后不提交迟到编辑。编辑或新消息会结束同线程尚未继续的暂停 Run。没有匹配检查点的消息无法编辑。
  • 对话页不提供检查点选择或任意检查点重跑入口，也不请求检查点列表；检查点由运行时内部管理。历史检查点查询/重跑 HTTP 接口保留兼容，前端只通过消息编辑接口重跑该消息后的模型与后续只读工具。待审批或已批准但未完成的 Run 会阻止同线程新 Run，后者可通过“继续执行”恢复。
  • Run 完成、暂停、错误、取消与非正常断流分别处理；会话切换使用上下文版本检查，避免迟到事件 覆盖另一线程，取消请求避免重复发送。
  • 历史来自 Agent checkpoint；浏览器状态不是持久化事实源。断线后的完整事件重放仍未提供。
  • 当前工具集均为只读，因此尚无真实业务写入审批样例；新增写工具还需业务权限、幂等键和效果审计，不能仅依赖确认卡。

工具展示继续使用当前安装的 @assistant-ui/react 0.15.21 和已有注册表组件，在原组件中调整运行指示，没有升级依赖或新增组件。带样式的 Thread、ToolFallback、ToolGroup 和 Reasoning 是项目已有的官方注册表入口，不是 npm 包的直接导出。实际接入如下：

官方另有 Run Activity，支持折叠公开过程与工具，并接收整轮状态和时长标签。它是通过 shadcn 安装源码的 registry 组件，不是当前 @assistant-ui/react 的直接导出，仓库也没有该组件。按本次禁止复制或新增工具展示组件源码的约束，未安装它。其摘要与时长需要应用提供真实运行边界、正文分类和持久化时间，并非仅更换组件即可自动生成。

事件适配保留参数片段顺序，并由官方 Runtime 解析参数。TOOL_CALL_END 只表示参数流结束；收到结果后才结束执行状态。Agent 将真实 ToolMessage.status 放入 AG-UI 的 metadata.chein.isError，现有渲染入口将失败映射为官方 incomplete/error 状态。开始和结果事件提供 epoch 毫秒时间；timing.startedAt/completedAt 交给官方耗时 Hook。该时长包含参数生成到结果返回的时间，不是整轮回答或纯工具执行耗时。运行中每秒更新并按整数秒显示；完成后小于 10 秒保留一位小数并四舍五入。ask_user 不显示耗时，避免把用户等待时间当作执行耗时；原始时间戳仍保留在事件及历史部件中。旧调用没有计时数据时不补造耗时，取消且没有结束时间的调用也不显示完成时长。

历史读取从 checkpoint 恢复有序 text/tool-call 部件，按租户、用户和线程读取既有 Run 事件中的状态与时间。旧 content 字段保留兼容；没有建立第二套工具数据存储，也不改变数据库 Schema。正文、工具结果和最终回答按实际消息顺序显示，刷新与切换会话继续使用同一 Runtime。内部语义路由和 Judge 调用使用 nostream 标签，工具节点的内部模型片段不进入回答流；工具调用仍作为工具部件展示，不转成 reasoning。

完整页与浮窗在回答结束后的操作栏内显示本轮开始时间；时间与操作按钮默认隐藏，悬停回答区域时一起显示，包括最后一条回答。采用浏览器本地时区的 24 小时 HH:mm，悬停时间可查看完整日期。实时消息保留发起时间，历史接口新增可选 createdAt，复用该用户消息对应的 agent_runs.created_at；同一回答的工具调用、补充输入和恢复共用原时间。无法关联运行记录或时间无效时不显示，不用页面加载时间补造。BFF 透传该兼容字段，管理后端 OpenAPI 没有新增 Schema，数据库无需迁移。

RAGFlow 引用通过 agent.citations 传递经过检索结果核对的文档与 chunk ID；现有 Markdown 渲染器显示数字引用及文档链接。服务端仍保留旧客户端使用的文档链接正文，没有新增 Sources 组件或引用样式。

RAGFlow 文档引用Agent 仅将回答中标记了真实检索 chunk ID 的文档追加为 Markdown 链接；现有 MarkdownTextPrimitive 渲染链接，点击经同源 BFF 鉴权下载未配置 RAGFlow 时无引用；未实现租户私有文档 ACL、索引版本固定或通用产物存储
其他引用/图片事件events.ts 支持投影；页面经 sameOriginArtifactUrl 过滤后追加 Markdown不代表已实现通用产物存储或专用下载服务
Markdown 安全辅助security.ts 中有 DOMPurify sanitizeMarkdown，并有单元测试该辅助函数目前仅被测试调用，不能声称线上消息链路已统一经它消毒
Markdown 主渲染当前 MarkdownTextPrimitive + GFM 未配置 raw-HTML 执行插件完整 URL/内容安全仍需渲染链路测试，不能用独立辅助函数测试替代

RAGFlow 文档链接只使用现有 assistant-ui Markdown 渲染器和链接样式，没有新增引用组件或样式。模型需输出 [chunk:<chunk_id>]；服务端只认可检索工具返回的 ID，完整标记输出后即通过 agent.citations 发送已引用文档的累计快照，不等待整条回答结束；只有来源或已引用片段发生变化才发送事件。文档按正文首次引用顺序编号，checkpoint 历史读取采用同一顺序。前端保留原文与来源映射，在展示时将已核对的完整标记转为数字 Markdown 链接，后续再次引用也即时转换；展示层隐藏未核对的完整及流式半截标记。回答结束后追加一份参考文档汇总；服务端保留旧客户端的文档链接正文。未标记的检索结果不会列出。引用点击沿用同源 BFF 鉴权文档下载，不代表已实现片段定位。

提示词管理页面位于 /agent-prompts，使用 Ant Design Pro 原生表格与表单；正文编辑和只读查看均使用 Milkdown Crepe 内置主题，保存格式仍为 Markdown。对话页可选择 general 或当前用户可用的业务场景；BFF 按当前登录用户及场景组合 Nacos 提示词。系统提示词只向租户超级管理员显示；个人提示词只有创建人可查看。详情和每次新对话均重新读取 Nacos 正文，页面保存使用 CAS 检测并发修改。

上述是当前代码边界。补齐深度思考、图表或 Markdown 安全接线时，需要同时验证实际页面、异常输入及后端授权，而不只是增加组件文件。

6. 渲染与安全要求​

  • 模型输出只能作为数据，不执行 JavaScript、原始 HTML widget 或任意图表函数配置。
  • ChartSpecV1 校验限定 bar/line/pie/radar、有限行数/维度、来源 ID、有限数值及安全键； 只有显式注册受控渲染器后才能开放工具图表，未知/无效输入安全降级。
  • sameOriginArtifactUrl 仅接受同源 HTTP(S) 且路径以 /api/v1/agent-ui/ 或 /api/v1/files/ 开头的地址；这只是客户端过滤，不替代服务端资源授权与短期 URL 签发。
  • Markdown 禁止 raw HTML；危险链接、内容消毒和图片加载行为必须在真实消息链路验收。 DOMPurify 辅助函数存在但未接线的事实不得掩盖。
  • 不向浏览器暴露模型密钥、RAGFlow 原始地址、数据库连接或跨租户数据。

7. 配置、运行和验证​

后端 Nacos runtime 使用 AGENT_API_URL 与 AGENT_API_TIMEOUT_SECONDS；本机 Agent 内部地址示例为 http://127.0.0.1:8100/internal/agent/v1，不是浏览器访问地址。 Backend 的共用转发入口直连该地址，不继承系统或环境代理；Agent 必须能从 Backend 所在机器或容器直接访问。GET /threads 只验证委托上下文并查询 Agent 会话表， 不调用模型或 RAGFlow；该接口的 502 应先排查 Backend 到 Agent 的连接与代理。 三个进程启动方式见本地开发。

React 测试使用根目录 pnpm frontend:pro:test，覆盖事件投影、SSE、取消、URL/ChartSpec 等边界；类型检查与构建见前端架构。真实 BFF/Agent E2E、 恶意内容渲染、刷新/会话切换、移动端、归档/删除和已注册工具图表需另行验证。

浮窗本地测试覆盖延迟加载、业务 URL 不变、收起后流式回答、历史搜索/切换/新建、作用域变化清理以及入口权限；完整页跳转测试覆盖 RUN_STARTED 前后切换、会话 ID 连续、输入草稿、历史消息与场景保留、返回业务页面以及缓存 Agent 标签不重复挂载。浮窗使用独立弹层层级，内部提示/菜单和图片预览位于浮窗上层。真实构建产物在模拟 BFF 下验证了桌面与窄屏的完整页跳转、同一会话的历史和草稿保留、生成中切换后继续回答、返回浮窗及刷新按 URL 恢复历史；模拟服务端记录一次对话请求、零取消请求，浏览器无错误或警告。这些本地证据不代表真实模型、RAGFlow、生产 BFF 或远端 CI 联调已经通过。

会话时间的本地测试覆盖真实 assistant-ui 外部运行时接入、列表重载、搜索与归档日期、运行开始/编辑后刷新、返回标签页时跨日更新、无效时间回退及中英文格式；日历计算另在 America/New_York 时区验证夏令时边界。构建产物在模拟 BFF 下检查了完整页面与浮窗、长标题与更多菜单、小屏和深色主题，没有发现时间遮挡或浏览器错误。真实 Agent 数据、生产浏览器与远端 CI 尚未验证。

  • 会话与消息游标加载：分页、快速滚动与兼容边界。
