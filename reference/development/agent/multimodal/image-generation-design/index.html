Agent 图片生成与创作中心

2026-10-11：代码实现与本地验证记录、真实服务验收范围见文末。仓库未发现此前图片设计，本文为本功能唯一专题事实源。

1. 现状与边界​

现有 Agent 已具备 DeepAgents、System One 决策 Middleware、AG-UI、签名委托、审批和历史会话。Analytics 拥有个人图表收藏，URL /analytics/favorites 不变。Platform 已有 S3/RustFS 存储适配器、菜单播种和模块权益；Nacos 在进程启动前加载配置，环境变量优先，更新需重启，不宣称热更新。

新增 Suite 可选模块 creation，拥有 creation.generated_image、图片 HTTP API、查询工具及清理 Schedule；Platform 仍拥有用户、权限和菜单。模型 Provider、优化与生成工具只在 agent/，不把模型依赖放进管理后端。无需新数据库、MCP 服务、向量库或通用资源框架。

2. 官方模型能力核实​

核实日期 2026-10-11。官方 Token Plan 个人版 列出 qwen-image-3.0-pro，但限制自定义应用后端和账号共享。Chein 多用户后端不能默认使用个人版套餐。团队版与当前账号授权范围须由运营者确认；代码默认关闭，不使用真实 Key 或付费请求验证。

采用官方 Qwen 图片 API 的同步调用。业务空间使用 OpenAI Images /images/generations；北京 Token Plan 主机根据官方 多模态接入文档 使用同一 origin 的 /api/v1/services/aigc/multimodal-generation/generation，将提示词转为 input.messages、尺寸转为 宽*高，从 output.choices[].message.content[].image 读取结果。协议按已知主机在请求前选择，不因报错切换接口再次付费请求。首期仅文生图、单张 PNG，不新增编辑或异步入口。两种协议共用下载主机校验和无凭据下载。响应为 URL，b64_json 不受支持；临时地址有效期为 24 小时，需及时转存。内部尺寸使用 宽x高，总像素 512²—2048²、比例 1:8—8:1。实际账单与套餐 Credits 由控制台确认，不把普通 API 调用等同于套餐抵扣。

3. 创作中心与菜单迁移​

由现有幂等菜单播种建立无业务权限的 /creation 目录。Analytics 声明其已有页面的父路径为 /creation，图片页面 /creation/images。保留收藏菜单 ID、RoleMenu、Permission 和 URL。对已拥有任一子菜单的角色及套餐补充父菜单关系，不扩大子菜单权限；重复播种不复制菜单。刷新现有 RBAC 缓存。Base/Items 无 Creation 入口；Suite 安装后仍需租户权益与角色授权。

4. 生成链路与 Agent 联动​

新增 image_generation 能力描述，由已有 decision-model-preview Middleware 判定首次请求；高置信度时只保留图片工具与日期/澄清工具。普通问答、复杂意图、续问与恢复沿用现有路径。模型不可用时沿用既有回退，不用关键词伪装模型意图识别。

原生 generate_image / regenerate_image 复用同一个 ImageGenerationService。调用须通过现有 HITL 确认；原始 prompt 不被模型优化覆盖，优化提示要求保留明确的主体、文字、数量、风格与禁忌。先在 Backend 原子预留额度和幂等记录，再调用模型；成功下载有界 PNG 并上传 Backend，后者验证 PNG、存 RustFS 原图与缩略图，再提交成功状态。模型不得传用户 ID、tenant ID 或对象 Key。

generate_image.prompt 是结合当前会话的完整图片描述，也是用户确认的工具实参；Creation 的 original_prompt 保存该描述，enhanced_prompt 才追加可选视觉细节。运行时最后一条用户消息仅用于 message_id 关联，不覆盖已确认的 prompt。风格补充和纠正反馈须合并到已明确的主体，不能将“写实的”或对错误结果的反馈单独作为出图主题。关闭优化时，供应商收到的 prompt 与已确认实参一致；开启优化时也以同一完整描述为基础，不新增上下文推断调用。

生成结果仅返回 Chein image ID。assistant-ui 按工具事件展示占位，成功时通过授权接口取图；历史记录不保存签名 URL。查询工具使用结构化条件与数据库文本搜索。多张候选先 ask_user，不任意重生成。删除不向模型注册工具。

聊天图片场景选项​

完整页与浮窗的输入工具栏提供“对话”和“图像生成”快捷入口，入口复用 Creation 的构建清单和 creation:image:generate 权限；实际工具权限、模块权益及审批继续由后端重验。 图像模式显示可退出的蓝色标签、独立“尺寸 自动”菜单及图片描述占位文案，不展示模型选择。 加号后的分隔线独立设置为 16px，在 32px 工具栏中居中，不随选项区换行拉长。 输入框下方提供 2688×1536、2368×1728、2048×2048、1728×2368、1536×2688 和自动， 数量固定显示 1 张，供应商仍使用已有 n=1。自动保留 Agent 结合描述选择尺寸的能力， 未指定时使用 AGENT_IMAGE_DEFAULT_SIZE。

智能改写默认开启以兼容原行为，关闭后跳过现有提示词优化模型。 聊天原文不拼接尺寸或开关指令，BFF 以可选 imageOptions DTO 透传到 Agent； Agent 保存为本轮 checkpoint 的 image_generation 状态，在审批前规范化图片工具参数， 执行时再次应用用户选择。模型不能覆盖显式尺寸或改写开关，审批/暂停恢复继续使用原状态， 编辑消息则使用编辑时的选择。普通新消息清空本轮选项，历史 checkpoint 缺少该字段时保持原行为。 上下文合并仍保留已有图片主体与明确要求，不恢复“最后一句反馈覆盖完整工具描述”的旧逻辑。 新增 DTO 拒绝未知字段、多图数量、非预设尺寸与非布尔开关；不新增依赖或数据库迁移。

部署时需同步更新 Backend 与 Agent 并重启进程，再交付前端；旧客户端省略参数仍使用原默认行为。 新前端搭配旧服务可能忽略选项，不视为受支持的混合版本。

5. 图片数据、权限与 API​

creation.generated_image 保存 tenant/owner、thread/message/run/tool refs、name、original/enhanced prompt、requested/actual parameters、model、status、原图/缩略图 Key、实际尺寸、大小、source_image_id 和 UTC 时间。唯一 (tenant_id, owner_id, run_id, tool_call_id) 防止重复收费重试；分页索引为 tenant/owner/created/id，并提供模型索引。来源记录逻辑删除后仍保留关联。

模块 UoW 与 FORCE RLS 同时限制 tenant 与 owner，管理员的个人接口也不读取其他用户。读、下载、重命名、删除、生成、重新生成分别使用 creation:image:* 权限。所有签名接口逐次重验 agent:chat、成员、当前权限、模块状态及权益；长任务完成时重新授权。

BFF 签发工具委托前复用 filter_module_scoped_permissions，同时过滤当前 Edition、模块运行状态、租户权益与启用状态；超级管理员拥有角色权限也不能为未开通的模块获得 Agent 工具 scope。执行端仍逐次重验，签发时过滤不能替代执行时授权。

公开 /api/v1/creation/images：GET 分页（name/prompt/ID、model、UTC start/end），GET /{id} 详情，GET /{id}/content?thumbnail=true 预览，GET /{id}/download 原图，PATCH /{id} 重命名，DELETE /{id} 逻辑删除，POST /{id}/regenerate 调用相同运行时服务（必填 UUID request_id，同一次用户确认及网络重试复用该 ID；参数改变须重新确认）。内部接口预留、完成、失败与查询只接受签名委托。

6. RustFS 生命周期与失败条件​

复用 Platform S3 客户端，通过公开私有对象存储端口读写，使用运行配置的 RustFS channel，不创建另一套存储中心。Key 含 tenant/owner/image，不能由模型或浏览器指定。必须是持久化 S3 channel，不回退本地或公共 URL。有 pending 或尚未清理的对象时，通过模块 ReferenceGuard 阻止删除渠道及修改 Provider/Endpoint/Bucket/Region；凭据仍可轮换。渠道读取/修改使用兼容的数据库行锁。受授权引用检查仅返回当前租户引用计数，不返回其他用户的图片元数据。

Pillow 用于验证与缩略图：现有依赖没有图像解码/缩放能力，标准库不能可靠验证和缩放 PNG，因此新增该最小依赖。限制文件字节、像素与单张生成；不引入图像服务。浏览器使用短期 Blob URL，卸载后释放。

删除先提交 deleted_at，立即不可读；现有租户 Schedule 幂等清理对象，失败保留 Key 下轮重试。任务失败保留记录便于清理；过期 pending 标失败，不自动重试付费调用。超时/取消不能保证供应商未计费，幂等重放禁止重复调用。历史图片失效显示“图片已删除或不可访问”，其他消息正常渲染。

7. 前端组件与详情​

管理页使用 Ant Design 原生 Masonry 的等宽瀑布流，图片保持原比例，后续图片接续填入较短的列，名称与更多菜单覆盖在图片内部底部，桌面悬停或键盘聚焦时显示，菜单展开期间保持可见；无悬停能力的触屏设备默认显示，复用 Ant Design 的 Search/日期/模型筛选、分页、Empty/Spin；共用 ImageCard、预览与操作。图库图片与底部渐变操作区由同一直角容器裁剪，底部使用深色渐变和白色文字；图库图片、容器和加载占位均去掉圆角，详情预览仍为 24px。读取失败时保留静态名称和菜单，不用遮罩覆盖错误提示；读取详情时不显示额外的处理文案，仍保留按钮禁用及失败提示。列表与详情共享当前 ImageCard 持有的缩略图 Blob URL，尚未完成的缩略图请求也只保留一份；打开详情仍读取元数据以重新授权，点击放大才获取原图，本次详情打开期间再次放大复用原图。缩略图随卡片卸载释放，原图随对应预览组件卸载释放，不建立全局或持久缓存。管理预览按原图比例显示，缩略图不强制正方形；加载占位及待解码图片都使用元数据宽高预留同等比例，名称和菜单从加载阶段就覆盖在框内，不先在外部展示，避免布局跳变。点击管理页图片直接使用 Ant Design 原生预览放大；通过图片下方菜单中的“图片详情”打开居中的详情弹窗，上方展示最大 240px 的完整预览与基础规格，点击预览可查看大图；窄屏上下排列。原始与优化提示词在下方占满内容宽度，长内容在弹窗正文内滚动，操作按钮保留在底部；规格分为图片尺寸、文件格式和文件大小，任务 ID 与参数等信息放在折叠区。聊天内只使用 assistant-ui Image 的圆角图片预览，不展示操作栏、图片名称、管理卡片头和模型/时间信息；下载、详情、重命名、重新生成和删除统一从图片管理页操作。点击聊天图片通过已有 Image.Zoom 弹层查看原图，Esc、关闭按钮或点击遮罩可关闭；管理详情从图片管理页进入。聊天直接读取授权原图 Blob，放大复用该对象 URL。生成阶段尚无实际宽高时使用参考官方 ImageGeneration Element 的方形淡出点阵占位；获得元数据后的读取占位与图片按实际比例展示，适配深浅色和减少动态效果偏好。聊天预览最大宽度 352px、最大高度 600px，窄屏随容器缩小；真实图片保持比例、不裁切、不拉伸，不在方形容器中补边。中断、删除、读取失败保留静态状态框，读取元数据失败可刷新重试。图片仍从授权接口读取 Blob，并在卸载时释放对象 URL，不使用供应商临时地址。详情含 ID、模型、尺寸、格式、大小、原始/优化 prompt、请求/实际参数、owner/thread/message/run/source refs。支持复制 prompt、重命名、下载、确认删除和可编辑 prompt 的重新生成。用已有 /agent?thread=... 打开会话，无新增聊天路由或消息定位协议。

图片名称在菜单对齐基础上再向下偏移 2px。使用现有 ResizeObserver 模式测量名称与可用宽度，仅超宽时启用 CSS 无缝循环滚动，短名称静止；悬停、键盘聚焦或菜单展开时运行，其他时候暂停，触屏默认运行。窗口或名称变化后重新测量；重复文本对读屏器隐藏，减少动态效果偏好下停用动画并显示省略文本。

图库复用已安装的 Ant Design Masonry，无新增运行时依赖。列数按视口断点为 xs 1、sm 2、lg 3、xl 4、xxl 5，横纵间距均为 8px；使用 fresh 观察卡片尺寸变化，在图片加载、失败状态和内容变化后重新排列。图片 ID 用作稳定 key，数据与 DOM 顺序保持接口顺序，视觉位置由列高度决定；筛选、分页和权限逻辑保持现有链路。

等待 HITL 确认时保留原工具调用 ID 并隐藏其图片占位，只展示审批卡片；审批提示文字不作为图片结果。确认后恢复一个生成占位，原调用收到结构化结果后展示图片。恢复事件可能直接返回 TOOL_CALL_RESULT，不能依赖再次收到 TOOL_CALL_START。实时对话和历史恢复使用相同展示分流，真实工具错误仍显示失败。

8. 手动 Nacos 配置​

使用现有 Namespace（部署 bootstrap 中 NACOS_NAMESPACE），Group 默认 CHEIN。不修改任何真实 Nacos。Agent Data ID 为 chein-agent-runtime.yaml；Backend Data ID 默认为 chein-backend-runtime.yaml（若部署覆盖 NACOS_CONFIG_DATA_ID，以覆盖值为准），字段采用现有大写扁平约定。

Agent 清单：

AGENT_IMAGE_ENABLEDfalse；确认授权、额度、RustFS 后启用否否
AGENT_IMAGE_API_BASE留空复用 QWEN_BASE_URL；独立地址示例 https://WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1启用时须有有效地址否
AGENT_IMAGE_API_KEY留空且图片与聊天地址同 HTTPS origin 时复用 QWEN_API_KEY；须为同地域且允许应用后端使用的 Key启用时须有有效 Key是

图片地址和密钥可以省略或设为 null，启用时解析为现有聊天配置；显式图片配置优先。独立图片地址与聊天地址不同 origin 时必须提供图片 Key，不向其他主机转发聊天凭据。图片模型保持独立的 AGENT_IMAGE_MODEL，不会继承 QWEN_MODEL。复用配置不证明账号授权或接口可用：北京 Token Plan 自动使用上述 DashScope 接口，其他共用地址须支持 /images/generations，个人 Token Plan 的应用后端限制仍适用；不将普通业务 Key 与套餐 Key 混用。当前 Nacos loader 不把 null 注入环境变量；已有环境变量覆盖值不会因在 Nacos 设 null 而清除，切换复用时须移除旧的图片专用覆盖值。

2026-10-11 实际排查：图片预留及提示词保存均为 200，Token Plan 的 /compatible-mode/v1/images/generations 返回 HTTP 400 invalid_parameter_error（URL 错误）。对官方多模态路径发送缺少 input 的无生成请求，返回 HTTP 400 InvalidParameter / Field required: input.messages，证明服务已识别该路径；这不证明模型生成、额度或上传成功。供应商拒绝时仅记录 HTTP 状态和白名单错误码，不记录响应正文；生成工具返回脱敏错误消息，保留失败记录，不自动重试计费。

Backend 清单：CREATION_IMAGE_DAILY_LIMIT（默认 20，用户每 UTC 日预留上限）；复用 S3_ENDPOINT_URL / S3_BUCKET / S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY / S3_OBJECT_PREFIX 的现有 RustFS 配置，两个 Key 敏感，不新增存储密钥。存储中心必须已有持久化、启用的默认 S3 渠道并指向 RustFS；Nacos 的 S3 字段用于现有配置/初始播种，不会覆盖已维护的渠道。私有 Bucket 与可信内网连接由运营者确认。API Key 采用 Field(repr=False)，不返回前端，不记录供应商响应正文。Nacos 的访问权限/TLS/密钥保护沿用部署约束；不假设 ${...} 被自动展开。

配置发布后重启对应进程；Edition 固定为 Suite。沿用 后端初始化文档 的 prestart：迁移管理员配置只进入 bootstrap，迁移前后执行 runtime role provision，再执行 app.initial_data。本机命令也见该文档，不使用 API 的运行账号迁移。菜单初始化会补父菜单关系与清理 RBAC 缓存；通过已有套餐/租户模块入口启用 creation，再授予六个 creation:image:* 权限与 agent:chat。Schedule Worker 须启用以执行清理；代码不在请求时安装模块。降级不删除图表数据；Creation downgrade 将删除图片元数据，须先导出并清理文件，不作为常规回滚方案。

排查生成失败时先检查 /creation/internal/prepare：模块访问判定返回 TENANT_MODULE_ENTITLEMENT_REQUIRED 表示租户权益缺失，此时尚未调用图片模型。在租户管理的“模块权益”中对 creation 单独授权，或在对应套餐授予权益，并确认租户启用；角色权限与模块权益是两项独立条件。默认存储若仍为 local，即使启用模块也不能生成图片，须在“存储渠道”配置并启用默认 RustFS/S3 渠道。历史卡片将生成中断、图片不可访问（403/404）和读取连接失败分别显示；连接失败只允许重试读取，不自动重试付费生成。

渠道测试出现 PartialCredentialsError 表示创建 S3 客户端时凭据不完整，此时尚未连接对象存储。自定义 Endpoint 的渠道须在渠道编辑页同时保存 RustFS/S3 的 Access Key 和 Secret Key；它们与图片模型 API Key 不同，持久化渠道不会自动继承 Nacos 的 S3 凭据。共用客户端入口检查缺失或空白字段并返回 503 配置提示，SDK 配置错误与桶检查的网络异常也返回安全提示；无自定义 Endpoint 且未显式配置凭据的 AWS 渠道仍使用 SDK 原有凭据链。配置提示不代表实际凭据或桶权限已经验证成功。

自定义对象存储 Endpoint 直接连接，不继承桌面系统代理；无自定义 Endpoint 的 AWS 渠道仍保留 SDK 原有代理行为。桶检查遇到 403 返回凭据或桶权限提示；只有 404/NoSuchBucket 且启用自动建桶时才创建桶，不因认证失败、网络异常或服务端错误尝试建桶。签名不匹配须核对同一套凭据，不能仅据 HeadBucket 的 403 判定桶不存在。

开通权益后仍收到历史式“不支持图片生成”回复时，须区分新进程读取的 Nacos 配置与运行中进程的配置。修改 Agent Nacos 配置后完整重启 Agent 开发命令，浏览器刷新不重新加载 Agent 配置；启动日志记录 image_generation_enabled 布尔值，不记录密钥。仅在本轮确实注册 generate_image 时注入图片能力说明，明确历史拒绝不代表当前工具不可用，并要求续问沿用已明确的图片要求及审批流程。历史消息不改写，图片生成仍需用户确认。

生成确认是现有 HITL 审批：等待确认时不会调用图片供应商。2026-10-11 后续实联记录显示用户已批准，PNG 已进入 complete 接口，但保存状态时报 StaleDataError。只读诊断确认，在 Creation UoW 内进行 Platform 权限复验会清空 app.tenant_id，使后续 ORM 更新被运行账号的 RLS 拒绝。Platform UoW 现保存并恢复进入前的事务租户 setting，同时拒绝未授权的租户切换；不放宽 RLS，也不跳过完成时复验。隔离数据库 HTTP 回归增加 app_runtime 分支（仅对象存储写入使用测试替身）：修复前复现相同错误，修复后完成接口成功保存 PNG 元数据。管理员成功不能替代运行账号验证；真实服务新的出图与存储验收仍待用户确认生成。
