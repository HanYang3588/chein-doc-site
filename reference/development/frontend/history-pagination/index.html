Agent 会话与历史消息游标加载

状态：实施中，验证结果见文末。

范围与边界​

会话与消息由顶层 Agent 持有，Platform BFF 只验证现有权限和签发受信委托。前端继续使用 assistant-ui ExternalStoreRuntime、ThreadPrimitive.Viewport、Messages 和 ThreadList，不创建第二套聊天运行时。Edition、权限、审批和模型上下文不变；分页只改变浏览器展示的数据窗口。

当前安装 @assistant-ui/react 0.15.21 / @assistant-ui/core 0.3.20。官方新文档提供 hasEarlier/onLoadEarlier，但本地版本的 ExternalStoreAdapter 没有这两个字段；ThreadList.LoadMore 面向 RemoteThreadList，当前 ExternalStoreThreadListAdapter 也不支持分页字段。因此本次复用原生容器/消息/会话组件，用应用层 IntersectionObserver 与可操作按钮接分页，不升级依赖或重写 Runtime。

依据：官方 ExternalStore 历史分页、列表滚动触发。具体能力以仓库锁定版本源码为准。

接口与一致性​

  • 新增 GET /threads/page：默认 30 条、上限 100，archived、search、cursor、可选的 updated_from / updated_before；返回 items/nextCursor。按 (updated_at DESC,id DESC) 真实 SQL keyset 分页，使用 limit+1 判断是否还有下一页；不用 OFFSET，不做全量计数。当前普通会话已有 owner/updated_at 部分索引，归档仍可能需要排序；实际索引命中与生产性能需 EXPLAIN 验证。
  • 新增 GET /threads/{thread_id}/messages/page：默认最近 10 轮、上限 50 轮，游标固定 checkpoint 与上一页首个 HumanMessage 标识，从边界向前取完整轮次。消息按原顺序返回，同一轮的工具调用与结果不拆页，返回会话元数据以正确展示未在列表首屏的深链与归档会话。
  • 两个接口在同源 /api/v1/agent-ui BFF 下提供同名路径。旧数组接口保留用于兼容已有调用方；当前前端改用新接口。删除旧入口需另行完成消费者审计和兼容窗口。
  • 游标有版本、长度和作用域校验，绑定 tenant/owner、会话或归档/搜索/更新时间范围条件。无时间筛选时保留旧游标作用域；带筛选时先规范化到 UTC，禁止跨时间范围复用游标。它不授予权限，也不依赖可选的 Langfuse 密钥；每次查询均从已验证委托取得身份，历史接口重新验证会话拥有者。伪造或混用游标不能突破 SQL/checkpoint 的身份边界。无效游标 400，已清理的历史快照 410，未拥有的会话 404。
  • 列表为实时 keyset，排序字段变更时通过刷新重新取得首屏；前端按 ID 去重。消息基于固定快照，新增回答不会挤动历史边界。编辑/重放作废旧分页状态，重新获取对应最新分支。

性能的实际范围​

浏览器只接收并渲染加载过的页。会话列表在数据库端分页；历史的 RunEvent、反馈关联和分析授权处理缩小到当前页。

LangGraph 当前保存的是物化 checkpoint，读取一页历史仍需反序列化该 checkpoint 的消息通道。 本次没有创建消息投影表，不能宣称消息存储已实现逐行数据库分页。若快照反序列化成为经测量的瓶颈，应单独设计可重建、可失效的 Agent-owned 消息索引，并处理编辑、审批、分支和权限撤销；不能在本次绕过 checkpoint 或复制另一套运行事实源。

前端滚动与并发​

  • 列表向下滚到边界加载下一页；消息向上滚到边界加载更早轮次。初次挂载不自动拉完所有页。归档页独立管理页状态，通过“加载更多”取下一页；聊天运行时不再请求归档列表。
  • 每个分页器同一时刻只允许一个请求；快速滚动复用进行中的 Promise。ID 去重且保留已有消息对象，使用函数式更新，避免覆盖流式新消息。
  • AbortController 配合 epoch/scope 校验，拒绝忽略 abort 的迟到响应。切换会话、开始新 Run、编辑/重放会取消或重置旧请求；失效响应不推进游标。
  • 插入旧消息时保留可见消息元素及其相对顶部位置，在布局阶段补偿滚动位置。保留可聚焦的加载/重试按钮，网络失败保留已加载内容与当前游标。
  • 标题搜索延迟 250ms 后在服务端检索，覆盖未加载的会话。归档页的原生日期范围同样在数据库筛选（更新时间起点包含、终点不包含），查询参数必须带时区，空/倒置范围返回 422。计数只表示已加载数量，有下一页时提示“还有更多”，不冒充全量计数。

会话切换等待优化（2026-10-20）​

点击不同会话后立即更新选择并清空旧消息；旧 Run 的协作取消异步完成，取消错误仅作用于原会话，不能覆盖新会话。重复点击当前会话不重新加载。历史、审批和恢复状态仍并发读取，历史请求完成后即可渲染；审批状态确认前保持输入与发送禁用，读取失败时继续禁用，可切换到其他会话后重新打开重试。切换会取消历史及控制状态请求，并继续通过会话/版本校验拒绝忽略 abort 的迟到响应。

Backend 委托权限按当前请求批量查询，复用单权限检查的同一 SQL 规则，保留租户、用户、角色/菜单启用状态与模块权益过滤；权限结果不跨请求缓存。可恢复 Run 状态只需要 agent:chat 委托并由 Agent 校验 tenant/owner；历史与审批详情继续计算所需执行权限并保留内容重验。

本地验证：前端页面与游标组件 72 项通过，Backend BFF/权限/Memory/租户作用域 25 项通过；类型检查、React 构建、Backend Ruff 通过。真实一次性 PostgreSQL 数据库中，合成普通用户的同组 17 项权限检查由 17 条权限 SELECT 合并为 1 条，权限集合相同，停用角色/菜单和错误租户仍拒绝。前端延迟审批/恢复状态、取消未返回、迟到响应和审批状态失败的组件回归通过。测试使用一次性数据库，不消费正在运行的视频队列。

这些检查验证等待关系与 SQL 数量，不是当前用户实际会话的端到端耗时；真实登录态的网络瀑布、长 checkpoint 解码、生产负载与远端 CI 尚未测量。HTTP/DTO、迁移、依赖和 Edition 集合保持兼容。

历史内容权限校验等待优化（2026-10-20）​

同一页中每轮分析历史原先分别调用一次 /scope，每次经 MCP/Nacos 发现工具并重新查询当前源权限；随后再串行等待 Memory lineage 校验。现在一次历史请求只读取一次当前分析 scope，各轮仍独立检查 scopeHash、schemaHash 和 expiresAt；该 scope 仅在本次调用中复用，下一次请求重新读取，无分析工具结果的历史不查询分析 scope。源权限拒绝、scope 响应格式错误或记录过期仍屏蔽对应轮的答案及工具结果。

历史页先按完整 checkpoint 的 HumanMessage 轮次定位游标，然后并行执行分析与 Memory 校验。Memory 校验失败时，最终只保留该页原始用户消息，答案、工具结果、引用和分析失效提示均不返回。页内容必须等待两项校验完成才能发布；会话拥有者、固定 checkpoint 与跨作用域游标校验不变。

当前真实会话的只读单次采样：内部历史读取从 14.658 秒降为 6.402 秒；分析 scope 请求从两次合计 9.415 秒降为一次 4.299 秒，Memory 校验约 3.1 秒且与分析校验重叠。修复前 checkpoint 读取约 0.68 秒。运行中 Agent HTTP 复测：历史页 200、10 条展示消息、9.728 秒；审批状态 200、0.586 秒；恢复状态 200、0.907 秒。内部调用和 HTTP 采样是不同测量，不能混作浏览器总耗时或 p95，也不能据此承诺秒开。

本地验证使用显式隔离 PostgreSQL 的 Agent 全量测试 304 passed、6 skipped；新增同请求分析 scope 复用/跨请求重验、失效与格式错误屏蔽、并行校验及 Memory 撤销负向测试。额外分页回归覆盖 Memory 允许/撤销后连续翻页、工具轮次完整性、快照固定和跨拥有者拒绝。Agent/Backend Ruff 与 git diff --check 通过。未修改前端、公开 HTTP/DTO、依赖、数据库结构或 Edition；未调用模型或写真实业务数据。已登录浏览器验证因本机屏幕捕捉服务错误未完成，远端 CI、网络瀑布和生产负载仍未验证。

配置与验证​

无新增运行时依赖、数据库表、迁移或中间件配置。需一同部署 Agent、Backend 和前端。历史加载不改变模型可见的 checkpoint 上下文；开发测试不调用真实模型或写用户业务数据。

待完成：游标边界/身份/快照测试，前端快速请求/迟到响应/错误重试测试，原有聊天/审批/编辑回归，类型检查、客户端生成、Edition 构建及浏览器滚动验证。真实数据库 EXPLAIN、生产时延和远端 CI 不以本地测试替代。
