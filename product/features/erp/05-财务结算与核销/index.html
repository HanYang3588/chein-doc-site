财务：付款单、收款单与结算（核销）

状态：操作与事实说明（以 application/settlement.py、finance_document_routes.py 为准）。

适用范围：付款单 FKD、收款单 SKD，以及它们对采购/销售单据 settled_amount 的影响。

相关：02-采购业务.md、03-销售业务.md、06-对账与一致性.md。

1. 单据与方向​

单据表单号前缀往来方可核销的来源
付款单finance_payment / finance_payment_itemFKD供应商 supplier_idpurchase_in（正方向）、purchase_return（负方向）
收款单finance_receipt / finance_receipt_itemSKD客户 customer_idsale_out（正方向）、sale_return（负方向）

正方向 = 增加应付/应收（采购入库、销售出库），负方向 = 冲减（采购退货、销售退货）。 明细的 source_type 字段取值范围就是上表的四种值（枚举 SettlementSourceType）。

2. 金额字段含义​

表头：

字段含义
total_settlement_amount本次核销的净额（正方向合计 - 负方向合计）
discount_amount本次享受的优惠/折让总额
payment_amount / receipt_amount实际收付现金 = total_settlement_amount - discount_amount

明细：

字段含义
source_total_signed来源单据金额（负方向为负数）
settled_before_signed本次核销前已结算金额（负方向为负数）
settlement_signed本次核销金额（负方向为负数）
discount_allocated该行分摊到的优惠（只有正方向行会大于 0）

signed 后缀表示"已经按方向取过符号"：查询时不要重复取负。

3. 核销规则（SettlementService）​

计划阶段 plan()：

  1. 至少一行明细，否则 empty_document。
  2. discount_amount >= 0，否则 negative_discount。
  3. 来源类型必须匹配单据方向、不能重复，否则 invalid_or_repeated_source。
  4. signed_sum = 正方向金额合计 - 负方向金额合计； cash_amount = signed_sum - discount_amount，为负则 negative_cash_amount。
  5. discount_amount 不得大于正方向金额合计，否则 discount_exceeds_positive_sources。
  6. 折扣只在正方向明细上按 settlement_amount 比例分摊， 每行 ROUND_HALF_UP 保留 4 位小数，最后一行的差额由剩余值兜底（保证合计精确相等）。
  7. 每条来源逐项校验：
    • 必须 status = approved → source_not_approved；
    • 往来方必须与表头一致 → counterparty_mismatch；
    • 本次核销额 + 分摊折扣（仅正方向） <= total_amount - settled_amount → amount_exceeds_source_balance。

执行阶段 apply()：

按 (source_type, source_document_id) 排序后逐条加锁，并比对 no（变化则 source_changed）， 然后回写来源单据的 settled_amount：

  • 正向核销：settled_amount += |settlement_signed| + discount_allocated（正方向行）；
  • 负方向核销：settled_amount -= |settlement_signed|；
  • 反向（reverse=True）：先检查 settled_amount >= 应扣回金额，否则 source_balance_inconsistent。

关键点：折扣会让来源单据的 settled_amount 增加得比现金更多—— 一笔 1000 元采购入库、优惠 50 元、实付 950 元，核销后 purchase_in.settled_amount = 1000。

4. 审批与反向流程​

审批付款/收款单时：

  1. 校验单据 draft 且 version == expected_version，否则 409 Payment document version conflict （收款单为 Receipt document version conflict）。
  2. 校验结算账户存在且启用，否则 409 Settlement account is unavailable。
  3. 调用 SettlementService.apply() 回写各来源单据的 settled_amount。
  4. status -> approved、version += 1、写审计与事件 erp.payment.approved / erp.receipt.approved。

反向时：先按明细把 settled_amount 扣回，再 status -> draft、version += 1， 审计 reversed，事件 erp.payment.reversed / erp.receipt.reversed。

因此：只要某张采购入库/销售出库被已审批的付款/收款单引用，它就不能被反向 （见 02-采购业务.md / 03-销售业务.md 的失败条件）。

5. 排查​

Q：某张入库单/出库单的已结算金额对不对

SELECT 'purchase_in' AS kind, i.no, i.total_amount, i.settled_amount,
       COALESCE(SUM(
         CASE WHEN p.status = 'approved'
              THEN ABS(item.settlement_signed)
                   + CASE WHEN item.source_type = 'purchase_in' THEN item.discount_allocated ELSE 0 END
              ELSE 0 END), 0) AS applied
FROM erp.purchase_in i
LEFT JOIN erp.finance_payment_item item
       ON item.source_document_id = i.id AND item.source_type = 'purchase_in'
      AND item.tenant_id = i.tenant_id
LEFT JOIN erp.finance_payment p
       ON p.id = item.finance_payment_id AND p.tenant_id = item.tenant_id
WHERE i.tenant_id = '<tenant>' AND i.no = '<单号>'
GROUP BY i.no, i.total_amount, i.settled_amount;

上面只统计已审批付款单的明细，与后端对账口径一致；已反向（status 回到 draft） 的付款单不计入，因为它退回草稿时来源单据的 settled_amount 也已同步扣回，两侧应一起归零。 如果 settled_amount 与 applied 仍然对不上，说明来源单据的 settled_amount 与 已审批核销明细不一致，这正是 06-对账与一致性.md 中 settlement_difference_count 报出的差异（定位步骤见该文档第 4 节）。

Q：一张付款单核销了哪些单据、优惠怎么分的

SELECT item.source_type, item.source_document_no, item.source_total_signed,
       item.settled_before_signed, item.settlement_signed, item.discount_allocated
FROM erp.finance_payment_item item
JOIN erp.finance_payment p ON p.id = item.finance_payment_id AND p.tenant_id = item.tenant_id
WHERE item.tenant_id = '<tenant>' AND p.no = '<付款单号>'
ORDER BY item.source_type, item.source_document_no;

Q：为什么付款单审批报 "Settlement amount exceeds source balance"

说明该行 本次核销额 + 分摊折扣 > total_amount - settled_amount。核对： 来源单据是否已被别的付款单核销（含未反向的）、是否把退货金额写成了正数、 或者折扣分摊把超出部分压到了这一行（折扣只在正方向行分摊，最后一行兜底）。

Q：往来方不一致的报错

counterparty_mismatch 表示明细里的来源单据不属于表头的供应商/客户。按 source_document_id 回查 purchase_in.supplier_id / sale_out.customer_id 即可确认。

Q：negative_cash_amount 是什么意思

负方向（退货）金额超过了正方向金额减去优惠，导致实收/实付为负。业务上应当拆成两张单， 或在同一张单里调整正负金额的搭配。
