Chein · 本体、业务与 Agent 的结合探索

Chein 是一个以验证本体与业务结合的可行性为核心的系统，同时用于探索 RAG 知识检索、Agent 开发和自然语言数据分析。它把业务对象、关系、规则、知识资料与数据查询接入同一工作台，探索智能体如何基于明确的业务语义和可核对的证据完成任务。

其中，RAG 和数据分析功能已在企业中使用。本体与业务结合仍是重点验证方向，Agent、规则推导与多模态能力持续迭代。本站展示系统的功能、技术选择、架构设计和操作界面。

系统已经实现哪些功能​

本体建模与业务语义​

OWL 可视化构建器支持创建独立工作区，也可从文件导入初始定义。在画布中维护类、子类、对象属性、数据属性、实例及关系，查看定义详情和源码，保存或恢复草稿，并导出本体文件。

数据源目录可以为建模提供表、字段与类型信息。用户选择目录中的表和字段，将其复制为 OWL 定义；选中带有目录标识的对象后，可以在当前权限范围内查看原始表数据。目录复制、原始表预览和规则数据绑定是不同能力，导入定义不会自动建立实时业务映射。

画布将业务定义与字段类型放在同一视图中。用户可以进一步查看对象详情、调整定义，并进入校验与发布流程。查看原图。

校验、版本与规则推导​

本体正文支持版本管理和受控发布。OWLAPI / HermiT 承担复杂 OWL 语义校验，发布前要求与本人当前输入对应的有效校验结果；发布后的版本保持不可变。

Logic Pack 用于配置受限业务规则、状态机、派生属性、目标和数据绑定。推导从已授权的事实快照取得前提，返回 TRUE、FALSE 或 UNKNOWN，并提供证明与重放能力。缺少证据时保留 UNKNOWN，避免把未知当作通过。

系统还实现了受限假设分析和历史证明影响分析。假设结果用于比较与解释，不能作为真实业务操作的依据。完整功能和限制见本体与业务结合及规则推导设计。

数据源接入​

数据源管理支持连接配置与测试、元数据采集、库表字段目录、结构变化记录、业务名称、表启用、字段暴露和脱敏设置。目录浏览采用逐级加载，数据预览采用受限只读查询。

在数据目录中选择表、字段及 OWL 类型，建立业务概念的初始定义。查看原图。连接器、预览和外部绑定的支持范围见数据源交付说明。

RAG 知识检索​

知识库模块支持系统、租户及个人知识资料管理，提供文件上传、解析状态、访问控制和 Agent 检索接入。检索复用 RAGFlow，结合已授权知识目录、问题处理、证据判断和来源引用，使回答能够回到文档依据。

知识库权限和文档状态在读取时重新检查。检索结果不能扩大业务权限，知识回答也不能替代当前业务系统的真实状态。该方向已在企业使用，功能与接入见知识库管理和知识检索交付。

自然语言数据分析​

用户通过业务语言说明指标、时间范围和分组，Agent 调用获准的分析工具，将问题转换为受控查询，展示结果和图表，并支持个人图表收藏。

查询通过数据所有者的固定契约执行，保留租户、用户及业务范围约束。分析快照、查询口径和图表结果分别管理，重新打开收藏时仍检查当前权限。数据分析功能已在企业使用；查询、图表与收藏的实现见SQL 分析交付。

Agent 交互与执行​

Agent 提供文字会话、历史记录、项目归类、工具事件和结构化结果展示，支持取消、协作式暂停、检查点恢复、追问及审批交互。输入框中的本体与决策开关控制当前运行的使用偏好，实际能力仍取决于工具目录和授权。

工具通过现有模块契约接入 MCP；Agent 负责模型与工具编排，业务系统继续拥有业务数据与权限。长期记忆采用 RAGFlow Native Memory，自动化任务使用独立调度进程，观测与 Token 计量分别记录运行链路和用量。入口说明见Agent 对话，专题边界见Agent 文档。

多模态与业务底座​

  • 多模态：图片生成、视频任务与资产管理、实时语音入口；语音与文字复用会话和执行状态。各能力按 Provider、权限与部署配置启用，见图片、视频与实时语音。
  • 业务验证场景：ERP 提供主数据、采购、销售、库存、财务与对账，为语义建模、分析和规则验证提供业务链路，见ERP 业务说明。
  • 管理基础：多租户、成员与组织、RBAC、菜单、模块权益、文件及配置管理，为不同用户的业务与智能体访问提供隔离和授权。

本体如何与业务真正结合​

本体在这里承担业务语义层：定义业务对象及其关系，连接数据所有者提供的事实，再通过明确规则解释业务条件。RAG 提供文档证据，数据分析提供数值结果，Agent 将这些能力组合为可交互的任务过程。

以销售出库的条件判断和人工审核为例：

  1. 在 OWL 中定义相关业务类、属性与关系，形成已校验的发布版本。
  2. 在 Logic Pack 中配置目标及规则，并绑定数据所有者提供的授权目录。
  3. 对当前用户有权访问的出库单取得事实快照，检查规则并返回结论与证明。
  4. Agent 根据真实推导结果解释“哪些条件满足、哪些不满足、哪些证据不足”。
  5. 用户进入 ERP 人工审核页面确认；ERP 再次核验证明、当前单据、库存及审核权限，执行自己的业务事务。

这条链路用于验证：本体能否把业务语义、数据、规则与操作连起来，让智能体的结论可解释、可核对。 推导成立不会授予审核权限，Agent 的相关 MCP 工具保持只读，库存写入仍由 ERP 的事务入口负责。

实际入口、页面截图及使用步骤见本体与业务结合。当前展示截图包含尚未发布的工作区，规则入口会要求先完成校验和发布；流程实现与具体工作区是否就绪分别核对。

用了什么技术，各自负责什么​

层次技术在系统中的用途
管理前端React、TypeScript、Umi Max、Ant Design、ProComponents业务工作台、权限菜单、表单与数据管理
Agent 与本体界面assistant-ui、AG-UI、React Flow、dagre流式会话、工具结果、本体画布与图布局
业务后端Python、FastAPI、SQLModel、AlembicAPI、业务模块、授权、事务与数据库迁移
Agent 运行时Deep Agents、LangGraph、LangChain、MCP模型调用、工具编排、检查点与执行恢复
知识与记忆RAGFlow文档解析、检索与原生长期记忆
本体与图数据RDFLib、Neo4j、pySHACLRDF 定义处理、授权图读取与投影、受限模型校验
OWL 计算Java、Spring Boot、OWLAPI、HermiT独立进程中的 OWL 校验与有界推理
数据与文件存储PostgreSQL、Redis、RustFS / S3 兼容存储业务与运行状态、缓存、文件和媒体资产
配置、调度与观测Nacos、APScheduler、OpenTelemetry、Langfuse配置与提示词、定时任务、链路与用量观测

整体采用模块化管理平台 + 独立 Agent 运行时。PostgreSQL 保存业务、本体版本和运行状态等各自所属的数据；Neo4j 服务于授权语义读取与投影，ERP 继续拥有实时业务实例。技术边界与调用链见系统架构和架构视图。

为什么现在没有开放源码​

项目源码现阶段暂不开放，因为部分功能已经在企业中实际使用。 当前以功能说明、设计文档、架构介绍和页面展示的形式介绍项目，帮助读者了解系统做了什么、采用了什么技术，以及如何验证本体与业务结合。
