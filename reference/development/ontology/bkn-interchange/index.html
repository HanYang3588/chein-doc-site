BKN 文件互操作支持范围

当前 Profile：chein.bkn/1。接口只生成预览和当前模型草稿，不创建权限、不替换网络身份、不直接发布。它是 OpenBKN 声明格式的受控子集，不是 OpenBKN 服务、SDK 或完整语言的替代实现。

格式依据官方 SDK 快照 aa1f5ffd1e2e71ef21b9b5d6e088ce6f3934c03e 的 语言说明核对，解析器为 Chein 独立实现。运行依赖复用已有 PyYAML 和 Python 标准库。

文件与预检流程​

工作区“导入模型”支持：一个 Chein JSON、多选 .bkn 文件、一个 Base64 传输的 ZIP 文件集。界面选择文件后先预检，展示分类数量、校验问题和不兼容变化，再由用户明确采纳；存在校验问题时不能采纳。采纳只修改前端草稿，仍需保存、校验、提交和另一位成员审核。失败不修改原模型。JSON 也通过同一服务端预检，不再使用只检查 format 的前端旁路。

  • 合并：按类型与稳定 code upsert，保留未出现在导入内容中的定义；不将遗漏条目当作删除。
  • 替换：替换整个草稿模型，展示删除、类型、映射和指标口径变化。
  • network.bkn 中的名称/标识用于文件说明，导入目标始终是当前工作区；不会将当前网络改成另一个身份。
  • 导出：工作区 JSON 可导出当前未保存草稿；BKN ZIP 导出指定的已保存版本，未保存时禁用，避免导出内容与界面不一致。

API：POST /ontology/imports/preview（ontology:edit）；GET /ontology/networks/{id}/versions/{version}/export（ontology:read），download=true 返回 ZIP，默认返回文件清单与 Profile。导入复验 Knowledge 来源权限；导出通过相同网络 Tenant/owner 可见性和来源检查。

支持矩阵​

定义原生结构Chein 补充与约束
网络YAML frontmatter 的 type/id/namechein.profile、来源引用；不改变导入目标身份
对象ObjectType、Data Properties、Keys、Data Source单主键、实例展示属性、描述；Data Source 必须是当前授权目录中的 resource
属性Name、Display Name、Type、Description、Mapped Field必填、唯一、可查询/展示、敏感性、默认值、精度、上下界、枚举、引用目标保存在 chein.properties，逐项通过严格 DTO 校验
UUID 属性reference，或已注册 UUID 源字段的 string/uuid仅目录明确声明 reference 的源字段进行转换；不会把任意文本强行转成 UUID
关系RelationType、Endpoint（direct）、Mapping Rules原生映射必须唯一匹配代码维护的两端字段；Chein 导出用扩展保存固定 binding、基数、描述、反向关系
分组ConceptGroup、Object Types成员必须存在；分组描述保留；不允许重复成员
行动ActionType 声明容器仅 Chein Contract 扩展中的已注册只读 executor；外部 tool/MCP、调度、触发和写操作拒绝导入
指标Metric 声明容器仅 Chein 注册指标契约，严格比较口径、维度、聚合、字段和时间，不解释自由表达式

Chein 扩展存放在 YAML 的 chein 下。原生表格保存对象的结构性事实，扩展不能覆盖其 code/name/type/source。行动、指标与扩展约束不能保证被上游产品识别，因此不能把 ZIP 宣称为无损的全产品跨平台迁移包。实际迁移到另一平台前还需要那一平台的资源 ID、执行器和权限映射。

明确拒绝：多主键、间接关系/任意 join、逻辑属性表达式、自由 SQL/Cypher、脚本、未登记 URL、外部行动、risk_type、非空 tags 及未知结构化小节。不会忽略不支持的执行契约后仍报告成功。已有对象/属性 code 仍使用 Chein 的字母开头、字母数字下划线、最多 64 字符规则。

安全与容量​

最多 262 个条目；压缩包本体和所有解压后内容分别不超过 256 KiB，单个 frontmatter 不超过 64 KiB，最终 Schema 仍不超过 256 KiB。超过导出预算时明确返回错误，可继续使用 JSON，不生成无法重新导入的无界包。

只在内存中读取 ZIP，逐个有界读取，不解压到文件系统；拒绝路径穿越、绝对路径、非规范路径、重复文件名、控制字符、符号链接、加密文件和嵌套非 BKN 文件。YAML 使用安全解析，禁止 anchor/alias 和重复 key；JSON 也拒绝重复 key。重复类型标识、跨文件缺失引用、无效字段、未知来源和模型预算均阻止采纳。来源、数据权限和发布验证仍由服务端执行，界面预检不能授予权限。

兼容与发布​

DSL 仍为 chein.ontology/v1，新增可选 display_key、属性/分组描述、受控筛选和只读 executor/指标枚举；旧 JSON 和不可变历史版本继续读取，无 ORM 字段变更、无数据库迁移。

本次扩展了 ERP 目录，目录指纹随之改变。旧发布版本仍可查看，但数据执行按既有规则返回 ontology_mapping_changed。应由有权限成员保存为新草稿、重新校验并走双人审核发布；不自动重写旧版本或沿用旧审核。既有固定 MCP 服务版本不自动发布或变更，运营需要按既有发布流程显式发布新工具契约，旧 Run 保持原绑定。
