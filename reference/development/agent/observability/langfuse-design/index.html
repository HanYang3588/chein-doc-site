Chein Agent 可观测性与持续优化总体设计

状态：Proposed；P1–P5 本地实现已接线，目标环境及完整验收待完成。当前事实见 实施与启用。 前置阅读：代码审计、官方调研；实施和验收以阶段计划为准。

本文维护拟议的 Trace 模型、性能、安全及质量闭环；运行时边界仍以Agent 架构为事实源，部署参数仍以Langfuse 部署为事实源。接入前设计结论保留；当前实施证据及配置见 P1–P5 实施，不以设计要求代替已上线事实。

2026-10-14 增补：可读链路与脱敏问答设计 根据运行证据增加显式 opt-in 的选取问答模式与控制面连接复用；以下默认 metadata-only 要求仍适用，新增模式的采集例外以该专题契约为准。

1. 决策与证据等级​

正文“建议”“应”“目标”均为设计要求，不代表已经实现。四种证据标记含义：

标记含义
已通过代码验证静态读当前实现、lock 或官方固定 SDK 源码；不是运行验收
已通过官方文档验证已查官方页面，其能力/限制仍须适配部署版本
待实验验证需真实依赖、端点、故障/并发/性能测试
待业务决策涉及成本、隐私、保留期、管理员和产品范围，须 Owner 决定

拟议决策：

  1. B + D：官方 LangChain Callback + 少量业务 Span + 原有元数据日志。只在顶层 agent/ 引入 Langfuse/框架依赖；Backend 不导入 Agent 或 Langfuse 框架 Callback。
  2. 默认关闭、metadata-only、观测可丢弃。观测不可用不影响 Run、checkpoint、审批、安全审计、健康/就绪。
  3. 一个请求执行一个 Trace。多轮/恢复按 Session、Run 和 execution 关系聚合，不维持等待人工数小时的常驻根 Span。
  4. 每次模型调用一个成本所有者。Callback generation 与手工 System One/image 调用互斥计量；Langfuse 与 Higress 只核对，不相加。
  5. Nacos 继续是 Prompt 正文和发布版本唯一来源。Langfuse 用于观测、评分、数据集和实验，不新增独立 Prompt 发布入口。
  6. 先内部运维访问，后按需求提供 Chein 受控 API。不直接把 Langfuse 项目角色等同于租户/部门权限，不建设完整控制台副本。

2.1 未来跨服务 OTel 与 SkyWalking​

P1 只在 Agent generator 内建立根，BFF 的认证/Prompt 耗时继续看 request_id 日志。这不是完整 HTTP 端到端 Trace；P2 才连接 BFF 根、授权工具服务和 ERP 查询阶段。

P2 由每进程组合根初始化唯一 OTel Provider。BFF 生成可信 server span，把 traceparent 经现有内部 HTTP/MCP transport 注入；Agent 仅在委托 JWT 验证成功后接收关联。浏览器提交的 traceparent/baggage 不决定租户、用户、采样优先级或父 Trace，不向模型供应商透传身份 baggage。Span ID 是 16 hex、Trace ID 是 32 hex，均不得全零。

Backend 只增加通用 OTel 接线，不引入 LangChain/Langfuse 业务框架；P2 BFF 的少量安全根 Span 可经标准 OTLP 出口或后续 Collector 发往 Langfuse。端点/密钥由服务端组合根持有。通用 DB SQL 文本与 bind parameters 默认不采集。Langfuse exporter 默认不接所有 APM scopes，按目的筛选；被过滤的外部父 Span 可以存在，但需要明确文档/界面语义，若要求完整树则导出对应安全父节点。

ASGI 入口 call_next 返回不是 SSE 结束。BFF/Agent Span 的结束应挂在 stream generator finally，并测试客户端断开；禁止只在 HTTP middleware 包一层就宣称覆盖全流。asyncio.create_task、to_thread、线程池、MCP SDK 各自传播方式要验证；手工线程必要时 copy_context/OTel inject，且每并行任务独立 context，禁止共享 attach token。SkyWalking 仅作为未来接收端选项，先验证实际部署版本的 OTLP/W3C 支持。OTel Python propagation。

4.2 模型用量、延迟、重试和成本​

实际代码缺口已见审计：ChatOpenAI 自定义 base_url 没启用 stream_usage，已有 Callback 只读一种 LLMResult 用量；辅助 Judge 只留下部分 input token，路由 classify 丢弃 usage。

后续统一提取顺序：原始 AIMessage/最终聚合 Chunk 的 usage_metadata → response_metadata.token_usage / LLMResult.llm_output.token_usage → 供应商协议字段。只选择一份可信原始结果，不相加同一累计 usage；非负整数校验，拒绝 bool/负数/NaN，partial 单独标记。Provider/request_id 来自校验后的响应；Higress requested_model、resolved_model、route alias、cache hit 仅在真实可获得时填写，缺失不猜。

状态定义使用方式
actual供应商响应或明确经过网关透传的真实计量写 generation usage_details；注明 source 与 complete/partial
estimated明确 tokenizer/版本和输入定义的本地估算仅独立 estimated_* metadata；禁止混入 actual Usage 汇总
missing上游未返回、被取消、网关不支持或错误响应无法确认空值 + reason；不能填零或伪造完整 total

P1 对 Qwen/Higress 合成请求验证显式 stream_usage=True/include_usage；可用才改源模型设置。比较非流式原始计量和流式最终聚合，验证思考/缓存 token details 的定义。缺失时不靠获取用户正文再做后台 tokenization 补“真实用量”。官方 Callback 已产生的 generation 不外层再建一条 generation；补字段应更新原 observation 或按业务调用引用的安全元数据，无法可靠更新时保留缺失。

成本分四类：供应商实际费用（需要账单/明确返回）、实际 Usage × 已审核价格的计算成本、估算 Usage 的估算成本、缺失。价格需模型真实映射、币种、输入/输出/缓存/思考/图片单位、生效时间、合同折扣来源；无价格时 cost=null。即使 Langfuse UI 自行推断 token/cost，也不得计入 Chein 的实际口径。metadata-only 无正文可以减少推断，但仍要测试自动价格推导；禁止把 unknown cost 填 0。官方 Token/cost。

统一主键 (environment, model_call_ref/provider_request_id, invocation_attempt) 对账。同一次调用的 Langfuse/Higress 记录只选一个用量来源；网关计数包含流量重试/缓存时，要分别显示 logical invocation 和 physical attempts。SDK 内部 HTTP retry 没有独立 Callback generation 时记 attempts=unknown，不能以 graph 重试次数替代。已实际重做的独立模型 invocation 保留所有费用；重复 trace 上传按 Span ID 去重。采样 Trace 不作为全量账单/预算扣减依据。

延迟定义：model_ttft=调用开始→第一个模型 chunk；server_ttft=执行开始→第一个可见文本 yield；browser_ttft=点击发送→第一个文本进入 UI；generation_duration=首请求→最后响应，包括工具参数/思考的时间另标。输出 tokens/s 只用 actual output_tokens/定义的生成窗口，不能拿 chunk 数冒充 Token 输出速率。取消导致 usage 不全时吞吐 null。

4.3 RAGFlow、重排和引用​

在既有 search_knowledge 分解 plan/catalog/route/fetch/judge/feedback 阶段；Callback Tool 是总外壳。每 fetch 标 attempt_index、reason（initial/rewrite/expand）、authorized/selected base count、profile hash、candidate_count、context_count/char_count、truncated、evidence_status、no_result_reason、citation_count、反馈复验结果。仅对 ACL 内 ID 做 HMAC，不记录 query、rewrite、chunk 原文、目录描述/文档标题。

需要区分三个来源：主模型本已把对话改写成 Tool query；辅助 QueryPlan 可拆查询；EvidenceJudgment 在有界循环中可要求重写/扩库。记录触发方式与次数即可，不复造第二路由器。

RAGFlow 当前返回最终 similarity/term/vector 分数，重排在远端内部。只有 fetch 总耗时和可获得最终排名，没有独立 rerank 耗时或完整 pre-rerank 列表。这两项字段置 unavailable，不从总耗时拆分或编造前排名；将来供应商提供阶段 DTO/Span 才增补。部署 RAGFlow MCP 只作为可选适配，不重复提供第二知识检索 Tool。

既有 KnowledgeRetrievalTrace 保存原/改写查询及候选目录，仍属 Chein 受 ACL 控制的业务记录；不能直接整条同步。业务 retrieval UUID 留在 retrieval_ref；未来日志中的 OTel trace_id 保持真正链路 ID。回写证据反馈时重验文档状态的失败不能因 Langfuse fail-open 而绕过。

5.2 流式执行与取消​

根观测从 events() 内建立，在 graph、事件/状态完成或取消/异常退出的 finally 中结束。不能仅装饰返回 StreamingResponse 的函数：那会在 generator 真正执行前结束根。generator 内明确绑定安全 request/run/trace 上下文，避免只依赖 middleware context 在响应头返回后的生命周期。

对 messages/updates/custom 原有分支保持原顺序，常态只记录首 chunk 时间和末尾汇总，不为 Chunk 调用远程 API、不在 yield 前 flush、auth_check 或在线 Judge。BFF 继续逐字节透传。记录 CancelledError/GeneratorExit/lease_lost 时必须保留原控制流，不转换为观测错误；停止后禁止新模型/工具调用，已发生的费用/外部效果不能删除。

不可用观测按以下区分处理：SDK import/init、Span/属性更新、mask/export 异常→禁用本次/进程观测并记限频本地事件；业务 await/HTTP/DB/checkpoint 抛出的异常→按现有业务逻辑处理。禁止一层 try/except 包围整个 Agent，把业务异常吞掉后重跑。SDK root context 若会自动记录异常 event/status.description，生产接线要显式管理 Span 生命周期、只导出错误码，并确保业务异常仍向原路径传播；不能只依赖 mask hook 擦除不可修改的事件。

关闭开关应跳过 SDK 初始化/handler 注入；只写 tracing_enabled=false 而仍启动 score/media 线程不算完整关闭。P1 采集/脱敏无法保证时禁用 Langfuse，不能降低业务隐私门禁。

7.2 用户反馈与 Scores​

拟议流程：assistant-ui 动作（赞/踩/分类错误/人工纠正/成功确认）→已认证 Chein API→当前会话/Run/消息归属校验→Agent-owned feedback 持久化→后台/受控发送到 Langfuse create_score。前端只提交业务 message/run 引用，trace_id/user/tenant 由服务端映射；历史消息需要从持久化消息映射，不依赖当前页面 runRef。

反馈记录至少 tenant/owner/run/execution/message、kind/value/category、server timestamp、revision、score schema/evaluator version；纠正正文留 Chein 受控存储。Score 类型采用 numeric/boolean/categorical 的稳定 v1 口径，user_vote 与 task_success 分离。每用户/消息/维度稳定 Score ID，改赞踩更新同一 Score；人工更改保留本地 revision 审计。模型 Judge Score 与用户 Score 不覆盖彼此。

SDK create_score(trace_id=..., name=..., value=..., data_type=..., score_id=...) 具体参数在 P4 对固定版本确认；跨服务发送用受控 API/SDK，不直连生产业务数据库。未采样 Trace/未导出时反馈仍保存 Chein，外发可标 unlinked，不能制造一条空 Trace冒充已观测执行。同步请求不等 Langfuse，发送失败允许重试；长期自动队列若届时确有需求，遵循现有可靠任务/Outbox 契约，别新建 Redis 旁路。新 feedback 存储/异步任务必须另走 migration/tenant 隔离测试。

7.3 规则、人工、LLM Judge 和决策模型复用​

方法优先用途限制/成本
确定性规则QuerySpec、AST、schema、引用 ID、gold 数值、权限反例不能自动评价自然语言语义完整性；复用测试/evaluator
人工标注金额/制度/权限关键样本、gold、争议裁决需要授权查看受控内容，记录 reviewer、版本和分歧
System One知识充分性/是否满足指定要求/有限类别的离线 Judge当前适配只校验 choice/noul；score 类型须另行扩展，不能假定已支持；不可作授权器
生成式 Judgefaithfulness、citation entailment、回答语义在合成/审核脱敏证据上评估；额外 Tokens；不可靠自评，需要 gold 校准
Langfuse 在线/批量 evaluator内容已获批外发时按 observation/rule 评估v4 为 observation 模型；实例/许可/模型 endpoint/供应商协议须核实，不能沿旧 trace-level 设计

生产 metadata-only 不能在 Langfuse 端凭空评价回答准确性/忠实性。默认由 Chein 受控离线 evaluator 读经批准内容并复验授权、调用已批准模型，只外发 typed Score。先少量人工/规则，Judge 独立预算、并发、timeout、失败状态和项目；不能在 SSE 关键路径增加 token 请求。

System One 复用现有 decide HTTP 协议，但评测运行在独立进程/配置，避免评测过载触发线上路由的共享冷却。它可以做有限判定，不自动等于 Langfuse UI 的某个预置 evaluator 协议兼容。随机排列候选、盲化模型身份、注入反例/文档指令、明确证据上限；不要求输出隐藏思考。

建议首批 100–200 个合成或已审查用例，跨普通聊天、ERP、知识、组合、拒绝、无结果、取消/恢复分层；数值是设计规模。Judge 先与双人 gold 核对 confusion matrix、agreement、分歧；候选目标 agreement≥0.85、安全关键漏放=0，仍需团队确认且有限用例不证明全部安全。confidence 需观察校准，不当作正确率。关停/评测失败产生 unknown，不填低分/满分混进质量平均。

每日额外成本估算：N_evaluated × avg_judge_input/output_tokens × 审核价格，System One 按真实 input-only 计量。候选在线比例 1%、每 Run 最多一次/规定维度、日预算≤业务计算模型成本5%（业务待决）；先绝对预算上限，模型 cost 缺失时禁止用比例预算推导无限额度。

7.4 数据集、实验与发布闭环​

不能自动把生产 raw Trace 一键升级为 Dataset。metadata-only Trace 只有定位能力：内容需从 Chein 授权域受控取出；租户撤销、数据删除、许可失效则拒绝导入。Dataset 保存合成/脱敏 input、expected_output、gold evidence、allowed capabilities、scenario、rubric/version、reviewer_ref、source_trace_ref、retention/deletion policy；dataset item 不是原 Trace 的镜像。

Experiment 在隔离 tenant/合成 ERP/KB 上运行同一应用授权路径，不能绕过 MCP/RLS 直接调用业务 ORM或允许生产写入。固定 checkpoint 起点、数据快照/日期、时区、检索 profile、toolset/model/prompt/schema 与 Git/lock 指纹；相同病例成对比较，随机分组、每变体多次重复。设置最大并发/调用数/Token/运行时长，失败/timeout/拒绝计入统计，报告 N 与置信区间；共享数据库试验串行执行。

每次只改一个主要变量（prompt/model/tool strategy/retrieval profile；Skills 有真实执行版本后才比较）。安全负向零失败是门禁；质量提升同时比较延迟、拒绝率和成本，不能只优化平均 Score。评测 Prompt 不允许修改生产 Nacos latest；审核后走既有发布和回滚。

Nacos 当前 resolve_prompts 仅返回合成正文，Agent prompt.applied 只有 hash/source，不是完整可重放发布快照。后续在已有读取中捕获实际 Prompt 版本/模板 digest，传安全 provenance DTO；组合提示词还需记进度/分析附加说明版本。版本不能在 latest 读取后另请求一次并假定同一版。运行恢复若按既有行为重新解析 Prompt，则不同 execution 分别记录实际版本；不要悄悄改成固定 Prompt 恢复。

默认不启用 Langfuse Prompt Management。若以后需要 UI Prompt 对比，可把已批准非敏感发布产物单向镜像为只读实验资料；不能反向运行/发布回 Chein。迁移唯一事实源需要独立 ADR、全调用者审计、兼容/回滚设计和人工签署，不能本次顺带完成。官方 Prompt link、Experiments。

9. 容量与运维成本模型​

服务器实际资源和流量未知，下面是假设驱动的预算模型，不是生产实测配置。官方单机 Compose 起点为 4 CPU/16GiB/100GiB SSD 的整套环境，不等于两个新增 Web/Worker 容器开销。官方 Compose 部署。

变量：日逻辑请求 R，平均 execution/request E（恢复/重领增加），采样概率 p，Observation/execution O（框架节点、辅助调用和业务 Span全部包含），平均脱敏编码字节 B，保留天 D，实测 CH 压缩系数 c，副本数 r，安全余量 h。

trace/day = R × E × p
observation/day = trace/day × O
原始观测 bytes/day = observation/day × B
CH 基础数据量 ≈ 原始/day × D × c × r（另加索引/merge/日志/元数据）
S3 原始 event 量 ≈ 原始/day × event保留天（再按实际编码、压缩、版本测）
总磁盘预算 ≥ (CH + S3 + PG + logs + 临时 merge/备份) × h
峰值 observation/s ≈ 峰值 execution/s × p × O
各 worker queue 理论缓存秒 ≈ queue_count / 本 worker ended_span_rate

取假设 E=1.1、O=25、B=2KiB、D=30、c=0.3、r=1、h=2、p=1。2KiB 是设计样本均值，不是 metadata 上限；活跃大 payload/评测成本需另算。1GiB=2^30 bytes。

假设规模R / 峰值 execution/sTrace/日；Obs/日原始GiB/日30日CH压缩基础；S3原始事件规划建议，待实验验证
小1000 / 11100；275000.0520.47GiB；1.57GiB单 Web/Worker 起步；按官方整套起点和共享实例余量核查，不据表承诺16GiB足够
中10000 / 1011000；2750000.5254.72GiB；15.74GiB先测 Worker/CH写入和merge；为 Langfuse 独立资源配额；候选生产10%减少诊断数据
高并发100000 / 100110000；27500005.24547.21GiB；157.36GiB峰值2500 Obs/s；按需多 Worker/独立Redis/CH，评估SSD/写入带宽/备份；不能直接外推 CPU最低值

10% 采样下观测数据各量约十分之一，但全量错误/usage 汇总和评测数据不按它缩减。长任务若 O=200，则观测存储/队列压力是上表8倍；恢复次数 E 增加同样放大。CH+S3安全预算仅按两者总量×2：小约4.1、中约40.9、高约409.1GiB；尚不含 PG、副本/历史迁移、备份和基础镜像/日志，不能拿此数当完整服务器磁盘。

每 execution 的 O 用 P1 合成 trace 实测，不假定 LangGraph 一个节点等于一个 observation。PG 主要项目/配置/评分/数据集与控制记录，需实测 schema增长；不能将所有 trace 总量都算为 PG表增长。Redis 内存估算用 pending ingestion jobs ×实测平均 job bytes 加索引/持久化开销；对象存储事件大小/生命周期与 CH留存分别测。Web关注并发查询/分页/大树；Worker关注摄取与评估并发。网络预算以上表 raw bytes 为基础，测协议和gzip，不把压缩后的 CH 体积当上传带宽。

以下为隔离压测环境的预算起点假设，不是实测最低配置、服务器采购建议或容量承诺；先统计已有Chein/RAGFlow/数据库占用，再讨论可分配量。峰值和长任务可能迫使升档，10%采样也不能按比例缩减进程基础内存。

假设规模整套Langfuse及专用中间件测试预算Web/Worker起步与扩展判据
小4vCPU / 16GiB / 至少100GiB SSD，沿用官方整套起点Web1、Worker1；预留CH merge、PG/Redis和备份空间
中候选8vCPU / 32GiB / 200GiB SSD；与业务共机时按增量分配而非覆盖其预算Web1、Worker1；Worker CPU/queue持续积压才试2个Worker；测CH写入和查询争用
高并发候选16–32vCPU / 64–128GiB / 1TiB SSD；副本/备份另计Web1–2、Worker2–4作为压测候选；独立Redis/CH优先，按2500Obs/s和长任务8倍场景验证

预算由上表数据量和冗余余量提出；CPU/RAM还取决于评测并发、查询复杂度、压缩、CH merge、网络/磁盘速度，不能从request/day唯一推导。验收后用实测峰值核秒/Obs、RSS、队列drain rate重新估算并保留30%以上资源余量；这些配额未在本次部署设置。

运维成本包括主机/磁盘/备份、跨机/VPN带宽、CH merge/Redis容量、人员/升级、可能的 EE许可和 Judge模型费用；没有报价/真实业务量，不能报货币成本。Tailscale仅是受控连通，不证明 TLS、吞吐或应用权限。

建议保留期候选：prod metadata 30天、dev合成7天、经批准 gold Dataset 90天后复审；待业务决策。原生自托管自动 retention 属 EE；OSS 上上线前必须选定许可功能或已验证的公共删除API/运维清理方案，分批/限速且核对 v4数据模型，禁止直接改 CH内部表 TTL。清理要覆盖 CH、对象事件/media、Score、dataset/experiment/备份；dataset 不随 trace自动删除，不将 S3lifecycle 当全局清理。官方保留期。

备份/恢复复用部署文档：PG+CH+事件bucket+私有配置和解密密钥的一致可恢复组合，Redis共享实例恢复不得覆盖业务队列。候选 RPO24h/RTO4h 为待业务决定的目标，恢复到隔离环境验收。Langfuse自身升级回滚涉及数据库/写入模式，不能只换旧镜像；Agent观测回滚不动任何 checkpoint/业务库。
