Neo4j 与 Legacy 双 Provider

状态：2026-10-24 双 Provider 基线及历史验证记录。2026-10-25 的标准语义、独立工作室、迁移、真实模型与当前验收以十一阶段交付为准；下文早期能力/验证范围有日期限制。

现状与改造边界​

modules/ontology 已拥有 PostgreSQL ontology.network/version/audit/candidate、private/tenant scope、FORCE RLS、双人审核和不可变发布版本。application/service.py 管理发布；application/runtime.py 编排 search/describe/query/traverse/metric/action；ontology.data 由 ERP 提供当前授权目录及实时数据，ontology.evidence 由 Knowledge 复验文档来源。原七类 ERP 映射复用原 capability；2026-10-25 增补销售/库存/仓库固定映射与只读诊断，不建立第二套 SQL 查询框架。

用户消息 → api.py 加载获准 MCP 工具 → DeepAgents 规划 → mcp_tools.py interceptor 重验注册契约 → Backend MCP 验 delegation → Ontology UoW → 当前发布指针/目录摘要/来源 → Provider → 当前权限过滤 → MCP ToolMessage → 下一次模型规划/回答。不存在预先整图注入 System Prompt 的阶段；继续复用 ToolMessage、原有压缩与 checkpoint。

当前 DSL 有对象、属性约束、关系、固定只读 Action、Metric、分组、别名、来源和可选 semantic 扩展；支持受控类/属性层级与样本 SHACL，没有任意业务规则表达式、写 Action、OWL DL 推理或任意图查询。两种 Provider 必须显式报告这些能力差异。ERP 实例仍由 ERP 持有，Neo4j 不复制业务行、Memory 或文档正文。

双 Provider 与数据所有权​

保留 PostgreSQL 为定义、审核、发布和 ACL 的唯一事实源。Legacy 从通过授权的发布版本取模型；Neo4j 从同一版本的显式图投影取模型。统一接口只负责读取发布语义快照，不重复实现现有六个查询接口。业务执行始终经过当前 ERP capability。

Neo4j 使用固定标签 Snapshot/Element 与固定关系 CONTAINS/RELATES_TO。快照身份包含 tenant、network、owner、scope、version、definition digest、catalog digest。Element 按 section/code 保留稳定业务标识及有界 JSON payload；对象关系额外生成图边。加载时校验所有元素的快照键、顺序、完整模型摘要和当前 PostgreSQL 摘要，禁止读取任意孤立节点、跨快照边或外部 RDF 自动生成的模型。来源、分组与属性约束无损保留；不存在的规则能力明确 unsupported。

投影通过受 ontology:publish 与 ontology:query 保护的显式接口执行；重新验证当前发布版本和来源，事务原子写入，重复操作幂等，已存在但不匹配的投影拒绝覆盖。普通工具只有固定读取 Cypher；不向模型暴露 Driver、Cypher、数据库身份、导入 URL 或写权限。不自动迁移、同步或混合两套数据。发布新版本后必须显式投影，否则 Neo4j 失败关闭。

选择与故障​

配置走已有 Backend Nacos bootstrap；目前不是动态订阅，切换需重启 Backend，进行中的 Run 不迁移或重做。默认 auto；未启用 Neo4j 的现有安装仍用 Legacy；显式启用后优先 Neo4j。neo4j 模式禁用自动回退，配置不完整报配置错误。

每个工具/HTTP 请求冻结配置并固定一个 Provider，包括嵌套 Action→Traverse。Auto 只对连接不可用、会话失效和明确超时回退，且须显式开启 fallback。回退重跑整个只读查询，丢弃先前全部候选，不混合 provider；每次结果和观测都带实际来源与回退原因。同一 Run 的后续工具仍重验当前发布指针，可能明确记录恢复/回退；不持久化授权结果或跨用户缓存。禁止把一次请求固定 Provider 误称为跨部署版本的 Run 全局锁定。

空查询结果不回退。缺失投影、摘要不一致、权限拒绝、Schema 不兼容、代码错误均失败关闭。完整模型摘要匹配是回退前提；没有可验证发布快照就不回退。没有无限重试、隐式图数据合并或对外泄漏数据库原始异常。

统一上下文​

保留六个 v1 工具原字段，增加 provider/requested_provider/fallback 元数据及结构化 ontology context，包含对象、关系、带稳定 ID 的属性约束、Action 契约、版本、定义/目录摘要、来源、显式能力集合与权限。先按当前数据目录过滤，再有界构建；预算不足按 schema 顺序批量削减尾部，保留对象 key/display_key 属性，并明确 truncated，不能截断 JSON 或伪造精确 Token。字符硬上限兼顾中英文；ONTOLOGY_CONTEXT_MAX_TOKENS 以 UTF-8 字节上界保守约束当前 byte-tokenizer 的工具正文，不包括消息 framing，也不等于实际模型计费。实际 Token 仍由既有模型 usage 提供。本次报告字符数及此保守上界。

关系路径使用现有至多三跳实例遍历，真实数据及每个端点仍由 ERP 授权。Neo4j 图保存 Schema 关系，不把 Schema 路径当成业务事实。搜索无匹配仍返回正常空结果，普通问答按既有 Agent 策略继续。

可观测性​

Backend 现有通用 metadata OTLP → Langfuse；Agent 已有 Langfuse SDK/原生 callback 配合相同 stage。复用已签 delegation 后的 W3C traceparent 传播，不增加 SDK 或独立根 Trace。新增 resolve_provider/retrieve/build_context/inject_context/fallback stage；Agent 成功返回 MCP 工具结果时标记交付上下文，不能据此声称模型已经正确引用。

字段只放固定枚举、布尔标志的枚举表示、数量、版本数、字符预算和耗时；不记录问题、模型正文、来源 ID、tenant/user ID、URL、连接凭据、Cypher 参数或原始异常。本体版本可用于评估分组，来源引用只在本人授权工具结果中保留。观测失败不改变执行。

连接、部署与 n10s​

使用官方 neo4j Python Driver：进程级连接池，独立 Session，连接/池获取/事务超时、有界返回，应用退出关闭。原有 Backend Dockerfile 已按 lockfile 安装依赖，不新增镜像安装旁路。新增独立 Compose，不启动或改写现有部署。运行期查询与显式维护操作分离；Community Edition 缺少细粒度数据库权限时，网络隔离及 Chein 当前授权不可省略。

n10s 除官方过程可用性探测外，当前执行受控 RDF 预览和已发布 Schema 类别推理；SHACL 使用隔离进程的模型局部样本门禁，详见当前范围。n10s 不是完整 OWL DL 引擎；外部 RDF 不直接变为获准 Chein Schema。按实际安装版本启用插件，APOC 仅在确有 JSON-LD 等需求时启用，不使用任意插件 URL。参考 Driver、事务、n10s、n10s 安装。Context7 本地连接返回 API key 错误，本次以官方文档及安装源码核对 API。

验证与回滚​

验证 Provider 三模式、只对可回退错误切换、正常空结果、权限/Schema/版本错误不切换、全请求一致性、并发 ContextVar 隔离、池复用/关闭、固定参数化查询和元数据脱敏。真实 Neo4j 集成测试使用随机 scope，只清理该 scope；PostgreSQL 使用已有一次性测试数据库脚本串行回归发布、RBAC、owner scope、RLS 和 ERP 查询。采购订单/供应商/明细/商品是真实已有业务示例；销售订单/出库/库存映射、固定只读诊断及真实模型验收已补齐，见当前证据。

记录 Legacy/Neo4j 相同采购问题的发现、描述、实时查询与关系遍历结果、字符/Token 上界和 P50/P95；Mock 模型工具选择仅证明链路，真实模型回答质量、真实 Langfuse UI、部署负载、n10s RDF 导入/SHACL 与安全运维为独立验收。

回滚：Nacos 改 ONTOLOGY_PROVIDER: legacy，重启 Backend。应用策略回滚不删除图或旧本体；新增工作区 PostgreSQL 迁移与降级限制见当前交付，不得直接降级丢弃语义分类；不修改旧本体，不改 Run/checkpoint/RAGFlow。关闭 Neo4j 容器前先切回 Legacy。新增 HTTP 接口/响应字段为兼容扩展，客户端通过原生成器维护。

使用方法​

  1. 在项目外创建私有插件目录，按官方 release 下载与数据库版本相符的 n10s JAR，核验发布方签名/摘要后放入目录。本 Compose 固定 neo4j:5.26.32-community，版本来自 官方 5.26 补丁记录，不能因插件发布号相同就退回 5.26.0 数据库。候选插件为 n10s 5.26.0；本次尚未完成该组合的运行验证，不宣称兼容。不要仅凭大版本相同就升级镜像/插件。本地无法运行插件时不能宣称 RDF/SHACL 验证成功。APOC 默认不安装；JSON-LD 等功能需要时单独验证版本。
  2. 私下设置 NEO4J_PASSWORD、NEO4J_PLUGINS_DIR，运行 docker compose -f compose.ontology.yml config --quiet 和 docker compose -f compose.ontology.yml up -d。端口只绑定 localhost；跨主机部署使用私有网络与 TLS，不能直接向公网开放 Bolt。该 healthcheck 只确认 Bolt 端口启动，完整授权/过程健康使用下一步命令。
  3. 把 deploy/nacos/ontology-backend.patch.yaml.example 合并到现有 Backend runtime Data ID；先保留 ONTOLOGY_PROVIDER: legacy，启用 ONTOLOGY_NEO4J_ENABLED 并私下填写完整地址/数据库/账号/密码。当前 Nacos loader 不展开 YAML 内 ${...}，凭据必须由已有私有配置注入。Backend 重启读取配置，Agent 不需要数据库凭据。
  4. cd backend && uv run python scripts/ontology_neo4j.py init 显式创建快照唯一约束；uv run python scripts/ontology_neo4j.py health 检查数据库版本、可执行 n10s 过程/函数。n10s_version: null 表示当前探测未取得插件版本，不代表兼容性已通过。初始化使用具备建约束权限的受控 Neo4j 账号；运行期不自动执行 DDL。
  5. 使用当前本人登录态，显式 POST /api/v1/ontology/networks/{network_id}/versions/{version}/neo4j-projection，要求当前 ontology:publish、ontology:query、模块权益、可见网络及来源有效。状态为 projected 或 unchanged；图提交后再次复验当前发布指针并记录 PostgreSQL 审计。若 PostgreSQL 后续审计失败，图快照可能已存在；重试为幂等，图存在本身永远不能授予读取权。每个当前用户可见的已发布网络都应投影；发现缺失投影会返回 409，不降级掩盖同步缺口。
  6. 配置改 ONTOLOGY_PROVIDER: neo4j 或 auto，重启 Backend；auto 只有显式配置 ONTOLOGY_FALLBACK_ON_ERROR: true 才对连接/超时回退。GET /api/v1/ontology/providers/health 受 ontology:read 保护，返回配置模式及健康；单个工具响应的 provider 才代表该次实际读取。没有新增前端设置页面，使用已有 Nacos 运维入口。
  7. 旧 Studio 继续管理 Legacy，/ontology-neo4j 独立管理语义模型。原六个工具输入保持兼容，新增 semantic/diagnose 工具需按现有流程审核发布；客户端通过 pnpm generate:api 生成。

Langfuse 中打开既有 Run 的 Trace，过滤 ontology.resolve_provider、ontology.retrieve、ontology.build_context、ontology.inject_context、ontology.fallback。Backend 使用 langfuse.observation.metadata.ontology_provider 等白名单字段，Agent 使用原 stage adapter；resolve/query/retrieve 能区分 requested/actual provider，失败子 Span 保留错误类型，fallback Span 保留最终降级来源。inject_context 仅证明工具结果交付至 Agent adapter，不证明最终回答已正确引用。既有 tracing 开关关闭时仍正常执行，真实 Langfuse 配置及部署方式继续遵循 现有交付。

独立验证：uv run pytest tests/modules/ontology/test_providers.py -q 不使用数据库 fixture。数据库回归复用 uv run python scripts/test_creation_isolated.py tests/modules/ontology -q --tb=short，创建、迁移并清理一次性数据库。真实图测试改用正常 runtime Nacos 连接，由 scripts/verify_ontology_workflow.py --live 显式启用；不配置独立 TEST 连接。普通数据库回归未启用 live 时，两个图专有测试明确 skip；早期采购 Mock 延迟不能作为 Neo4j 性能结论。

实施验证记录​

代码位置：backend/app/modules/ontology/application/ports.py 定义内部读取契约，providers.py 管请求级选择/回退，context.py 管有界语义；infrastructure/neo4j.py 为官方 SDK 图适配器，runtime.py 是原六个工具共同入口；routes.py 新增健康和显式投影。Agent 只改 harness.py 的获准工具规划说明及 mcp_tools.py 的交付观测，未新增图连接或模型框架。共享 stage 白名单位于 observability/src/chein_observability/stages.py。
