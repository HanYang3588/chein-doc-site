ERP 接口约定与排障手册

状态：操作与事实说明（以各 *_routes.py、public_api/dto.py、platform/web_api 为准）。

适用范围：ERP 的 HTTP 接口调用、权限、幂等、错误码与常见故障定位。

1. 接口约定​

  • 前缀：/api/v1/erp（模块 ModuleDefinition.api_prefix）。
  • 权限：所有业务接口都通过 require_module_access("erp", "<权限码>")； 权限码规则是 erp:<资源>:<动作>，动作有 list / create / update / delete / approve / reverse / export / query / read / execute（assign 仅用于仓库授权 erp:warehouse:assign；query 仅用于统计 erp:statistics:query； read 用于 erp:reconciliation:read 与 erp:finance-sensitive:read； execute 仅用于手工对账 erp:reconciliation:execute）。 完整清单见 backend/app/modules/erp/module.py 的 menus（共 132 个权限码）。
  • 列表接口统一参数：page、page_size（分页规范化在 normalize_pagination）， 以及按业务可选的 keyword、product_id、supplier_id / customer_id、owner_id、 status、remark、business_from、business_to。 business_from > business_to 返回 422。
  • 数据范围：列表、详情、审批、反向、导出都叠加两层过滤—— owner_id（业务归属，非超管只能看自己的）与仓库授权 （warehouse_user_grant，单据涉及的仓库必须全部授权）。
  • 导出：GET /api/v1/erp/<resource>/export，返回 CSV，单次上限 100000 行， 与列表接口使用同一套范围条件；以 = + - @ 开头的字符串会被加上 ' 前缀防公式注入； 导出成功写 document_action_log（action = exported）。
  • 统计：GET /api/v1/erp/statistics/summary（today/yesterday/month/year 的采购与销售金额）、 GET /api/v1/erp/statistics/time-series?type=purchase|sale&start=&end=&granularity=day|month 都要求 erp:statistics:query；口径是只统计 approved 单据， 时间范围按 erp_setting.timezone 折算到 UTC 边界，采购/销售金额均扣减退货； 统计同样叠加 owner_id 与仓库授权两层数据范围（与列表接口一致）。

2. 写命令的幂等与乐观锁​

所有 approve / reverse（以及部分 create）接口：

  1. 必须带请求头 Idempotency-Key（1~128 个可打印 ASCII 字符）， 服务端只保存其 SHA-256（command_receipt.idempotency_key_sha256），不保存原文。
  2. 必须带 body expected_version（DocumentCommand / DocumentReverseCommand）。
  3. 幂等判定：同一 (tenant, command_name, key) 再次提交
    • 请求体哈希一致且已完成 → 直接返回首次结果（重放，不重复执行）；
    • 请求体哈希不同 → 409（密钥复用）；
    • 上一次仍在执行 → 409（处理中）。
  4. 完成后写入 resource_type、resource_id、resource_version，到期后由 计划任务 erp.command_receipt.cleanup 清理。

3. 常见错误码​

状态典型 detail含义与下一步
403Not enough permissions权限码缺失，或单据不在你的 owner/仓库范围内（超管除外）
404Purchase receipt not found 等单据不存在，或不在当前租户内
409... version conflictexpected_version 与当前 version 不一致（被他人改过）；重新拉详情再提交
409Purchase order must be approved 等前置单据状态不满足

409Stock is insufficient / Stock snapshot is stale库存不足 / 盘点快照过期（见 04-库存管理.md）
409Settlement amount exceeds source balance核销超出来源单据未结算余额（见 05-财务结算与核销.md）
409... has downstream documents已有下游单据（入库/退货/出库），不能反向
409... has approved settlement documents已被已审批收付款单引用，不能反向
409Attachments cannot be changed after document approval附件只允许在 draft 状态增删

503Agent delegation 未配置平台尚未配置委托签名密钥（AgentDelegationNotConfiguredError），非请求本身错误

4. 症状排查清单​

症状优先检查常见原因
列表少数据 / 看不到某张单该用户的 owner_id 与仓库授权；请求是否带租户上下文单据归属别人、单据涉及未授权仓库、跨租户访问
统计金额与列表合计不一致统计只算 approved；列表可能包含 draft；时区边界有未审批单据、跨时区日界差异、退货未扣减
审批报 409 版本冲突单据当前 version、是否有并发/重复提交前端用了旧的 expected_version；同一单据被重复审批
重复点击审批没有报错但也没重复过账command_receipt幂等重放（这是预期行为），核对 resource_version
单据"审批后又变回草稿"document_action_log 的 reversed 记录被反向冲销过（反向即回到 draft 并 version + 1）
库存数量与业务直觉不符stock_ledger 明细其他入库/出库、调拨、盘点也会改库存；反向分录成对出现
erp_setting.integrity_status = degraded最近一次 reconciliation_run见 06-对账与一致性.md
导出行数与列表不一致导出上限 100000、过滤条件是否一致超上限被截断、导出未带相同筛选参数

6. 快速取证 SQL​

某用户当前能看到哪些仓库

SELECT w.id, w.name
FROM erp.warehouse w
LEFT JOIN erp.warehouse_user_grant g
       ON g.warehouse_id = w.id AND g.tenant_id = w.tenant_id
      AND g.user_id = '<user_id>'
WHERE w.tenant_id = '<tenant>' AND (w.is_active OR g.id IS NOT NULL);

某单据的完整生命周期轨迹

SELECT occurred_at, action, old_status, new_status, old_version, new_version, actor_id, reason
FROM erp.document_action_log
WHERE tenant_id = '<tenant>' AND resource_type = '<resource_type>' AND resource_id = '<id>'
ORDER BY occurred_at, new_version;

最近的历史写命令（幂等凭证）

SELECT command_name, status, resource_type, resource_id, resource_version,
       created_at, completed_at, expires_at
FROM erp.command_receipt
WHERE tenant_id = '<tenant>' AND command_name LIKE 'erp.%'
ORDER BY created_at DESC LIMIT 50;

单据的附件

SELECT document_type, document_id, file_id, sort, created_by, created_at
FROM erp.document_attachment
WHERE tenant_id = '<tenant>' AND document_type = '<document_type>' AND document_id = '<id>'
ORDER BY sort;

document_type 取值：finance_payment、finance_receipt、purchase_order、purchase_in、 purchase_return、sale_order、sale_out、sale_return、stock_in、stock_out、 stock_move、stock_check。
