OWL 规则、Agent 与计算任务集成

本文先于本次代码变更写入。基础计算边界继续以架构为准；本轮执行证据另见交付记录。ADR-0015 保持 Proposed。

数据所有权与输入​

在 OntologySchema 增加可选 owl_rules，每项有稳定 code/name/description 和有界 Turtle 公理正文；空列表不序列化，保持历史版本 digest。规则随整个本体版本发布，不引入独立的 ruleSetVersion：ruleSetVersion 就是本体 version + definitionDigest。编辑已发布版本产生新草稿，删除只影响草稿；恢复旧版仍须重新校验、审核和发布。SHACL 继续使用 semantic.shapes，业务操作仍留在原模块。

组装从 PG 受控声明生成 TBox，移除 CHEIN binding 注释，并逐规则解析后合并 RDF 图；不能直接拼接 Turtle 文本，空白节点必须分离。使用已有隔离解析进程、大小/CPU/三元组限制及 canonical blank-node + 排序 NTriples 输出，使相同正文得到相同 inputDigest。每个命名引用必须来自声明的类/属性及标准词表；OWLAPI 执行正式语法与 OWL2DL 全局限制检查。规则发布输入禁止 ABox 和 SWRL、远程 Imports、脚本。任意 RDF 注释不能冒充逻辑证明。

现有 ReasonerSource(networkId,version,definitionDigest,catalogDigest) 与 inputDigest/engineVersion/ontologyVersion 继续绑定结果；tenant/owner 来自签名身份。TBox-only 明确没有 dataSnapshotId，不能伪造 ERP 数据快照。用户上传仍是本人私有计算，不自动成为发布规则或实时事实。

初始高风险门禁： ERP 的分页/三跳遍历不是同一事务的完整 RDF 数据快照；初始 capability 没有跨资源快照 ID、边界完备性、更新失效与稳定实例 IRI 契约。禁止把该结果包装成“全量组织推理”。不得修改共享 GraphConfig/Namespaces/Shapes 或调用全库 /onto 来规避该问题。

用户确认后的 ERP ABox 增量设计​

用户在本次执行中确认首批范围为 ERP 采购、销售、库存，复用当前映射。以下设计先于此部分代码实现；组织用户/部门不进入该范围。

  • ERP 在既有 ontology.data capability 增加 reasoning-snapshot-v1，复用 _graph、固定 RESOURCES/RELATIONS、成员/RBAC、owner/仓库范围和 Tenant UoW。仅此操作的行读取使用独立 READ ONLY + REPEATABLE READ 事务，授权保留独立 READ COMMITTED 会话并在读取后复验当前权限/模块/owner/仓库签名。不得把 RR 事务中的旧权限当作当前授权。
  • 输入为已发布本体中映射的根对象/记录 UUID、1–3 跳范围；最多 50 节点/200 边/30 个数据查询和现有 SQL/总时间预算。只选择有语义类/对象属性映射的资源/关系。缺权限、未知映射或任何截断都失败，不提交 HermiT，不把遗漏当作零关系。
  • dataSnapshotId 是确定性排序后的行/边、选择器、catalog 与当前权限 scope digest 的内容哈希；asOf 只描述读取时点，不进入内容哈希。完整 OWL 输入仍原子保存在现有本人私有 journal，不新增业务表、队列或副本。相同授权内容可重建相同哈希。
  • IRI 固定为 urn:chein:erp:<可信tenant>:<数据所有者binding>:<UUID>，不使用 Neo4j 内部 ID，也不从模型 IRI 解析身份。相同 binding 的本体别名共享同一实例 IRI。模型只提供现有对象 code/行 UUID，ERP 先验证根及每个端点的当前可见性。
  • 类事实取发布映射，对象属性取发布关系绑定；数据属性必须有与 owner catalog/Property.type 相符的单一 XSD range。decimal 使用原有十进制字符串，boolean/integer 严格区分，dateTime 必须带时区；缺失值不生成断言，不生成否定或闭世界默认值。
  • ReasonerSource.data 绑定选择器、dataSnapshotId、scopeDigest、asOf 和固定 authorized-erp-subgraph-v1 范围。completeWithinScope=true 仅指本次授权映射/跳数内未截断；wholeOntologyComplete=false 始终为假，不声称全库一致性或全局否定。局部一致不证明隐藏/范围外事实全局一致，结果不能替代 ERP 写操作的事务校验。
  • 任务读取、结果、导出、取消及 Agent 历史重验重新取得同一授权范围快照；任何当前权限、数据、映射或版本变化导致快照哈希不同即失败关闭。不能缓存旧 scope，不把旧数据结果标为当前业务真值。查询返回原输入时间与快照引用。
  • 统一工具增加实例分类、对象属性与固定蕴含操作；types/property-values 可省略 entity IRI，由服务端从授权根生成；显式 IRI 必须属于该快照。属性必须来自发布声明，模型仍不能上传 OWL/SQL/URL/身份。TBox-only 旧请求继续工作，没有 ABox 的实例查询仍明确拒绝。

设计反例：读取根后并发修改下游记录，RR 快照不能混入新值；读取结束后撤权，由 RC 重验拒绝；根之外存在导致全局不一致的隐藏事实，不把本次局部结果冒充全局保证；超预算/截断拒绝计算。验证增加真实 app_runtime、跨 owner/tenant/仓库、并发更新、数据失效、数值/时区及真实 HermiT ERP 属性链测试。此设计不建立 OWL 自动业务写入能力。

发布门禁与 API​

复用现有 JSONB Version/Audit，无新增数据库表/索引/迁移，沿用现有 tenant/owner RLS。增加专用 validate-rules 计算操作：OWLAPI 解析/Profile、禁止实例断言、HermiT 一致性与不可满足类检查。不可满足类不等于全本体不一致，但本平台的规则发布门禁拒绝两者。

POST /ontology/reasoner/rules-validation 以 network/version/expected_revision 和 Idempotency-Key 创建当前保存正文的私有检查任务。Transition.validation_job_id 引用本人成功任务；每次 validate/submit/approve/publish 重新绑定当前完整输入哈希、schema/catalog digest、operation、状态和无截断结果，检查当前来源权限。执行校验或发布的当前用户使用自己的任务，不能跨 owner 读取他人 journal。私有及租户本体允许单账户直接发布 Validated 版本；历史 In Review 版本同样可发布，不再要求独立审核。TTL 到期需要重新检查，不能让旧证书永久放行。任何正文、类、映射、规则变化都会使旧任务失效；服务禁用或不可用时规则不能发布。旧无规则版本保持原生命周期。

任务继续使用现有 PENDING→RUNNING→SUCCEEDED/FAILED/TIMED_OUT/CANCELLED；终态不可被迟到写入覆盖，重启不自动重提。新增当前本人分页任务列表，Backend 对每项重验绑定的当前版本和来源；不可读条目不返回正文/错误详情。状态、时间、operation 筛选在服务端进行；不新增跨用户管理员正文读取权限。查询/导出/取消保持同一授权边界。

公开任务详情保留有界 entityIri/propertyIri/direct/typed axiom 参数摘要；完整 OWL 仅在私有 input journal，参数正文不写 ES。历史 journal 缺少新增摘要字段时按空值读取，不重算或覆盖输入。列表在本人 keyset 游标页内进行服务端状态、本体、规则版本、operation、创建时间及输入类型筛选，并逐条重验来源；ACL 或筛选可使页为空，仍须保留 next 继续读取。UI 可按当前本体/版本、状态、时间和输入类型筛选；跨用户/部门审计与独立触发来源筛选尚无授权/持久化契约，不从“读取本体”权限推导读取他人正文权限。

Agent、失败恢复与实时 UI​

只增加两个 MCP 入口：统一枚举操作的 ontology_reason_v1（当前已发布 TBox，可显式选择上述授权 ERP 快照，不接受模型 OWL/身份/URL），和 ontology_reasoning_result_v1（本人任务状态/有界结果）。显式事实继续 query/traverse，基础语义层级可用现有 semantic；只有需要 OWL 时 reason。无 ERP ABox 时工具不能声称推出真实实例关系。提交键在服务端由 Run/Thread/请求形成，重复调用不重提；读取可复用同一快照结果，但每次复验授权和数据摘要。不得通过工具偏好扩大已审核目录。

结构化 envelope 返回 job、输入范围、状态、可用于决策标记、错误 code/retryable/recoveryHint 和有界结果。PENDING/RUNNING 没有结论；consistent=false、truncated、失败、超时均无可用推导。未蕴含表示 unknown，非业务否定；asserted 区分原始断言与推导，不提供虚假的 HermiT 证明链。

不自动重提不明提交、不修改发布公理、不扩大权限；临时查询失败允许用户/下一轮重读同一 job，不无界循环。Agent 原生 middleware 限制同轮推理调用次数，并在不可用结果后阻止依赖推理的进一步工具执行；模型最终解释仍须独立真实模型 E2E 验证，提示词不是可靠性证明。

含 owl_rules 的版本不允许继续调用基础 semantic 类别推理（409 ontology_formal_reasoning_required），防止忽略正式公理后把不完整层级当成完整答案。显式实例 query/traverse 仍走原数据所有者；形式 TBox 查询只用 HermiT。手动计算在收到明确 202 后可以由用户重新发起新任务；不明提交保留原幂等键，不能盲重提。

UI 在 Neo4j Studio 内增加规则/推理任务面板，复用现有版本历史/恢复与权限；规则表单生成常见公理，高级模式保留 Turtle。assistant-ui 通过现有模块 ToolResult 分派渲染任务卡片，用真实 job 状态轮询；刷新后按持久化 jobId 恢复。只能展示已观测的队列/运行/终态，不伪造 OWL 内部阶段。停止轮询不取消业务事务；取消计算使用既有授权接口。

观测、安全与运维​

输入及完整结果留在已有有界私有 journal，保留期与磁盘上限见部署文档；关键发布 Audit 在 PG 事务内。ES 只索引 metadata（job/operation/status/error/duration/inputDigest/trace），不记录 OWL、JWT、敏感事实或系统提示。复用现有 trace headers 与 Java Micrometer；工具 Run/Thread/ToolCall 由原有 Agent RunEvent/ToolMessage 关联 jobId，不把客户端身份字段当鉴权。ES 故障不能改变成功状态；journal 持久化故障须拒绝任务。实际 ES 接收与按 Trace 查询须单独实测，不能仅凭日志调用认定完成。

威胁与反例：跨 tenant/owner jobId→404；撤权/换发布版本→读取失败；模型注入→当作数据、不提供脚本能力；Imports/XXE/SWRL→拒绝；不一致→无推导；全局 ontology 样本裁剪→不宣称完整；队列满/CPU/OOM→稳定终态；重复提交/取消竞态→既有幂等与锁；校验后编辑→哈希失效；审核人撤权→原链重新校验。

不引入运行时依赖、额外消息队列、图数据库或新鉴权。维持单实例单 Worker/有限队列/可杀 JVM。无共享全局 reasoner 实例；新引擎出现时才扩展已有 Worker 契约，禁止故障切换混用语义。回滚可关闭 reasoner；新规则版本会拒绝推理/发布，旧声明子集仍可查询。旧版本进程不认识新字段，因此启用规则后不支持未经兼容演练的 N-1 降级。

设计自检与验证计划​

自检：PG/ERP 所有权不变；规则与 SHACL 分离；真实 OWLAPI 为门禁；不改 Accepted ADR；不改共享图全局配置；新旧摘要兼容；有限私有任务；当前授权逐次检查；无默认全量推理/物化。ERP 仅按上述有界快照契约接入；组织或全库 ABox 无相应契约时保持关闭，不能以合成测试代替生产语义。

执行 Java21 mvn verify：真实继承/等价/互斥/传递/逆/链/存在/基数/实例/不可满足/不一致/Profile 与任务隔离；Backend 使用一次性数据库串行运行 lifecycle、hash/replay/revocation/owner/RLS/路由/模块边界；检查全部 ruff。重新生成 suite OpenAPI，typecheck、受影响 Vitest、base/items/suite build；UI 浏览器验证按项目截图归档规范。真实 Neo4j/n10s、Agent 模型、ES、Trace、网关与 Docker 仅在实际执行后记录通过；Benchmark 复用既有脚本，记录合成样本 CPU/RSS/堆/耗时，不能宣称生产 P95。

参考：n10s RDF 导出、基础推理、OWL2 Profile、assistant-ui Tool UI、LangGraph streaming。在线文档可能晚于 lockfile，接口以安装源码和测试为准；本次 Context7 返回 invalid API key，改查官方文档，不修改用户连接配置。

2026-10-27 审查修复设计（实施前）​

本轮修复复用既有边界，不把普通对话强制送入 HermiT，不引入新图存储、策略引擎或共享 Reasoner。发布审核、当前授权、ERP 事务仍分别由现有所有者负责。

  1. Agent 推理失败、证据复验失败、非蕴含和修正预算在模型与工具两层失败关闭。参数修正只允许同一正式推理工具的单次调用，不能夹带业务工具；历史完整性错误返回确定性说明，不清除证据后悄悄恢复业务执行。普通无推理请求继续原执行路径。
  2. 结果 envelope 增加逻辑裁决与原因、输入范围、查询公理和规则引用，明确不授予业务权限。未蕴含为 INDETERMINATE；错误、矛盾与逻辑结果分开。无证明链时明确为空，不让模型补造。
  3. 发布 Action 可声明可选 precondition（已声明类 URI、固定快照深度）。含 OWL/SHACL 规则但未配置前置条件的旧 Action 失败关闭。模型在现有 reason 工具提交完整 ActionQuery，由 Backend 从发布定义派生 ABox 与正向分类蕴含查询，将规范化动作参数摘要写入已有不可变 ontologyVersion 标签；执行入口要求本人 job 引用，核对摘要、版本、根、快照、正向蕴含及当前权限，前后复验。仍仅支持原固定只读执行器，禁止借此增加 ERP 写工具。新可选字段省略时保持旧发布正文摘要；API 客户端重新生成，MCP 契约需重新审核发布。
  4. 本体字段 required/range/precision 已由 runtime.property_value 执行，unique 与关系 cardinality 已由发布目录门禁保证，不能重复实现成错误的 OWL 闭世界断言。ABox 增加实际快照的唯一性/关系上界校验及显式 SHACL 门禁；检查只覆盖当前授权子图，不把范围外缺失当否定。
  5. 正式工具在既有 1000 条总预算内收齐结果页并复验同一不可变结果，分页不再冒充计算截断。轮询仅在内部读取本人计算状态，输出前仍完整重验来源；TBox 纯序列化使用有界进程内缓存，按完整正文失效，不缓存权限或实时 ABox。
  6. ERP 事实依据现有代码：年度统计沿租户时区及已审核入/出库减退货口径；采购订单指标仍保留其独立口径，不混称客户年采购额。合同、授信不在当前数据模型中；tax_no 可空且无唯一约束，不能据此自动 owl:sameAs。明确暴露不支持/无法判断，不创建虚构字段或按名称合并；业务实体仍使用数据所有者稳定 IRI。
