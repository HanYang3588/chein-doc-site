2. 方案与边界​

扩展既有结构化能力 video_generation，继续由同一个 DeepAgents 执行已授权 generate_video，沿用 HITL。业务 Job/Asset、额度、权限、存储生命周期归 Suite Creation；模型、补充 prompt 和 Token Plan Adapter 归顶层 Agent。独立 Backend 视频 Worker 只调版本化 Agent HTTP，无模型框架依赖。Worker 使用现有 leader runner，数据库到期时间即可靠队列，不增加 Celery、Redis Queue 或第二套 Scheduler。

3. 状态机​

生成中的删除返回 409，避免误以为远端已取消。供应商 cancel 能力未确证，不伪造取消。失败后再次生成是经确认、使用新 request_id 的新收费任务；submission_unknown 禁止直接重试，需运营核对供应商账单/任务。

4. 数据模型与事务​

Creation 独立迁移追加 video_generation_job（tenant/owner、幂等键、request hash、thread/message/run refs、VideoSpec JSON、原始/优化 prompt、creative_status_messages、provider/model、业务状态、provider_status/task_id/request_id、重试/错误、created/submitted/started/completed/last_polled/next_poll、预留 storage_channel/key、逻辑删除）。video_asset 保存 job 唯一引用、tenant/owner、channel/key、content_type、size、checksum、duration、resolution；width/height/fps 未测量时为空，不能把请求参数当实际元数据。

video_job_route 仅保存 job/tenant/owner 路由 ID，无 prompt/状态/结果；Worker 读取目录后逐 owner 进入普通双重 RLS scope。目录同时用于恢复未完成/待清理任务；完成后移除路由。全局状态计数由这些 scope 读取，不能用 RLS bypass 扫业务内容。Job、Asset 使用 FORCE RLS；扩展现有 Creation UoW，个人入口不能继承 maintenance。

幂等 (tenant, owner, idempotency_key) + request hash：同键同内容返回同 job，同键异内容 409。模型工具使用稳定 run 身份，工具重试/重复 tool_call_id 不重复收费，同一 Run 首期只允许一个视频需求。管理页 UUID request_id 覆盖网络重试和双击。

外部存储非 ACID：先提交 persisting 及确定 key，再上传，再同事务写 Asset、Job succeeded 和版本化完成 Outbox。DB 失败保持 persisting，重试覆盖相同 key，不 submit。失败/删除保留 key 至清理成功；清理也逐 owner 执行。通知写失败仅重试既有 Outbox，不能回退 Job 或重做生成。UserMessage 用 job UUID 的稳定派生 ID，重复消费由 InboxReceipt 和主键共同保护。

5. Provider / VideoSpec / Prompt​

2026-10-18 核实 Token Plan 多模态官方文档 与 HappyHorse 文生视频 API。Token Plan 主机与普通 DashScope 不互相回退；独立可配置 API base/key/model。默认模型 happyhorse-1.1-t2v；POST /api/v1/services/aigc/video-generation/video-synthesis 带异步 header，GET /api/v1/tasks/{task_id}。基线 5 秒、720P、16:9，轮询 15 秒。模型/参数由配置和严格 DTO 限定；不发送未经官方确认的 audio 开关。音效可表达在 prompt 中，不能保证独立音频轨。

VideoSpec v1 只接受 text_to_video、原始/优化 prompt、duration、resolution、aspect_ratio、受控模型和 creative copy；身份来自签名上下文，不是模型实参。references/edit/extend 首期拒绝，未来通过版本化 spec 新增受授权资源 ID；不预先接收不安全 URL。需要人物/首尾帧素材时由 Agent 澄清，不假装文生视频支持参考素材。

DeepAgents 已看到会话及个人偏好，传入完整用户确认描述。优化器只追加可选主体运动、运镜、光线/节奏细节，明确要求优先；失败用原文，输出有长度预算。保存两层 prompt。creative copy 由结构化优化输出生成，前端明确标注“创作氛围文案”，与真实阶段独立，不声明内部步骤已完成，不展示百分比。

6. API 与授权​

公开前缀 /api/v1/creation/videos：POST /generations（request_id + prompt + 参数），GET /generations/{id}、GET 列表（分页、状态、文本、模型、时间）、GET /{id}、GET /{id}/playback、DELETE /{id}、POST /{id}/regenerate。job ID 为库条目稳定 ID；Asset 只在成功时存在。

read/generate/delete/regenerate 权限为 creation:video:*；重生成还需 read/generate，播放逐次 read。API revalidates membership、模块权益及当前用户归属；内部创建接受既有签名 delegation，Worker 每阶段重新验证当前授权再签短期 Agent 操作令牌，不保存用户 JWT。403 权限，404 不属于本人/删除，409 冲突/忙/不明提交，429 额度/排队上限，503 未配置/Provider 不可用。私钥、Provider key、临时 Provider URL 不进入响应/历史/日志。

7. Worker / 并发 / 故障​

独立 CLI 复用 background_workers.run_worker 的 PostgreSQL session advisory leader lock；每 job 再有数据库 advisory lock，双 Worker 不可同时处理。终态路由保留至提交间隔冷却结束，限流窗口跨任务完成和进程重启保持；只有路由 ID 留在控制面。global/per-owner active、pending/daily cap、submit 间隔、poll 时间、最大重试、截止时间、下载上限全部配置。串行有界外部调用，远端生成并发由 DB active 计数控制；首期不需要线程池。leader 每轮核对锁连接；逐 job 锁与先落库的提交状态使 leader 故障不重复 submit。

queued 可以安全重试；submitting 失联标为 submission_unknown，不能证明供应商未计费；已有 task_id 的 job 永远 poll 原任务。查询 429/5xx/超时及存储网络故障使用指数退避+jitter，持久化 next_poll_at。UNKNOWN、明确 FAILED、过期失败关闭。Provider 下载只允许官方 HTTPS 结果桶，不跟重定向，不带 Authorization，限制 MIME/字节及 MP4 ftyp；结果使用有界内存，验证临时文件仅放系统临时目录。Redis 全部丢失无影响。Web/Agent API 重启后 Worker 继续按 DB 状态处理。

反例：Provider 已受理但响应丢失，供应商未提供幂等键/按本地 ID 找回契约，因此不能承诺 exactly-once。选择可能留下需人工核对的任务，不能选择自动重提扣费。

8. RustFS / Range / 前端​

复用 storage channel，key 与图片一致采用 prefix/agent-generated-videos/tenant/owner/job/source.mp4。private bucket，短期 presigned GET，固定 video/mp4、inline、private/no-store；浏览器直接发 Range，不经 Python 整文件播放代理。渠道地址必须浏览器可达；跨源需运维配置 GET/HEAD、Range/If-Range 及 expose Content-Range/Accept-Ranges/ETag/Content-Length。不能仅凭 SDK 签名断言真实代理支持 206。配置和验收脚本明确以 Range bytes=0-1023 请求验证 206/Content-Range、无凭据读拒绝和链接过期；实际版本/网关环境为外部门禁。

VideoGenerationTaskCard 只在工具返回后挂稳定 job ID，GET 立即恢复状态；轮询用于刷新显示，页面卸载不取消任务。库用同一组件，分页/筛选。已完成卡片进入可见区域后请求短期授权 URL，用原生静音 video 的 preload=metadata 和 #t=0.1 展示真实首帧附近画面，不自动播放、不另存封面；未进入可见区域不请求视频预览，浏览器实际读取量取决于 MP4 元数据布局与 Range 实现。预览失败可重新加载。列表无任务标题，保留简短原始描述、模型、请求规格、创建时间和下方状态；实际 Prompt 只在详情弹窗展示，详情使用 HTML5 video controls/playsInline/preload=metadata，失败允许刷新签名。保留失败原因、确认后再生成和删除；进度无伪造数字。历史卡片授权失败清空内容并显示不可访问。

9. Observability / 验证矩阵​

Worker 业务日志只记录 job/user/provider/model/task refs、状态、provider_status、retry、elapsed/queue/generation/persist 时间和稳定 error_code；不记 prompt、key 或临时 URL。数据库状态可统计排队、成功率和耗时，不依赖 LangGraph Trace。

单测及集成覆盖正常流程、幂等冲突、同 Run Tool 重放、active/pending/day cap、Provider PENDING/RUNNING/FAILED/UNKNOWN/429/5xx/超时、下载/存储失败、DB 提交失败后同 key 恢复、重复处理成功任务、Worker 双处理锁、提交不明、超时、逻辑删除/清理、通知失败与重复消费、runtime 无 scope/跨 owner/跨 tenant/bulk DML。前端测试覆盖 job 恢复、阶段更新、点击才加载、失败/授权、卸载不改业务状态。刷新/重新登录/SSE 中断同样从 GET 恢复，不依赖旧连接。

10. 实施文件与 Review​

扩展 Creation models/UoW/migration env/module、增加 video DTO/service/routes/worker 与版本化 events；Platform 仅扩展私有签名端口和通知 consumer。Agent 增加 videos Provider/service/tools/HTTP，扩展 settings/tools/harness/capabilities/decision。前端增加卡片/库，扩展 renderer/page map/locale，OpenAPI 由仓库生成器重建。配置/Compose/架构导航同步更新。

Review 结论：复用现有端口、HITL、能力路由、UoW、Outbox 和 PG leader；不新增长期记忆、Redis 队列、视频专用 DeepAgent、播放器包或 ffmpeg；不把 checkpoint 当 Job；提交不明禁止收费重试；双重 RLS、当前授权和存储引用保护不得省略。设计可按以上边界实施，不需要另建平行架构。

11. 交付记录​

启用顺序：先执行 cd backend && uv run python -m app.modules.migrate --edition suite 并用既有 bootstrap 授权流程更新 runtime 表权限；发布 deploy/nacos/chein-backend-runtime.yaml.example / chein-agent-runtime.yaml.example 中的视频配置，保持两端模型一致，私下配置 Key。确认账号授权范围、默认 private 存储及额度后才将两端 enabled 设为 true，重启相关进程。

首次消息需要按结构化能力缩减工具时，将既有 AGENT_DECISION_MODE 配为 active 并验证其决策供应商；off/shadow、决策失败、复杂任务和上下文续问继续沿用现有 DeepAgents/HITL 路径，不宣称这些路径已经做了硬意图隔离。未改动既有全局路由默认值。

独立 Worker：在仓库根目录运行 npm run video:worker，Ctrl+C 停止；npm run video:worker -- --once 可运行一个恢复周期。脚本调用既有 app.modules.creation.video_worker，不自动启用视频功能。Compose：docker compose -f compose.yml -f compose.videos.yml up --build。Backend 已有 Outbox 生命周期线程可投递通知；关闭 BACKGROUND_WORKERS_ENABLED 时必须同时部署现有独立 Outbox Worker（standalone-workers profile）。Base/Items 不装配视频页面/接口；视频 worker 只在 Suite 部署。

播放验证：通过本人已授权 /api/v1/creation/videos/{job_id}/playback 获得 URL，将 URL 经 stdin 传入 uv run --project backend python scripts/check-video-storage.py --origin <浏览器origin>。该命令验证 206、Content-Range、MIME、响应字节上限、CORS expose 以及去签名后的拒绝；不打印签名 URL。若 CORS 未配置，先用私有 bootstrap 入口运行 cd backend && uv run python -m app.platform.configure_video_storage --tenant-code <租户编码> --origin <浏览器origin> 审阅新增规则，再加 --apply。该命令保留其他规则，仅增加指定 origin 的 GET/HEAD、Range/If-Range 与可读取的响应头，不改变 bucket ACL/公共读取策略。生产必须使用实际前端 HTTPS origin，不复用本地来源。

部署反向代理不应剥离 Range/If-Range/206，不能缓存授权 API，私有对象不授予公共读权限。签名有效期 300 秒，历史不保存签名，播放错误可手动刷新。生产域名与 TLS 需运维配置，不对 endpoint 猜测重写。

首期资源规格显示请求的 duration/resolution；未部署探测器时不声称这些是实测时长、宽高或 fps，Asset 的 duration 保存请求时长供审计。无自动封面、字幕、参考媒体、视频编辑/延长或 Provider cancel；这些模式在 DTO 明确拒绝。串行 transfer 的上限为配置字节数，两端均有界；跨进程 HTTP 会产生额外一次有界内存拷贝，吞吐不足时再改流式上传端口，不先增加存储凭据副本。Provider 仍运行但本地超时/提交不明时可能继续计费，当前并发上限约束可跟踪的任务，不承诺停止远端任务。

短剧功能移除记录（2026-10-21）​

Creation 移除短剧项目、剧集、创作版本和镜头编辑页面、API、DTO、ORM、权限声明及 9 份专题设计文档；图片和视频生成、资源库、播放、Agent 工具及视频 Worker 保留。当前短剧实现只有文本与版本数据，5 张表没有被图片/视频表引用；本次不删除 RustFS 对象或媒体记录。

这是 Creation 2.0.0 的破坏性接口移除：原 /api/v1/creation/dramas 及其子接口不再注册，旧客户端应随本次重新生成的客户端一起发布；旧页面入口不再可用。Platform 的 b9e3a1d02c84 迁移清理短剧菜单及角色/套餐授权，将非短剧自定义子菜单移到存活的 Creation 目录。Creation 的 creation_remove_drama_v1 迁移只删除 drama_project、drama_episode、drama_revision、drama_shot、drama_shot_revision 和专用触发器函数；历史创建 revision 保持不变，以支持已有数据库升级。

迁移前先确认目标库身份、备份上述表与关联菜单/授权，再通过既有管理员 CLI 串行迁移；不得把管理员配置传入 API 或 Worker：

cd backend
NACOS_CONFIG_DATA_ID=chein-backend-bootstrap.yaml uv run python -m app.modules.migrate --edition suite

迁移提交后通过现有 redis_cache.bump_namespace 更新 CacheNamespace.RBAC 和 CacheNamespace.MODULE_ACCESS，使在线菜单/权限缓存失效；然后发布新版本并刷新前端。升级不会重建短剧菜单。数据库降级仅恢复空表、约束和 RLS，不能恢复被删除的内容；菜单及授权降级不会自动重建，完整回滚需要旧应用版本及经审阅的数据库备份。

本地验证：独立临时 PostgreSQL 上 Creation、迁移、模块边界及 Manifest 回归 55 passed，覆盖 upgrade/check/downgrade/re-upgrade、媒体数据保留、菜单授权清理和 app_runtime 无 scope/跨租户/跨拥有者隔离。Backend ruff check app tests、前端类型检查、前端 32 个文件 / 269 项测试、Base/Items/Suite 三种 Edition 构建均通过，最后恢复 Suite 生成产物。没有调用付费模型；本次未执行真实浏览器、远端 CI 或镜像部署验证。

实际配置库目前仅做只读盘点，尚未执行删除迁移：Backend runtime 与 bootstrap 都标记为 ENVIRONMENT=production，虽指向同一数据库，仍需用户确认它确为此次授权清理的开发库。确认后才能备份并迁移，不能将隔离库测试结果视为已完成实际库清理。
