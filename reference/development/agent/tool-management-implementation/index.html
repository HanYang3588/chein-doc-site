Agent 工具管理实施设计

当前状态：自研 ERP MCP 继续启用；以下 RAGFlow MCP 是保留方案，当前默认改为原生 Tool → KnowledgeService → HTTP API。本文原方案与验证历史保留，当前事实见原生 Tool 集成。恢复官方 MCP 还须显式设置 RAGFLOW_RETRIEVAL_TRANSPORT: "mcp"，仅配置旧引用不会启用。

自研只读工具已接入 FastMCP 与 Nacos；Analytics 已复用同一入口，发布步骤见 SQL 分析交付。RAGFlow 改用官方 MCP 客户端，本地契约检查通过；远端端口未响应，启用、登记与实联尚未完成。

目标与选择​

自研工具在业务模块声明一次，后端统一发布，Agent 从 Nacos 加载获准的固定版本。第三方已有 MCP 时使用其官方服务。当前自研工具为 ERP 统计与 Analytics 分析，日期保持原生实现，写工具不开放。

范围实现
自研只读工具已安装 FastMCP 与 LangChain MCP Adapters
RAGFlow 检索MCP Python SDK 2.3.0 原生客户端，官方 Streamable HTTP 服务
服务目录已有 Nacos Python AI SDK 3.2.0
业务授权现有 RBAC、模块访问检查、Tenant UoW

MCP 与 httpx2 已是 FastMCP 的锁定依赖；本次声明后端直接使用的版本，不升级框架。Nacos AI 服务位于 v2.nacos.ai.nacos_ai_service，使用 gRPC，控制台 HTTP 连通不能证明发布 RPC 可用。上传、解析、更新、删除及下载继续使用 RAGFlow 官方 HTTP API。

所有权与调用链​

自研契约保存在 ModuleDefinition.agent_tools，处理函数留在所属模块；组合根只装配当前 Edition，Platform 从声明推导委托权限。服务逐次校验当前成员、权限及模块权益，再进入 Tenant UoW。工具名带主版本，契约参与模块摘要，SDK 对象和 Session 不进入公开契约。

Analytics 的四个 MCP 工具经 capability 调用 ERP 数据所有者。Agent 用两个模型工具处理目录、快照与摘要，隐藏底层结果、scope 和 cancel 工具，保留原有工具 UI 名称。MCP 开关及契约逐次核对，配置 MCP 后不回退旧分析 HTTP；原始行只用于生成授权快照。其发布顺序、结果预算和 HTTP 兼容窗口以 SQL 分析交付为准。

Knowledge 不再声明 knowledge_catalog_v1、knowledge_retrieve_v1，也不提供 FastMCP 包装。Agent 的 list_knowledge_bases、search_business_knowledge 使用现有授权 HTTP Facade，保留语义路由、Judge、Trace、引用和历史证据重验。后端在授权边界调用官方 MCP，API Key 仅留在后端。

官方工具缺少 Dataset IDs 时会搜索 API Key 可见的全部库。后端要求明确且非空的授权 Dataset IDs 和 Document IDs，最多 500 个文档；召回后重验权限、文档状态及 Metadata，范围外结果不进入回答。共享 API Key 和原始目录不能直接交给模型。官方工具说明包含库名称和 ID，发布时替换为通用说明；Nacos 只登记当前使用的 ragflow_retrieval，不开放原始目录或聊天工具。

发布、撤销与 Run​

自研发布 Schema 来自 FastMCP 实际工具。Nacos 会省略 default: null，发布时仅统一这项注解；必填、类型、范围及业务 null 不变。CLI 检查完整版本目录并拒绝覆盖；RPC 超时后核对精确版本的工具、元数据和 endpoint，全部一致才确认成功，不重复写入。

Agent 固定服务名称、版本及带端口的 /mcp 地址。每个 Run 读取 Nacos 和实际工具列表，只有已启用、只读、权限获准且 Schema 一致的工具进入模型。逐次调用核对撤销和契约摘要；摘要写入 mcp.tools.bound RunEvent，恢复时发生变化要求新建 Run。自研 MCP 启用后不注册旧 ERP HTTP 工具，避免绕过开关。

官方 RAGFlow 客户端逐次核对 Nacos 的固定版本、endpoint、工具开关、权限元数据及实际 Schema。连接禁用环境代理和重定向，超时、撤销、漂移或错误结果均失败关闭；配置 MCP 后不回退 HTTP。结果上限为 256,000 字节，这是 SDK 接收后的检查，不能替代网关限制。

官方 v0.27.2 的 top_k 上限为 1024，Chein 将 knn_top_k 映射为该参数，超限拒绝，不静默缩小。官方工具没有 metadata_condition 和 rerank_candidates_count；Chein 在召回前后过滤文档 Metadata，重排候选数由官方服务控制。启用前检查检索配置不超过此上限。

知识参数兼容模型将 base_ids 数组输出为 JSON 字符串，再执行数量、UUID 和授权目录校验。图默认预算为 25 步，计算中间件及框架步骤，不等于工具调用次数；配置边界仍为 1–100。自研服务最多 4 个，每服务最多 32 个工具。

部署与迁移​

本次没有新表、SQL、Worker 或前端页面。先同步锁定依赖：

uv sync --project backend --frozen
uv sync --project agent --frozen

自研工具​

在 chein-backend-runtime.yaml 设置 AGENT_MCP_ENABLED: true 并重启后端。沿用 Ed25519 委托密钥，在 backend/ 预览实际 Edition：

NACOS_CONFIG_DATA_ID=chein-backend-runtime.yaml uv run python -m app.modules.agent_tools \
  --edition suite --name chein-backend-tools --version 1.3.0 \
  --endpoint http://chein-backend.internal:8000/mcp

审查后添加 --publish。示例版本必须尚未发布，已有版本不可重发。Suite 发布 erp_statistics_v1 及 analysis_catalog_v1、analyze_data_v1、analysis_scope_v1、analysis_cancel_v1。在 Nacos MCP 管理中保留 permission、read_only 元数据，不手改 Schema。

Agent 的 chein-agent-runtime.yaml：

AGENT_MCP_SERVERS:
  - name: "chein-backend-tools"
    version: "1.3.0"
    endpoint: "http://chein-backend.internal:8000/mcp"
AGENT_MCP_TIMEOUT_SECONDS: 30
AGENT_MAX_GRAPH_STEPS: 25
AGENT_KNOWLEDGE_URL: "http://chein-backend.internal:8000/api/v1/knowledge/internal/agent/v2"

重启 Agent，以有权限及无权限用户验证新 Run。旧 Run 不能静默切换契约，先完成或取消再切换版本。新增自研工具仍需模块实现、权限声明及越权测试，再发布新版本，不再维护 Agent 的固定注册列表。

官方 RAGFlow MCP​

v0.27.2 MCP 为独立进程，默认关闭，地址为 http://目标主机:9382/mcp，不是 Go 版本的 /api/v1/mcp。按部署手册启用 host 模式，客户端使用真实 RAGFlow API Key。旧派生镜像需更新入口脚本，修改仓库不会改变远端容器。

保留后端 RAGFLOW_BASE_URL 和 RAGFLOW_API_KEY。先在维护 CLI 的临时环境配置服务，避免在验证端口前切换运行时：

cd backend
NACOS_CONFIG_DATA_ID=chein-backend-runtime.yaml \
RAGFLOW_MCP_SERVER='{"name":"ragflow-official","version":"1.0.0","endpoint":"http://ragflow.internal:9382/mcp"}' \
uv run python -m app.modules.agent_tools --ragflow-official

预览会真实握手并读取官方 Schema。确认后以相同参数添加 --publish；已有版本使用新版本号。登记完成且核对 endpoint、Schema 和开关后，在后端 Nacos 运行时配置加入以下内容并重启：

RAGFLOW_MCP_SERVER:
  name: "ragflow-official"
  version: "1.0.0"
  endpoint: "http://ragflow.internal:9382/mcp"

Agent 不添加该服务到自己的允许列表，而是经授权 Facade 使用官方检索。验证真实回答及引用、授权撤销和 Nacos 禁用后阻止调用。空 RAGFLOW_MCP_SERVER 保留 HTTP 检索，用于启用前兼容或显式回滚，不是失败时自动降级。

Nacos 修改工具开关无需重启，每次调用重验；修改启动允许列表或传输配置需重启对应进程。回滚自研 MCP 时将 Agent 的 AGENT_MCP_SERVERS 置为 []；关闭后端入口时将 AGENT_MCP_ENABLED 设为 false。两种回滚均需重启，无数据库回滚步骤。

此前自研 Knowledge MCP 1.1.1 的真实 Qwen 图返回五条采购证据及引用，这是旧传输路径的证明。2026-10-09 删除该包装，发布自研 ERP 1.2.0，通过 CAS 切换 Agent 允许列表并重启。该次后端及 Agent 健康检查为 200，无委托 MCP 请求为 401；更新前保存了受限权限配置备份。2026-10-10 Analytics 新契约仅完成本地验证，尚未向用户 Nacos 发布或切换运行配置。

移除包装后，用当前用户签名委托、真实 Nacos、Knowledge HTTP Facade、RAGFlow HTTP 与 Qwen 再次运行完整 Agent 图。模型主动调用目录与知识检索，两次均成功，最终回答包含引用；没有工具错误或中断。该联调使用内存 checkpoint，不替代持久化浏览器会话或官方 MCP 实联。

当前部署的 RAGFlow Web/API 使用宿主机 9380 端口；独立 9382/mcp 连接失败，Web/API 的 /api/v1/mcp 返回 404。Tailscale SSH 要求用户完成身份验证，尚未取得容器启动状态。官方服务启用、Nacos 登记与真实调用仍待完成，后端保持 HTTP 检索，不把不可达服务登记为可用。

远端 CI、镜像扫描、签名和生产网络验收未执行；此前依赖审计受 PyPI TLS 下载失败阻塞。写工具、沙箱与运营审批仍见治理设计，不属于本次交付。
