本地启动

1. 首次准备​

根目录 .env 只配置 Nacos 连接信息。按 deploy/nacos/*.example 在 Nacos 创建：

  • chein-backend-bootstrap.yaml
  • chein-backend-runtime.yaml（本机填写 AGENT_API_URL: "http://127.0.0.1:8100/internal/agent/v1"）
  • chein-agent-migration.yaml
  • chein-agent-runtime.yaml

安装依赖并生成当前 suite 版本清单：

cd frontend && pnpm install
cd ../backend && uv sync
cd ../agent && uv sync
cd ..
pnpm build:edition -- --edition suite

首次初始化数据库时，按后端初始化文档执行；Agent checkpoint 额外执行一次：

cd agent
NACOS_CONFIG_DATA_ID=chein-agent-migration.yaml uv run python scripts/migrate_checkpoints.py
NACOS_CONFIG_DATA_ID=chein-agent-migration.yaml uv run python scripts/migrate_projects.py

2. 启动项目​

在仓库根目录执行一个命令，启动本机 Backend、Agent、React 前端与视频/记忆共享 Worker：

npm run dev

该入口适用于 macOS/Linux 或 WSL。各 npm 脚本已经指定对应 Nacos Data ID：Backend 和共享 Worker 使用 chein-backend-runtime.yaml，Agent 使用 chein-agent-runtime.yaml；不需要在命令前手写配置。根目录 .env 仍保存现有 Nacos 连接信息，业务配置与密钥留在 Nacos。

启动前会检查 8000、8100、5174 端口；已有服务时先在原终端停止，启动器不会终止其他终端的进程。Ctrl+C 统一停止本次启动的服务并等待当前 Worker 操作结束；任一服务退出会停止其余服务并返回非零状态。启动不执行依赖安装、数据库迁移或功能启用。前端内部仍使用项目现有 pnpm workspace，需要已安装 pnpm。

Docker 启动保留为 npm run compose:up。需要分别启动时，也可使用以下入口：

端口预检同时覆盖 IPv4/IPv6 的 loopback 与通配监听。单独启动前端也会在进入 Umi 前检查 5174，并设置 STRICT_PORT=5174。端口被占用时明确报错，不自动换到 5175；预检位于 Umi 清理生成目录之前，避免重复启动破坏已有开发实例。

# 终端 1：Python Agent
npm run agent:dev
# 终端 2：后端 API 与 Agent BFF
npm run backend:dev
# 终端 3：React 前端
npm run frontend:dev

分别启动时，另开终端运行共享 Worker（从仓库根目录执行；一键启动已包含它）：

npm run video:worker

使用 Ctrl+C 停止；npm run video:worker -- --once 只处理一个恢复周期后退出。该命令读取与后端相同的运行配置，不会自动启用视频或记忆功能。配置与部署前置条件见视频生成设计和长期记忆交付记录。

3. 访问​

服务地址
前端http://localhost:5174
后端 OpenAPIhttp://localhost:8000/docs
Python Agenthttp://127.0.0.1:8100（私有 API，已关闭 Swagger / ReDoc）

若后端提示 Agent API is not configured，检查 Nacos 的 AGENT_API_URL，然后重启后端。

后端模块、路由或 Edition 变化后，重新执行：

pnpm build:edition -- --edition suite

构建不会执行数据库迁移，backend:dev 也只启动 API。新增模块或迁移后，先停止后端，执行以下步骤，再重新启动：

cd backend
uv run python -m app.modules.migrate --edition suite
uv run python -m app.platform.provision_db_roles
NACOS_CONFIG_DATA_ID=chein-backend-runtime.yaml uv run python -m app.initial_data

例如 Enabled build modules are not ready: creation 表示构建中的模块尚未就绪；通过 Edition 迁移日志检查并修复，不能手工改成 ready。管理员配置、授权与初始化说明见后端初始化文档。

4. React 前端入口与验证​

管理前端为 frontend/apps/web-pro（@chein/web-pro）。 框架与实际调用链见前端架构。以下命令在仓库根目录执行：

pnpm frontend:typecheck
pnpm frontend:pro:test
pnpm frontend:build

开发代理由 frontend/apps/web-pro/config/proxy.ts 定义：浏览器请求同源 /api，代理默认 连接 http://127.0.0.1:8000；后端不在本机时使用 CHEIN_BACKEND_URL 指向受控后端。 Docker 内的 loopback 指向容器自身，开发代理需改用容器可达的后端地址 （例如 Compose 网络中的 http://backend:8000）。

实时语音使用优先于通用 /api 的 /api/v1/agent-ui/voice 代理，保留浏览器原始 Origin。当前 Umi 在 changeOrigin: true 时还会重写 HTTP Origin，导致一次性票据 接口返回 403 Voice secure origin required。语音代理因此使用 changeOrigin: false 并启用 WebSocket；通用 /api 代理不再启用 WebSocket，避免两个处理器对同一次握手 重复转发并重复消费票据。不要通过放宽后端来源白名单解决。代理配置修改后需重启前端开发服务。

frontend:pro:dev/build/typecheck 是默认 React 命令的显式别名；根 frontend:e2e 目前执行 Vitest，不能当作 Playwright/真实后端 E2E。不要使用模板 max openapi 生成 Chein 客户端。

5. 开发验证截图归档​

截图通过 saveDevArtifact 保存时同步上传 RustFS，不在源码目录生成图片；对象键为 <business>/screenshots/<上海日期>/<随机ID>/<文件名>。默认本机配置位于 ~/.config/chein/dev-artifacts.json（权限 0600）：

{
  "endpoint_url": "http://localhost:9000",
  "region": "us-east-1",
  "bucket": "chein-dev-artifacts",
  "access_key_id": "<开发产物账号>",
  "secret_access_key": "<通过本机安全配置提供>"
}

预先创建私有 bucket 并配置对应对象的读写权限；归档工具不创建 bucket、不修改 ACL，也不读取 RAGFlow 配置。项目根 .env 仍只保存 Nacos 引导配置。这里是开发工具配置；管理页面“存储渠道”中的 S3 默认渠道只控制经 /api/v1/files/upload 等已有接口保存的业务文件，不能接管开发工具的磁盘写入。

在浏览器验证工具的 Node 环境中，将截图字节直接传入入口：

const { saveDevArtifact } = await import('/absolute/path/to/chein/scripts/save-dev-artifact.mjs');
const artifact = await saveDevArtifact(await tab.screenshot({ fullPage: false }), {
  business: 'agent-ui', name: 'composer.png',
});

也可执行 pnpm dev:artifact --business agent-ui --name composer.png < /tmp/composer.png；工具不删除调用者的源文件，调用者在归档成功后清理系统临时文件。保存只经内存和项目外的 ~/.cache/chein/dev-artifacts/ 待发目录，下载校验 SHA-256 成功后删除待发文件；网络错误或校验失败返回非零状态并保留待发文件，使用 pnpm dev:artifact --retry 重试相同对象键，不覆盖已有不同内容。返回值是 bucket、对象键、大小和校验值，不生成公开链接。归档工具只处理开发验证截图，不改变业务附件、数据库、日志或构建产物的已有链路。
