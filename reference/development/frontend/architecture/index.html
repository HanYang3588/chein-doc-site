前端架构与技术栈

状态：当前源码与交付入口说明，不等同于生产验收报告

适用范围：frontend/apps/web-pro

本文维护前端技术栈、实际执行链路和现状/目标边界。模块所有权服从 模块化架构实施基线，Agent 协议与渲染细节见 Agent 交互前端设计，原重构范围与验收要求见 前端迁移设计。

1. 当前交付结论​

  • /ontology-neo4j 独立语义本体页面已移除，Ontology 仅注册 /ontology-builder；构建器及 Agent 共用 Neo4j/推理能力保留，见 退役与菜单清理。

  • Suite 的 /datasources 页面位于 modules/datasource，动态连接表单、虚拟表树、字段分页与表配置复用 Ant Design 和现有模块装配；接口及本地验证见 数据源交付。

  • OWL 构建器可由 page registry 按 Manifest 注入数据源 public_api/catalog 的只读 Reader，消费方只类型引用目录 DTO；未装配或无读取权限时不显示入口。选择仅转换成已有 OWL 草稿命令，不授予实时数据访问，见 目录批量新增。

  • 原始表数据由独立的 datasource/public_api/preview Reader 可选注入，沿用数据源 read/preview 权限。目录对象选中后在底部自动加载，分隔处突出标签控制折叠，原生 Splitter 调整高度并同步表格滚动区，刷新及翻页使用紧凑文字样式；分页从服务端读取；折叠取消请求并清空数据，身份/工作区/对象切换丢弃旧响应，不将样本写入本体或持久状态。见 原始表面板。

  • /automations 任务页与 /automation-runs 运行页位于 modules/platform/agent/automations，在“自动化”目录下配置为两个独立子菜单，沿用 Ant Design 主题和同源 Agent BFF；日程计算、统计聚合与运行事实留在后端。设计与验收边界见 Automations。

  • 默认管理应用为 frontend/apps/web-pro，包名 @chein/web-pro，不是 Vue/Vben。

  • Ontology 提供独立 ReactFlow 本体构建器，支持 Neo4j Resource 现库读取、原文件预览、分页实例、草稿编辑及受控工作区发布；复用 page registry 和模块权限。工具区可折叠，提供层级树、横向关系、网格三种布局。绑定、ACL、发布与显式写回的实施及部署限制见 OWL 画布交付边界。

  • 根目录 frontend:dev、frontend:build、frontend:typecheck，Edition 构建默认值， frontend/Dockerfile 和 compose.override.yml 均指向 React 应用。

  • 旧 Vue 应用、Vben workspace 公共包、文档站和兼容客户端已从源码树删除。

  • “默认入口已切换”“源码已迁移”“真实环境 E2E 通过”“已上线”是不同结论。 本文只确认当前工作区事实，不推断线上运行版本或远端 CI 状态。

菜单维护界面​

pages/platform/SpecialPages.tsx 的菜单维护使用 ProTable 树表与 Ant Design Drawer / Form： 操作列固定在右侧，提供新增下级、展开/收起、中文类型标签和原生列设置；窄屏用原生 Dropdown 收纳行操作，避免遮挡菜单标题。 标题、路由、组件和权限的本地筛选保留祖先；编辑时上级选择排除自身、下级与按钮，清空上级会提交 null。 页面组件使用原生可搜索 Select，候选项直接取自 runtime/page-registry.ts 的当前 Edition 页面映射，不另建组件目录；旧 .vue / #/ 标识回显为不带扩展名的 key，保存时使用该 key。未注册的旧值保留显示并阻止表单保存，必须重新选择或清空。 图标 Select 的选项和预览与侧栏共用 runtime/icons.tsx 的受控映射：提供 Ant Design 官方线框、实心、双色图标的 antd:<组件名> 标识，并保留旧 lucide: 编码及其外观。原生 Select 按样式分组，可搜索并即时预览；官方图标按名称显式导入，不整库动态加载或引用外部图标脚本。 表单按目录、菜单、按钮区分字段，桌面双列、窄屏单列；仅维护现有 API 的字段，未引入 Vben 的外链、内嵌、徽标或激活图标能力。 这些界面变化不需要数据库迁移，后端权限、循环层级校验和组件 key 的失败关闭规则仍是安全边界。

AI 工作台导航​

/agent-center 为统一的“AI 工作台”目录。数据分析助手、已归档会话、提示词管理是二级入口； 知识库管理和创作中心保留分组，其下页面为三级入口。统一的是使用入口，模块边界与授权不合并： Knowledge、Analytics、Creation 的页面仍由本模块 NavigationSpec / Platform 组合根按 Edition 装配， 保留 /agent、/agent/archives、/agent-prompts、/knowledge/*、/creation/* 与 /analytics/favorites 地址和菜单 ID。

工作台目录不携带 agent:chat。已有角色和套餐根据已授予的子入口补齐中性目录关联； 新角色绑定同样补齐中性祖先，不授予兄弟页面或带权限码的父菜单。只有知识库、提示词或图片权限的用户 无需聊天权限即可进入自己的功能。前端不展示没有可见子项的目录，隐藏兼容页仍保留受控路由。 目录默认落点按实际菜单子树选择首个可访问页面，不再要求子页面 URL 与目录有相同前缀。

此变更没有数据库结构迁移。通过现有菜单初始化流程应用层级与关联，刷新权限和菜单后生效； 菜单合并不替代服务端权限、模块权益与租户隔离。归档页行为见 Agent UI。

模块权益配置​

Platform 的 TenantPages.tsx 在租户套餐和租户管理的行操作中提供“模块权益”，共用 ModuleEntitlements.tsx。仅平台超级管理员可访问这些页面，后端状态读取和写入仍逐次校验超级管理员身份。默认租户提供模块权益入口，其生命周期和其他编辑限制保持不变。

套餐开关管理使用该套餐的所有租户；租户面板展示套餐权益、当前有效授权/禁用例外、租户启用偏好及当前模块访问结果。例外操作要求填写原因，复用现有审计与缓存失效接口。可选模块清单来自后端当前 Edition Manifest，必选 Platform 不作为可授权项；查看页面不会播种菜单、安装模块或创建授权记录。

模块权益不替代用户角色权限。开启模块后仍由角色管理分配用户权限，页面提示刷新权限或重新登录。首次部署新增模块仍需执行菜单初始化，步骤见 SQL 分析交付。本次新增两个只读状态接口并重新生成客户端，无数据库结构迁移。

状态管理不是 Pinia，也不是“已全面接入 Query”​

当前用户、租户成员关系、权限和菜单由 Umi getInitialState / useModel('@@initialState') 维护；页面交互主要使用 React Hooks。TanStack Query 依赖和 Umi reactQuery 插件已配置， Zustand 也已声明依赖（附件组件使用其 useShallow 辅助函数），但当前业务源码未形成 useQuery / useMutation 或 Zustand store 的统一状态层。不能仅凭安装了依赖就把它们写成已完成的全局状态/缓存架构。

4. 初始化、路由和权限执行顺序​

  1. config/routes.ts 保留认证与错误页， 其他路径进入 Workspace.tsx。
  2. app.tsx 读取已有 token；无 token 的受保护访问 跳转 /auth/login?redirect=...。
  3. getInitialState 并发加载后端 Build Manifest、/users/me、/permissions/me、 /menus/me、租户成员关系；这些相对路径均使用 /api/v1 前缀。
  4. runtime/manifest.ts 始终比较 schema_version、Edition、Platform 契约、模块迁移 head 与 OpenAPI 摘要；生产构建还必须精确比较 source_revision 和 manifest_digest。本地开发不比较这两个产物标识，避免提交后前端生成文件与后端 当前 HEAD 的必然差异掩盖真正的契约检查；不兼容或初始化失败时显示错误，不继续进入业务页面。
  5. runtime/menu.tsx 规范化组件 key、路径、排序、重复/循环菜单；Workspace.tsx 通过 runtime/page-registry.ts 中唯一的受控 pageMap 映射 React 组件，按 Manifest 注册 Knowledge / Items / ERP 入口；菜单组件选项从同一映射派生。
  6. can(initialState, permissionCode) 控制页面和操作的 UI 访问；未知组件停止加载， 无权限显示 403。真正的用户、租户、模块访问与 RLS 校验仍由后端执行。

历史菜单下发 views/.../index.vue、#/views/.../index.vue 或 modules/.../index.vue 格式的兼容 component key。 这些是逻辑映射键，实际加载 React 页面，不是 Vue 文件路径。运行时去掉 #/ 前缀和 .vue 后缀， 新建和编辑菜单使用不带扩展名的标识（例如 views/system/tenants/index）；未编辑的数据库记录无需迁移。 候选项只包含当前 Edition 注册的业务页面，不扫描测试、弹框或基础组件；新增可路由页面仍须在受控映射中注册，注册后自动进入下拉列表。 该目录不授予访问权限，路由仍通过菜单授权与后端 API 校验。认证旧 URL 与 /erp/settings 等兼容入口继续保留。

管理页面使用手动挂载的 ProLayout（Umi 配置 layout: false）；Agent 经同一工作区 授权后在管理布局内展示，进入时自动折叠管理菜单，保留 Agent 自身的会话侧栏。

仪表盘的五个图表通过 pages/dashboard/index.tsx 的 ChartFrame 共用 Plots ConfigProvider，将 Ant Design 当前 token 映射到图例文字、坐标轴文字/边线和图表背景。 Ant Design 根主题不会自动配置 Plots；主题切换时由 token 更新触发图表重绘，无需重新请求统计数据。 2026-10-18 本地主题往返切换回归、类型检查及前端构建通过；独立 Playwright 浏览器以拦截的 测试数据确认明暗模式下五个图表文字可见，截图已归档至 RustFS 的 platform-ui 分类。 本次未执行远端 CI，不涉及 API、数据迁移或 Edition 装配变更。

登录页蓝色光晕通过 CSS 缓慢漂移。大图标在固定的图标区域内跟随鼠标进行轻微 3D 倾斜， 移出或取消指针操作后平滑复位；触控输入不触发倾斜。开启“减少动态效果”时，光晕及图标 交互保持静止。装饰效果不参与表单提交或登录状态。

登录使用须知​

密码登录及 pages/auth/flows.tsx 中的短信、扫码、扫码确认、OIDC 回调和注册入口共用 components/UsageNoticeGate.tsx。访问认证页时直接显示表单，不自动弹出须知。 有效表单提交登录、注册、生成二维码或确认扫码登录时，经 useUsageNotice() 弹出须知。 密码登录关闭 ProForm 的额外 Enter 提交逻辑，由原生表单处理回车，避免同一次按键在弹窗 焦点切换后误触关闭按钮。点击登录与回车提交共用同一校验及确认流程。 勾选并确认后才继续本次操作。关闭弹窗、按 Escape、点击遮罩或选择“我再考虑一下”都会 取消本次操作，保留表单输入；下次提交须重新确认。获取验证码及登录方式状态查询不受影响。 企业 OIDC 发起前须确认；回调页及密码登录页收到企业票据后，显示“继续企业登录”按钮， 点击并确认后才交换票据，不在页面加载时自动交换。找回/重置密码保持可访问。

须知采用适用范围、敏感数据、第三方处理、生成内容、资料权利、使用责任与解释争议七项条款， 提醒用户不要输入敏感数据，提交前脱敏、确认提交权限，并自行备份与保护凭据。 确认文案简化为“我已阅读使用须知并知晓风险”，底部在空间足够时同排展示复选框与按钮， 小屏幕自动换行；取消按钮为“我再考虑一下”，放行按钮为“我已知晓风险”，勾选后可用且呈红色。 不再显示黄色提示，未勾选时放行按钮保持禁用。 弹窗遮罩使用背景模糊效果，弹窗内容保持清晰，关闭后恢复原页面。 Agent 交互的问题和生成回复所需上下文会发送至阿里云百炼的 Qwen 模型服务；上下文 可能包含文件内容、引用资料和工具结果。须知提醒不同产品及套餐的规则可能不同， 部分订阅条款包含输入输出用于服务改进和模型优化的约定，以适用产品协议为准。 弹窗提供以下官方文字链接，供用户了解第三方数据处理规则：

  • 阿里云百炼常见问题（数据保存与使用）
  • 阿里云百炼服务协议
  • 阿里云百炼隐私政策

外部链接在新标签页打开，使用 noopener noreferrer，不向第三方传递认证页来源地址。 模型调用由 agent/src/chein_agent/model_provider.py 的 QwenModelProvider 实现， 实际上游地址和模型由 QWEN_* 配置决定；更换服务提供方时须同步更新须知与链接。 Agent 输出仅作辅助参考，须独立核实。作者解释权以法律允许范围为限，不排除法定责任 和用户权利。中英文文案维护在现有 locales/*/component.ts。

确认仅放行当前提交，不写浏览器存储；页面卸载时取消待确认操作。 不新增后端确认记录、API 或数据库迁移，也不能作为服务端鉴权或法律同意留痕。 OIDC 票据若在阅读期间过期，沿用现有失败提示，需重新发起登录。

5. API、生成客户端与 Edition​

  • HTTP 调用统一经 Umi request，app.tsx 设置 /api/v1、Bearer token、语言头、超时 与 401/403/404/409/503 错误处理。手写调用位于 src/api 及现有页面适配器；不能宣称 所有页面都已直接调用生成 SDK。
  • scripts/generate-openapi.mjs 从所选 Edition 的 FastAPI 应用导出临时 OpenAPI，使用 Hey API 生成 Platform 与模块子客户端；不要求先运行 8000 端口服务，但需要可用的后端依赖及其导入所需配置。
  • 同一命令只更新 React services/generated、模块 api/generated 和 runtime/build-manifest.ts。
  • scripts/build-edition.mjs 只构建 React。Edition 内容由 editions/<edition>.yaml 决定， 不是由前端菜单或环境变量临时增加模块。
  • React 当前是 Manifest 条件注册 + 手写 pageMap，不是已实现的生成静态模块注册表。 “未注册入口”不等于“dist 中完全没有可选模块代码”；Base 物理裁剪仍需产物检查。

6. 开发、验证与部署入口​

以下命令均在仓库根目录执行；首次配置见本地启动。

pnpm frontend:dev                 # React / Umi，默认 5174
pnpm frontend:typecheck           # tsc --noEmit
pnpm frontend:pro:test            # vitest run
pnpm frontend:build               # max build -> apps/web-pro/dist
pnpm generate:api -- --edition suite
pnpm build:edition -- --edition base
pnpm build:edition -- --edition items
pnpm build:edition -- --edition suite

frontend:pro:dev/build/typecheck 是同一 React 应用的显式别名。根脚本 frontend:e2e 当前实际执行 web-pro 的 vitest run，不能作为 Playwright 或真实后端 E2E 的证据。生成/Edition 命令会更新派生文件，执行前确认 Edition 并检查生成差异。

本机开发由 config/proxy.ts 将 /api 代理到 CHEIN_BACKEND_URL，默认 http://127.0.0.1:8000；浏览器不得直接访问 Python Agent。容器内代理目标必须是 可达的 backend 服务地址，不能把容器自身 127.0.0.1 当作后端。

生产 Docker 复制 apps/web-pro/dist，Nginx 提供 SPA fallback、/api 反代及关闭缓冲的 Agent SSE 路径。React 请求基址仍是同源 /api/v1。Compose 端口及外部依赖见部署。

Agent 回答操作栏复用 assistant-ui 的消息状态和持久 execution 标识，提供受控运行摘要与版本化反馈。旧历史回答未关联时隐藏操作；浏览器只调用同源 BFF，不持有 Langfuse Key。实现、权限与启用条件见 Langfuse P1–P5 实施。

Knowledge 页面​

Suite 通过受控组件映射加载知识库、检索测试、Agent 知识配置三个菜单入口。五种分类在列表通过原生 Tabs 切换；旧地址为已授权隐藏路由。buildMenuTree 保留隐藏 RouteEntry，使用原生 hideInMenu 隐藏入口并排除默认落点，停用页面/按钮不注册路由。NavigationSpec.is_visible 是模块显示状态声明，播种保留菜单 ID 与角色关联。租户级参数集中到检索测试页。权限与操作见知识管理。

Analytics 页面与聊天图表​

Suite 的组合根按 Manifest 注册 modules/analytics/favorites 和 analyze_data 独立工具 renderer；Base/Items 不注册。ChartSpecV2 仅携带快照引用，组件通过同源后端 API 获取重新授权的结果。完整聊天、浮动助手、个人收藏共用模块内 renderer，旧 ChartSpecV1 解析继续兼容。行为、精度降级、迁移和本地浏览器验证见 SQL 分析交付。

Agent 会话列表与历史消息按游标分批请求，复用当前 assistant-ui 组件，滚动触发、版本限制与真实性能范围见 分页设计。

Agent 归档记录独立为「AI 工作台 → 已归档会话」二级菜单，聊天页保留归档操作，移除底部归档列表；页面、权限与菜单更新方式见 Agent UI。

视频生成工具返回稳定 job ID，由 Creation 的 VideoGenerationTaskCard 通过授权 GET 恢复阶段；视频库 /creation/videos 使用分页和按需 HTML5 video。前端轮询不拥有任务状态；真实 RustFS Range/CORS 验收边界见 视频生成。
