数据源与数据表管理：DataVines 提炼与 Chein 适配

设计用户已要求按此设计开发。 下文保留提炼与设计提案，当前实现、差异及验证见 交付说明 和 接口/数据库。

1. 参考范围与结论​

参考用户指定的 datavane/datavines，本次读取的 dev 提交为 c0a8ed89317668279fd325c39d5ffefb54c0f724。未获得其他本地路径或二开分支，不能声称已覆盖用户私有二开版本。下文引用均固定到此提交；若二开版本另有来源，应在实现前补充差异核对。

采用其核心设计：数据源连接配置 → 类型连接器 → 持久化库/表/字段目录 → 刷新任务与结构差异 → 左树右详情。保留统一目录实体，不另建三套库、表、字段 CRUD。

需要纠正三个前提：

  • Chein 当前后端是 Python，不能直接使用 JDBC DatabaseMetaData。拟用现有 SQLAlchemy 的反射接口等价实现，必要时在 MySQL Adapter 内补充 information_schema，不引入 JVM 或 Spring 服务。
  • DataVines 通用 JDBC 元数据 DTO 不包含本次要求的完整长度、默认值、可空、外键和索引信息；必须扩充，不能宣称原样照搬即可满足。
  • DataVines 提供自由 SQL 查询入口，不能直接作为本次安全预览接口；固定 IV 加密、错误日志打印连接参数等行为也不能照搬。

本次不实现本体生成、Ontop、Agent 工具、新调度平台、跨库查询、SQL 编辑器或数据库写入。

2. DataVines 已核实的设计​

连接参数通常为 host、port、database、user、password、properties，其他类型可增加 catalog/schema。保存时加密整个 param；列表解密后将密码置空，内部读取方法会返回解密参数。

DataSourceServiceImpl 使用 CryptionUtils；其 AES 实现 为 AES/CBC/PKCS5Padding、固定 IV、十六进制密文，密钥配置有源码默认值。只参考“服务端可逆保护连接凭据”的职责，不复制此实现或默认密钥。

2.2 连接器与插件​

ConnectorFactory 聚合 Connector、ConfigBuilder、DataSourceClient、Executor、Dialect、类型/参数转换器，以及 SQL/质量相关扩展。PluginDiscovery 读取 META-INF/services/io.datavines.connector.api.ConnectorFactory，按插件名/别名解析工厂；前端类型列表过滤 showInFrontend()。

Connector 提供 testConnect、getDatabases、getTables、getColumns、getPartitions、keyProperties。MySQL 继承通用 JdbcConnector，库列表使用 JDBC catalogs；其他差异留在具体 Connector。

上游新增数据库通常需要新增插件 Maven 模块、驱动、Factory/SPI 声明、连接信息与 Connector、ConfigBuilder；按需要实现 Dialect/Executor/转换器，并加入打包依赖。不是只新增一个 Java 类就一定能完成支持。

JdbcDataSourceManager 按连接唯一键复用 Hikari 池，源码设置最大池大小 10；连接器归还借用连接，管理器有 close。Chein 复用其职责划分，但不照搬无界池目录或异常处理方式。

2.3 元数据获取、持久化与刷新​

JdbcConnector 读取 DatabaseMetaData.getTables/getColumns/getPrimaryKeys；表包含 TABLE/VIEW。通用 ColumnInfo 仅 name、type、comment、isPrimaryKey；TableColumnInfo 另含主键名称列表，不能据此证明主键顺序、名称等已完整持久化。已检查的通用采集链不提供 imported keys 和 index info。

采集执行器 将库表字段写入 entity_instance/properties 和 rel；新建数据源触发采集，刷新请求通过任务服务提交，亦有调度机制。Controller 的库/表/字段浏览读取持久化目录；Service 中还存在直连元数据方法，不能混为同一条请求链。

差异枚举覆盖库增删、表增删/注释变化、字段增删/类型/注释变化；没有证据表明已完整比较索引、外键、长度、默认值和可空变化。实体更新时间可显示目录更新情况，但不能等同于一个独立、完整成功的“最近同步批次时间”。

4. 拟实施方案（待确认）​

4.1 所有权与最小分层​

模块代码 datasource，后端 backend/app/modules/datasource，前端 frontend/apps/web-pro/src/modules/datasource，仅依赖 Platform。连接器与外部连接池在该模块 infrastructure，内部统一 Connector 端口在 application；public_api 仅导出后续消费者需要的 DTO/查询契约，不提前建设映射引擎。

路由 → 当前授权/模块 UoW → application 服务 → repository / Connector。连接器不决定租户和权限；业务层不按 MySQL/PostgreSQL 写分支。按受控类型注册 Connector 及表单描述；新增类型添加 Adapter、描述/注册、驱动和测试即可，业务服务不改。首期仅 mysql 可选，不显示尚未实现的类型为可用，也不开放上传驱动、运行时加载插件。

Connector 契约覆盖 test_connection、list_databases、list_tables、describe_table（列/主外键/索引/估计行数）、preview、close。使用 SQLAlchemy Inspector 等价于 JDBC 元数据，缺失信息由实现内固定查询补齐。catalog/schema 分开表达，MySQL database 对应 catalog；不预设 PostgreSQL 的 database/schema 与 MySQL 相同。

保留 DataVines 的 datasource、统一目录实体、关系、差异概念；不复制其可配置元模型引擎。以下表位于拟新增 PostgreSQL datasource schema，全部带可信 tenant_id、UUID 标识、UTC 时间与 FORCE RLS：

表实体 properties 使用类型化 DTO 保存有序主键 {name,columns}、有序索引（名称、唯一性、列/表达式、前缀长度等）与估计行数；列保存 ordinal、原始/标准类型、长度、precision/scale、nullable、default、generated、注释。未知值为 null，不能把“无法读取”写成无主键/零行数。索引无需独立业务配置，首期不再拆一张表；外键单独可查询。

关系及层级外键带 tenant 和 connection 一致性约束；防止跨源、跨租户关联。配置限制实体类型，标签有数量/长度上限；至少索引 tenant+type+created_at、tenant+connection+parent+kind+presence、外键两端、tenant+connection+change_time、任务状态/租约，标签筛选按实际查询增加 JSONB 索引。物理标识保留大小写，不擅自 lower，按 MySQL 实际名称语义处理。

按后续确认的交互规则，新发现的表默认启用，用户可以手动禁用。旧停用表仅在配置 revision=1（从未通过人工配置入口保存）时，于下次成功同步发布该表时启用并递增配置版本；revision>1 的人工配置不覆盖，保留手动禁用。人工配置过的旧表可通过现有批量启用入口调整。新发现敏感字段默认 exposed=false，其他字段默认 true；规则只作保守初始分类，业务人员仍需核对。_bak/_tmp/_log 等规则显示“不建议”及原因，不误判为权限。人工配置、源存在状态与同步状态互不替代。删除后同名重建使用新实体身份，旧配置保留为历史，禁止自动继承旧映射/暴露授权；重命名保守视为删除+新增，不按相似度合并。

未来生成器须同时检查表存在且启用、字段存在且暴露、当前授权和元数据版本。IRI 引用不等于发布或业务许可。本次没有跨模块本体引用；未来接入时由消费者使用公开契约/ReferenceGuard 登记与复验引用，不能仅凭 IRI 字符串认定引用安全。存在引用时删除返回 409，不通过“二次确认”绕过；删除/引用创建需同一受控并发约束，接入映射前完成竞争测试。

4.3 同步、差异与性能​

  • 新增数据源显式创建首次采集任务；GET 浏览只读目录，不隐式连接或写库。手动全源/单表刷新返回 task_id，UI 轮询状态；首期不增加定时自动刷新产品能力。
  • 通过 ModuleDefinition 的 ScheduleHandler 接入现有后台执行。每次按受控租户 UoW 获取任务，复验请求人当前权限/权益及配置 revision，租约领取；任务执行分批，有单表与总预算，避免长时间占用平台数据库事务或阻塞其他模块调度。
  • 同源刷新串行合并重复提交，配置修改使旧任务过期；租约恢复复验配置/权限。外部采集成功后在短事务中发布该范围的完整快照与差异，失败保留旧快照，绝不将网络异常或未完成分页解释成删表。
  • MySQL 权限缩小可能表现为表消失，不能仅凭列表认定物理删除；差异标记“源中缺失/不可见”，后续映射失败关闭。采集期间 DDL 改变则重验结构摘要，不能声称拥有跨 MySQL DDL 的事务快照。
  • 首次采集显示基线结果；后续只比较结构属性，人工业务信息及预估行数波动不混入结构变更；单表刷新不标记同库其他表删除。保留最近成功同步时间、当前任务进度和失败原因。
  • 树/列表从 PostgreSQL 按父实体分页（默认 50，上限 100），服务端名称/前缀/关键词/启用/标签过滤；搜索可命中未展开节点并返回祖先。字段分页；页面防抖建议 300ms，取消旧请求或丢弃迟到响应。
  • 批量更新限定显式 ID、同源/同租户、最多 100 项，revision 防覆盖，校验后事务提交；外键依赖预览返回缺失目标/环和有界传递集合，用户明确“一并启用”后再原子提交，不自动启用。

4.4 连接、安全与预览​

连接列表不实时逐个探活；显示最近测试结果、测试时间及对应配置版本，避免旧成功被当作当前连通。编辑不返回明文、密文或密码尾号，只返回 has_password；密码省略表示不变，显式替换才更新，首次创建必填，禁止用 ****** 作为密码。

注入现有 SensitiveValueProtector；其当前实现使用 SECRET_KEY 派生 Fernet key，轮换该 key 会影响历史凭据解密。首期沿用现有机制，不另建 KMS；上线前需有密钥备份/轮换迁移方案。完整连接参数、凭据、驱动异常原文、查询行均不写入日志、审计、Sentry/OTLP。

需要特别处理现有验证异常链：main.py 会输出 exc.errors()，其中可能携带非法输入。敏感 DTO 使用受控校验与统一错误清洗；必须测试嵌套连接参数、错误 extra 字段、密码格式错误，不能仅使用 SecretStr 就宣称不会泄露。

MySQL 使用只读账号提示、服务端只读事务、固定 SQL；禁止前端传 SQL、表达式、排序片段、URL 或驱动选项。额外参数改成有类型白名单（字符集/TLS/超时等），未知选项拒绝；不照搬自由 JDBC properties，禁止 init SQL、local infile、多语句及关闭证书验证等危险选项。TLS 验证默认开启。

数据源只有具备 datasource 管理权限的用户可配置。按用户确认的调整，主机与端口完全由页面配置，不设应用级网络/端口白名单；驱动直接连接该地址并执行 TLS 主机与证书校验，不需要在 Nacos 逐项放行目标。

预览输入仅 table_id、limit（默认 20、上限 100）；后端复验当前权限、表存在/启用与字段 exposed。标识来自当前目录白名单，方言正确引用；查询前复验外部结构摘要，变化返回冲突要求刷新。显式 SELECT 获准列，禁止 SELECT * 后前端隐藏；exposed=false 的字段不查询不返回，mask_policy 在服务端执行。无可见列返回明确空态。无 ORDER BY 时是任意样本，UI 不保证稳定“前 N 条”。

预览不持久化、不缓存行数据，响应 no-store；限制行数之外还需列数、单元格与总字节预算，Decimal/大整数用字符串，二进制/大文本有明确截断。估计行数来自元数据并标注估计，不执行无界 COUNT(*)。

连接池按 tenant+connection_id+config_revision 缓存，建议每池 2、overflow 0、全局最多 16 池；淘汰/配置变更/删除/停机 dispose，借用连接与游标始终 finally 释放，失败连接失效。保存前测试使用短连接不进入持久池；多实例在借用时读取 revision，不能只清理本进程旧池。

拟定连接超时 5s、单查询 5s、预览总预算 10s；全部操作须同时有驱动读写超时和受支持的数据库执行限制，不能把线程等待超时当作真正取消。MySQL 版本、权限或驱动无法提供安全时限时明确拒绝相应能力，测试取消后连接不可继续携带后台查询。错误以稳定类别返回：网络、超时、认证、库不存在、权限不足、TLS、未知；未知原因只返回安全提示/关联 ID，不透传原始连接串。

4.5 Chein API 草案​

全部为拟新增路由，基址 /api/v1；成功为 DTO，分页采用 {items,total,page,page_size}（与 Items 风格一致），page_size 上限 100。权限统一 require_module_access("datasource", "datasource:...")，每个资源继续复验 tenant；body 不接收身份字段。

方法与路径主要输入 → 输出权限后缀

POST /datasource/test新配置，或已授权 id+草稿覆盖 → success,reason_code,message,tested_at,测试版本标识test（引用已存源另验 read/update）

沿用 DataVines 的 datasource/catalog 两个资源组；配置、预览是其下能力。不保留 script/variables/execute，不引入额外通用查询资源。路由静态路径优先避免 {id} 捕获；OpenAPI 定义固定 DTO 并通过 pnpm generate:api -- --edition suite 生成客户端。具体错误码由项目现有异常映射接入，401/403/404/409/422/503 含义保持一致。

4.6 前端方案​

  1. 数据源列表用 ProTable：名称、类型、地址、最近连接状态/时间、创建人/时间；服务端搜索、分页和类型过滤，行操作收进二级菜单。
  2. 新增/编辑 Drawer 用 ProForm/Ant Form，按后端类型描述渲染受控字段组件；密码留空保留，提示只读账号。测试/保存各有 loading、重复提交保护；连接参数变化立即失效测试结果，保存未测试时确认提示，不强制要求网络永远可达才允许维护配置。
  3. 元数据页左侧库表虚拟树（分页“加载更多”），右侧表概览、字段、主外键/索引、预览、结构变更 Tabs；显示成功同步时间/任务状态，不将任务提交提示成同步完成。
  4. 表配置页用同一目录数据的 ProTable 批量启停/标签和表/字段配置 Drawer；业务配置不挤占详情顶部，敏感字段默认提示、暴露权限明确。低频刷新/设置放二级入口。
  5. 外键提示及“一并启用”展示受影响集合，未知目标不伪装成功；删除有确认和引用冲突说明。未采集/连接失败/无库表/未启用/无暴露字段分别提供引导；分页、防抖和过期请求处理覆盖大库场景。

菜单/page-registry、生成客户端、locale、权限和 Edition 条件装配复用当前机制；不引入 Redux、DataVines FormRender、Monaco、Vue/Vben 或第二套状态层。

6. 实施顺序与验收门禁​

确认本文后按后端 → 前端 → 集成验收推进，每阶段报告改动、成功命令与未验证项；不创建分支、不暂存/提交/推送。

  • 后端：先模块装配/权限、模型迁移/RLS和加密，再 MySQL Adapter、持久目录/刷新差异、配置与预览；同期补公开 API。完整 DDL、索引、字段注释、grant/policy 与 downgrade 由独立 Alembic revision 实现；建表 SQL 从该迁移生成并核对，不另维护可绕过迁移的手写脚本。
  • 前端：生成客户端后实现列表/动态表单、元数据树与详情、配置批量操作；沿用后端安全边界。
  • 测试：MySQL 用隔离真实容器/一次性库，不能以 SQLite/内存库证明 MySQL 元数据正确；创建带复合主键/外键、索引、默认值、注释与特殊标识名的样本。验证成功/错误密码/不可达/TLS/超时、连接释放、SQL 注入、多实例配置失效。
  • PostgreSQL 使用一次性数据库，先审查直接/间接 fixture；共享库测试串行。覆盖 CRUD、租户/无 scope/bulk DML/跨租户引用负例、runtime FORCE RLS、密码保留与响应/日志/验证异常脱敏、引用删除竞争、失败同步不删表、重试/并发/权限变化、配置保持和预览上限。
  • 前端 Vitest 覆盖动态表单、测试失效、密码省略、配置/批量校验和迟到请求；真实浏览器验收 500+ 表的加载与未展开搜索、10 表启用刷新保持、外键带上、DDL 后差异、不可见敏感列。记录数据规模/环境与耗时，不能以虚拟滚动组件存在代替性能证据。
  • 运行 cd backend && uv run ruff check app tests、受影响 pytest、迁移 upgrade/downgrade/对应 tests、uv run alembic check；pnpm frontend:typecheck、pnpm frontend:pro:test、受影响构建；装配变更跑 Base/Items/Suite Edition 构建及边界/Manifest tests。浏览器截图按仓库开发制品脚本上传，不写源码目录。

初版提炼阶段仅完成源码/文档核对；后续实现证据统一维护在 交付说明，本提案不是上线报告。

7. 待确认的边界与假设​

确认本文即确认以下实施默认值：以已固定的上游提交为参考；新增独立 datasource 模块，仅 Suite；租户共享资源受模块 RBAC 管理；Python/SQLAlchemy + MySQL Adapter 代替 JDBC；沿用统一目录实体并分离人工配置；采用 PostgreSQL 持久目录、异步手动刷新；首期仅 MySQL、预览默认 20/最多 100 行；扩展 IRI 字段不触发本体写入。

仍需部署时提供获准 MySQL 目标网络、只读凭据和隔离测试环境，凭据不得写入文档。若需要参考另一个二开版本，或数据源应为个人私有/细粒度 ACL，需在编码前修订本节及隔离设计。
