Agent LangSmith 观测接入设计

状态：Proposed（设计已确定，配置与代码尚未接入）

适用范围：顶层 agent/ 独立运行时、模型调用、Deep Agents/LangGraph 执行链路

本文是 LangSmith 接入的唯一设计事实源。LangSmith 是辅助观测链路，不是 AgentRun、RunEvent 或 Checkpoint 的事实源；关闭 LangSmith 不能改变 Run 的执行语义。

1. 结论​

  • 首期使用 LangSmith Cloud 的 APAC SaaS 区域，端点为 https://apac.api.smith.langchain.com，控制台为 https://apac.smith.langchain.com。
  • 只修改顶层 agent/ 运行时的配置和 LangGraph 调用参数。backend/、 frontend/、Agent API 契约、PostgreSQL schema 和迁移都不变。
  • 首期默认记录“元数据级 trace”：模型、工具、耗时、状态、Token、错误和 run_id/thread_id，默认隐藏 Prompt、消息、工具参数、工具结果和模型输出。
  • 生产环境不能通过请求 Body、Browser 或模型输出开启内容级调试。内容级 调试只按环境显式配置，并在启用前完成数据分级和脱敏评审。
  • LangSmith 故障或网络中断不能使 Agent Run 失败，也不能进入 readiness 判定。
  • 如果后续合规要求数据留在境内，只需把 LANGSMITH_ENDPOINT 切到 Enterprise 自托管实例；业务契约和调用点不变。

2. 当前实现与接入点​

当前 agent/ 的执行路径已经具备 LangSmith 所需边界：

Backend delegated context
  -> agent API /internal/agent/v1/ag-ui
  -> QwenModelProvider（ChatOpenAI compatible mode）
  -> create_data_analysis_agent（Deep Agents + LangGraph）
  -> agent.astream
  -> 当前 `/internal/agent/v1/ag-ui` 的 AG-UI 事件流

关键代码位置：

位置当前职责LangSmith 接入关系
agent/src/chein_agent/settings.py从根目录 .env 读取 Nacos bootstrap，再把 Nacos YAML 注入 os.environ，最后构造 Settings增加 LangSmith 配置字段和启动校验
agent/src/chein_agent/model_provider.py构造 Qwen ChatOpenAILangChain 自动产生 LLM spans
agent/src/chein_agent/harness.py创建 Deep Agents/LangGraph Agent自动产生 graph、chain 和 tool spans
agent/src/chein_agent/api.pyrun_ag_ui 领取 Run，并调用 agent.astream在现有 config 中注入 run_name、tags、metadata
agent/uv.lock已通过 langchain-core 引入 langsmith仅使用环境变量自动装配时，不需要新增直接依赖

当前代码没有 LANGSMITH_* 配置，也没有直接导入 langsmith。现有 _load_nacos_config() 在 Settings 初始化前把 Nacos 配置写入 os.environ，因此 LangSmith SDK 可以直接读取 Nacos 中的配置。

3. 数据流与所有权​

边界规则：

  1. LangSmith 只接收 tracing，不参与 Run 领取、权限校验、取消、恢复和最终结果。
  2. LangSmith 中的 trace 不向最终用户直接开放；首期只供平台运维和研发排障。
  3. agent_runs、agent_run_events、PostgreSQL checkpoint 仍是状态和审计事实源。
  4. LangSmith 项目按环境隔离，不按每个租户创建 Project 和 API Key。
  5. backend 和 frontend 不持有 LangSmith API Key，不代理 LangSmith API。

4. 配置设计​

4.1 Nacos chein-agent-runtime.yaml​

LANGSMITH_TRACING: "true"
LANGSMITH_ENDPOINT: "https://apac.api.smith.langchain.com"
LANGSMITH_API_KEY: "<Nacos secret>"
LANGSMITH_PROJECT: "chein-agent-dev"
LANGSMITH_WORKSPACE_ID: "<optional workspace id>"
LANGSMITH_TRACING_SAMPLING_RATE: "1.0"
AGENT_ENVIRONMENT: "dev"
AGENT_VERSION: "local"

# 生产默认不记录内容；staging 只有在数据已脱敏/获批时才可设为 false。
LANGSMITH_HIDE_INPUTS: "true"
LANGSMITH_HIDE_OUTPUTS: "true"
配置必需说明
LANGSMITH_TRACING是总开关。生产、预发、开发分别配置，默认必须为 false
LANGSMITH_ENDPOINT是APAC 为 https://apac.api.smith.langchain.com；自托管为 <host>/api
LANGSMITH_API_KEY是使用 workspace service key；不得提交 Git，不得下发到 Browser 或 Backend
LANGSMITH_PROJECT是建议 chein-agent-dev、chein-agent-staging、chein-agent-prod
LANGSMITH_WORKSPACE_ID否只有 service key 覆盖多个 workspace 时需要
LANGSMITH_TRACING_SAMPLING_RATE否0.0-1.0；首期低流量保持 1.0，采样率调整必须先评估错误覆盖
LANGSMITH_HIDE_INPUTS是生产默认 true，隐藏模型/链/工具的输入
LANGSMITH_HIDE_OUTPUTS是生产默认 true，隐藏模型/链/工具的输出
AGENT_ENVIRONMENT是dev、staging 或 prod；用于 trace tag 和排障筛选
AGENT_VERSION是发布版本或 Git commit；由 CI/CD 注入，不能依赖本地默认值

LANGSMITH_ENDPOINT 不能带结尾 /。使用 APAC Project 的 service key 时不能 连接美国默认 endpoint；区域和 API Key 必须一致。

4.2 配置注入顺序​

部署环境 .env / Secret
  -> Nacos bootstrap 参数
  -> chein-agent-runtime.yaml
  -> settings.py 注入 os.environ
  -> LangSmith SDK / LangChain tracer 读取

Nacos 中只保存运行配置引用和密钥值；Git 中只提交 deploy/nacos/*.yaml.example 占位文件，不提交真实 Key。

5. Trace 关联字段​

在现有 agent.astream 的 RunnableConfig 中增加以下字段：

字段值用途
run_namechein-data-analysis统一根 trace 名称
tagsenv:<environment>、agent:chein-data-analysis、engine:deepagents、model:qwen低基数筛选
metadata.run_id当前 AgentRun.id与 Agent 控制面精确关联
metadata.thread_id当前业务 thread_id会话级串线
metadata.environmentdev/staging/prod环境筛选
metadata.agent_versionAgent 发布版本回归定位
metadata.contract_versionanalysis.v1契约版本
metadata.enginedeepagents引擎定位
metadata.model实际 Qwen 模型名模型对比

默认不把 tenant_id、user_id、delegated JWT、Qwen API Key、数据库连接串或 ERP 原始数据写入 LangSmith。需要按租户筛选时，先用内部 run_id 关联 agent_runs，后续如需在 SaaS 侧直接筛选，再单独评审加盐的 tenant_ref。

6. 默认数据策略​

LangSmith 默认会记录 LangChain/LangGraph 的输入和输出。该行为与 Agent 架构第 12 节 的默认 “只记录元数据”原则冲突，因此必须使用以下策略：

环境HIDE_INPUTSHIDE_OUTPUTS允许内容
devtrue 默认true 默认只做链路和性能调试
staging仅在数据脱敏/批准后 false仅在数据脱敏/批准后 false合成数据、脱敏样本
prodtruetrue只记录元数据、状态、Token 和耗时

内容级调试必须满足：

  • 不接收真实用户 Prompt、ERP 明细、JWT、凭据和原始工具结果。
  • 需要时先实现 callback/anonymizer 脱敏，显式开启、限时并审计。
  • 不接受行内请求参数控制，不能由前端、模型或普通业务用户打开。
  • 开启前单独记录数据分类、保留期限、责任人和关闭时间。

7. 失败与降级语义​

  • LangSmith 报送采用后台异步发送；网络失败、429 或服务不可用只记录脱敏日志 和指标，不改变 Run 成功的终态。
  • readiness 不检查 LangSmith。数据库、checkpoint 和关键模型依赖的检查逻辑 保持现状。
  • 进程退出前尽可能 flush；flush 失败只记录，不阻塞 Run 结束。
  • 关闭观测使用 LANGSMITH_TRACING=false 并重启进程；不需要数据库回滚。
  • 不把 LangSmith trace 当作重放来源。恢复和取消继续使用 checkpoint、 AgentRun 和 RunEvent。

8. 实现改动清单​

8.1 配置层​

在 agent/src/chein_agent/settings.py 增加：

  • LANGSMITH_TRACING: bool = False
  • LANGSMITH_ENDPOINT: str = "https://apac.api.smith.langchain.com"
  • LANGSMITH_API_KEY: str | None = Field(default=None, repr=False)
  • LANGSMITH_PROJECT: str = "chein-agent"
  • LANGSMITH_WORKSPACE_ID: str | None = None
  • LANGSMITH_TRACING_SAMPLING_RATE: float = Field(default=1.0, ge=0, le=1)
  • LANGSMITH_HIDE_INPUTS: bool = True
  • LANGSMITH_HIDE_OUTPUTS: bool = True
  • AGENT_ENVIRONMENT: Literal["dev", "staging", "prod"] = "dev"
  • AGENT_VERSION: str = "0.1.0"

当 LANGSMITH_TRACING=true 时校验 endpoint、API Key 和 LANGSMITH_PROJECT；缺失或格式错误时启动失败关闭，不静默产生无认证 trace。

8.2 调用层​

在 agent/src/chein_agent/api.py 的现有 agent.astream 调用处，扩展现有 config：

config = {
    "configurable": {
        "thread_id": checkpoint_thread_id,
    },
    "recursion_limit": settings.AGENT_MAX_GRAPH_STEPS,
    "run_name": "chein-data-analysis",
    "tags": [
        f"env:{settings.AGENT_ENVIRONMENT}",
        "agent:chein-data-analysis",
        "engine:deepagents",
        "model:qwen",
    ],
    "metadata": {
        "run_id": input_data.run_id,
        "thread_id": input_data.thread_id,
        "environment": settings.AGENT_ENVIRONMENT,
        "agent_version": settings.AGENT_VERSION,
        "contract_version": "analysis.v1",
        "engine": "deepagents",
        "model": settings.QWEN_MODEL,
    },
}

checkpoint_thread_id 继续使用现有 tenant_id:user_id:thread_id 拼接值，LangSmith metadata 中不复制该拼接值。

只有在第二个执行入口需要相同的 tracing 配置时，才把这段配置提取为小型 helper；不要提前建立自定义 tracing 框架。

8.3 依赖层​

首期通过 LangChain 的环境变量自动装配，不直接导入 LangSmith SDK，因此不需要 新增直接运行时依赖。若实现中需要 langsmith.Client、traceable 或 tracing_context，必须在同一次变更中把 langsmith 加入 agent/pyproject.toml、更新 uv.lock，并通过依赖审计。

8.4 测试层​

本地自动化必须覆盖：

  • LANGSMITH_TRACING=false 时 Agent 正常执行且不发 trace。
  • 开启 tracing 时 RunnableConfig 包含 run_id、thread_id、环境和 tag。
  • API Key、delegated token、Qwen Key 不出现在构造出的 metadata/tags 中。
  • LangSmith 网络异常不把 Run 置为 failed。

真实 LangSmith 发送与 UI 可见性属于显式手工冒烟，不在默认 CI 中依赖外部 服务和真实业务数据。

9. 前置工作​

  1. 创建并确认 LangSmith APAC Organization、Workspace 和 chein-agent-* Project。
  2. 创建 workspace-scoped service key，并通过 Nacos 或部署 Secret 注入。
  3. 完成数据出境和 trace 保留评审，确认 APAC（GCP Sydney）是否满足业务要求； 若不允许，改走 Enterprise 自托管。
  4. 确认 Agent 运行环境可以访问 https://apac.api.smith.langchain.com，并完成 防火墙、DNS、代理和出站白名单配置。
  5. 准备 Nacos 配置项、命名空间 ACL 和 production/dev/staging 三套 Project。
  6. 确认生产默认 HIDE_INPUTS=true、HIDE_OUTPUTS=true，并指定内容级调试的 审批人、脱敏方案、保留期限和关闭流程。
  7. 确认配额、采样率和告警责任人；trace 中断或超额不能影响 Agent 执行。
  8. 在 dev/staging 用合成数据完成一条端到端冒烟，再以 LANGSMITH_TRACING=false 作为回滚开关演练一次。

10. 分阶段实施​

Phase A：元数据观测​

  • 配置层、RunnableConfig、关闭开关和本地测试。
  • APAC Project 仅接收元数据、状态、耗时、Token 和错误。

Phase B：生产灰度​

  • 在 chein-agent-staging 验证模型、工具、取消和失败 trace。
  • 生产以 100% 低流量开始，按证据调整采样率，不先开启内容捕获。
  • 建立按 env、model、run_id、thread_id 的排障手册。

Phase C：受控内容调试​

  • 仅在确有需要且完成脱敏评审后，对 dev/staging 的选定 Project 临时关闭 HIDE_INPUTS/HIDE_OUTPUTS。
  • 生产内容级 trace 必须单独设计和审批，不能把本阶段默认配置直接复制到生产。

11. 验收标准​

  • 一次真实 Agent Run 在 LangSmith 中产生一条根 trace，并包含 LLM 和 tool 子 span。
  • trace 能通过 run_id 与 agent_runs 对应，通过 thread_id 关联会话。
  • trace 中不存在 API Key、delegated JWT、数据库连接串、Qwen Key 或未批准的 原始业务数据。
  • LangSmith 停止或断网时，Agent Run 仍能成功、失败或取消，状态不被 trace 改变。
  • LANGSMITH_TRACING=false 可立即关闭上报，不需要数据库变更。
  • 生产默认不记录内容；内容级调试的开启和关闭可审计。

12. 待决项​

  1. APAC SaaS 是否被法务和数据责任人接受；不接受时切换自托管的时间点。
  2. 生产 trace 的保留期限、费用上限和采样策略。
  3. 是否需要将加盐 tenant_ref 纳入 LangSmith metadata 以支持 tenant 级筛选。
  4. 是否在后续阶段引入 OpenTelemetry/统一观测网关；当前不在首期范围内。
