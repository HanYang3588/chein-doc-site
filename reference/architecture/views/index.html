Chein 当前系统架构视图与证据

图例：实线＝已找到实现/声明；虚线＝显式可选配置；数据库节点＝逻辑数据所有者，不强制不同数据库服务器。 前端、API、Agent 的事实分别由 前端架构、平台实施基线、Agent 架构维护。本页是跨系统视图导读，不替代专题。

分层系统总览​

打开 SVG 原图，无损放大。

管理后端采用模块化单体，Agent 为独立运行时，自动化 Scheduler 独立启动。总览按能力和数据所有权分区，橙色虚线表示可选集成，紫色点线表示异步削峰设计。Higress 统一承担系统与模型网关；下方链路图分别展开各领域的内部关系。

网关、削峰与向量存储补充​

  • Higress：系统网关与 AI 模型网关。 统一承接系统 API 路由和模型代理，提示词相关的响应缓存与输入输出安全治理在网关执行。Redis 提供缓存存储；缓存类型为受控模型/响应缓存，Nacos 继续管理提示词正文，Platform 管理适用范围元数据。缓存按租户与数据范围隔离；后端负责当前成员、RBAC、ACL、模块权益、工具权限及 Tenant UoW/RLS 校验。相关能力见 Higress AI Cache 与 官方插件目录。
  • RocketMQ：异步缓冲与削峰设计。 对允许异步完成的业务任务，计划采用“所属模块持久任务/事务 Outbox → RocketMQ 积压缓冲 → 所属业务 Worker 限并发消费”；不把所有 HTTP、SSE 或实时语音请求强制改为排队。消息仅作唤醒信号，携带受控路由引用与任务 ID，不携带可直接信任的权限或任意执行参数。消费端按当前可信上下文重验授权、进入相同 UoW、原子领取任务并幂等处理，完成后确认；失败复用既有重试、租约、死信和回执语义，不建立旁路投递。跨数据库与 MQ 的提交必须由 Outbox 衔接，消息重复不能重复业务副作用。队列集成按所属模块接入，保留现有数据库任务、Scheduler、视频 Worker 与 RAGFlow 内部 Redis 队列的所有权；HermiT 保持独立私有计算。接入验证覆盖积压、重投、崩溃恢复和跨租户隔离。削峰用途见 RocketMQ 官方领域模型。
  • Elasticsearch：RAGFlow 的向量与全文索引存储。 现有部署模板已使用 DOC_ENGINE=elasticsearch，连接配置来自 RAGFLOW_ES_*。Chein 经授权的 Knowledge/RAGFlow 链路检索，向量写入、索引与检索由 RAGFlow 管理；Agent 不直连 ES，也不恢复已移除的 Agent 独立 ES/pgvector 记忆实现。此框不表示 Langfuse 使用 ES，也不取代 PostgreSQL 的业务事实、发布版本和权限事实源。

核对入口：

  • 前端与接入：前端架构、Manifest 兼容检查、Backend API 组合根、Platform/BFF 装配。
  • 模块与协作：Suite 模块集合、模块注册与工具声明、模块化实施基线。
  • Agent 与状态：运行时架构、Agent API 装配、编排与中间件、自动化边界。
  • 可选服务与数据边界：HermiT、Neo4j Provider、Native Memory、Token 交付与外部门禁、部署。
  • 网关与检索配置：模型网关接线示例、缓存隔离设计、RAGFlow 部署与 ES 向量检索、RAGFlow 存储配置。

1. 系统总体架构​

证据：backend/main、组合根、registry、BFF、Agent main、harness、retrieval、RAGFlow Adapter。图里的业务模块是同一 API 部署内的所有者，不是新微服务；Agent 不导入 Backend ORM。

2. 前后端初始化与交互​

证据：app.tsx、manifest.ts、菜单适配、唯一组件映射、Workspace、代理。前端权限只控制交互；菜单隐藏不会撤销后端权限，也不能替代数据库隔离。

3. Agent 执行与恢复架构​

证据：api.py、runs.py、threads.py、harness.py、checkpoints.py、decision_middleware。图示为当前 Agent API 内执行，不是已经拆好的 Gateway/Worker 集群。内置 shell/文件系统工具受限；没有业务写入工具。通用 ArtifactStore、独立 ApprovalRequest/通知、独立 Worker 仍是目标态。

4. Knowledge / RAGFlow 检索与引用​

证据：tools.py、knowledge_pipeline、retrieval client、Knowledge routes、application/retrieval、RagflowClient、原生 Tool 当前说明。默认 HTTP；官方 MCP 是显式可选 Adapter，不是 Agent 直接向原始 RAGFlow 目录查询。空允许列表、撤权或动态模式失败不扩大范围/不回退静态资料。

5. 数据存储与所有权​

证据：Platform 所有者 metadata、ERP 模型、Knowledge 模型、Analytics 模型、Agent migration、Agent snapshot migration、RAGFlow 模板。这些是逻辑命名空间；不推断实际部署是一个还是多个 PG 实例。全局系统库、租户库、Agent owner 快照具有不同安全策略，不能画一条“所有表 RLS 已完成”的统一标签。

6. 模块依赖与可选能力​

证据：4 个 Edition、registry、ERP definition、Knowledge definition、Analytics definition、纯 DTO。实线是声明/使用依赖，不等于任意 import 均合法；可选能力不能画成 Analytics 静态导入 ERP 私有实现。Root 指向的是候选模块，本次具体包含关系以各 YAML 为准，Base 不含全部这些模块。IOA 不在 registry 中。

7. 网络与部署组件​

证据：Compose base、override、Backend Dockerfile、Frontend Dockerfile、Nginx、RAGFlow run。默认 API 生命周期托管后台线程，standalone profile 不是首发必须组件。显式生产 override 有已知旧服务残留；此图不能证明 compose.production.yml 可直接启动。RAGFlow run 只映射 loopback 端口，跨容器可达性取决于实际网络，不能照抄 localhost。

8. 认证、权限与数据库隔离​

证据：API deps、模块访问、Platform web_api、Tenant UoW、委托签名、Agent security、ERP 分析范围、Knowledge 服务。这是适用检查的示意，不主张所有 Platform 路由都执行业务模块门禁。来源 body/query/header 的 tenant_id 不成为可信身份；RLS 与应用授权互为补充；模型建议/图谱不能授予权限。

9. SQL 分析、图表与收藏调用链​

证据：analytics tools、analytics application、analytics routes、ERP analysis、编译器、Agent analysis、前端 renderer。HTTP 内部 query 配置为兼容路径；启用 MCP 时撤销/错误不能回退 HTTP。快照属于 Agent，收藏属于 Analytics，交易数据/口径属于 ERP。

10. 日志与可观测性​

证据：logging adapter、HTTP 摘要、Backend main、metrics、Agent observability、log query、runtime logs、ES provision。这不是已经接入 LangSmith/SkyWalking 或完整分布式 tracing 的图。ES 内存队列可能丢弃；PG 审计独立；不记录 prompt、工具参数、请求正文、模型正文或凭据。

维护与发布检查​

每图更新与所引用源的变更同步复核：当前模块/入口、边方向、可选开关、所有权、状态和部署边界。新图直接发布本页经审核的 Mermaid 文本，旧 PNG 原位保留且不作为当前图入口。源 API/配置路径只有确有实现时才进入图。

正式开发验收必须覆盖 Mermaid 全部渲染、暗色/窄屏、引用跳转和发布集审核；本阶段只提交这些视图供评审，不声称页面已经开发或已经部署。
