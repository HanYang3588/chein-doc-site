Chein 实时语音：调研与实施设计

设计，2026-10-24 本地实现与验证。状态：核心链路已实现并本地验证，默认关闭；完整生产验收尚未完成。

1. 调研结论​

  • 前端实际使用 React 19、TypeScript 6.0.3、Ant Design 6.6.4、assistant-ui/react 0.15.21（安装源码核对），主入口 frontend/apps/web-pro/src/pages/agent/index.tsx 使用 useExternalStoreRuntime，消息由 React 外部 Store 管理，AG-UI 经 api.ts/sse.ts 合并；现有 Thread 已识别 metadata.modality=voice。
  • 安装的 core 0.3.20 导出 RealtimeVoiceAdapter、createVoiceSession、useVoiceControls；无需依赖升级。实际 Session 没有 sendText，连接期间普通 send/edit/reload/startRun 会被原生 Runtime 拒绝。不能用官方最新版可选 sendText 推断本地行为。
  • ExternalStoreAdapter.onVoiceTranscript 只通知宿主追加消息；不实现时转写只保留本次会话。它不是后端持久化。语音工具桥接应在服务端执行，不能调用被语音锁住的浏览器 Runtime。
  • VoiceConversation、VoiceControl、VoiceOrb 是官方可复制 UI 配方，不是本项目已安装的组件导出；当前未引入配方文件。优先按原生接口装配，沿用 assistant-ui/Base UI 和 AntD theme token，不升级整套依赖。
  • DictationAdapter 是填写 Composer 的单向听写；SpeechSynthesisAdapter 是消息朗读，二者不能替代双向通话。项目没有已接通的音频采集链路。
  • 后端 FastAPI 现有 /api/v1/agent-ui BFF 用 CurrentUser/CurrentPrincipal/CurrentTenant、agent:chat 和短期 EdDSA delegation；普通浏览器 Bearer 只在 HTTP Header。所有新接入适配器进入 Platform 模块包，模型协议留在顶层 Agent。
  • Agent api.run_agent_stream 是文字和自动化共享执行入口；runs.claim_run 在 Thread 行锁内拒绝未结束 Run。Checkpoint 是聊天历史来源；不能只新增一张语音转写表而不更新历史/模型上下文。
  • Nacos 沿用 settings bootstrap，启动必须指定 NACOS_CONFIG_DATA_ID=chein-agent-runtime.yaml。默认 .env 的 Data ID 不一定是 Agent；首次未显式指定时配置探测为空，已纠正。指定运行配置后 Qwen Key/Checkpoint 已配置。只检查存在性，不输出密钥或连接串。
  • 模型使用 Token Plan 文本域名；不代表该域名支持语音 WS。DeepAgents/LangGraph、已授权 MCP、RAGFlow Memory、审批和 metadata-only 观测继续复用，不引入 MQ 或新的 Agent 引擎。

2. 官方协议证据与待核实项​

2026-10-23 读取以下官方页面：

  • assistant-ui voice、API、speech。版本兼容最终以安装源码 @assistant-ui/core/src/adapters/voice.ts 与 runtimes/external-store 为准。
  • Qwen 模型接入、WS、客户端事件、服务端事件。

官方文档确认 3.0 支持 WS/WebRTC/AOQ；首版选 WS，便于 BFF 服务端授权与工具桥接。WebRTC 具备原生媒体传输，但增加信令/网络穿透；AOQ 需要额外客户端能力，项目无现有实现。这里不作未经实测的延迟排序。

3.0 输入为 pcm/16kHz/16bit/mono，输出 pcm/24kHz/16bit/mono。tools 使用嵌套 function: {name,description,parameters}，不是 OpenAI 扁平结构。3.0 音色使用 longanqian、longanlingxin、longanlingxi、longanxiaoxin、longanlufeng；不使用 3.1 音色及 input/output language 专有参数。支持 server_vad、smart_turn、turn_detection=null 的手动提交。自动模式 clear/commit 被忽略，不能依赖 clear 停止 VAD。

Token Plan 权益、专属 Workspace/地域、并发/最大通话时长/上下文/限流/单价必须由账号实际 API 与控制台确认，不填猜测数字。真实测试必须包含音频和工具，不以握手成功替代全部验收。Context7 查询因连接 Key 无效失败，协议调研已回退官方网页和已安装源码。

3. 目标架构与职责​

Qwen client 只持有官方连接、配置、事件和有界数据。Gateway 持有连接取消和统计。Session 管理复用 PG 租约与 Thread 锁：语音与文字竞争同一个服务端所有权边界，浏览器 disabled 不是互斥保障。Bridge 仅注册 invoke_chein_agent(question)，身份由可信 delegation 给定；不能接受模型指定 user/tenant/URL/SQL/scopes。

4. 身份、安全与互斥​

票据仅通过已认证 HTTP 取得；32 字节随机值，摘要键存现有 Redis，30 秒 TTL，Lua 原子 GET/DEL，绑定 tenant/owner/thread/origin/voice_session；重放失败。WebSocket 握手通过 Sec-WebSocket-Protocol 的 chein.voice 与票据槽传递短期票据，验证 Origin 后原子消费、重验身份，再 accept；长期 Bearer 和票据均不进入 URL。鉴权完成前不连接 Agent 或模型；每用户每分钟最多申请 10 张票据。不是把长期 Token 放进 URL 的方案。不得把长期 Bearer 填到 WS URL；日志也不记录票据。BFF Origin 精确允许列表，生产只 HTTPS/WSS；内部 WS 仅可信网络并验证签名上下文。

当前实现使用独立 PostgreSQL 连接持有 session advisory lock，分别限制集群总量、每用户数量与 Thread；普通 Run、归档和删除取得相同 Thread 的事务 advisory lock。连接关闭自动释放，不新建语音租约表。必须直连 PostgreSQL 或使用 session pooling，禁止将该锁方案部署在 transaction pooling 后。失联不恢复旧上游。每次工具执行重验成员/模块/数据权限；delegation 过期前重签需要当前授权，不盲延长。所有线程读取/更新同时带可信 tenant 与 owner；RLS 及 app_runtime 负向测试是发布门禁。

输入只允许二进制 PCM 和 end/interrupt 控制，拒绝任意上游 session.update/function result；默认帧 20–40ms，有界单帧/每秒字节、控制消息速率、发送队列与上游 max_size。超限关闭，不无限缓冲。禁永久录音、默认 trace 正文及自动重连重放工具。

5. 帧、事件及标识​

浏览器到 BFF：binary = 16kHz signed little-endian PCM；JSON {type:"interrupt"} / {type:"end"}。BFF 不多次编解码；在 Agent 到 Qwen 边界进行一次 Base64 转换。出站 binary 是 24kHz PCM；JSON 控制/字幕先到，顺序关联当前 response_id。客户端使用有界播放队列，不能把帧存 React State。服务端 notice/voice_spoken_limit 表示本次口播已达 25 秒上限，客户端提示查看文字结果且不结束整通会话。

6. 前端生命周期​

复用 createVoiceSession 防重复挂断及异步 setup 晚到；本地 Adapter 包装 disconnect，补齐当前安装 SDK 在 setup 尚未完成时不会调用控制器清理的行为。取票和等待 ready 共用 60 秒启动预算，取消会中止取票、清除计时器并结束等待，不遗留后台连接。getUserMedia 开启 AEC/NS/AGC；AudioWorklet 按实际 AudioContext 采样率跨块重采样到 16k，输出限幅 PCM16LE，并附采集时钟。页面阻塞后，客户端跳过超过 500 ms 的积压帧并提示重说，避免集中补发触发速率保护；服务端速率与大小限制保持不变。播放 24k Buffer，限制待播放秒数、结束释放节点。初始化必须源于点击；拒绝麦克风、track ended、隐藏页面及卸载释放 stream/context/socket；静音停止上行但不冻结网络事件。

原生 voice controls 驱动通话入口和挂断/静音。语音转写直接复用 Thread 的普通 UserMessage/AssistantMessage，包括 Markdown 和操作栏；不再维护 SpokenMessage 分组卡片或输入框上方的重复字幕栏。modality 元数据继续保留用于历史来源，不决定单独样式。工具、图表和附件仍通过既有 AG-UI renderer，绝不把原始 JSON 作为口播。具体的设备、认证、额度、占用、限流与超时错误使用本地化提示，未知错误保持通用提示，不显示上游正文。通话期间文字发送/编辑/重跑禁用，挂断后重新读取服务端历史；本版本不提供 sendText。

通话视觉采用 assistant-ui 官方 VoiceOrb registry 组件，源码固定于 7beac6fc271435b8c60e842a8e5ba327725d25e2，存放 components/assistant-ui/voice.tsx 并保留 MIT 许可；它不是当前 npm 包的直接导出。原 useVoiceState/useVoiceVolume/useVoiceControls 已在安装的 React 0.15.21/Core 0.3.20 中核对，无 SDK 升级或新增依赖。VoicePresence 经既有 composerTop 插槽紧贴输入框上方、水平居中显示蓝色 Orb、状态及计时；展示区使用固定紧凑高度，不拉伸占据剩余对话空间，连接/结算阶段显示加载图标；静音和回答沿用真实 Session 状态。减少动态效果偏好使用静态图标，无 WebGL2 时也有静态回退。完整消息、业务工具和图表继续使用原 Thread，不使用只显示末两条字幕的独立对话投影。通话期间 Composer 改为紧凑圆角栏和静音/蓝色 X 挂断按钮，仍不提供 sendText；挂断后恢复原输入框及功能。非通话布局、鉴权、音频协议、历史与导航确认不变。

代码生成、修改和解释请求复用 invoke_chein_agent，由原文字 Agent 将完整实现和说明写入同一 Thread；语音模型仅简短提示查看页面，不朗读符号、变量或逐行转述。代码工具结果和恢复历史中的助手代码只在送入语音上下文时替换为固定短提示，AG-UI 事件和 checkpoint 正文不经过该过滤。若语音模型仍直接输出 Markdown 代码围栏或可识别的常见函数/变量定义，Gateway 取消当前口播并 clear 待播放音频，保留已生成的文字和通话；该启发式补充保护不是编程语言解析器，不能追回早于识别字幕已播放的音频。25 秒口播硬上限继续保留，voice_spoken_limit 不表示代码或业务 Run 失败；工具关闭时明确引导文字入口，不能声称已生成结果。

通话或连接期间，站内路由、切换/新建会话和关闭浮动聊天统一弹出“继续对话 / 停止对话并离开”。继续会取消本次跳转并保留页面及通话；停止等待 Adapter 完成挂断和设备释放后再执行原跳转，不取消已提交的业务 Run。浏览器刷新/关闭使用原生 beforeunload 确认，其文案和按钮由浏览器控制。相同 URL 的内部同步不触发确认，多个同时到来的跳转只接受首个待确认请求。

空白会话在渲染时预留 UUID，只有实际发起请求才持久化；draft 转为 active 时不更换 assistant-ui 的 Thread 身份，连接回调固定绑定通话 Thread。入口等待原生 voice capability 装配后才可点击，避免启动竞态造成通话计时、控件或后续事件消失。

最终转写按服务端稳定 messageId 更新；业务事件信封增加 runId/userMessageId，RUN_STARTED 同时带最终 userText，前端复用现有 projector 并将助手消息绑定原用户轮次。迟到摘要插入所属轮次，不追加到下一问题之后。挂断回填使用原历史接口合并，保留尚未进入 checkpoint 的业务事件及页外旧轮次，完成后用服务端消息替换实时投影并清除 SDK 的临时分支。私有分页响应显式返回 contentRedacted；当前权限/Memory 策略已撤回内容或旧服务端缺少此标记时，只接受服务端历史，禁止合并保留旧正文。仍运行的任务按退避最多回查约 210 秒，覆盖最高 180 秒工具预算和结算窗口；开始新通话、切换会话或卸载后停止应用旧回填。

非通话状态下，右侧主操作按原生 composer.isEmpty 切换：空输入或纯空格显示语音波形按钮，输入文字或附加文件后显示原发送按钮；移除左侧重复电话入口。生成中且无待发内容时继续显示停止按钮，有草稿时保留原排队发送行为；语音未启用时保留原发送布局。通话的静音与挂断通过同一右侧插槽呈现，复用当前 Adapter 和权限/加载禁用条件，不新增发送或连接路径。 工具区保持单行，宽度不足时使用原生横向滚动；右侧发送/语音/停止按钮位于滚动区外且不收缩，浮窗与完整页面复用该布局。 浮窗 Portal 可能不继承 Ant Design CSS 主色变量，三种主操作均使用带默认蓝色的 CSS 变量回退，避免透明背景上的白色图标不可见。

7. Agent 桥接、持久化与取消​

高层工具只允许有界 question、无其他字段。调用前验证 call_id 和当前用户最终转写，避免模型用任意外部文本冒充用户事实；串行执行，重复 call_id 返回原结果；同 ID 不同参数失败关闭。持久幂等依赖既有 Run，不能只用进程内 set 证明跨重启安全。工具结果只给有界口语摘要，引用、ChartSpec 和附件沿原事件通路。

若遇 waiting_approval/waiting_input，暂停模型口播任务并显示现有服务端决定 UI；模型不能宣称审批通过。语音首版不新增写工具；原 Runtime 中已有的非只读能力仍由原 interrupt_on 和服务端审批约束，不能把 WebSocket 收到的模型输出当批准。

最终有效用户转写与 AI 完成字幕由 Agent 写入既有 checkpoint，稳定 ID=UUIDv5(voice:session:item:role)，作为既有 HumanMessage/AIMessage；不让浏览器和服务端各写一次。前端按相同 ID 回填本地 UI；旧协议仍可使用原生 onVoiceTranscript，恢复后以服务端 ID 为准。Transcripts 按 response_id 绑定用户 item，缓存先到的 assistant 字幕，等用户最终转写后按 user→assistant 顺序提交；ASR 增量使用官方 text+stash，环境音事件完全排除。真实测试复现了 response.done 先于 ASR completed，因此挂断给予最多 5 秒结算窗口，浏览器随后刷新持久化历史。纯语音有效轮次以相同用户消息 ID 进入既有 Agent Run，完成后经 finish_run 写入来源 intent；复用 MemoryContextMiddleware 的当前 owner/policy generation 和 should_extract，Memory 失败或 1 秒授权超时只跳过来源入队，不伪造提取成功。实际提取仍由原 jobs/离开 Thread/Worker 治理，关闭或清空继续按 generation 拒绝迟到任务，assistant 输出不是用户事实。高层工具轮次复用原 Agent Run 的来源流程，不额外创建一份 voice Memory job。输入、输出和 function_call 的来源 ID 只存既有 checkpoint/Run，不建第二套历史。

response.done 按 response_id 独立结算，不清除其他响应的当前状态。业务 Run 完成时，如原响应被打断或已有下一用户轮次，只保留业务结果，不再触发过时口播。已有业务任务执行时，第二次 function call 返回忙碌提示，保持通话且不重复提交。历史状态查询使用 checkpoint 中 voice_execution_run_id 对应实际 Run，避免用语音消息 ID 查不到完成状态。以上为 Agent 私有 HTTP/WS 的增量字段，Backend 公共 OpenAPI 不变；无需数据库迁移，Agent 与前端应一起更新以获得完整行为。

音频 interrupt 清播放并隔离旧 response；response.cancel 只取消语音模型。挂断会结算最多 5 秒的最终转写、关闭上游和锁连接；已开始的业务 Run 在原预算内完成，显式 Agent 取消仍走既有 cancel API，已提交事务不会撤销。断连不自动重新提交工具。超时、限流、配额、无权限均给明确错误与手动重试，不自动重放不明提交。

8. 配置、观测和部署​

配置进入现有 Agent Settings/Nacos，AGENT_VOICE_* 独立模型、Endpoint、密钥（repr 隐藏）、音色、VAD、并发、最大时长、空闲、帧限制、工具超时、输出限额。不得自动把 Token Plan 文本 URL 改造成 WS；不得未经确认把聊天 Key 发给另一个域名。功能默认关闭，凭证不进入前端。

复用现有 metadata-only OTLP/结构化日志：session ID、脱敏身份、连接成功/失败/时长、输入输出音频秒数、首响应/首音频、工具次数与耗时/错误率、中断与异常断连。无供应商 usage/cost 则 unknown，音频秒数不当 token。观测异常不能改变授权/执行。

部署顺序：官方连通实测 → 有界协议适配 → 数据库互斥与持久化迁移及 app_runtime 验证 → BFF 单次票据和 WSS 代理 → 原生 UI/音频 → 端到端验收 → 灰度开启。回滚先关闭入口、排空会话，再回滚应用；保留 checkpoint 和已执行 Run，不删除用户历史。默认关闭不改变文字聊天，无计划升级 assistant-ui。

在现有 Agent Data ID 配置 AGENT_VOICE_ENABLED=true、明确的 Endpoint/API Key；按需启用 AGENT_VOICE_TOOLS_ENABLED。现有配置只在进程启动读取，发布后重启 Agent。前端启动时读 status，因此开启/关闭后刷新页面；Backend 必须已有 Redis、AGENT_API_URL 和 delegation 配置，外部网关必须 HTTPS/WSS，Origin 必须精确配置在现有白名单。生产同时检查 ASGI 的 https/wss scheme；TLS 入口必须保留可信转发链，Uvicorn FORWARDED_ALLOW_IPS 只配置实际可信网关地址/CIDR，不使用 *。当前 Nginx 示例监听 80，只能在可信内部或开发使用；生产应在 Nginx 终止 TLS，或由入口将 API 转发到能保留真实 scheme 的 Backend。TLS 证书、入口与信任链仍需部署环境实测。先保持默认关闭完成验收，再开启用户入口；回滚先关闭功能，保留全部 Thread/Checkpoint。

尚未完成，不能标记生产级全阶段交付：

  1. 移动端、真实物理麦克风/扬声器听感、回声、设备撤权和 HTTPS 证书入口验收；合成语音或本机浏览器验证不能代替这些证据。
  2. 普通中文、ERP 与知识库的正常登录 BFF 链路已实测；仍需普通非管理员账号、生产模块权益及负向权限场景的业务验收。不能把本次管理员只读测试当作所有用户角色验收。
  3. 真实 RAGFlow 的语音来源提取/关闭/清空联调：来源 intent、generation 与 Worker 接线已有代码和单测；未用合成身份冒充真实 Platform 账号去调用私有 Memory。
  4. 本次首版明确采用 WebSocket + server_vad/smart_turn；manual 是协议探测能力。PTT、WebRTC/AOQ、自动恢复旧上游和独立最小化通话窗不在首版实现范围。关闭浮动聊天需确认停止，避免隐藏采集。
  5. 并发 CPU/RSS/播放缓冲压测、多实例撤权与异常断网演练；当前有资源边界和复现方法，没有生产容量结论。
  6. 远端 CI、镜像扫描、签名、生产配置发布、套餐账单/配额上限确认均未执行。metadata 日志记录连接/首响应/音频时长/工具/取消/供应商明确 usage，不虚构费用；voice span 与统计 metadata 已接线；真实 Langfuse 环境的采样、看板和业务联查仍待验收。
