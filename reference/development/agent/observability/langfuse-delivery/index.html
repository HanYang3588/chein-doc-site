Langfuse P1–P5 实施与启用

P1–P5 的本地实现及工具已接线；目标环境的新功能尚未启用，生产性能、真实模型评测和治理签署尚未完成。设计与候选门槛仍见 阶段计划，本文记录当前实现和需要配置的内容。

1. 阶段与当前行为​

阶段当前实现边界
P1 安全接入官方 Callback、execution 根、HMAC 身份、源端屏蔽、属性白名单原始问题、答案、思考、工具内容和图片不上传；Input 为 null 属于预期行为
P2 业务与跨服务关联BFF 请求/Prompt、检索目录/规划/提取/证据、能力决策、MCP、ERP 授权/查询、分析快照、图片生成/保存、消息关联每个进程使用私有 OTel Provider；内部 JWT 验证后接受 parent；浏览器的 traceparent 不透传
P3 运行保护有界队列/批次/请求大小/导出及关停时间，确定性采样，全量低基数耗时/Usage 指标，压测与故障工具SDK 遥测允许丢失；不保证可靠重投；生产 P99、容量和可见性仍须实测
P4 反馈与评估消息/执行持久关联、类型化反馈、版本与去重、Score 同步/重试；合成 Replay、规则评估、配对比较、可选独立 Judge、原生 Dataset/Experiment 发布纠正文本仅本地保存；离线样例不是生产质量结论；外发内容必须逐项审核
P5 受控查询回答操作栏的运行详情、数量/耗时/Token、反馈与同步状态；本人和租户管理员查询 API先验证本地 tenant/owner/run/thread，再查询获准子树；不提供任意 Langfuse 过滤器代理

Langfuse SDK 和模型框架留在顶层 agent/。Backend 只使用 observability/ 的通用 metadata OTLP 适配层；业务模块仍拥有授权、SQL、检索和图片数据。Run、checkpoint、审批和权限继续由原系统管理，Nacos 继续负责 Prompt 正文与发布。

运行详情只返回所属 Agent execution 的后代，远端 BFF 父节点不会混入本人摘要。查询固定调用 /api/public/v2/observations，最多 100 个节点、256KB 响应和三秒 HTTP 总截止时间（包括慢速分块响应）；存在后续页时明确标记截断。24 小时查询窗口覆盖常规 execution，不保证覆盖更长任务。模型仅返回已配置的有限标签，Usage 缺失显示“暂无计量”，不补造零费用或独立重排耗时。

2. 先执行迁移​

升级代码、安装锁定依赖后，使用原有私有迁移配置执行。迁移账号不能注入 API/Worker；运行角色必须无 SUPERUSER、BYPASSRLS、CREATEDB 和 CREATEROLE。数据库地址和角色沿用实际部署值，本次没有替你执行生产迁移。

Agent 的 chein-agent-migration.yaml 增加 AGENT_CHECKPOINT_RUNTIME_DATABASE_ROLE，填写 Agent 连接串实际使用的角色名，默认 app_runtime。然后在项目根目录执行：

cd agent
uv sync --locked
NACOS_CONFIG_DATA_ID=chein-agent-migration.yaml uv run python scripts/migrate_checkpoints.py
NACOS_CONFIG_DATA_ID=chein-agent-migration.yaml uv run python scripts/migrate_observability.py

第一条迁移沿用既有 checkpoint/Run 结构；已有正确迁移的部署也可重复执行。第二条在 Agent schema 增加 agent_message_executions、agent_feedback、agent_feedback_revisions，以 agent_schema_migrations 记录版本，重复执行不会重建。三张表启用 FORCE RLS，必须同时具备 tenant 和 owner scope。运行角色只能追加反馈修订，不能更新修订历史。

Backend 使用已有 bootstrap 配置和当前交付 Edition；下面以 Suite 为例：

cd backend
uv sync --locked
NACOS_CONFIG_DATA_ID=chein-backend-bootstrap.yaml uv run python -m app.modules.migrate --edition suite

新增 Platform revision e9a2b3c4d5f6 注册权限动作，并为已有 Agent 套餐加入相应动作。它不自动授予现有用户角色。没有新的业务模块、后台反馈 Worker、Redis 桶或 Docker 网络变更。

3. Agent 运行配置​

在已有 chein-agent-runtime.yaml、Group/namespace 中保留模型、工具和数据库配置，补充下列项。Langfuse 地址是你部署的 Web origin，例如 http://langfuse.internal:3000；不能填 Console/S3 地址或 API 路径。

LANGFUSE_TRACING_ENABLED: true
LANGFUSE_BASE_URL: "http://langfuse.internal:3000"
LANGFUSE_ALLOW_HTTP: true # 私有 HTTP 的显式允许；HTTPS 时改为 false
LANGFUSE_PUBLIC_KEY: "replace-with-project-public-key"
LANGFUSE_SECRET_KEY: "replace-with-project-secret-key"
LANGFUSE_TRACING_ENVIRONMENT: "development"
LANGFUSE_RELEASE: "replace-with-release-or-git-sha"
LANGFUSE_SAMPLE_RATE: 1.0
LANGFUSE_TRUST_ENV: false
AGENT_OBSERVABILITY_ID_KEY: "replace-with-independent-random-key-at-least-32-characters"
AGENT_OBSERVABILITY_ID_KEY_VERSION: "v1"
AGENT_OBSERVABILITY_QUERY_ENABLED: true
AGENT_FEEDBACK_ENABLED: true
AGENT_FEEDBACK_SYNC_ENABLED: true
AGENT_METRICS_ENABLED: true
AGENT_METRICS_TOKEN: "replace-with-another-independent-random-key-at-least-32-characters"

以上开关默认关闭。采样率和 environment 是应用上报配置，不是 Langfuse 页面里的全局开关。HMAC 密钥和 Metrics Token 使用两个独立随机值；可分别用 python3 -c 'import secrets; print(secrets.token_hex(32))' 生成，不要提交到仓库。

默认保持 AGENT_OBSERVABILITY_DATA_POLICY=metadata-only-v1、LANGFUSE_MEDIA_UPLOAD_ENABLED=false、LANGFUSE_DEBUG=false。队列默认 2048、每批 128、导出间隔五秒、HTTP 超时两秒、请求上限 256KB、关停宽限五秒。保留既有 P1 配置即可，不靠增加业务超时处理观测故障。

LANGFUSE_TRUST_ENV=false 让 exporter 直接连接目标，避免本机系统 HTTP 代理拦截内网 Langfuse。只有确认必须经过代理时才显式允许它。Query/Score HTTP 客户端固定直连。改配置后重启全部 Agent worker；不会热更新已初始化的 SDK。

QWEN_STREAM_USAGE_ENABLED=true 仅在真实 Qwen/网关已验证支持 stream_options.include_usage 后启用。图片供应商或模型没有实际计量时继续标为 missing，不用估算值填充账单。

4. Backend 跨服务配置与权限​

在 chein-backend-runtime.yaml 增加：

OBSERVABILITY_TRACING_ENABLED: true
OBSERVABILITY_OTLP_ENDPOINT: "http://langfuse.internal:3000"
OBSERVABILITY_OTLP_ALLOW_HTTP: true
OBSERVABILITY_OTLP_PUBLIC_KEY: "replace-with-the-same-project-public-key"
OBSERVABILITY_OTLP_SECRET_KEY: "replace-with-the-same-project-secret-key"
OBSERVABILITY_SAMPLE_RATE: 1.0
OBSERVABILITY_TRACING_ENVIRONMENT: "development"
OBSERVABILITY_RELEASE: "replace-with-release-or-git-sha"

Endpoint 同样只填 origin，适配器自动拼接 OTLP 路径。Backend 和 Agent 必须使用同一项目、environment/release 与相同采样率，才能保持确定性 Trace 关联和采样一致；先在隔离项目用 100%，生产比例根据性能报告调整。重启 Backend；前端不配置任何 Langfuse Key。

给使用者角色分配 agent:chat、agent:observability:view、agent:feedback:create。租户管理员按需增加 agent:observability:admin；它允许传 owner_id 查询本租户的指定拥有者，不允许跨租户查询或替他人写反馈。新建租户的默认用户/管理员种子包含本人查询和反馈，超级管理员包含租户管理动作；已有角色需要在权限界面明确分配。

前端回答结束后显示“运行详情与反馈”、赞/踩、问题分类、本地纠正、任务完成/未完成和同步重试。只对已持久关联的回答显示；启用前的历史回答不会猜测绑定最近一次 Run。启用后的实时与 checkpoint 消息共享反馈标识，刷新后不会重复建 Score。

API 位于现有 BFF：

  • GET /api/v1/agent-ui/threads/{thread_id}/messages/{message_id}/observability?run_id=...
  • GET/PUT /api/v1/agent-ui/threads/{thread_id}/messages/{message_id}/feedback?run_id=...
  • POST /api/v1/agent-ui/threads/{thread_id}/messages/{message_id}/feedback/sync?run_id=...

浏览器传入的标识只是查找参数，服务端会重新验证所有权、成员权限和对应 Run。观测 API 失效不会阻断对话。

5. 反馈可靠性与 Metrics​

本地 PostgreSQL 是反馈事实源。同一消息/类型的完全相同提交不增加 revision；修改追加修订历史，每个拥有者一分钟最多 20 次实际修改。user_vote 只允许 -1/1，task_success 只允许 0/1；纠正文本最多 2000 字符。消息关联写入最多等待 500ms，失败时隐藏可选操作，原 SSE 与 Run 继续执行。

观测/反馈 API 总截止为十秒，数据库或网络等待超限返回固定 503。

每个反馈的随机 score_id 持久保存，刷新、重试、checkpoint 别名和 HMAC 密钥轮换都复用它。向 Langfuse 只提交数值、有限分类和 revision，不提交纠正文本或原始业务身份。仅在对应观测可查到后提交 Score；未采样记录仍保留本地反馈，但标为 unlinked。

提交后的后台同步只有一次、有界八秒；进程退出、Langfuse 不可用或尚未消费时保留 pending。没有持续自动重试 Worker，用户可点“重试同步评分”。同步确认表示 API 接受，不保证 Worker 已消费；远端异步旧修订仍可能晚到，手动重试会强制重发当前本地版本。需要无人值守恢复时再接现有 Outbox 契约，不用内存任务冒充可靠队列。

Agent Metrics 位于 /internal/agent/v1/metrics，通过独立 Authorization: Bearer <AGENT_METRICS_TOKEN> 读取；无 Token 返回 401，未启用/配置不完整返回 503。仅供内部采集，不加入公开 BFF。

指标包括 chein_agent_stage_seconds 和 chein_agent_usage_total，只使用有限 stage/status/role/dimension 标签，没有 tenant/user/run/thread 标签。涵盖 execution、首次文本、event-loop lag、业务阶段与实际/缺失 Usage；即使 Trace 关闭或未采样也记录。计数是进程内的，重启后归零；多 worker 需要按部署采集和汇总。Backend 原有 Prometheus 指标不变。队列丢失与最终可见性通过 SDK 固定告警、压测预期集合和目标 API 对账，不把 SDK 私有队列字段当公开契约。

6. 离线评估与原生 Experiment​

已有 100 条合成 fixture 和两个 Replay 输出版本，覆盖 chat/knowledge/analytics/creation/denied/no_result/resume。它们验证比较算法，不是实际模型输出、人工金标准或当前 Agent 的准确率；所有 approved_for_export 默认 false。

cd agent
NACOS_ENABLED=false uv run python -m chein_agent.quality \
  --cases evaluation/langfuse/cases.jsonl \
  --variant baseline=evaluation/langfuse/baseline.jsonl \
  --variant candidate=evaluation/langfuse/candidate.jsonl \
  > /tmp/chein-langfuse-quality-report.json

报告复用既有检索评估器，增加回答覆盖率、拒绝样例、安全失败、耗时/费用覆盖率和配对 bootstrap 区间。缺失费用、缺失金标准或缺失答案显式 unknown/null；合成拒绝状态通过只证明该 fixture，不证明真实权限安全。

对真正经过审核的合成数据和各版本实际 Replay 输出，在项目外保存文件。审核每个输入和输出后才标记 approved_for_export=true。另外建立评测专用 Langfuse 项目，私有环境需要：

EVALUATION_LANGFUSE_BASE_URL
EVALUATION_LANGFUSE_PUBLIC_KEY
EVALUATION_LANGFUSE_SECRET_KEY
EVALUATION_LANGFUSE_PROJECT_ID
EVALUATION_PRODUCTION_PROJECT_ID
EVALUATION_LANGFUSE_ALLOW_HTTP=true  # 仅评测私网 HTTP；默认 HTTPS

评测与生产项目 ID 必须不同，发布前会查询项目 ID 验证；若进程知道生产 Public Key，还会禁止复用。然后执行：

NACOS_ENABLED=false uv run python -m chein_agent.quality \
  --cases /tmp/reviewed-cases.jsonl \
  --variant baseline=/tmp/reviewed-baseline.jsonl \
  --variant candidate=/tmp/reviewed-candidate.jsonl \
  --publish-dataset reviewed-synthetic-v1 --max-requests 1000

使用 SDK 原生 run_experiment 发布 Dataset、各版本 Replay 与规则评估，不触发在线 Agent/付费模型。所有 HTTP 路径共享请求预算和五分钟发起截止，SDK 单次 HTTP 超时三秒；发布上限默认零，必须显式填写。SDK 4.17 的旧 dataset-run-items 路径在 v4 可返回 404，原生 Experiment 的 OTLP 属性仍会使用其 fallback run ID；真实项目中的可见性需要核对，不能以本地 mocked SDK 成功宣称已上线实验。

独立 Judge 另需 EVALUATION_JUDGE_URL（完整 HTTPS System One URL）、EVALUATION_JUDGE_API_KEY、EVALUATION_JUDGE_MODEL、EVALUATION_JUDGE_MAX_CALLS、EVALUATION_JUDGE_MAX_SECONDS、EVALUATION_JUDGE_MAX_INPUT_TOKENS、EVALUATION_JUDGE_MAX_COST_USD、EVALUATION_JUDGE_INPUT_PRICE_PER_MILLION，再在本地比较命令追加 --judge。输入预算至少 32768 Token，调用 1–1000 次、总时限 1–3600 秒；价格与成本必须为正值。它不复用在线密钥、冷却或熔断，低于 0.8 的置信度记 unknown；非法计量或 Provider 错误会停止后续调用。

Judge 成本限制依据实际输入 Token 与审核过的输入单价计算，不是供应商总账单硬上限。输出、其他计费项和账号硬限额需在供应商侧单独控制。本次没有调用付费 Judge、审核人工金标准或发布真实 Experiment，也没有自动发布 Nacos Prompt。

7. 压测、故障与验收​

可离线运行 Callback 对照，保留原日志回调，比较关闭/100%/10%：

cd agent
NACOS_ENABLED=false uv run python scripts/bench_observability.py \
  --n 100 --concurrency 8 --rounds 3 > /tmp/chein-langfuse-benchmark.json
# 测试 exporter 异常；不连接实际 Langfuse
NACOS_ENABLED=false uv run python scripts/bench_observability.py \
  --n 100 --concurrency 8 --rounds 3 --fault 500 > /tmp/chein-langfuse-fault.json
# 本地 loopback 专用 OTLP 故障服务；另有 401/403/429/timeout/disconnect
uv run python scripts/otlp_fault_server.py --mode 500 --port 0

bench_observability.py 是 Fake 模型 Callback 闭环开销工具，每组预热 200 次，记录时序、客户端排队、CPU、RSS、采样和 exporter 收发统计。它不是完整业务压测；少量请求得到的 P99 不可当作门禁。

已有 scripts/bench_sse.py 对隔离 BFF 的真实 SSE 做计时，私有环境使用 CHEIN_BENCH_BASE_URL、CHEIN_BENCH_HEADERS_JSON、CHEIN_BENCH_N/C。它会创建合成线程，不自动删除；测试结束使用原授权接口清理。不输出消息正文或认证 Header。闭环并发结果不能代替固定 arrival-rate 的容量报告。

本地 100 请求/并发 8/三轮冒烟中业务均成功，100%/10% 分别采样 100/14 条；100% 组的开销明显高于 baseline，部分总耗时 P95 增量超过候选 20ms，CPU 增量也不能作为通过证据。生产性能门禁没有通过结论；需要目标硬件、真实工具负载、10000 请求/单元、长时 RSS、固定 arrival-rate、真实计量、故障恢复/可见性和 SIGTERM/SIGKILL 演练。按 阶段计划 的矩阵和候选门槛执行，未达标就降采样或关闭，不能增加业务 timeout 掩盖开销。

本次不改实际 Langfuse、ClickHouse、RustFS、Redis 或 Docker 网络。故障工具只能指向隔离 exporter/测试栈，不能把生产中间件停机当验收步骤。

剩余外部门禁：目标迁移与角色分配、所有 worker 重启、真实功能/浏览器联调、生产压测和完整容灾矩阵、人工金标准审核、独立评测项目与 Judge 的账号预算/可见性、现有 Backend 漏洞处理、远端 CI、镜像扫描/签名与团队签署。负责人为部署/安全/业务数据 Owner；本地实现不代替这些证据。

回滚先关闭 AGENT_OBSERVABILITY_QUERY_ENABLED、AGENT_FEEDBACK_ENABLED、AGENT_FEEDBACK_SYNC_ENABLED、AGENT_METRICS_ENABLED、LANGFUSE_TRACING_ENABLED 和 Backend OBSERVABILITY_TRACING_ENABLED，滚动重启。保留三张新增表、反馈版本和旧客户端可忽略的可选历史字段；无需删除 Run/checkpoint/业务数据。权限 revision 降级仅禁用新动作，保留角色绑定，再升级会重新启用。依赖回退使用原镜像/lock，不手工降级运行中环境。

可读问答与连接复用​

默认继续不采正文。需要查看选取的脱敏问答时，先阅读 可读链路设计与启用步骤，再在 Agent 私有配置中显式选择 redacted-content-v1 并重启。该模式不代表完整模型上下文或任意敏感信息识别保证；Backend 查询继续只有元数据。历史 trace 不回填。本次无需新迁移或 Docker/网络配置。

2026-10-21 审计后代码优化​

本节对应 2026-10-20 审计快照。状态为代码与本地验证，不是目标环境上线验收。沿用 Agent Langfuse SDK 4.17.0、Backend 原生 OTel 与现有直接 OTLP 路径；没有新增依赖、Collector、表/迁移、公开 DTO 或前端改动，没有修改 Nacos、Langfuse 配置或主动重启服务。

行为变化与边界​

审计项本次处理实际限制
OBS-01 数据策略所有导出 Agent Span 增加 data_policy、effective_data_policy、content_suppression_reason；Memory 保护也在最终导出层执行Memory 开启仍不导出问答；不代表正文型 Evaluator 已可运行
OBS-04 维护关联一个 owner 的维护批次使用 memory.maintain 根，携带 tenant/owner/worker HMAC 引用，授权/清理等阶段挂为子节点；无 owner 时不生成维护 Span不冒充用户 Session；有 owner 的无变更维护仍会留记录，没有实现空轮询动态采样
OBS-05 Worker/启动生命周期视频 Worker 在 Memory 线程结束后关停 OTel；独立 Outbox/Schedule CLI 正常或异常退出均清理；Memory CLI 启停 SDK/池与指标；Agent 数据库启动失败、Backend 注册/预检失败也执行既有清理不保证 SIGKILL、崩溃或关停超时后的 Span 交付
OBS-06 错误语义Agent/Backend 的 failed/unavailable/denied 阶段写 ERROR；Backend 请求失败也标 ERROR保留固定 STAGE_FAILED 与现有 error_category，不发送原始堆栈/异常消息；取消不混作失败
OBS-07 采样/父链Agent 改用 ParentBased；执行根继承真实 OTel parent，不再给 SDK 显式 trace_context；无父链时由 ID generator 保留原 execution seed 产生的确定性 Trace ID只接受现有认证后的 traceparent；不扩大浏览器输入信任范围
OBS-08 首事件RUN_STARTED 先发出，再尝试 PG 消息映射与可选 trace-reference event写入仍有界 await，权限与 lease 校验不变；不宣称模型 TTFT 或整轮 P95 已改善
OBS-09 交付诊断用一个轻量 wrapper 为原 Exporter 计数，现有指标端点增加 tracing state 与导出成功/失败 Span 数不新增队列或重试；不统计尚未进入 Exporter 的队列溢出，也不是丢失率或持久交付保证
OBS-10/12 小范围补充remember_preference、generate_video 有稳定工具名；重复初始化不再注册第二在线 Provider未扩展视频 Provider/RAGFlow 内部埋点；SDK 私有 Callback 接口仍需升级契约测试

采样修复有安装版本证据：SDK 4.17.0 的 langfuse/_client/client.py::_create_remote_parent_span 会给显式 trace_context 创建固定 sampled 的父 Span，且没有 parent_span_id 时也生成一个随机父 ID。因此只将 sampler 改成 ParentBased 不够。本次通过 Provider 的标准 ID generator 保持执行根 ID，通过现有 OTel context 继承真实父级，避免伪父节点和采样覆盖。回调仅在执行根已采样时注册，框架子节点仍引用该真实执行根。行为符合 OTel ParentBased 语义。

正文防护既在 Callback/Execution 选择阶段执行，也在 SDK mask 和最终 mask_otel_spans 白名单执行；测试直接注入一个格式合法的 SDK I/O 属性，Memory 开启时最终导出仍为空。该边界沿用 Langfuse 源端/导出脱敏机制，没有把 SDK 支持正文当成允许采集正文。

指标含义​

既有受认证的 Agent 指标端点新增：

chein_agent_tracing_state{state="enabled"} 1
chein_agent_telemetry_spans_total{result="success"} ...
chein_agent_telemetry_spans_total{result="failed"} ...

state 仅允许 disabled、enabled、initialization_failed、stopped，每次渲染只输出当前状态；result 仅允许 success/failed。计数受已有 AGENT_METRICS_ENABLED 控制，没有 tenant/user/run/错误原文等标签。success 表示底层 Exporter 返回成功，不证明平台 UI 已可见；failed 包含 Exporter 失败返回或异常。队列溢出、被采样/过滤的 Span 不纳入该计数。进程重启后归零，指标开关和认证配置沿用已有配置。
