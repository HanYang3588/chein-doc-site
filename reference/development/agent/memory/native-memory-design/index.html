RAGFlow Native Memory 迁移设计

2026-10-21 创建，2026-10-27 更新为每轮完整问答同步与官方默认提取；运行验证与交付状态见本文末尾。会话历史、LangGraph Checkpointer、中断恢复、上下文压缩不属于替换范围。

审计与版本证据​

旧链路：harness.MemoryContextMiddleware → memory.api.authorize → Platform 当前成员/权限校验 → memory.store → PostgreSQL item/revision/grant；可选 vectors → pgvector/Elasticsearch。成功 Run 在终态事务内生成引用型 Job，视频 Worker 托管线程经私有 HTTP tick 调 Agent Worker，后者从 checkpoint 取原始用户消息，经 LangMem create_memory_manager 生成候选。正文、分类、合并、向量投影都由 Chein 实现。没有使用 LangGraph Store 保存长期记忆；Checkpointer 是独立短期执行状态，必须保留。

审计开始时，本机 Agent 为 Python 3.13.7，DeepAgents 0.7.13、LangGraph 1.2.11、LangChain 1.4.0、ragflow-sdk 0.27.2、LangMem 0.0.30；迁移后已移除 LangMem。使用 Backend Nacos 中现有 RAGFlow 连接只读请求 /api/v1/system/version 返回 v0.27.2，GET /memories、GET /models 可访问。本机没有正在运行的 RAGFlow Docker 容器，远端镜像 digest 尚未确认。Context7 凭据不可用，版本依据改用官方固定 tag 源码及实际 HTTP，不以 main 分支替代部署版本。

固定版本源码：HTTP 路由、应用服务、异步任务、消息存储。

关键限制：

  • user_id 在 API Key 模式下是可由调用方提交的外部归属字段，不是 Chein 用户认证。Only me 指 RAGFlow API Key 所属账号，不能据此宣称隔离了同一 Key 下的 Chein 用户。
  • 创建 Memory 可同时指定 raw/semantic/episodic/procedural；模型和容量/FIFO 由 RAGFlow 管理。不自建提取、Embedding 或召回引擎。
  • POST /messages 先存 Raw 并排队提取；返回成功只代表提交，不提供可靠业务幂等键、Raw ID 或提取完成保证。响应丢失不能盲目重发。
  • 消息列表按 Raw 分页，衍生记忆嵌套在 extract，内容需详情接口读取；keywords 实际过滤 session_id，不是全文搜索。全文检索走 search_message，不能伪造全局按类型分页。
  • 消息 DELETE 设置 forget_at，并非物理擦除；停用使用 PUT status。任意文本编辑不存在。迟到提取不保证级联遗忘，Chein 必须保留最小的来源拒绝记录。

目标边界与选型​

采用每 tenant/owner 独立 Memory；映射从服务端可信身份解析，所有外部接口拒绝 memory_id/user_id/tenant_id 自由字段。公共 Key 仅在 Agent 使用；管理权限不能枚举他人正文。共享及系统记忆不在本次实现，旧共享记录不自动迁入私人空间；角色/部门权限仍由现有 Platform 重验，不引入平行 ACL。

Agent PostgreSQL 仅保存 owner policy、space（随机标识、remote ID、创建/删除状态）、delivery（Run/checkpoint/message 引用、幂等与提交状态）、sync_batch（一次离开的新增 Run 引用集合、容量激活状态）、source rejection（会话/消息墓碑）和安全审计事件。不持久复制正文或向量。按 tenant/owner FORCE RLS 隔离业务记录；无正文目录只用于有界 Worker 路由。数据库角色继续使用 app_runtime。

创建与写入使用持久不明状态：连接尚未建立可有限重试；一旦开始发送，超时、服务端错误或 Worker 失联必须视为结果不明，禁止自动重提。成功提交后通过原生消息列表中的任务 progress 观察提取完成；无可追溯对应关系时显示待核对，不能伪报完成。重试只允许证明尚未发送的失败；不明提交须人工核对。

开启长期记忆和自动同步后，每个成功 Run 在终态事务中持久化本轮 checkpoint/message 引用，离开 Agent 页面、切换会话或关闭助手后，新增来源归入一次同步批次，由现有 Worker 增量提交各轮用户原文与助手最终回复。文字与语音共用这条路径，不判定寒暄或记忆价值、不跨 Run 合并相同文本，也不重复提交整段历史。仍排除系统/个人提示词、工具原始返回、思维链和媒体字节，这些不是用户与助手的最终问答。失败、取消、缺失最终回复的 Run 不伪装成完整问答。已提交记录不重放；旧 SKIPPED 任务不因升级被重捞。

离开会话入口复用当前鉴权，按最后可信 Run 边界冻结未归批来源，并以确定批次 ID 去重。未归批来源不能提交且不显示为处理任务；批次预算满时保留批次但延后激活，Worker 排空后推进。迟到成功 Run 与 deferred 恢复来源只能加入已冻结且包含该 Run 的批次。列表按批次显示问答数和进度；awaiting_leave 仅保留旧客户端字段兼容，服务端恒为 false。每个 delivery 使用 chein-turn:<delivery UUID> 作为原生 session_id，以解决官方 POST 仅返回队列确认、不返回 Raw ID 的关联问题；对外显示时恢复原 Chein thread_id。原始问答不插入关联标记。观察状态使用官方列表的任务进度及问答 HMAC，重复相同问答仍能按轮次区分。提取失败时 Raw 已保存，标为失败而非重新 POST；未产生衍生记忆也可完成。

关闭开关增加策略 version、更新提取时间屏障并取消未提交任务，关闭后停止保存和召回；每次读前后重验当前成员、权限、策略和 generation，撤权中的响应不得注入。清空增加 generation、先隔离旧空间，再异步删除，迟到任务不能复活当前映射。删除来源先保存墓碑；所有列表、详情、最近消息、搜索和恢复都过滤来源。用户归档/匿名化/租户归档复用既有 Outbox，删除在功能关闭时仍可恢复。

RAGFlow 默认提取负责 semantic/episodic/procedural 的生成，Raw 始终保存完整问答。官方可以返回空数组，但不保证只保留“有用事实”、语义去重、事实核验或自动更新旧偏好。Chein 不再调用 System One 做保存前后审查，不另建分类器。写入前仅对明确以 Chein memory-governance-v1. 开头的旧内置限制 Prompt 清空 system/user Prompt，让官方恢复默认；保留其他自定义 Prompt。既有四类、私有权限、模型与 FIFO 配置不变。

召回复用官方 GET /messages/search 的混合检索参数；最近消息和管理页继续使用官方接口。新记录通过 owner/generation 范围内的 delivery 引用关联来源，不再依赖本地价值批准 ID，也允许官方返回 Raw。已有明确批准/本人启用的旧私人记录兼容，无法关联或未经批准的旧记录仍不自动放开。每次新记录召回、详情及历史恢复，重验来源 checkpoint 的完整业务证据与继承的 memory_usage：复用 Analysis、Knowledge 和 Memory 现有授权；未知工具、缺失证据、已撤销来源失败关闭。Backend 仅附加当前拥有的固定只读来源 scope，不能借 Memory 权限授予业务权限。这些是授权屏障，不是保存价值过滤。

请求级参考只作为低信任历史问答/经验，包含模型生成内容，不当成用户事实或当前业务真值，不授予工具权限。保留超时、Token 预算与 opt-in；请求级正文不写回 checkpoint，仅存空间/策略版本/具体消息 ID。来源业务撤权、删除/停用及循环来源均不能通过继承历史绕过。源 checkpoint 过期或工具类型尚未接入来源授权时，记录保留在 RAGFlow，但暂不允许自动使用。全文同步会让普通对话及用户主动输入的敏感内容也进入本人 RAGFlow 空间；不再宣称具有旧的敏感文本/DLP 预筛。

用户选择：向量 text-embedding-v4，提取 deepseek-v4.1-flash，部署实测标识为 text-embedding-v4@qwen-embedding@Tongyi-Qianwen 与 deepseek-v4.1-flash@qwen-token-plan@OpenAI-API-Compatible，发给原生 API 的引用必须包含供应商段；配置允许短名，但必须先按模型类型唯一解析。默认 Agent Nacos 在连接均缺失时只复用 Backend runtime 的 RAGFLOW_BASE_URL/API_KEY/TIMEOUT_SECONDS 白名单，显式连接不混用，迁移凭据不进入运行时。使用现有 httpx 的异步有界调用；不再增加 SDK 或 Python 版本依赖。

迁移与验证计划​

先增加 Native metadata schema 与新运行代码，再通过维护 CLI 导出旧记忆供审阅。迁移只接收明确选中的本人确认内容，提交 RAGFlow 后重新提取，不能承诺保留旧分类/ID/向量。旧候选、过期、共享和已删除记录不自动转换。最终清理要求备份凭据及逐项验证，不在 API 启动或新 schema 安装时删除旧正文。历史 SQL migration 保留；删除旧 LangMem、向量/ES 运行代码、配置、CLI 入口及旧设计正文，统一到本文和交付文档。

验证按顺序进行：固定 v0.27.2 HTTP 合约与合成服务；临时 PostgreSQL 的迁移、RLS、幂等、并发、关闭/删除/撤权屏障；真实 RAGFlow 合成私有空间四类提取与 A/B 隔离（测试后删除空间）；Backend BFF 越权、Agent Checkpoint/恢复/会话回归；管理页过滤/状态/错误与三个 Edition 构建。实际运行、Mock、未执行项分别记载，不把可保存配置当成功提取。

回滚优先关闭新写入/召回并保留撤销校验，恢复旧正文须经备份和旧应用兼容审阅，不双写、不自动回退旧引擎。不修改远端 Nacos 或共享数据库，不重启既有服务，除非获得相应目标授权。

交付状态​

设计、代码、管理页与迁移工具已完成，本地回归和真实合成提取结果见交付记录。本次未修改现有用户策略、Nacos 或业务数据库；新增 0011_memory_sync_batches 元数据迁移；需先停止旧提交进程、完成迁移，再启用更新后的 Agent/Worker 和前端，避免旧 Worker 抢先提交待归批来源。生产启用仍需迁移备份、容量/质量/负载指标及部署审核。

2026-10-27 研究与实现证据​

固定 tag 的 SDK 方法、默认提取 Prompt、Raw 与异步提取核对了问答输入、默认提取及追加语义。当前实现继续使用现有异步 httpx Adapter，未新增依赖。

NACOS_CONFIG_DATA_ID=chein-agent-runtime.yaml uv run python scripts/verify_memory_governance.py --live 保留诊断入口历史命名，现只验证官方默认提取和搜索，不再调用 Chein 治理。它仅创建并最终删除本次的合成私有空间，不操作已有用户记录。真实 v0.27.2 实测：3 轮问答原文完整、三类衍生提取、官方搜索命中；临时空间已删除。该结果不代表语义准确率或生产质量保证。其余本地回归与未执行门禁见交付记录。

2026-10-27：按页面离开触发增量同步批次（本次变更设计）​

本节按用户最新要求替代此前“每轮完成后立即同步”的交付行为：例如新增 10 轮问答，离开 Agent 页面后形成一条同步记录；后续批次仅包含尚未归批的新问答。RAGFlow 仍保存逐轮完整问答，批次不是把不同用户/助手角色混成一段正文，也不新增内容提取或价值判断。原自动同步开关保留，文案改为离开对话时同步。

复用已授权 /threads/{thread}/leave、Run 终态引用、视频 Worker 调度、私有空间、逐轮 session/HMAC 与来源授权。新增仅含引用的 native_memory_sync_batch（本人/租户 FORCE RLS）和 delivery 的批次外键；原 delivery 作为内部待同步来源和提交状态，不再逐轮展示为处理任务。批次冻结当前可同步 Run 集合，含离开时正在结束的可信 Run；正在执行的回答只有成功完成并生成正式来源引用后才纳入，失败/取消不伪装成完整问答。归批只接受本人当前 generation、开启时间之后、未提交/未归批来源；旧 SUBMITTED/UNKNOWN/终态不得重放。

归批与 Run 终态写入使用同一 owner policy 锁，重复切页、StrictMode 卸载、相同边界 Run 的重复通知返回同一批次。离开通知只传 thread/Run 引用，不传正文；后端核对所有权，绝不信任浏览器发送的消息、身份或时间。批次外键包含 tenant/owner/generation，防止跨作用域归批。页面离开、切换会话和关闭浮动助手继续沿原入口通知，不阻塞导航；HTTP keepalive 是尽力通知，浏览器强杀或断网仍不能保证送达，未归批引用须保留到后续正常离开再收敛，不宣称浏览器事件具有可靠投递。

Worker 只处理已激活批次的来源（显式确认的旧私人记忆 CLI 导入仍沿用其既有独立资格）。单批最多 1000 个 Run，超限拒绝归批且保留来源，不静默截断。原每人待处理预算按同步批次计算，按现有单 owner tick 与 PG leader guard 限制工作量；未激活批次保留引用后有界推进。只对证明未发送的失败重试，不重发 UNKNOWN。批次列表汇总待完成 Run、引用恢复、各消息提交/提取状态与数量；一条批次部分失败不能显示成全部成功。原生 Raw 提交和原生提取仍是不同阶段，界面改称“同步记录”，不把官方异步提取隐藏成已完成。

所有召回/详情/搜索/历史来源校验仍使用原逐轮 delivery 与 checkpoint，无需改写原文或降低授权。当前 generation 的批次及成员元数据保留，以保证增量去重和历史状态；旧 generation 且超过 30 天的终态成员及空批次按既有 Worker 清理。关闭、清空、会话删除、来源墓碑与 generation 屏障作用于未完成批次；历史已提交消息不重新导入。新增元数据迁移先于运行代码启用，只在一次性数据库执行本地验证；本次不操作共享数据库、远端 Nacos 或既有用户策略。

验证反例：10 轮完成但不离开不发送；离开形成一条记录并提交 10 轮；再新增 2 轮只提交新增 2 轮；重复/并发离开不重复归批；离开早于最终 Run 提交仍归原批；失败/取消不保存半截回答；断网/未知提交不盲重试；队列满保留后续激活；跨租户/owner/generation 外键与运行角色拒绝；关闭/删除后不得迟到提交；页面路由、StrictMode、切会话和浮窗退出验证。
