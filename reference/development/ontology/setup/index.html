OWL / Logic Pack / Agent 启用操作单

本操作单用于当前工作区代码；配置值于 2026-11-02 只读核对，不代表已经执行上线。下列地址适用于当前 Mac 本机启动 Backend、Agent、HermiT 的方式。容器或跨主机部署时，改为各进程实际可达的私网地址，并保持 MCP 登记与 Agent 引用完全一致。

1. 当前已有项与待办​

项目已核对的事实需要做什么
EditionBackend 为 suite保持；构建/部署当前代码
数据库上轮只读检查为 ontology_saved_drafts_v1，无 native mode；runtime/维护配置连接同一远端库备份后仅补 Ontology 三项迁移，执行后核对实际 revision

内网访问不使用代理直连上述 MCP 地址实际返回401；默认代理路径曾返回502启动命令所在终端设置 NO_PROXY；401是匿名请求的正确结果

维护配置 chein-backend-bootstrap.yaml 标为 production；runtime 配置标为 local，但连接远端数据库。不要因为前端是 localhost 就把数据库当作一次性库。本文命令由维护者执行，本轮没有替你修改远端数据库或 Nacos。

推荐顺序：备份/停止本项目进程 → 构建 → Ontology迁移 → 确认配置和HermiT → 启动Backend → MCP预览/发布 → 修改Agent引用并启动 → 权限 → 发布本体和规则包 → 新对话验收。

2. 执行位置、网络与构建​

以下命令从仓库根目录开始；迁移块使用子shell，执行后仍留在根目录。其他终端需重复设置自己的环境变量。

cd /Users/hanyang/Task/SelfStudy/agentStudy/chein
export NO_PROXY="localhost,127.0.0.1,::1,macbook-pro,100.70.245.60${NO_PROXY:+,$NO_PROXY}"
export no_proxy="$NO_PROXY"

macbook-pro 本次解析为100.70.245.60。保留你原有代理配置，NO_PROXY 只补内部直连；不要把 NO_PROXY 当作 Agent Nacos YAML 字段。保持根 .env 原有的 NACOS_ENABLED、SERVER_ADDR、namespace ID、Group及凭据，Group沿用CHEIN。

结束当前 Agent Run，按现有进程管理方式停止本项目 Backend、Agent及相关Worker；不需要停止PG、Redis、Neo4j。先用既有备份流程备份远端目标库，以及 Backend runtime、bootstrap、Agent runtime 三个私有 Data ID。

依赖已经安装时不必重装；需要时使用锁文件：

uv sync --project backend --frozen
uv sync --project agent --frozen
pnpm --dir frontend install --frozen-lockfile
pnpm build:edition -- --edition suite

构建会通过命令生成 Manifest/API 客户端并构建前端，不迁移数据库、不发布Nacos。若部署设置了 BUILD_MANIFEST_PATH，必须部署此次 Suite 的 Manifest，而不是旧产物。

3. 仅升级 Ontology 数据库​

当前需要的链：

ontology_saved_drafts_v1
  → ontology_logic_pack_v1       # logic_pack / inference_run及RLS
  → ontology_binding_refs_v1     # 外部绑定最小引用索引及RLS
  → ontology_native_builder_v1   # 原生工作区mode/约束/不可变触发器

现有 bash scripts/ontology-setup.sh migrate 会迁移全部Suite，并重新设置运行角色密码；本次不要用它代替下面的单模块维护命令。当前已验证 app_runtime 存在且受限，这三项迁移自带新增表授权，不需要重新 provision 角色。

先核对私有 bootstrap 的 POSTGRES_ADMIN_URL 指向正确数据库；只在维护进程使用它，API/Worker继续用runtime的app_runtime。下面命令复用全局迁移锁、模块自己的Alembic namespace与版本表，并记录Ontology运行状态；只迁移Ontology，不修改其他模块、租户权益或角色权限。失败时保持Ontology降级，停止后续启用并排查原因。

(
cd backend || exit 1
NACOS_CONFIG_DATA_ID=chein-backend-bootstrap.yaml uv run python - <<'PY'
from app.platform.admin_db import configure_admin_database
configure_admin_database()  # 必须先于导入数据库Engine
from alembic import command
from alembic.runtime.migration import MigrationContext
from sqlalchemy import text
from sqlmodel import Session
from app.core.database import engine
from app.modules.migrations import (
    MIGRATION_LOCK_KEY, module_alembic_config, transition_module_observed_state,
)
from app.platform.core.runtime_models import ModuleRegistry, ModuleObservedState

config = module_alembic_config('ontology')
target = 'ontology_native_builder_v1'
allowed = {
    'ontology_saved_drafts_v1', 'ontology_logic_pack_v1',
    'ontology_binding_refs_v1', target,
}
def state(value, reason):
    with Session(engine) as session:
        row = session.get(ModuleRegistry, 'ontology')
        if row is None:
            raise RuntimeError('Ontology registry missing; use the reviewed initial-install flow')
        transition_module_observed_state(
            session=session, registry=row, observed_state=value,
            actual_revision='ontology-head' if value == ModuleObservedState.READY else None,
            reason=reason,
        )
        session.commit()

with engine.connect() as guard:
    acquired = guard.execute(text('SELECT pg_try_advisory_lock(:key)'), {'key': MIGRATION_LOCK_KEY}).scalar_one()
    guard.commit()
    if not acquired:
        raise RuntimeError('Another migration is running; stop and retry later')
    started = False
    try:
        context = MigrationContext.configure(guard, opts={
            'version_table': 'alembic_version_ontology', 'version_table_schema': 'public',
        })
        before = context.get_current_heads()
        guard.commit()
        print('Target host/database:', engine.url.host, engine.url.database)
        print('Ontology before:', before)
        if len(before) != 1 or before[0] not in allowed:
            raise RuntimeError('Unexpected Ontology revision; review target before proceeding')
        state(ModuleObservedState.MIGRATING, 'Operator: enable native OWL and Logic Pack')
        started = True
        command.upgrade(config, target)
        command.check(config)
        after = MigrationContext.configure(guard, opts={
            'version_table': 'alembic_version_ontology', 'version_table_schema': 'public',
        }).get_current_heads()
        guard.commit()
        if after != (target,):
            raise RuntimeError('Ontology revision verification failed')
        state(ModuleObservedState.READY, 'Operator: Ontology migration and model check passed')
        print('Ontology after:', after)
    except Exception:
        if started:
            state(ModuleObservedState.DEGRADED, 'Operator: Ontology upgrade/check failed; review required')
        raise
    finally:
        guard.rollback()
        guard.execute(text('SELECT pg_advisory_unlock(:key)'), {'key': MIGRATION_LOCK_KEY})
        guard.commit()
PY
)

验收输出包含 ontology_native_builder_v1、No new upgrade operations detected。不要用 alembic stamp 冒充迁移，也不要对这个远端库运行清理型pytest。已存在原生工作区时降级会拒绝，不自动删数据来回滚。

本机CLI的有效Data ID名称如有定制，替换命令中的名称；不要把包含管理员密码的URL粘贴到命令行或聊天里。

在同一Namespace、CHEIN Group的 chein-backend-runtime.yaml 核对/合并；这些项当前已配置，正确就保持，不要整份覆盖Data ID或追加重复键：

ONTOLOGY_ENABLED: true
AGENT_MCP_ENABLED: true
ONTOLOGY_REASONER_ENABLED: true

保留现有 ONTOLOGY_PROVIDER: neo4j、Neo4j连接、模型、Redis、存储和签名私钥。原生工作区不要求切换Provider，也不要求将定义写入共享Resource图。当前未配置独立ONTOLOGY_REASONER_PRIVATE_KEY，计算服务签名复用已有AGENT_DELEGATION_PRIVATE_KEY；Agent保留对应AGENT_DELEGATION_PUBLIC_KEY。Java只接收公钥。

本机HermiT已在运行可跳过启动；否则在独立终端运行：

该命令读取现有Backend配置、派生公钥、构建JAR并在127.0.0.1:8091启动，私有任务目录默认 ~/.local/share/chein/reasoner。它不会替你开启Backend开关或重配密钥；打包跳过测试不等于发布门禁已完成。

curl --noproxy '*' --fail --show-error http://127.0.0.1:8091/actuator/health/readiness

预期UP。容器部署使用计算服务运行手册（未发布资料）的私有卷、服务公钥与内部地址，Backend URL改为可达的服务名；不要把容器的127.0.0.1当作宿主机。生产跨主机采用TLS/mTLS，不将Java业务端口直接开放给浏览器。

5. 启动 Backend，预览并发布 MCP 新版本​

在已设置NO_PROXY的本机终端，从仓库根目录启动Backend：

pnpm backend:dev

在另一个已设置NO_PROXY的终端验证入口：

curl --noproxy '*' --show-error -i http://macbook-pro:8000/mcp

没有delegation时预期401；不是200，也不要为“测试通过”关闭鉴权。若是502，先查代理/地址；若连接拒绝，检查Backend是否监听。此检查不能代替带权限的工具实调。

从仓库根目录，先预览（不写Nacos）：

bash scripts/ontology-setup.sh mcp-preview 1.4.0 http://macbook-pro:8000/mcp

当前代码预览为21工具，必须至少包含下面7个，以及保留已有ERP/Analytics工具：

ontology_reason_v1
ontology_reasoning_result_v1
ontology_goals_v1
ontology_infer_v1
ontology_state_v1
ontology_explain_v1
ontology_whatif_v1

另有search/describe/query/traverse/metric/action/semantic/diagnose，合计15个ontology工具。它们均为只读；action也不是业务写回工具。不要手改输入Schema或移除permission/read_only元数据。

核对后由你执行真实发布（写Nacos）：

bash scripts/ontology-setup.sh mcp-publish 1.4.0 http://macbook-pro:8000/mcp

1.4.0在本次只读核对时尚未存在，若执行时已占用，改用新的x.y.z版本，并在下节使用同一版本；不要覆盖/删旧版。发布后检查该新版本服务enabled、目标工具enabled，endpoint是精确的 http://macbook-pro:8000/mcp。Nacos发布/发现需要现有gRPC连接可用，不是仅控制台HTTP能打开。

6. Agent Nacos 配置与启动​

在同一Namespace、CHEIN Group的 chein-agent-runtime.yaml 中，将既有 chein-backend-tools 条目从1.3.0改为新发布的1.4.0；保留其他服务条目（总计最多4个），不要另建同名前缀的重复条目：

AGENT_MCP_SERVERS:
  - name: chein-backend-tools
    version: "1.4.0"
    endpoint: "http://macbook-pro:8000/mcp"
AGENT_MCP_TIMEOUT_SECONDS: 30
AGENT_MAX_GRAPH_STEPS: 25
AGENT_DELEGATION_ISSUER: chein-backend
AGENT_DELEGATION_AUDIENCE: chein-agent

保留已有公钥、QWEN_BASE_URL/QWEN_API_KEY/QWEN_MODEL、checkpoint数据库及其他功能设置。本体不要求重建模型账号、修改Token计费配置或重配Knowledge服务。进程启动环境和Nacos都能覆盖配置，确保终端没有保留旧的AGENT_MCP_SERVERS环境变量。

先确认Backend和新MCP版本可用，再在独立终端启动Agent，最后启动/刷新前端：

pnpm agent:dev
# 另一个终端
pnpm frontend:dev

本机开发命令不是远端生产进程管理命令；远端按现有部署流程更新代码并重启对应服务。不要同时启动两个进程抢8000/8100/5174。

无需另建提示词Data ID。当前Agent识别到获准的ontology_goals工具后，会在现有Nacos系统提示词后追加LOGIC_INSTRUCTIONS；正式OWL工具也追加相应约束。若运维维护业务提示词，保留并同步以下约束，不用整份替换已有提示词：

  • 业务结论先发现已发布Pack/目标，再对当前有权读取的真实记录推导。
  • 只使用本次Run工具真实返回的derivationId引用，不能编造。
  • UNKNOWN/INDETERMINATE明确回答无法判断并列缺失证据；CONFLICT报告冲突规则。
  • Memory和模型猜测不充当业务前提；what-if结果标为假设，不能引用为业务事实。
  • 推导不授予业务操作权限，MCP不执行出库审核等写操作。

7. 套餐、租户、角色与数据范围​

通过现有系统管理流程核对当前Suite包含ontology；ModuleRegistry为enabled/ready，目标租户套餐/权益及租户开关允许ontology。读取ERP实例还需同一租户的ERP权益；外部绑定则需Datasource权益。不要通过修改数据库绕开这些门禁。

使用人所需权限
本体/规则配置与发布者ontology:read、ontology:edit、ontology:publish、ontology:query
只在Agent中查询的成员agent:chat、ontology:read、ontology:query
销售出库示例按实际绑定读取erp:sale-out:list、erp:sale-order:list、erp:stock:list、erp:product:list、erp:warehouse:list、erp:customer:list
外部数据目录/绑定datasource:read及当前连接/目录可见性，沿用数据所有者授权

权限只是上限，用户还需在当前租户、owner/部门/仓库范围内可见目标记录。不要给全库权限来让UNKNOWN变TRUE；缺库存权限应得到无法判断。角色菜单在套餐允许范围内分配，非默认租户按原“同步租户菜单”流程同步；本体入口仍是OWL可视化构建器。当前已有用户不必重新seed全库菜单或重设内置角色。

当前默认Agent聊天“业务本体”开关保持开启。新对话默认ontologyProvider=neo4j、ontologyTools=null（全部获准工具）、ontologyInference=true。旧Run或API自定义工具子集可能仅包含旧10个工具，会排除新增Logic工具；保留默认全部，不手工塞入尚未支持的枚举值。

若仅做推理，不需要erp:sale-out:approve或隐藏审核页。人工审核是独立可选功能，不能为只读Agent查询默认增权。

8. 发布可用模型和规则包​

  1. OWL可视化构建器 → 创建工作区 → 新建空白本体，填写编码、名称、范围。无需原文件。
  2. 在画布新增类/属性/关系，点击“保存本体”。之后点击“校验当前草稿”，刷新到真实SUCCEEDED，再发布版本。
  3. 打开“规则与状态”，配置类/属性/关系到数据所有者目录的绑定；填写规则、状态机/派生属性、可回答目标和合成用例。
  4. 每个goal配置TRUE/FALSE/UNKNOWN合成用例。选当前真实可读样本做私有试运行，检查证明树和missingEvidence；不要把真实业务快照写入共享合成用例。
  5. 保存规则包，完成本人HermiT校验及目录、编译、用例、预算门禁，再发布规则包。本体发布与规则包发布是两次操作。

注意：现有Neo4j/AdventureWorks图里看得见实例，不等于它已绑定ERP实时事实。业务推导必须能映射到ERP固定目录，或当前支持的PostgreSQL单连接、UUID单列主键Datasource目录。外部整数/字符串/复合主键目前不支持，不能靠改配置假装已接入；仅进行OWL类关系推理则不要求ERP事实。

9. 新对话验收与排错​

配置切换后新建会话/新Run，不用恢复旧Run检验新契约。用当前有权限用户提问，替换为真实且本人可读的单号：

请根据已发布规则判断销售出库单【单号】能否出库，说明依据并附推导证明；证据不足时列出缺失项。

应观察到goals发现packId/goalId及subjectBinding → 当前授权实例解析 → infer（状态问题则state）。回答有本次真实 [derivation:<id>]；点击引用可展开证明树，verify重放通过，refresh读取新快照并报告漂移。试运行结果或what-if不能当正式引用。结果TRUE不等于已经审核或扣减库存。

纯OWL的ontology_reason工具目前只接受既有已发布semantic模型（可含owl_rules）；原生画布的rdf_document正文虽能进行真实HermiT发布校验，却尚未接入该Agent正式查询入口，当前会因缺semantic模型被拒绝。这项需要补代码，不能靠改Provider、填UUID/版本或混入两套Schema绕过。原生本体发布后的Logic Pack业务推导是另一条已实现路径，可按本清单使用。HermiT结果目前没有Logic Pack那种逐规则证明树，不把校验任务ID冒充derivationId。

现象首先核对
页面报缺表/缺列实际库是否到ontology_native_builder_v1，是否部署了对应代码
Agent完全没有ontology工具MCP发布的新版本、Agent精确引用、服务/工具enabled、ontology:query与业务本体开关
工具502/连接失败macbook-pro解析、NO_PROXY、运行位置、端口；不要关闭鉴权
匿名MCP401正常；正式调用由Backend签发delegation
找不到Pack/目标本体和规则包是否都已发布，范围/当前用户权限是否匹配，当前本体版本是否已变化
UNKNOWN查看missingEvidence和截断说明，检查实际数据及源权限；不能自动改成通过或拒绝
ontology_semantic_model_required检查是否把原生画布RDF用于仍要求semantic的正式OWL查询；这是现有代码边界，不要靠放宽鉴权或改库绕过
