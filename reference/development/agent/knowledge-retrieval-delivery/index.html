Chein Knowledge Platform：实施与验收

2026-10-04，当前工作区实现记录。代码验证与真实供应商联调、生产部署是不同事项；下文分别记录。

共 5 个实施阶段：检索基础、权限与知识管理、检索与证据判断、JEV 决策与降级、评测与验收。审计见历史审计。实现复用现有模块、Platform 目录、Outbox、LangGraph middleware 和 Ant Design，没有新增运行时依赖或重写向量检索。

1. Current Architecture​

原有管理模块已经管理个人库、系统库、分享、文件上传、解析状态、检索与下载。先前的缺口是固定范围/粗粒度分享、知识选择与充分性判断缺少闭环、配置/调试界面不足。原始审计是当时快照，不代表当前代码仍存在同样缺口。

2. Target Architecture 与当前实现​

管理后端只负责资源、权限、供应商映射、混合检索请求与 Trace；Agent 负责语义路由、查询计划、证据判断和回答；RAGFlow 负责解析、索引、混合召回与配置的重排。没有把 LLM、Deep Agents 或 JEV 放进管理后端。

3. Database ER Diagram​

这是一种统一逻辑资源；系统公共库继续使用独立全局表和显式 writer policy，避免把平台公开与普通租户 RLS 混在一起。项目没有 Group/Project 主数据，不创建未经验证的组织 UUID。团队库目前使用已有 Department；创建者保留维护权限，部门成员默认 READ，WRITE/MANAGE 通过 ACL 单独授权。

4. Knowledge Permission Model​

READ 允许检索、查看与下载；WRITE 允许上传、解析、元数据、启停文档；MANAGE 允许删除、授权、绑定与编辑分块。对象 ACL 与模块 RBAC 同时生效：例如有 MANAGE 仍需要 knowledge:delete 才能删除。

个人库可以对有效 USER、ROLE、DEPARTMENT 授权；角色/部门来自 Platform 公开目录，必须属于当前租户且有效。当前租户公开提供 READ，平台系统库通过发布提供 READ。统一权限接口原子保存公开范围与显式 ACL：租户公开可保留管理授权，指定范围要求至少一个主体，切换私有时明确清空授权。省略 visibility 的兼容调用保留原租户公开范围。旧 Sharing 写入在已有组织 ACL 时返回 409，防止旧页面清空新授权。所有者不可从 ACL 中移除。

每次访问重新查询当前角色、成员关系和部门状态，无长期 ACL 缓存。Knowledge 表使用租户 UoW、tenant 不可变与强制 PostgreSQL RLS；系统写入只在已经授权的全局管理入口或可信 Worker 中激活。Trace 只允许作者且有 debug 权限读取，并重验目录授权；知识缺口不展示其他用户的私人问题。

5. Knowledge Routing Pipeline​

Catalog 只包含当前可读、启用、就绪、Agent 绑定未 Disabled 的库；只返回 Chein ID、名称、说明和 hint。REQUIRED 在有效范围内保留，DEFAULT 是兜底，OPTIONAL 可在不足时增选。Explicit IDs 是硬边界，Required 和模型都不能突破它。

JEV 高置信度可以从有限授权候选中选一个库；不可用或低置信度交给主模型结构化计划；仍失败使用 Required 加一个优先 Default。后端再次校验所有 ID，超出范围返回错误。没有“每次搜索全部知识库”的默认行为。

6. RAGFlow Integration​

使用 RAGFlow 0.27.2 官方 HTTP API，复用 httpx 超时和现有 Worker。浏览器与 Agent 都不持有私人检索的 RAGFlow Key 或 dataset/document ID。官方 Python SDK 只保留历史共享来源的只读兼容。

创建/上传通过稳定的唯一远端名称恢复超时；更改通过文档 pending_changes 保存最新期望状态，同一事务提交 Outbox。元数据 PATCH、分块 PATCH、重新解析的停止/启动使用官方接口，Worker 锁住资源并在成功后清除待同步更改，重复普通更改不重复写入。重新解析是至少一次效果，崩溃重试可能重复解析，不能宣称外部 exactly-once。

知识库说明修改也提交 Outbox，通过官方 Dataset PUT 同步最新说明；超时后允许重复幂等 PUT。远端唯一名称保持不变以支持创建恢复，页面显示名仍由 Chein 管理。启停与共享范围由 Chein 权限层控制，供应商 Dataset 保持 permission=me。

7. Query Rewrite Strategy​

主模型工具参数先形成独立问题，查询计划保留原始意图和上下文解析结果。结构化计划中的查询长短、数量与 KB ID 都校验。语义模型失败回到原查询，不产生假定的部署参数。Trace 保留原始与改写问题及每次请求。

8. Retrieval Strategy​

默认混合权重 0.3、相似度阈值 0.2、候选 30、最终片段 5。复杂问题最多 3 个 Query，实际调用数受租户 Profile 的尝试预算限制。各 Query 的返回结果去重、按供应商真实分数排序，再做证据选择；普通明确问题保持单 Query。

Metadata 只支持当前明确有用的 system/module/version/environment/document_type，值最多 120 字符。后端在远端请求前与结果返回后都检查本地 Metadata，并向 RAGFlow 传递相同条件。空文档允许列表不会请求供应商。

9. Rerank Strategy​

召回与 rerank 由 RAGFlow 完成，使用 Profile 中真实配置的 rerank_model。没有重新实现 embedding、向量库或 reranker。未配置模型时保留混合检索排序，不能声称进行了模型重排。多 Query 各自经过 RAGFlow 排序，合并后由 Evidence Selection 筛选；没有独立全局 rerank API，也不伪造一个全局 rerank 分数。

10. Evidence Evaluation​

管理端检索测试返回 PARTIAL/INSUFFICIENT，保持不调用模型。Agent 对候选执行结构化充分性与有用片段选择：SUFFICIENT/PARTIAL/INSUFFICIENT，选出的 ID 必须来自真实候选。相似度不等于覆盖全部问题。

简单问题可以由达到门槛的 JEV 对最终有界证据直接判断，避免额外生成模型；低置信度、复杂问题或失败走 LLM Judge。Judge 不可用则保守返回 PARTIAL/INSUFFICIENT 并澄清。最终上下文若丢弃或截断判定所需证据，不报告 SUFFICIENT。回写时检查 Run、当前 ACL、文档启用/解析状态和待编辑分块；无法完成这次重验则不向回答模型暴露证据。

11. Retry Strategy​

默认最大 2 次，配置上限 3 次。不足可 Rewrite 或在授权目录内增加一个库；显式范围不自动扩展。到达预算必须 ASK_USER，不无限重试。不会自动放宽用户显式 Metadata 条件。服务失败返回可澄清的不足状态，不回退到静态共享账号。

RAGFlow 网络/5xx 错误触发 10 秒进程内冷却；JEV 网络失败触发 30 秒冷却。冷却期间不重复请求。文档同步失败保留待更改与页面错误，服务恢复后重试；无需重新上传元数据/分块更改。

12. JEV Decision Points​

复用 阿里云 System One 官方决策 API。支持 off/shadow/active，默认 off。active 只筛减已经授权的工具或 KB，参数与回答仍由主模型生成。置信度门槛 AGENT_DECISION_CONFIDENCE_THRESHOLD 默认 0.8；超时、无效分布、低置信度进入 fallback。

当前决策点为新 turn 的工具类别、授权 KB 路由、简单问题最终证据充分性。复合任务保留主模型的全部授权工具，不强行选择单一路径。JEV 不用于 Query Rewrite 或答案生成，不是权限系统。

13. Tool Routing​

当前真实工具是日期、已配置且获授权的 ERP 统计、知识目录、知识检索、ask_user。active 通过原生 ModelRequest 的工具子集筛选，未知/复合/改变数据诉求不新建执行路径。主模型负责参数；权限先在组合根决定工具是否存在，后端 Facade 再重验。当前没有订单明细工具，因此“订单 123456”只能明确说明当前能力边界或澄清，不能虚构查询结果。SubAgent 仍明确关闭，测试覆盖框架不存在越权旁路。

14. Frontend Page Structure​

原生 Ant Design / ProComponents：知识库、检索测试及集中 Agent 知识配置三个菜单入口，知识库内用 Tabs 展示五种分类。菜单播种先建立父目录，再关联子菜单，可重复执行。详情保留文档为默认 Tab，提供 Agent 绑定、统一共享/权限、检索与有权限者的知识缺口；租户参数集中到检索测试页。列表支持名称、所有者类型/名称、状态筛选，展示所有者、文档/分块/Agent 数，操作列使用 fixed: 'right'。Agent 页可搜索并维护所有可管理库的绑定，工作台不再只编辑首个选中库。

文档支持批量上传、选择后重新解析/启停/删除。删除有确认和后端权限检查，批量请求最多 50 个文档并逐项返回结果。文档抽屉包含原文下载/预览、供应商分页分块、Metadata、解析/更改同步状态和最近 100 次实际处理记录；分块编辑仅维护者可用。PDF 使用原文 Blob，文本以纯文本呈现，HTML 不执行；Office 展示当前页解析文本并提供原文下载。事件在上传排队、同步、失败、解析状态变化和启停时持久记录，不补造升级前历史。文档变更与同步使用行锁，避免并发状态刷新覆盖待更改字段或历史。权限抽屉统一维护范围与有效用户/角色/部门的 READ/WRITE/MANAGE，远程搜索并精确回查已有主体。

15. Retrieval Testing UI​

工作台支持搜索、分页选择已授权就绪知识库并测试，详情测试限制当前库。可以维护元数据条件，查看真实分数、片段与重新授权下载。有 configure 权限者维护租户 Profile；普通用户不默认获得底层配置或 debug 功能。测试不消耗聊天模型，真实充分性测试通过 Agent 完成。

16. Retrieval Trace​

记录原始/改写 Query、候选/选中库、每次请求参数、Metadata、真实分数、候选/最终引用、尝试数、耗时、Run、错误阶段与判定反馈。反馈包含路由/Judge 类型与置信度；供应商实际报告的 input token usage 分别记录，未报告时为 null，不估算冒充实测。Trace 不保存完整 Chunk 正文、密钥或真实远端 ID。页面以原生描述、折叠尝试和表格展示结构化记录，可按问题、结果筛选并分页；详情页的记录和统计限定当前库，不把整个 Catalog 当作已检索范围。读取记录再次验证作者和资源权限。

17. Knowledge Gap​

复用最近 100 条本人仍有权限的 Trace，聚合检索次数、命中率和平均耗时，展示 INSUFFICIENT 问题作为知识缺口。不另建分析平台或自动采集私人会话；跨用户统计需先确定隐私与授权策略。

18. Migration 与部署​

knowledge_governance_v3 接在既有 v2 后，增加 ACL、逻辑所有权、文档 Metadata 与待更改状态；本次新增 knowledge_document_history_v4 接在 v3 后，为租户/系统文档增加 processing_history JSON 字段。旧个人/系统库不需重建，旧 user grant 保持读取兼容，更新 ACL 时原子替换旧 grant。v1 历史引用只读兼容暂不移除。

v4 降级仅丢弃处理历史；继续降级 v3 会丢弃新 ACL/部门归属、Metadata 管理与调试字段；访问会失败关闭，不迁移为公开权限。存在未同步文档更改时拒绝降级，需先完成/受控取消并备份。不要将旧版本与正在消费新更改的 Worker 混跑。

Observation 格式：id/chunks/selected_kbs/evidence_status，chunks 与预期使用相同的稳定 Chein 键。此数据集是合成契约基准；真实准确率需要另建已人工标注、映射到真实库/文档/分块的案例与真实供应商 observations，不能把 mock 结果声称为实际检索质量。

20. Performance Impact​

默认 100 个目录候选、3 个选中库、500 个文档、30 个召回候选、5 个最终片段、12000 字符、2 次检索。简单高置信度 JEV 路由/证据判断或单库明确请求减少生成式辅助调用；复杂问题才进入拆分计划与重试。每个辅助模型调用有 10 秒默认超时（上限 30）。沒有生产延迟或费用加速承诺，需以真实 Trace 调整。

21. Security Analysis​

模型和 JEV 不能添加授权范围外的库/工具；服务账号只在管理后端；Metadata 不是 ACL。当前会员、角色、部门、文档、Agent 绑定在关键边界重验。历史证据撤权后清除旧工具结果和衍生回答，持久化后只保留最新用户消息。Trace/知识缺口保护私人问题，下载禁止共享缓存。

22. Known Limitations 与外部验收​

代码与本地契约测试不证明真实 RAGFlow、Qwen、JEV 配置可用或达到业务准确率。本轮真实 RAGFlow 联调只验证上述临时库操作；仍须在部署环境验证重排模型、模型结构化响应、JEV 账号权限、完整 Agent 回答与引用、真实账号撤权及业务准确率、实际成本。尚未执行远端 CI、镜像扫描/签名、N-1 演练、团队 ADR 签署或生产上线。

没有 Group/Project 主数据、订单明细 Tool、索引版本固定与历史精确重放、单独全局多 Query rerank、自动私人对话沉淀或跨用户私人问题分析；这些需要相应数据/业务/权限来源才可增加。文件暂存仍受 10 MiB 限制，大规模文件/组织目录应扩展原存储/目录契约，不放宽权限或静默搜索全部资料。

20. 默认检索传输调整（2026-10-09）​

RAGFlow 默认接入改为 LangChain 原生 Tool → 已有 Knowledge 应用服务 → 官方 HTTP API。官方 MCP 适配与上述历史记录保留为可选方案；当前传输、配置、验证与恢复步骤以原生 Tool 集成为准。ERP MCP 不变。
