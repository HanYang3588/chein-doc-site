OWL 画布构建器

当前交付边界​

画布现在支持命名类、子类、对象属性、数据属性、实例、实例关系和类型的草稿编辑。右键选择操作后在右侧表单输入；拖线按节点类型选择语义，撤销/重做按整次表单提交恢复。RDF 图仍是唯一编辑正文，复杂公理及匿名表达式保留只读。当前开发环境已增加工作区绑定迁移；不会在打开页面、编辑或查看源码时修改 Resource 图。

紧凑工具栏（2026-11-04）​

顶部移除“新增类 / 子类”快捷按钮，创建类仍从画布或节点右键菜单进入。创建工作区、规则与状态、撤销/重做、保存/恢复草稿及整理操作采用小号图标加文字；工作区保存、校验、发布和导出操作同样使用紧凑文字样式，原有权限、禁用条件及确认流程保留。

展开工具区将工作区、查找/显示与导出放在同一行，常规高度37px；宽度不足或工作区操作较多时仅在工具行内横向滚动，不另起一行或使整页横向溢出。错误和校验警告仍在工具行下方独立展示。类、实例、只读表达式、子类关系、对象属性及虚拟类型边收进原生多选下拉，收起显示已选项数；沿用原 visibleGraph 筛选，只改变画布显示，不提交命令。选中项正常字重且仅用勾号标记，没有蓝色背景；选中并悬停/键盘激活时同样无蓝底。工具文字、标题及下拉激活项的 hover 色读取当前主题主色，禁用操作保留禁用样式。实现与验证见 交付记录。

查看导入对象的原始表数据（2026-11-03）​

装配 Datasource 且具有 datasource:read、datasource:preview 权限时，画布底部提供原始表面板。选中从目录导入的类、数据属性或对象属性后，通过 IRI 中保留的目录实体 ID 定位源表并自动加载；画布与表格之间的突出标签负责折叠/展开，顶部仅保留紧凑的文字刷新，不显示来源路径、查询按钮或常驻说明。上下拖动分隔线可调整表格高度（可用区域的20%–80%，默认40%）；表头固定，表格滚动区随高度变化。折叠后不占表格高度，再展开恢复本次页面中调整后的高度；不持久保存高度。刷新与上一页/下一页使用文字样式，行数选择去掉边框。折叠会取消请求并清空展示数据，切换对象保持折叠；再次展开重新读取。每页20或50行，使用服务端分页与上一页/下一页，不伪造全表总行数。切换对象、工作区或身份时，旧响应不能显示到新对象下。

字段沿用数据库物理名称和数据源预览返回值，前端不额外脱敏或格式化日期；源配置为 none 的值直接展示，既有隐藏/脱敏规则和大小预算继续生效。该面板不写入 OWL、草稿、Pack 或本地存储，不接收任意 SQL，也不按类名或表名猜测映射。已改写目录 IRI、丢失目录 ID、源实体已删除或无权访问时不回退到其他表。普通外部 OWL/Neo4j 对象及 Logic Pack 的 ERP 绑定不属于本次目录预览入口。

前端组合根另行注入 datasource/public_api/preview Reader；原 catalog Reader 仍只提供元数据。Backend 数据源入口逐次使用既有身份、模块权限和 Tenant UoW，复验表启用、字段暴露/脱敏、结构摘要及外部读取后的授权。共享应用表的数据库 RLS 仍会生效；如果外部连接账号没有该表要求的 scope，结果可能为空，不能通过去掉页面鉴权或向连接注入租户来绕过。

新增 GET /datasource/catalog/entities/{id}/source-table，原 preview POST 兼容增加可选 offset：不传时保留旧的100行样本行为；传入时每页最多50行，额外读取一行确定是否有下一页，偏移上限10000。SQL 驱动按返回投影稳定排序，MongoDB 按 _id 排序；JDBC 沿用厂商原有限行语法并有界跳过前面的行，不假设所有厂商支持 OFFSET。翻页是实时查询，不能保证源表并发变化时跨页一致快照。无数据库迁移、运行依赖或 MCP 变更，需同步部署 Backend、前端及命令生成的 API/Manifest。

从数据源目录批量新增​

以下记录描述此前的目录导入交付；导入本身仍不自动读取业务样本。

Suite 装配数据源模块且账号具有 ontology:edit、datasource:read 权限时，空白画布或可编辑类的右键菜单增加“从已有数据源新增类 / 属性”。窗口居中显示原生 Ant Design 目录树，桌面默认820×820，受视口宽高约束；窄屏改为适配屏幕的纵向布局，内容内部滚动、底部操作保持可见。目录收起或选表后不改变弹窗高度，虚拟树按剩余空间调整可视高度。目录按数据源 → 数据库 → PostgreSQL Schema → 表 → 字段逐层懒加载；MySQL 在数据库下直接展示表。只列出已启用表、已暴露字段；空目录需先在数据源管理中同步并启用目标表。Schema（MySQL 为数据库）节点提供全选、全不选；全选遍历完整表和字段分页，失败或超出剩余额度时不应用部分选择，已读取分页可供重试复用，关闭窗口取消未完成的请求。

空白处默认新建类与属性，在已有类上打开时默认向该类添加数据属性。可切换模式、目标类与 IRI 命名空间。普通表生成类及所选字段的数据属性；勾选表后，OWL 类型直接显示在树的表节点行内，不再使用树下方的独立配置表格。改为对象属性时，同一行显示可选的起点类（Domain）、终点类（Range）选择框，可搜索已有类并引用同批新增的普通类；允许两端留空、只选一端或两端选择同一个类，也可以清空后稍后在编辑面板补充。未指定的一端不生成对应的 domain/range 声明，不自动补为 owl:Thing。已指定但失效的引用仍拒绝；重复导入只跳过两端声明完全一致的已有属性，不清除或覆盖已有约束。操作选择框不会展开、收起或重新加载分支。切回普通类保留原字段选择与关系端点，取消勾选后移除该表的行内配置。窄屏沿用原生虚拟树的横向滚动访问行内控件，不撑宽页面。对象属性连接实例，该模式不导入该表的字段；需要保留时间、状态等关系自身的业务字段时应作为类处理。当前不根据表名或外键自动猜测对象属性两端。

IRI 使用命名空间与目录实体 ID 生成，区分跨 Schema 同名表及字段；重复导入保留已存在且类型、domain/range 一致的定义，有实质冲突则拒绝覆盖。类和数据属性名称优先使用业务名，对象属性使用表名，冲突时加来源限定；注释取业务描述或源注释。整数、数值、布尔、时间及二进制等 SQL 类型对应 XSD 类型，未知或数组类型作为不透明 string；这只生成定义，不执行值转换。xsd:date/time 等仍受现有 OWL Profile/HermiT 发布校验约束，不会为通过校验而隐式改成其他数据类型。可在现有编辑面板中继续调整定义。

选择结果通过现有 /ontology/builder/draft/preview 批量命令链路验证后才进入当前草稿，一次撤销/重做恢复整批；沿用现有500条累计命令和画布预算，失败不替换原草稿。发布、校验及显式图库写回流程保持不变。导入不读业务样本、不生成实例或 Ontop/SQL 映射，不向数据源配置写回 IRI，也不保存活跃引用；源结构后续变化不会自动更新已复制定义，删除数据源不会因此删除 OWL 定义。

前端组合根按 Build Manifest 可选注入 datasource/public_api/catalog 的只读目录 Reader；Ontology 仅类型引用公开 DTO，不导入数据源组件、私有实现或客户端。请求仍通过数据所有者现有授权 HTTP 接口与 Tenant UoW/RLS，未装配时不提供入口，服务端拒绝时不回退或绕过鉴权。本次无后端接口、数据库迁移、运行配置或依赖变更。

在当前系统中打开​

当前开发环境入口：AI 工作台 → OWL 可视化构建器，也可直接访问 http://localhost:5174/ontology-builder。新增菜单已同步到当前数据库，并沿用原 Neo4j 语义本体入口已有的 ontology:read 角色和套餐关联；已打开的系统需刷新以重新获取菜单。平台管理员打开页面自动加载 Neo4j 当前 Resource 图，不再需要先上传文件；“读取 / 刷新 Neo4j 现库”可以重新读取。点击“打开 OWL / Turtle 文件”会切换到独立的原文件基线预览，不能混合两份数据，也不会导入数据库。有编辑权限的账号可从顶部工作区选择器打开已授权的绑定；未绑定的全局现库仍仅供平台管理员核查。不需要启动独立预览服务或测试 Neo4j 容器。

有 ontology:read/edit 权限即可点击画布顶部 创建工作区，默认 新建空白本体（无需文件）。填写编码、名称和可见范围（默认仅本人）后得到独立空白画布，可新增类、属性、关系及实例；保存本体 将当前正文保存为可继续编辑的版本，重新打开工作区可恢复。原有 保存草稿 仍是本人私有编辑检查点，与共享工作区正文保存区分。校验当前草稿 → 发布版本 继续要求本人当前输入对应的真实 HermiT 成功任务与当前发布权限；独立工作区发布后即可配置规则与状态，不需要 Resource 写回。

向导另有 从文件创建独立本体：文件仅作为初始正文，沿用 UTF-8/4 MiB/隔离 RDF 解析限制，不核对或绑定 Neo4j。独立工作区可创建多个，使用 PostgreSQL 的 Network/Version/Audit 与现有 Tenant UoW、FORCE RLS；不会读取或覆盖共享 Resource 图。builder_binding.mode=native 表示原生编辑状态，original_source 是系统生成或导入的初始基线，不要求用户提供原文件；正文的当前事实源仍是 Version.rdf_document。原生状态为 local，projected_version=0，明确没有 Resource 投影。模式、初始基线与归属不可修改，不能通过 /project 将其切换成历史现库绑定。

只有历史 绑定现库工作区 选项仍要求平台检查与发布权限、原始文件和当前图摘要。该选项先核对原文件与现库差异，再显式登记；整套 Resource 图只能绑定一个历史工作区，发布后仍需显式写回。不能将有损重建图伪装为原文件。这一历史接管限制不适用于空白新建或独立文件导入。

规范化模型与读取接口​

public_api/builder.py 定义 chein.rdf/v1：namespaces 和 subject/predicate/object statements；每个 term 显式区分 URI、空白节点、literal，并保留 language 或 datatype。类、对象属性、数据属性和只读公理是该文档的投影。RDF 图是集合，空白节点标识、声明顺序、前缀排版、XML 注释不属于无损语义往返保证；保证以 RDF 图同构为准。

序列化与资源上限​

浏览器文件入口要求有效 UTF-8，非法编码明确拒绝，不以替换字符静默改写标签；其他编码须先转换。HTTP content 是已解码的 Unicode 字符串。

源码面板直接提交当前 RdfDocument，不调用 n10s 导出。序列化复用 RDFLib。Turtle 输出采用合法的 N-Triples 子集，避免 RDFLib Turtle 序列化器的全图排序。全部文件实例导出将三元组直接写入临时 SQLite Store，再使用逐三元组/逐 subject 的成熟序列化器写入临时文件；HTTP 以 64 KiB 分块流出，断开时关闭文件。完整输出先在隔离进程完成，因此不是解析同时向客户端传输；不会在 API 进程组装完整输出字符串。

现库完整导出不在 API 内构造全量节点列表：驱动游标必须在同一只读事务内消费，三元组直接落临时 SQLite；只保留单条记录与单个 subject 的内存，完整序列化后按 64 KiB 分块传输。现库输入编码预算 32 MiB、最多 20 万三元组、输出 64 MiB，复用两个并发槽及现有 Neo4j 查询超时。现库值的 RDF datatype 还原仍有歧义，不能宣称与原始导入文件无损等价。匿名节点 ID 统一映射为稳定合法的 XML NCName，避免 n10s 数字开头的 ID 导出无法解析。

文件预览安全预算：输入文件 4 MiB、20 万三元组、每进程 15 秒 CPU / 20 秒总超时、输出 64 MiB、并发解析 2 个。Linux 另限制 512 MiB 地址空间；macOS 不使用不可靠的 RLIMIT_AS。文件输入字符串本身仍受 4 MiB 内存预算约束。这些是当前预览的上限，不是无限规模实例导出的完成证据。

仅本体范围保留未知结构与孤立匿名表达式，移除文件实例及其独占空白子图。同 URI 同时为类/实例时保留完整共享 subject，避免丢失公理和歧义注解，因此 TBox 导出可能保守保留该 subject 的实例陈述；完整导出保证全部陈述往返同构。XML 不能表达的字符或谓词将明确拒绝，不能返回不可解析文件或静默删值。

全局现库比较目前最多读取 2 万 Resource 和 20 万条边，且只支持 SHORTEN/SHORTEN_STRICT + LABELS，要求 keepLangTag、keepCustomDataTypes、applyNeo4jNaming 为 false；这些编码规则为 true 或其他配置/预算不支持时失败关闭。现库画布同样限制 TBox 2 万节点、20 万条边；不加载 ABox 节点列表。两种核查均不等于后续普通租户按工作区 ACL 读取的接口。

服务端私有草稿​

画布顶部的“保存草稿”将当前编辑基线及命令写入 PostgreSQL；“恢复草稿”列出本人保存记录，可在刷新后、尚未打开文件或加载画布时使用。第一次保存创建记录，恢复后继续保存更新同一记录，显示服务器已保存/有未保存修改。列表按更新时间倒序每页50条，可刷新和加载更多；每条显示工作区/文件来源名称与更新时间。恢复会替换当前编辑，有未保存改动时先确认，失败保留原画布。删除已保存草稿需确认和当前草稿 revision，仅删除服务器记录，不删除当前画布或已发布定义。恢复保留已执行命令及本次编辑实例；浏览器内撤销/重做栈不持久化，恢复后新操作仍可撤销。

保存不是发布：允许保存现有语义约束未通过的草稿，仍复用隔离 RDF worker 验证安全、命令引用和解析预算；语义错误在恢复视图中继续显示。发布校验任务及审批/写回状态不保存在草稿中，正式发布仍需当前版本对应的本人真实校验任务和原有显式流程。工作区草稿保留 workspace_id、expected_revision 与命令，读取/更新时逐次重验工作区可见性、版本及写回状态；变更后失败关闭，不静默改基线或修改已保存记录。

未绑定现库和上传文件的草稿保存原始 RDF 基线快照及命令，不保存数据库连接凭据。未绑定现库保存时必须传 base_digest，与完整图投影出的当前 TBox 基线摘要一致，否则409；现库快照同时绑定连接 graph_key，恢复和更新仍需当前平台检查权限，连接变化时拒绝。恢复后的文件/现库快照作为私有离线编辑输入，不会自动合并外部图库变化，不会直接写回图库或成为已发布版本。仅保存已授权的 RDF 编辑输入（可含原有实例），不执行数据源样本查询。
