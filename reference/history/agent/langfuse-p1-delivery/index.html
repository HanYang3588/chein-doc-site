Langfuse P1 接入与配置

本文保留 P1 阶段历史与排障记录；当前功能及配置以 P1–P5 实施 为准。 状态：P1 接线已实现；本地验证记录见下文，目标环境启用验收待配置。总体设计仍为 Proposed，本文不代替治理签署或上线记录。

本阶段接入 Agent execution 根和官方 LangChain Callback，保留已有元数据日志。默认关闭；启用后仅导出标识引用、状态、耗时和可获得的 Token 计量。Prompt、回答、思考内容、工具参数/结果、图片、原始错误和业务身份均不上传。

1. 当前实现​

入口行为
agent/src/chein_agent/main.py每个 ASGI worker 在 lifespan 初始化一次，关闭时做有界 best-effort shutdown；启动和请求不做 auth_check
agent/src/chein_agent/langfuse_tracing.pySDK 4.17.0；采集前屏蔽、导出属性白名单、不可清理字段过滤、固定错误码及限频传输日志
agent/src/chein_agent/api.py成功 claim 后，在 SSE generator 内建立 execution 根；每个采样 execution 一个新 Callback；根覆盖流式响应和清理
agent/src/chein_agent/settings.pyNacos/环境配置，默认关闭；观测配置错误只关闭采集，业务配置仍遵守原校验
agent/src/chein_agent/model_provider.pyQwen stream_usage 显式 opt-in，默认关闭

关闭时不导入 Langfuse、不初始化 SDK/线程、不注入其 Callback。开启后使用独立、非全局 OTel Provider；P1 不传播 BFF/MCP/HTTP 的跨服务 traceparent，也不替换其他组件的全局 Provider。固定 Trace ID 使用 SDK create_trace_id 和 HMAC execution 引用；TraceIdRatioBased 对整棵树保持一致采样，避免 SDK 指定 trace_context 的 sampled 父上下文绕过采样率。

可信 tenant/user 来自现有委托验证；session 引用包括环境、租户、用户和 thread。Run 和 lease_epoch 决定 execution；恢复/重领建立新根，同 thread 保持 session。暂停/等待人工输入结束根；断连或 Task 取消记 incomplete，保留原取消异常，不把断连擅自改成业务取消。核心 Run、审批、checkpoint 和权限仍由原调用链负责。

新增 observability.execution RunEvent 保存 schema_version、trace_id、execution_id、lease_epoch、message_id、sampled、release、data_policy。它复用原 owner/lease 检查和存储函数，写入采用 250ms 超时，失败只记录固定诊断；其他业务数据库错误沿用原处理。此映射不是可靠消息投递，失败时可能无法从 RunEvent 找到对应 Trace。

Generation 只保留供应商/框架返回的合法非负整数计量；缺失和部分计量分别标 usage_status=missing/partial，完整计量标 actual。不补造零 Token，不导出 SDK 错误回调的零成本，cost_source=unknown。Langfuse 界面可能按项目价格推导费用；该数值不是 Qwen 账单事实。

2. 你需要配置的内容​

先按 Langfuse 部署与合成摄取验证 确认 Web、Worker、ClickHouse 和存储链路可用。在 Langfuse 建立独立测试项目并创建该项目的 Public Key、Secret Key。

将下面配置填写到 Agent 使用的 Nacos chein-agent-runtime.yaml，Group 使用现有 CHEIN，namespace 沿用 Agent 的 bootstrap 配置。不要填入 Backend、前端或 Langfuse Web/Worker 的环境文件。

LANGFUSE_TRACING_ENABLED: true
LANGFUSE_BASE_URL: "https://langfuse.example.com"
LANGFUSE_ALLOW_HTTP: false
LANGFUSE_PUBLIC_KEY: "replace-with-project-public-key"
LANGFUSE_SECRET_KEY: "replace-with-project-secret-key"
LANGFUSE_TRACING_ENVIRONMENT: "development"
LANGFUSE_RELEASE: "replace-with-release-or-git-sha"
LANGFUSE_SAMPLE_RATE: 1.0
AGENT_OBSERVABILITY_ID_KEY: "replace-with-random-private-identity-key"
AGENT_OBSERVABILITY_ID_KEY_VERSION: "v1"
AGENT_OBSERVABILITY_DATA_POLICY: "metadata-only-v1"
LANGFUSE_MEDIA_UPLOAD_ENABLED: false
LANGFUSE_DEBUG: false
QWEN_STREAM_USAGE_ENABLED: false
配置填写要求
BASE_URLAgent 机器可访问的 origin；默认使用证书可信的 HTTPS。不带 /api/public/otel/v1/traces、账号、查询参数或片段
ALLOW_HTTP默认 false。可信内网的 HTTP 地址需显式设 true；项目凭据将明文传输，此开关不改变脱敏或其他地址校验
Public/Secret Key同一环境的同一 Langfuse 项目 Key；不是登录账号、PG/Redis/RustFS 密码
ID_KEY独立随机密钥，至少 32 个字符；同一环境全部 Agent worker 一致。与项目 Secret Key 分开保存
ID_KEY_VERSIONv1、v2 等；轮换会改变身份/session 聚合，需协调全部 worker
ENVIRONMENT / RELEASE1–128 个字母、数字、点、下划线或连字符；区分环境并标记实际发布版本
SAMPLE_RATE首次隔离验证用 1.0；降采样会丢弃整棵树，不是错误全量采集方案

当前部署使用可信内网 HTTP 时，可保留原地址并增加：

LANGFUSE_BASE_URL: "http://langfuse.internal:3000"
LANGFUSE_ALLOW_HTTP: true

可在可信本机生成 ID_KEY，并仅保存到私有配置：

python3 -c 'import secrets; print(secrets.token_hex(32))'

完整参数和默认值见 chein-agent-runtime.yaml.example。起步值：队列 2048 Span、批次 128、间隔 5 秒、导出 timeout 2 秒、退出观测宽限 5 秒。关闭媒体/Debug 是固定隐私门禁，不提供原始内容模式。不要设置 LANGFUSE_OTEL_TRACES_EXPORT_PATH 改写摄取路径。

配置优先级沿用现有实现：进程环境变量优先于 Nacos；配置在启动时加载，不热更新。若修改 Nacos 后不生效，检查启动环境中是否已有同名变量。然后更新 Agent 依赖/部署版本，并滚动重启全部 Agent worker：

cd agent
uv sync --locked

本地开发可重新启动已有 pnpm agent:dev；服务器使用其现有进程管理方式重启 Agent。默认 Chein Compose 没有独立 Agent 服务，不能用 docker compose restart agent 代替实际进程重启。后台、模型入口、Prompt 和 checkpoint 配置沿用现有值。

3. 启用验证与回滚​

  1. 启动日志应出现 Langfuse metadata tracing enabled。关闭诊断带固定原因码：HTTPS_ORIGIN_REQUIRED 表示使用 HTTP 但未显式允许；ORIGIN_INVALID 表示协议、地址结构、端口或凭据/路径/query/fragment 不符合要求；PROJECT_KEYS_MISSING、IDENTITY_KEY_INVALID、LABELS_INVALID、DATA_POLICY_UNSAFE、NUMERIC_OPTION_INVALID、EXPORT_PATH_OVERRIDE_UNSUPPORTED 对应项目 Key、HMAC 密钥/版本、标签、安全策略、数值或路径配置；INITIALIZATION_FAILED 表示其他初始化异常。核对上表和参数范围；诊断不会打印密钥、地址或原始 SDK 异常。
  2. 用隔离测试账号发一条不含真实业务数据的消息，再执行一个已有只读工具。等待后台批次导出后，在项目 Observations 中查看 agent.execution、framework.chain、model.chat 和 tool.invocation 父子关系。固定名称用于防止动态内容进入 Span name。
  3. 根的 metadata 应包含 HMAC run/execution 引用和终态；Langfuse session/user 也应是 HMAC 引用。原始问题、答案、图片、工具内容、checkpoint 复合身份不应出现。RunEvent 可提供本地 Trace 关联，日志中的 trace.id 应与之一致。
  4. 发第二轮以及一次暂停/恢复：同 thread 的 session 相同，各 execution 的 Trace 不同。重复 claim 冲突不能增加模型执行 Trace。
  5. 在隔离环境中阻断仅 Langfuse 的目的地址后再发送合成消息，确认原 SSE、审批和 Run 状态仍正常；不要中断模型或业务数据库网络来代替该实验。
  6. 对当前 Qwen/网关做独立合成流式请求，确认支持 stream_options.include_usage，且结束块中的 input/output/total 与非流式计量一致，再设 QWEN_STREAM_USAGE_ENABLED: true 并重启。若供应商不支持，保持 false 和 missing；不能拿模型生成的数字充当 Usage。

媒体上传关闭，图片生成本身继续走原业务链路。当前不会新增 image/SQL/检索阶段的手工 Span、辅助决策 HTTP generation、跨服务传播、反馈 Score 或 Dataset；这些属于 P2–P5。

回滚：LANGFUSE_TRACING_ENABLED: false 并滚动重启 Agent。无需数据库迁移、OpenAPI 重新生成或业务数据回滚。退出超过观测宽限会放弃等待，允许丢失尾部遥测；不承诺可靠补发。

4. 验证证据与未完成门禁​

本地可复现命令：

cd agent
NACOS_ENABLED=false uv run ruff check src tests
NACOS_ENABLED=false uv run pytest tests -q
uv lock --check

本次本地验证结果（2026-10-14）：ruff check src tests、uv lock --check 和 git diff --check 通过；Agent 全量测试 183 passed、2 skipped，跳过项需要独立测试数据库。复用 CI 的 pip-audit==2.10.1 --disable-pip --no-deps --strict，导出并扫描 149 个运行依赖，结果为零已知漏洞；该结论只反映本次扫描数据库。

初次扫描发现原 Agent 锁文件的 3 项依赖存在 6 个已知漏洞，已更新为 multidict 6.9.1、PyJWT 2.15.0、urllib3 2.8.0，并在更新后重跑全量测试及扫描。PyJWT 的声明下限同步提高为 2.15。修复依据见 multidict 发布说明、PyJWT 发布说明、urllib3 发布说明。这里只更新 Agent 交付依赖；默认 Compose 的 Backend 镜像没有 Agent 运行时，Agent 使用其自己的锁文件安装。

新增测试使用真实 SDK 和 InMemorySpanExporter，HTTP 客户端在内容测试中被拦截并断言零请求，覆盖原生 LangGraph/Tool、非流式与流式模型、并发父子关系、恢复、实际/部分/非法 Usage、关闭零 SDK 导入、采样为零、源内容与媒体屏蔽、Span name/status 过滤、导出异常、取消以及黑洞 exporter 下子进程退出。API 测试核对开启追踪及可选 RunEvent 写入失败时，暂停、取消、失败的原 SSE 和 Run 终态保持一致；执行根只在消费 SSE 时开启，首事件后断开会关闭根并标 incomplete。

尚未执行：目标 Langfuse 项目的真实摄取/可见性、当前 Qwen 或 Higress 计量核对、私有配置启用、运行角色下的数据库验证、真实 401/429/5xx/DNS/TLS 故障代理、长时 RSS/CPU 与 P95/P99 性能矩阵、目标环境停机演练、远端 CI/镜像扫描/签名及团队签署。两项数据库测试依赖独立迁移完成的测试数据库；不得连接生产数据库补跑。

本地测试只能证明本地接线与安全行为；目标环境配置、合成 trace 摄取及 阶段计划 的环境门禁完成后，才可以记录“启用验收通过”。

HTTP 地址排障补充（2026-10-14）​

本次从 Agent 使用的 Nacos Data ID 读取配置，确认开关开启、采样率 1.0，但 BASE_URL 为 HTTP；本地初始化在创建 SDK 前因 HTTPS origin 门禁失败。无凭据健康检查返回 HTTP 200，只证明 Web 可访问，不能证明项目 Key、Worker 消费或 ClickHouse 摄取。

初始化诊断现已记录固定原因码 HTTPS_ORIGIN_REQUIRED，不打印配置值或原始 SDK 异常。补充了诊断及秘密不泄漏回归，Agent 全量测试 184 passed、2 skipped；Ruff 和 diff 检查通过。没有新增数据库迁移或改变 HTTPS 门禁。当时的 HTTPS 门禁导致 SDK 未启用；随后已按用户要求增加默认关闭的 LANGFUSE_ALLOW_HTTP。保留 HTTP 地址并显式开启该参数，或更新为 HTTPS 入口后，需要重启 Agent，再核对目标项目中的 development 观测；真实摄取验证尚未执行。

HTTP 显式支持与目标环境验证（2026-10-14）​

按用户要求增加 LANGFUSE_ALLOW_HTTP，默认 false。开启后允许无凭据、无路径/query/fragment 的 HTTP origin；原有媒体禁用、HMAC、采集前屏蔽、导出白名单和观测失败隔离均保留。对默认拒绝、显式允许及非法协议/端口/凭据/路径/query/fragment 补充回归；本地 Agent 全量测试 192 passed、2 skipped，Ruff、配置键、文档链接与 diff 检查通过。无依赖或数据库迁移变更。

目标实例实测：以项目 Key 读取项目接口返回 200。使用临时诊断进程允许 HTTP、仅发送无业务内容的合成 execution；直连 OTLP 接口 /api/public/otel/v1/traces 返回 HTTP 500，对应 Trace 查询返回 404。诊断进程没有更改 Nacos 或真实会话，实际摄取验收未通过。已请求部署机 Web 错误日志；Web 可访问及 Key 有效不能代替写入/消费成功。此时扩大超时、关闭脱敏或改采样不能被视为已验证的修复。

使用当前 HTTP 地址的下一步：在 Agent 的 Nacos 运行配置增加 LANGFUSE_ALLOW_HTTP: true，重启全部 worker；同时依据 Langfuse Web 的 500 日志排查摄取链路。只把 HTTP 开关打开，不能保证目标实例立即出现对话追踪。

Waiting for first trace 复查（2026-10-14）​

再次读取实际 Agent Nacos 配置，确认 tracing 与 HTTP 允许开关均开启；项目 API 认证仍返回 200。合成追踪直连上报返回 HTTP 500，服务端 JSON 错误明确为 Failed to upload JSON to S3，该 Trace 查询返回 404。这不是仅凭截图推断的等待/筛选问题：当前至少存在 Langfuse Web 事件存储写入失败，底层原因需要部署机 langfuse-web 容器日志，不能直接判定为桶不存在、密钥错误或 region 不匹配。

下一步在部署机执行 docker logs --since 10m --tail 100 langfuse-web，去除密码、令牌和连接串后提供实际 S3 错误段。按 部署故障表 对照事件存储配置。未更改服务器对象存储或扩大其权限。

Web 日志确认 S3 响应异常（2026-10-14）​

用户提供 Web 日志，底层 S3 请求返回 404，同时 AWS SDK 报 XML parse error: unexpected content。这是日志事实；event endpoint 指向控制台/错误服务、端口映射或代理路由错误属于优先排查假设，尚未证实，不能据此直接更换密钥或扩大权限。下一步只读取 Web 容器的事件 bucket、endpoint、region、prefix 和 path style，确认实际 S3 API 地址；RustFS 默认 S3/Console 端口分别为 9000/9001，部署端口可改，依据 官方状态检查 与实际映射核对。配置项说明见 Langfuse Blob Storage。

S3 探测与摄取复测（2026-10-14）​

本机访问用户提供的 event endpoint，健康接口返回 RustFS 信息；未认证 GET 与 PUT 返回标准 S3 XML 403，没有复现此前的非 XML 404。因此不能把映射端口判为控制台端口。用户在 langfuse-web 容器内使用现有 event 配置、现有 AWS SDK 和随机诊断对象，确认 PUT_OK=200、DELETE_OK；这证明该配置可以上传和删除该测试对象，不证明其他前缀或 Worker 读取权限。

目标健康接口报告版本 4.56.0；该版本 S3 客户端源码 已设置 requestChecksumCalculation 与 responseChecksumValidation 为 WHEN_REQUIRED。测试上传成功不能单独证明校验选项是此前错误的原因，不据此增加兼容环境变量。

复测使用现有 P1 脱敏链生成合成跨度，经官方 OTLP 编码器直接提交；两次 HTTP 摄取均返回 200，第二次提交后累计等待约 27 秒，四次 Trace 查询均返回 404。没有调用模型、保存业务 Run 或更改 Nacos。当前只确认摄取接口接受请求，尚未确认正常 SDK 对话上报或完整落库；下一步核对 Worker 日志、运行状态及其事件存储配置，再依据错误检查队列、S3 读取或 ClickHouse 写入。

v4 查询接口与本机代理核对（2026-10-14）​

后续只读排查确认目标实例使用 events-only v4：旧 Trace/Observation 接口的 404 不能用来判定摄取丢失。改用 /api/public/v2/observations 后找到合成和实际 Agent 观测，说明此前旧查询路径的判断需要更正；这不自动完成生产完整性与延迟验收。

实际 Agent exporter 的 502 与本机系统 HTTP 代理有关：即使没有 HTTP_PROXY 环境变量，requests 仍可能读取 macOS 代理。仅在诊断进程排除目标代理后实际对话可见。当前代码默认 LANGFUSE_TRUST_ENV=false，exporter 使用私有直连 Session，不修改系统代理、Docker 或其他应用网络。P2–P5 新查询同样使用 v2 API 和固定字段；启用步骤见 当前实施。
