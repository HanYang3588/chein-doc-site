Agent 自动化任务

状态：实现已落地，本地代码、数据库和浏览器验证通过；经营分析示例未通过业务验收，外部门禁未执行，不能据此声称已上线。更新：2026-10-18。

进程与事实源​

同一 Agent 镜像运行 API 和独立 python -m chein_agent.automations.scheduler。API lifespan 不启动 Scheduler。APScheduler >=3.11.3,<4 的 AsyncIOScheduler 只承担触发，SQLAlchemyJobStore 使用独立同步 psycopg Engine；绝不传 AsyncEngine。PostgreSQL 会话 advisory lock 先于 JobStore 启动获取，失去连接立即停止调度；不允许两个实例共享运行中的 JobStore。

业务源为 agent_automation；apscheduler_jobs 是可重建投影。每 5 秒 reconcile。automation_owner_directory 是控制面路由目录，仅含 tenant/owner ID，不含配置、结果或授权；runtime 只获 SELECT/INSERT。保留目录 tombstone，使移除成员后仍能发现并拒绝其任务。Scheduler 枚举后逐 tenant/owner 开启现有 transaction-local scope，业务表仍受双重 FORCE RLS，无 BYPASSRLS。Backend 机器接口仅提供当前权限重验与通知。机器凭据只在服务配置中，不存业务行、Job 或 Snapshot。Backend 不导入 Agent/模型框架。

APScheduler 官方说明：3.x 用户指南。不选择 Celery/RQ 是因为没有现成运行部署且初期单 Scheduler 足够；XXL-JOB 增加不必要平台。

数据与 ER​

行同时使用 tenant/owner FORCE RLS。复合 FK 保证任务与 Run 的归属一致；scheduled 唯一索引 (tenant_id, owner_id, automation_id, automation_revision, scheduled_for)，部分唯一索引保证每个任务至多一个 PENDING/RUNNING。保留所有失败、跳过、重试与删除历史。表单配置为有界严格 DTO；无 Secret 字段。运行 Snapshot 保存 Prompt、调度、模式及通知偏好，不保存授权令牌和提示词服务正文。使用原运行 usage，不复制账本。

用户配额在事务内按 owner advisory lock 校验；租户配额通过只含 tenant/count 的 automation_tenant_quota、租户 RLS 和原子计数更新约束，不放宽个人任务的 owner RLS。创建、软删除与计数在同一事务提交，维护也应走同一服务。AUTOMATION_MAX_PER_USER 默认 20，AUTOMATION_MAX_PER_TENANT 默认 1000。任何新增生产依赖必须锁定并进入镜像。

调度同步与时间​

统一 TriggerFactory 支持 date、五段 cron（每日/每周/每月归一到 cron）、interval；IANA ZoneInfo、UTC 持久化、区间边界和最多五次后端预览。遵循锁定的 APScheduler 3.11.3 DST 行为：纽约 2026-11-01 的 01:30 对应两个不同 UTC instant；2026-03-08 不存在的 02:30 对应 03:30，预览通过 UTC roundtrip 显示实际本地时刻。比较与幂等使用 UTC instant，不承诺每天固定秒数。Agent 日期工具也通过 coroutine context 使用该任务的时区。interval 必须持久化 anchor，不能 reconcile 时重新锚定。

创建、编辑、暂停、恢复、删除增加 revision。执行前锁任务并重读 enabled/deleted/revision，旧 Job 记录 STALE_SCHEDULE 或 DISABLED。Job 固定为 automation:{id}，模块顶层 callable，不接受用户 import/callable。reconcile 保留与业务 next_run_at 一致的 Job；若入队失败导致投影先行推进，按业务时间修复偏移，避免重启或临时数据库故障漏跑。date 完成后 next_run_at 为空，不能复活。

默认 overlap=SKIP、coalesce=True、max_instances=1、grace=900 秒。错过很久只记录 MISSED，不追赶历史；RUN_ONCE 在 grace 内合并一次；SKIP 不补跑过期触发。调度入口持有准确 scheduled_for，不能以 actual now 代替幂等键。Manual/Retry 使用同一 durable Run 队列，不修改正常 next_run_at；不自动重放整个 Agent Run。

执行序列与恢复​

每次全新 thread，FRESH 上下文；不累积昨日聊天。无可展示最终回答是 EMPTY_RESPONSE；审批/追问不可无人值守继续，明确 FAILED/INTERACTION_REQUIRED，不冒充成功。timeout 传播原运行 cancel；停止时停止接单、取消并落 CANCELED。启动恢复过期 RUNNING 为 ORPHANED，不自动重试（副作用可能已经发生）。通知失败不改变 Agent 结果、不重跑 Agent。SMTP 无 exactly-once 保证，发送结果不确定时保留日志，不自动重发。

API、前端与部署​

浏览器只访问 /api/v1/agent-ui。提供 automations 列表/创建/详情/PATCH/软删除、enable/disable/run、任务 runs、automation-runs 分页/详情/retry、stats、preview-schedule、options。全部使用现有登录、agent:chat、可信 tenant 与 owner；Agent 内部也验证签名 delegation 与 scope。静态 stats/preview 路由优先于 UUID 动态路由。统计数据库按选择时区聚合 30 个自然日，禁止浏览器下载全量 runs 聚合。

菜单为「AI 工作台 → 自动化 → 自动化任务 / 任务运行」；/automation-center 是目录，/automations 是任务页面，/automation-runs 是运行页面。两页独立加载各自列表，不再提供页内切换或内容区顶部标题。任务页包含查询条件、任务 Table 和模板区域，不再加载运行统计；名称、创建日期区间、状态筛选与新建按钮同一行，窄屏可换行。运行页包含统计及运行 Table，刷新按钮在统计卡片内、运行次数右侧。立即运行、通知和消息中心均跳到 /automation-runs?run=<id>，旧 /automations?run=<id> 自动转入新页面。保留原任务菜单 ID，给原组合页面的角色/套餐授权幂等补齐父目录与运行子菜单，权限仍为 agent:chat，无新增权限码。

任务列表新增可选 query：name（最多 100 字符，忽略大小写的字面子串匹配）、created_from（含）、created_before（不含）、status（active/paused/error/exhausted）。日期必须包含时区且起点小于终点；浏览器将所选开始日零点及结束日的次日零点转换为 UTC，覆盖完整结束日。过滤、total 与分页均由 Agent PostgreSQL 查询完成并保留 tenant/owner RLS，不在当前页本地过滤。状态优先级与展示一致：暂停 → 最近失败 → 存在下次运行 → 日程结束。查询与重置回到第一页；新参数均可选，无数据迁移或旧客户端破坏性变更。

Drawer 提供名称、触发器、时区、Prompt、原深度思考模式、通知；用后端 preview，错误时禁止保存。Run Drawer 展示时间、延迟、耗时、Snapshot、结果和错误以及现有观测入口。仅有活跃 Run 时 5 秒轮询，终态停止；任务/运行表服务端分页。模板只是静态默认配置。页面拆分无数据表或 HTTP API 契约迁移；已有安装需运行现有 seed_menus 导航播种并失效 RBAC 缓存，新增初始化会自动包含两个子菜单。

新增 Agent Dockerfile（Python 3.13，与现有 pyproject 一致）、可选 Compose overlay，API 与 Scheduler 共用镜像，迁移单独执行；runtime 不注入迁移凭据。配置包括 Backend 内部地址、固定服务令牌、配额、最大执行时间；不在仓库写真实连接/凭据。现有 Backend 四 Web Workers 保持原样。

风险与验收边界​

短期 delegation 的有效期仍使用当前系统配置；长任务中令牌到期时工具失败关闭，不自动扩大 TTL。独立 Scheduler 的完整 Run 取消和数据库 heartbeat 失败会请求取消原运行；数据库不可用时保留 Run 的可恢复状态，不重放业务。

APScheduler JobStore 为 pickle：数据库写权限等价可信代码部署边界，禁止普通用户写该表。owner 枚举应限制内部网络与令牌、日志不记录请求 Secret。短期 delegation 过期后工具必须失败关闭；不扩大原令牌 TTL 或绕过权限。单进程容量有界，超容量待队列等待或跳过，禁止创建无界 asyncio tasks。多副本只能一个 leader；连接断开必须停止，不能仅启动时查一次锁。生产邮件/模型/Trace 验收需要真实已配置服务；本地假模型测试不能宣称该外部链路通过。

部署操作​

以独立 migration Data ID 执行；迁移凭据不得注入 API/Scheduler：

cd agent
NACOS_CONFIG_DATA_ID=chein-agent-migration.yaml uv run python scripts/migrate_automations.py

升级前备份。回滚先停止 Scheduler，再以迁移账号在 agent search_path 执行 migrations/0003_automations.down.sql。downgrade 会删除本功能任务、历史和投影，不能用于普通重启。迁移使用事务、版本 marker、advisory lock 和显式 runtime 授权，可重复执行，不修改历史 0001、0002。Agent 不使用 Alembic；Backend 没有新增业务表或 revision。

Agent runtime Data ID 使用既有 checkpoint runtime URL、模型与公钥；Backend/Scheduler 配置相同随机 AUTOMATION_SERVICE_TOKEN（至少 32 字符），Scheduler 的 AUTOMATION_BACKEND_URL 为 Backend origin。本地可使用被 Git 忽略的 .env，不提交、不输出实际值。邮件默认关闭；Backend 设置 AUTOMATION_EMAIL_ENABLED=true 后，还需有效的租户 automation_result MailTemplate 和 MailAccount，模板参数只允许 name,status,url。

cd agent
NACOS_CONFIG_DATA_ID=chein-agent-runtime.yaml uv run python -m chein_agent.automations.scheduler

容器使用 docker compose -f compose.yml -f compose.automations.yml up --build。Agent API 与 Scheduler 共用 Python 3.13 镜像，runtime 服务不携带 migration Data ID。另一个 Scheduler 取不到 advisory lock 即退出；重启后从业务源和持久化投影恢复。

浏览器接口前缀 /api/v1/agent-ui：automations CRUD、/{id}/enable|disable|run、/{id}/runs、automations/preview-schedule、automations/options、automation-runs、/stats、/{id}、/{id}/retry。PATCH 合并后按完整 DTO 验证，不能修改归属。固定机器接口 /api/v1/internal/automations/authorize|notify 不进入公开 OpenAPI，不能用普通用户 JWT 代替服务凭据。

最终范围与限制​

  1. 架构：独立 APScheduler 3.x 进程，PostgreSQL 业务源、持久化调度投影和 leader guard；复用真实 Agent 执行与当前权限。
  2. 文件：运行实现位于 agent/src/chein_agent/automations/，BFF/机器适配位于 backend/app/modules/platform_automations/，页面位于 frontend/apps/web-pro/src/modules/platform/agent/automations/；公共入口、配置、菜单、生成 API 和架构文档同步修改。
  3. Migration：Agent 0003_automations.sql / .down.sql 与 scripts/migrate_automations.py；回滚会删除本功能数据，必须先备份并停 Scheduler。
  4. 依赖：仅 Agent 新增 APScheduler（锁定 3.11.3）与 SQLAlchemy（锁定 2.1.5，供同步 JobStore 使用）；未新增前端 UI、队列或锁中间件。
  5. 启动：上节提供 migration 和 Scheduler 命令；短期授权仍沿用既有 TTL，长运行到期时失败关闭。
  6. 部署：agent/Dockerfile 与 compose.automations.yml；镜像构建、扫描、签名及真实 Compose 服务启动尚未执行。
  7. API：CRUD、启停、立即运行、重试、分页详情/统计、预览和 options；当前身份与 tenant/owner RLS 始终生效。
  8. 页面：/automations 任务页与 /automation-runs 运行页，独立子菜单；统计、模板、创建/编辑 Drawer 和运行详情沿用 Ant Design 与系统主题。
  9. 验证：以上本地矩阵与真实运行证据；远端 CI、生产重启/故障演练、N-1 和团队签署未执行。
  10. 已知限制：仓库无可选 Skill/Connector Registry，选择器明确禁用且后端拒绝未知 ID；邮件接入已有模板/账号体系但默认关闭，真实 SMTP 投递未验收；经营分析 MCP 失败原因尚未定位，示例业务验收仍未通过；仅单 leader、有界并发，未新增专用 automation metrics exporter，复用当前 Trace、usage 和日志。
