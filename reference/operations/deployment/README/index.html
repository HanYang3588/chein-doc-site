部署

本目录涵盖 Chein Compose、后端启动与 Nacos、Agent 提示词（含删除权限增量 SQL（未发布资料）及 Nacos MySQL Group 长度补丁（未发布资料））、知识库管理启用、RAGFlow 独立部署和 Langfuse 部署、账户配置与故障复盘（双容器复用中间件、迁移权限与 AMD64 离线传输）。默认 Compose 是本地开发入口；生产组合的配置与验收状态见本文末节。

Docker Compose​

在仓库根目录准备 Nacos 连接配置。macOS/Linux：

cp .env.example .env

Windows PowerShell：

Copy-Item .env.example .env

按 deploy/nacos/*.example 在 Nacos 创建 bootstrap 与 runtime 配置，再运行：

docker compose up --build

Compose 只启动 Chein 应用容器；Nacos、PostgreSQL、Redis 和对象存储是外部依赖，连接配置从 Nacos 获取。

后端默认自动运行 Outbox/Schedule，默认 Compose 不启动独立 Worker 容器。独立部署兼容 profile、配置开关和旧进程升级说明见知识库部署的 Worker 检查。

RAGFlow 不属于此 Compose 栈。它以独立的单容器镜像运行并通过运行时 docker run --env-file 注入外部中间件配置；默认原生 Tool 检索使用 HTTP；保留的可选 MCP 启动、参数和安全边界见 RAGFlow 独立部署。

服务入口：

  • 默认 compose.yml + 自动加载的 compose.override.yml 使用 React Umi 开发服务，入口为 http://localhost:5174；检查代理目标 CHEIN_BACKEND_URL，容器内不能使用后端默认 loopback。
  • 仅基础 Compose 或显式生产组合使用 Nginx 静态资源，映射为 http://localhost:5173；生产组合需先通过配置检查。
  • 后端：http://localhost:8000
  • OpenAPI：http://localhost:8000/api/v1/openapi.json

生产环境变量​

生产部署前，在 Nacos runtime/bootstrap data ID 中配置：

  • SECRET_KEY
  • FIRST_SUPERUSER_PASSWORD
  • PostgreSQL owner/runtime URL
  • Redis URL
  • BACKEND_CORS_ORIGINS
  • UPLOAD_DIR
  • UPLOAD_MAX_SIZE_MB
  • UPLOAD_ALLOWED_EXTENSIONS
  • STORAGE_PROVIDER
  • 当 STORAGE_PROVIDER=s3 时的 S3_BUCKET、访问密钥和端点

根目录 .env 只配置 Nacos 地址、命名空间、账号密码、Group、Data ID 和超时。完整模板见 deploy/nacos/；不要将真实 Nacos YAML 提交到 Git。

数据库迁移​

cd backend
uv run python -m app.modules.migrate --edition suite
uv run python -m app.initial_data

生产启动顺序、角色权限、初始化数据和 Nacos 配置见后端启动、数据库初始化与 Nacos 配置。不要只执行平台 Alembic 命令来代替 Edition 编排器。

文件存储​

默认使用本地存储，文件元数据保存在 fileasset 表中。Compose 已将后端 /app/backend/uploads 挂载到 app-uploads volume，重启容器后文件不会丢失。

要使用 MinIO 或其他 S3 兼容服务：

  1. 设置 STORAGE_PROVIDER=s3，并填写 S3_ENDPOINT_URL、S3_BUCKET、S3_ACCESS_KEY_ID、S3_SECRET_ACCESS_KEY。
  2. 生产环境建议预先创建 bucket 并关闭自动创建。

应用下载接口始终执行文件权限校验；S3 文件还可以从 GET /api/v1/files/{file_id}/download-url 获取默认 300 秒有效的预签名 URL，可用 S3_PRESIGNED_URL_EXPIRE_SECONDS 调整。

React 静态资源交付​

当前 frontend/Dockerfile 构建 @chein/web-pro，复制 apps/web-pro/dist 到 Nginx；不是 Vben 的 dist。frontend/nginx.conf 提供 SPA fallback、同源 /api 反代，并对 Agent /api/v1/agent-ui/chat 关闭代理缓冲。

React 请求基址固定为同源 /api/v1；开发代理与生产 Nginx 是两条不同配置链路。

变更 Edition 时先使用根目录 pnpm build:edition -- --edition <edition> 生成一致的 Manifest/契约/前端制品，再校验镜像和实际服务。

显式生产组合示例（先验证配置，不能把命令存在当作部署通过）：

docker compose -f compose.yml -f compose.production.yml config

2026-09-20 本地只读检查：默认 docker compose config --quiet 因根目录 .env 缺失而失败； 显式生产组合的 config --quiet 因 adminer 没有 image/build 而失败。生产 override 仍列出 db/mailcatcher/adminer/redis 的端口重置，但基础 Compose 已将这些依赖外置，因此不能 把该组合写成当前可直接部署。本次只记录问题，不创建 .env、填写凭据或修改编排。 真实启动、发布/回滚、镜像扫描/签名与浏览器 E2E 均未在本次执行。
