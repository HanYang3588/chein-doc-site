后端启动、数据库初始化与 Nacos 配置

本文记录当前代码的真实启动顺序，以及如何把运行配置移出 Git。当前事实以 backend/app/core/config.py、backend/scripts/prestart.sh、compose.yml 和 backend/app/modules/migrations.py 为准。

1. 当前启动链路​

Compose 启动时，顺序是：

prestart
  1. 从 Nacos bootstrap data ID 读取独立管理员数据库配置
  2. 等待外部 PostgreSQL 可连接（最多约 5 分钟）
  3. 用 PostgreSQL 超级管理员执行 app_runtime 角色/权限幂等授权
  4. 按 APP_EDITION 执行模块迁移
  5. 再次授权，让新表对 app_runtime 可用
  6. 从 Nacos runtime data ID 读取运行时配置并幂等播种平台初始数据
        ↓
backend / outbox-worker / schedule-worker

API 进程本身不会创建表。FastAPI lifespan 只读取构建 Manifest、配置事件投递，并校验数据库中的模块运行时状态；因此生产环境不能只启动 API 而跳过 prestart。

启动关键配置​

下表区分“代码没有默认值、启动必需”和“有默认值但生产应显式设置”的配置：

类别变量状态用途
应用PROJECT_NAME必填应用标识
应用SECRET_KEY有随机默认值；生产必填且必须稳定JWT、MFA、审计签名
应用ENVIRONMENT有默认值；生产必填环境和默认密钥校验策略
EditionAPP_EDITION有默认值；构建和运行必须一致选择模块组合，不放入 Nacos
EditionBUILD_MANIFEST_PATH可选；生产建议必填校验不可变构建产物
数据库管理员POSTGRES_ADMIN_URL（bootstrap data ID）新部署必填；旧部署兼容 bootstrap POSTGRES_URL数据库检查、角色授权和模块迁移；角色授权需要真实 SUPERUSER
数据库 runtimePOSTGRES_URL（runtime data ID）必填API、Worker、初始化数据的最小权限账号
数据库 runtime roleAPP_RUNTIME_DB_USER、APP_RUNTIME_DB_PASSWORD（bootstrap data ID）必填仅供 prestart 创建/更新最小权限数据库角色
首个管理员FIRST_SUPERUSER、FIRST_SUPERUSER_PASSWORD必填首次幂等播种管理员

API、Worker 和迁移统一通过完整 PostgreSQL URL 连接，不依赖 db 容器名。管理员与运行连接应指向同一服务器和数据库，使用各自的账号。

app.backend_pre_start、app.platform.provision_db_roles、app.modules.migrate 的 CLI 在创建数据库 Engine 前自动选择 chein-backend-bootstrap.yaml，优先使用其中的 POSTGRES_ADMIN_URL；显式环境变量 NACOS_CONFIG_DATA_ID 可指定自定义 bootstrap 名称。无需每次更改普通 POSTGRES_URL 或在命令前切换 Data ID。旧部署未设置管理员 URL 时，仍使用已有 bootstrap 连接。管理员 URL 只保存于私有 bootstrap Data ID，API、Worker 和 app.initial_data 读取 runtime Data ID 的普通 POSTGRES_URL。

启动时传入参数​

启动参数通过环境变量传入，不需要修改 Python 启动命令。Nacos 的连接参数是启动引导配置，必须在进程启动前提供：

NACOS_ENABLED=true \
NACOS_SERVER_ADDR=127.0.0.1:8848 \
NACOS_USERNAME=nacos \
NACOS_PASSWORD='replace-with-secret' \
NACOS_NAMESPACE= \
NACOS_CONFIG_GROUP=CHEIN \
NACOS_CONFIG_DATA_ID=chein-backend-runtime.yaml \
uv run fastapi run app/main.py --host 0.0.0.0 --port 8000

NACOS_USERNAME 和 NACOS_PASSWORD 也必须通过启动环境变量、根目录 .env 或部署平台 Secret 注入；它们不会从 Nacos 配置中读取。命令行直接写密码会进入 shell history 或进程列表，生产环境不要这样做，优先使用 .env（已被 Git 忽略）或 Secret。

根目录 .env 只保存这些 Nacos 引导变量；数据库、Redis、管理员、OIDC、对象存储及业务开关均从 Nacos 读取。启动时显式传入的环境变量仍优先于 Nacos，适合故障排查时的短期覆盖。

按功能还需要准备：BACKEND_CORS_ORIGINS/FRONTEND_HOST、Redis 配置、SMTP、OIDC、对象存储、监控等。它们多数有默认值或只在启用对应功能时才需要，但生产环境仍应显式审查，尤其是 STORAGE_PROVIDER=s3 时的 S3 参数和启用 OIDC 时的客户端密钥。

2. 数据库、表和初始数据​

首次部署​

  1. 外部 PostgreSQL 只负责提供数据库和用于角色授权的超级管理员连接，不负责业务表。
  2. python -m app.modules.migrate --edition <edition> 由 Edition 编排器按依赖顺序执行 Platform、Items、ERP 等模块迁移。每个命名空间有独立的 Alembic version table，并使用 PostgreSQL advisory lock 防止并发迁移。
  3. python -m app.initial_data 调用 app.platform.bootstrap.init_db，创建或补齐默认租户、Standard 套餐、租户模板、首个超级管理员、部门、角色、菜单/权限、字典、系统参数、存储/SMS/邮件渠道和站内信模板。该步骤是幂等的，不应被当作“清库重建”。
  4. 初始化后，API 启动时会拒绝未打包、未迁移或未 ready 的模块。

手工本机 PostgreSQL（不使用 Compose）可以执行：

cd backend
uv run python -m app.platform.provision_db_roles
uv run python -m app.modules.migrate --edition suite
uv run python -m app.platform.provision_db_roles
uv run python -m app.initial_data
uv run fastapi dev app/main.py

生产部署应使用与镜像相同的 Edition 和 Manifest；不要只执行 alembic upgrade head 来代替 Edition 编排器。

重启、升级和回滚​

  • 重启：迁移和播种会再次检查当前状态，已完成内容不会重复创建。
  • 升级：先发布包含迁移的镜像，再运行一次 prestart；迁移成功后才放行 API/Worker。
  • 失败：查看模块运行时状态和迁移日志，修复后重新运行同一 Edition；不要手工删除 alembic_version_* 表。
  • 回滚：遵循对应迁移的 downgrade/发布回滚方案；不要用 create_all 或启动时自动建表替代迁移。

3. 当前配置是否会进 Git​

当前 .gitignore 忽略 .env 和其他 .env.*，只保留 .env.example。因此：

  • .env 只能保存连接 Nacos 所需的 bootstrap 参数；不要放数据库、Redis、OIDC、S3 或管理员配置。
  • .env.example 和 deploy/nacos/*.example 只能放占位符，不能放真实密码、Token 或生产连接串。
  • 生产环境应由部署平台注入 .env 中的 Nacos 凭据；Nacos 控制台中保存运行配置。

4. 已实现的 Nacos 接入方式​

当前后端已经接入 nacos-sdk-python==3.2.0，与 Nacos Server 3.2.4 对齐：

  • app.core.config 创建 Settings 前，从 Nacos 拉取 YAML 作为默认配置。
  • 配置优先级为：环境变量 / .env > Nacos 配置 > Settings 代码默认值。
  • FastAPI lifespan 启动时注册 chein-backend 服务，退出时注销临时实例。
  • Nacos 不可用或 data ID 不存在时，NACOS_CONFIG_REQUIRED=true 会 fail-closed。
  • NACOS_ENABLED=false 时只能用于诊断；正常部署必须保持 Nacos 必填。

.env 已收敛为 Nacos bootstrap 参数，因此不会再意外覆盖运行配置。NACOS_SERVICE_* 属于服务注册配置，在 Nacos runtime data ID 中管理；Nacos 的连接地址、命名空间、账号、密码、group、data ID、超时与是否必需仍必须在 .env 或部署平台 Secret 中提供。

Nacos 连接信息本身仍必须由环境变量提供；应用配置不应依赖 Nacos 再去发现 Nacos。

Nacos 官方 Python SDK 支持 namespace、group、data ID、用户名/密码或 AccessKey/SecretKey，并支持配置监听和本地快照。nacos-sdk-python

配置组织：

namespace: chein-${ENVIRONMENT}
group: CHEIN
data_id: chein-backend-runtime.yaml

迁移脚本使用 chein-backend-bootstrap.yaml，API 和 Worker 使用 chein-backend-runtime.yaml。两个 data ID 分别维护管理员连接和运行连接；API/Worker 不依赖 Compose 服务名，且不会获取管理员凭据。bootstrap 的新增字段见上方“启动关键配置”和对应模板。

手动在 Nacos 控制台创建以下 YAML 配置，类型选择 YAML、Group 选择 CHEIN：

deploy/nacos/chein-backend-bootstrap.yaml.example -> chein-backend-bootstrap.yaml
deploy/nacos/chein-backend-runtime.yaml.example   -> chein-backend-runtime.yaml

先将模板中的占位符改成真实值，再复制 YAML 内容到对应 Data ID。需要脚本发布时，可使用：

cd backend
uv run python scripts/publish_nacos_config.py \
  --config-file ../deploy/nacos/chein-backend-runtime.yaml \
  --data-id chein-backend-runtime.yaml

生产环境把发布脚本替换为 CI/CD 或 Secret 管理系统调用；不要把 .env、Nacos 导出文件或真实密钥提交 Git。

将非敏感配置（CORS、日志、限流、功能开关）与敏感配置（SECRET_KEY、数据库密码、OIDC/S3/SMTP 密钥）分开管理。共享环境的 Nacos 必须启用认证、TLS、最小读取权限和审计；更稳妥的做法是 Nacos 只保存密钥引用，真实值放 Secret、Vault 或 KMS。

配置变更策略​

当前配置在导入 app.core.config 时读取一次；没有实现运行时热更新。以下变量必须由部署环境提供，不能依赖 Nacos 自己：

NACOS_SERVER_ADDR
NACOS_NAMESPACE
NACOS_CONFIG_GROUP
NACOS_CONFIG_DATA_ID
NACOS_USERNAME / NACOS_PASSWORD（或 AccessKey / SecretKey）

数据库连接、SECRET_KEY、数据库密码和 Edition 不支持热更新，配置变更采用滚动重启。Nacos 配置监听 API 暂未接入，避免修改已创建的数据库 Engine 和安全上下文。

不要让 Nacos 客户端参与迁移事务，也不要让 API 在每个请求中读取 Nacos。Nacos 是配置源，不是数据库迁移锁、租户配置或业务表的替代品。

5. 建议的落地顺序​

  1. 发布 bootstrap/runtime 两个 data ID。
  2. 将 NACOS_ENABLED=true 写入部署环境。
  3. 发布流程固定为：拉取配置 → 校验必填项和禁止默认值 → 运行 prestart → 健康检查 → 放行 API/Worker。
  4. 为该单一环境使用独立 namespace；后续需要多环境时再拆 namespace。
  5. 只有出现“无需重启的低风险配置”这一明确需求时，才评估监听和热更新。

6. 已知限制​

  • 当前 Compose 不再启动 Nacos、PostgreSQL、Redis 或 MinIO；这些服务必须是可访问的外部依赖，并在 Nacos 中配置连接信息。
  • 模板中的所有 replace-with-* 值都必须替换；非 local 环境应在进入进程前完成配置校验。
  • BUILD_MANIFEST_PATH 和 APP_EDITION 属于发布产物/组合事实，不应由普通运行时配置随意热切换。
