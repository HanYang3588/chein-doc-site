ERP 业务知识库（面向 AI / RAG）

状态：操作与事实说明。内容以当前工作区代码为唯一事实源。

适用范围：backend/app/modules/erp 已实现的轻量进销存 ERP。

本目录不是设计文档（设计见 erp-prd 和 erp-trd）， 而是给人和 AI 检索用的业务事实 + 表位置 + 数据流转 + 排障说明。目标场景： "某个业务问题该查哪张表"、"这笔数据是怎么流转出来的"、"这个报错是什么原因"。

2. 系统边界​

  • 后端模块：backend/app/modules/erp，API 前缀 /api/v1/erp（module.py 的 api_prefix）。
  • 前端入口：frontend/apps/web-pro/src/pages/erp，菜单路径以 /erp/... 开头（菜单见 backend/app/platform/bootstrap_navigation.py）。
  • 数据所有权：全部业务表位于 PostgreSQL schema erp，由 ERP 模块独占（module.py 的 migration.owned_tables 共 40 张表）。
  • 其他模块不得直接读写这些表；对外只暴露 public_api 的 DTO / 事件。
  • Agent 的只读统计口：/api/v1/erp/internal/agent/v1/statistics/{summary,time-series}， 需要平台签发的委托上下文（X-Chein-Agent-Context），权限 erp:statistics:query。

3. 查询数据前必须知道的四件事​

  1. 租户隔离：每张表都有 tenant_id，RLS policy 为 tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::uuid。 应用侧由 ErpTenantUnitOfWork 在事务内 set_config('app.tenant_id', ...)。 手工 SQL 必须显式 WHERE tenant_id = '...'；用 app_runtime 角色连接时还要先设置 app.tenant_id，否则会被 RLS 过滤成空结果。
  2. 不是只看租户：单据还有 owner_id（业务员）与仓库授权 （erp.warehouse_user_grant）。普通用户只看到自己 owner 的单据，以及自己获授权仓库 相关的单据；is_superuser 不受这两个限制。
  3. 金额与数量精度：金额 NUMERIC(20,4)，数量 NUMERIC(20,6)，计算统一 ROUND_HALF_UP。数据库里是 Decimal，不是浮点；不要在 SQL 里用 float 中转。
  4. 只追加的两张表：erp.stock_ledger、erp.document_action_log 不允许修改或删除 （应用层 ErpTenantUnitOfWork 会拒绝），历史修正一律靠新增反向记录。

4. 单据的公共结构​

所有业务单据（采购/销售/库存/收付款）都是"表头 + 明细"两张表，字段含义一致：

字段含义
no单号，规则 前缀 + YYYYMMDD + 6 位序号，由 erp.document_sequence 按天分配
status只有 draft / approved 两种取值
version乐观锁版本，命令接口必须带 expected_version，每次状态变更 +1
business_at业务时间（带时区），参与统计与列表过滤
owner_id业务归属人，列表/导出的数据范围依据
created_by / updated_by / approved_by / reversed_by各动作的操作人
approved_at / reversed_at各动作发生时间
settled_amount已结算金额（采购入库/退货、销售出库/退货、收付款才有）

单号前缀：CGDD 采购订单、CGRK 采购入库、CGTH 采购退货、XSDD 销售订单、 XSCK 销售出库、XSTH 销售退货、QTRK 其他入库、QTCK 其他出库、 KCDB 库存调拨、KCPD 库存盘点、FKD 付款单、SKD 收款单。

5. 状态与"反向"的语义​

  • draft：可编辑、可删除、可挂附件；此时尚未影响库存和结算金额。
  • approved：已过账（库存单据）或已核销（收付款单）；不能再改内容。
  • 反向（reverse）不是新增一张红字单：接口把单据 status 改回 draft、version + 1， 同时写入方向相反的 stock_ledger 分录（ledger_type 形如 *_reversal， reversal_of_id 指向原分录），或把 settled_amount 扣回。 因此"查已审批历史"要看 document_action_log，不能只看 status。
  • 反向有前置条件（下游单据、已结算、库存不足等），详见各业务文档的"失败原因"小节。

6. 演示素材（虚构）​

demo/（未发布资料） 的 外部资料/（未发布资料） 提供一整套明确声明为虚构的 往来单据样张，按"一件单据一个文件"编排，覆盖采购、到货与质量、采购结算、运输、 销售与发货物流、销售结算、主数据、月末与审计八个环节。文件名为中文，写法按真实单据 排版（表头、明细、签章栏），可以直接当模板用。

配套两份内部整理材料，不混入样张：

  • demo/外部单据与ERP字段对照.md（未发布资料）：每张外部单据落到 erp 库的哪张表、哪个字段，以及哪些条款/单据没有落点；含造数用的演示主数据。

  • demo/术语表.md（未发布资料）：中 / 英 / 缩写对照与"系统里有没有"。

  • 它们描述的是外部世界（供应商说他们是谁、报了什么价），不是 erp schema 里的行。

  • 造数与检索时请保留文件末尾的归档备注，避免把演示样张当成系统事实。

  • 已有通用造数脚本 backend/scripts/seed_erp_demo_data.sql 与本目录的实体并不一致， 两者关系见 演示资料总览（未发布资料） 第 6 节。
